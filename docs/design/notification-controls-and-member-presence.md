# 업데이트 알림·전체 무음·멤버 접속 상태·트레이 표시

2026-11-16. 상태: **승인된 설계 — Q1~Q8 개별 결정 및 Q9 문서 전체 확정, 구현 보류**. 사용자는 ‘설계 확정·구현은 보류’를 선택했다. 이번 작업은 설계만이며 제품 코드·의존성·버전·배포 설정을 변경하지 않는다. 구현 시작과 출시 버전은 별도 승인 사항이다.

기준 구현은 main `3af9cdf72daaf378647c7535dda57b4c4d43b17d`의0.8.1이다. 기존 [앱 업데이트](lan-app-updates.md), [LAN 공유](lan-project-sharing.md), [공유 변경 알림](shared-change-notifications.md), [날짜 알림](reminders-and-hierarchy.md), [로그인 자동 실행](windows-login-startup.md)의 대체되지 않은 계약은 유지한다. 이 문서는 네 변경의 공통 설계만 담고 기존 계약을 복제하지 않는다.

## 목적과 범위

추가 요청인 [호스트·멤버 도움말 창](host-member-help.md)은 H8 승인 후 별도 구현 요청으로 0.8.2에서 진행한다. 도움말 구현 승인은 이 문서의 알림 제어·접속 상태 기능 구현을 뜻하지 않으며 이 문서는 계속 구현 보류다.

트레이에서 실행 중인 멤버도 새 업데이트를 알아차리고, 호스트는 최근 통신 중인 멤버를 확인한다. 각 PC는 알림을 한 번에 끌 수 있으며 자동 실행 메뉴는 처음부터 실제 Windows 상태를 표시한다. 일정·공유 권한·설치 동작·기존 개별 알림 설정은 유지한다.

범위 밖: 앱이 완전히 종료된 상태의 알림, Windows 서비스, 외부 서버, 업데이트 강제 설치, 접속 이력 분석·사용자 활동 감시, 이미 Windows에 전달한 알림의 일괄 삭제, OS 방해 금지 설정 변경. 알림을 끄더라도 동기화·다운로드·UPDATE 버튼·저장 결과·필드 오류·DB/설치 오류 안내는 동작한다.

## 현재 구현과 근거

- [업데이트 서비스](../../src/main/updates/service.ts)는 연결·재연결/5분 주기로 인증된 새 배포를 확인한다. 상태 변경은 [UPDATE 팝오버](../../src/renderer/components/UpdatePopover.tsx)에 전달하지만 Windows 알림은 없다. 변경 callback은 진행률에도 발생하므로 단순 연결하면 중복 발송된다.
- [공유 호스트](../../src/main/sharing/host.ts)의 snapshot/변경 동기화는 IP·설치본 자격·승인 취소를 확인하고 device를 식별한다. [동기화](../../src/main/sharing/sync.ts)는 정상 시 약2초 주기, 요청5초 제한, 실패 시 간격이 늘어난다. TCP 연결 수는 현재 사용 멤버 수가 아니며, 승인 목록에는 마지막 통신 정보가 없다.
- [트레이](../../src/main/tray.ts)는 우클릭 때 startupState를 비워 미체크 메뉴를 먼저 표시하고, 조회 뒤 닫고 다시 연다. 실제 설정 변경이 아니라 미확인 상태의 잘못된 표현이다. [Windows 조회](../../src/main/windows-login-startup.ts)는 별도 PowerShell 프로세스와10초 제한을 사용한다.
- [날짜 알림 엔진](../../src/main/reminders/engine.ts)은 미처리된 오늘 알림을 다시 평가한다. 엔진을 멈추기만 하면 무음 해제 후 발송될 수 있다. [공유 수신함](../../src/main/db/sharing/change-inbox.ts)은 기존 개별 OFF에도 자료·cursor를 갱신하고 ON 후 첫 수신을 기준점으로 삼는다. [OS sender](../../src/main/reminders/native.ts)는 전달 결과와 클릭 callback을 관리하며 전역 무음은 없다.

## 접근 방식

Q1~Q8을 충족하는 접근은 **main의 공통 발송 정책 + 알림별 영속 억제 이력 + 기존 동기화 기반 접속 추정**이다. 아래 기술 구체화는 작성자가 제안했고 Q9 문서 전체 승인으로 확정됐다. Q1~Q8의 직접 답변과 기술 제안의 출처는 구분한다.

화면에서만 알림을 숨기는 방식은 트레이 실행 중 OS 발송을 제어하지 못한다. 모든 타이머를 정지하는 방식은 무음 기간의 미처리 알림이 남아 Q5에 맞지 않는다. 새 heartbeat 프로토콜은 가능하지만 현재 인증된2초 요청으로 접속 추정이 가능하고 구버전 멤버도 그대로 사용할 수 있어 추가하지 않는다.

## 업데이트 알림

1. 기존 보안 검사를 통과한 새 배포를 멤버 main이 확인한다. 현재 설치 버전 이하·호스트/개인 역할·인증 실패·배포 없음은 대상이 아니다. 기존 확인 주기와 다운로드/설치 계약은 바꾸지 않는다.
2. 중복 방지 키는 논리 hostId와 정식 버전이다. 주소·토큰·publicationId가 바뀌거나 같은 버전을 재배포해도 반복하지 않는다. 보안 검증에는 기존 pin/자격/공개 세대 검사를 그대로 사용하며, 알림 키로 신뢰를 대체하지 않는다.
3. OS 호출 전에 알림 전용 이력을 영속 기록한다. 후보·전송 시도·무음 억제·전달 결과를 구분한다. `observed.json`의 재생 공격 방지 순번을 알림 이력으로 재사용하지 않는다.
4. 알림 예시: 제목 ‘Planrail 업데이트’, 본문 ‘새 버전 0.8.2를 사용할 수 있습니다. 눌러서 확인하세요.’ 실제 배포 버전을 사용하고 프로젝트/자격 정보는 포함하지 않는다. Windows의 배너·소리 정책은 그대로 적용된다.
5. 같은 버전은 OS 전달 실패·결과 불명에도 자동 반복하지 않는다. 이력 기록 실패 시 발송하지 않고 앱 안에 지속 오류를 표시한다. OS 전달의 정확히 한 번 표시를 보장하지 않으며, 기록 후 OS 호출 전 비정상 종료 시 알림이 누락될 수 있지만 UPDATE 버튼은 유지한다. 기존 공유/날짜 알림의 실패 재시도 정책을 임의 변경하지 않는다.
6. 클릭은 제한된 main→renderer 요청으로 창을 복원하고 팝오버만 연다. 기존 UPDATE 버튼 클릭 handler를 재사용해 다운로드가 시작되면 안 된다. 열려 있는 편집/공유 설정의 입력을 버리거나 강제 닫지 않는다. 모달 때문에 팝오버 표시가 불가능하면 요청을 보류하고 모달 종료 후 최신 상태로 한 번 연다.
7. 오래된 알림 클릭 시 최신 호스트·승인·배포 상태를 확인한다. 중지/철회/교체된 파일을 클릭 payload로 다운로드하지 않는다. 새 배포가 있으면 현재 버전 안내, 이미 최신이면 최신 상태 안내, 연결 불가이면 기존 비활성/오프라인 설치 규칙을 따른다. 알림 클릭만으로 설치하지 않는다. 앱을 완전히 종료한 뒤 과거 알림으로 앱을 깨우는 기능은 추가하지 않는다.
8. 명시적 호스트 연결 해제 시에도 이름·주소·토큰 없는 최소 중복 방지 키(hostId/버전/처리 상태)는 해당 PC에 유지해 같은 호스트 재승인만으로 반복 알리지 않는다. 실제 수신 자료와 접속 자격의 삭제 정책은 유지한다.

## 전체 알림 끄기

트레이 표시:

```text
● 연결 상태
────────
About
✓ Windows 시작 시 자동 실행
□ 전체 알림 끄기
────────
Open
Exit
```

체크 여부는 실제 저장된 값이다. 초기값은 false이며 기존 설치 업그레이드에서도 기존 알림을 임의로 끄지 않는다. 새 체크가 설정되는 동안 항목의 중복 조작을 막고 저장 실패는 성공으로 표시하지 않는다. 기존 개별 설정은 별도로 남아 `전역 허용 AND 개별 허용 AND 기존 자격 조건`을 모두 만족할 때만 발송한다.

### 저장·발송 경계

- 개인 프로필의 SQLite에 전역 muted 값과 변경 세대, 필요한 무음/재개 기준을 저장한다. 날짜 알림 키·공유 cursor·업데이트 알림 이력과 원자적 정리가 가능하도록 main이 소유한다. renderer는 제한된 조회/설정만 사용하며 파일·DB 권한은 받지 않는다.
- 무음 전환 요청을 받으면 새 OS 발송을 즉시 잠그고 설정과 대기 이력 정리를 commit한다. 저장 실패 시 오류와 실제 이전 설정을 복원한다. 시작 시 설정을 읽기 전에는 OS 발송을 시작하지 않으며, 저장소 오류를 빈 기본 설정으로 덮어쓰지 않는다.
- 발송 직전 최신 설정/세대를 재확인한다. 이미 OS에 넘긴 알림은 회수됐다고 보장하지 않으며 무음 이후 새 발송을 차단한다. Windows 알림 센터의 기존 항목은 자동 삭제하지 않는다. 기존 항목 클릭도 데이터·권한·미저장 보호를 유지한다.
- 의도적 무음은 `submitted`나 `failed`로 위장하지 않는다. 각 이력에 억제/취소를 명시하고 실패 수·수동 재전송 대상에 포함하지 않는다. 저장된 설정은 앱 종료·트레이·재실행·업데이트를 거쳐 유지한다.

### 무음 중과 해제 후

| 종류 | 무음 중 | 해제 후 |
| --- | --- | --- |
| 개인 날짜 알림 | 오늘 도래한 알림을 키별 억제로 기록. 발송 대기·실패 재시도도 취소 | 해제 시점까지 도래한 기존 후보는 억제 확정 후 재개. 이후 도래한 알림 및 이후 날짜/시각 변경으로 생긴 새 후보는 기존 규칙 적용 |
| 공유 날짜 알림 | 연결·자격 검사는 유지하고 최신 자료의 해당 후보를 억제. 연결이 없으면 기존처럼 발송하지 않음 | 연결된 최신 자료로 재개 기준 확정. 미접속이면 첫 정상 동기화에서 당시 이미 도래한 후보를 억제한 뒤 재개 |
| 공유 변경/종료 | 최신 자료·cursor는 계속 반영하고 대기 발송은 취소. 개별 ON/OFF 값은 보존 | 첫 정상 수신을 기준점으로 삼아 그때까지의 변경을 소급하지 않고 이후 변경만 발송 |
| 새 업데이트 | 유효한 배포 확인과 UPDATE 표시는 계속. 발견 버전은 무음 억제로 기록 | 해제 후 첫 정상 버전 조회를 기준점으로 삼아 현재 알려진 버전은 소급하지 않고 이후 새 버전부터 발송 |

무음 상태에서 앱이 종료/절전돼 평가하지 못한 후보도 다음 실행과 무음 해제 경계에서 억제한다. 개인 날짜 후보의 기준 확정은 같은 DB 트랜잭션에서 수행하며 이후 생성/수정까지 영구 차단하지 않는다. 공유/업데이트의 첫 정상 조회 기준은 영속 저장해 재실행으로 빠지지 않도록 한다. 이 방식은 네트워크 단절 중의 정확한 발생 시각을 추측하지 않으며, 해제 후 첫 정상 조회까지의 변경도 소급하지 않는 보수적 재개 규칙이다.

무음 해제 시 연결이 가능하면 기존 직렬화 경로로 동기화·버전 조회를 즉시 요청해 기준점을 확정한다. 연결이 없거나 실패하면 재개 기준 확정은 보류하고 재연결 시 수행한다. 무음 해제가 실패한 네트워크 요청 때문에 원래 무음 상태로 되돌아가지는 않는다. 개인 알림의 재개는 호스트 연결을 기다리지 않는다.

전체 무음은 새로운 기능의 알림만 차단하는 상위 설정이다. 기존 ‘공유 변경 알림’이 OFF이면 전체 무음을 풀어도 그 기능은 OFF다. 사용자가 이후 일정을 수정해 새로운 알림 예정이 만들어지는 동작은 기존 날짜 알림 계약을 따른다. DB/통신/설치 오류와 입력 오류는 별도 앱 안내로 유지한다.

## 호스트의 접속 멤버 표시

- 기존 [공유 설정](../../src/renderer/components/SharingSettings.tsx)의 참여자 행을 확장한다. 이름·IP·수정/승인 취소/삭제 한 줄 배치와 승인 배지는 유지한다. 접속 배지와 마지막 확인 시각은 별도 보조 줄에 둔다. 목록 위에는 ‘연결된 멤버 N명’을 표시하며 호스트 자신과 승인 대기 PC는 세지 않는다.
- 녹색 ‘연결됨’과 중립색 ‘연결 끊김’을 텍스트와 함께 사용한다. 승인 상태와 혼동하지 않는다. 현재 실행 중 통신 기록이 없으면 시각은 ‘확인 기록 없음’. 시각은 호스트 PC의 현지 시각이며 접근성 이름에도 상태를 포함한다.
- 기존 `/v1/changes/sync`의 성공 응답과 `/v1/snapshot`의200/304 응답만 갱신 근거로 사용한다. IP·토큰·active 자격을 통과하고 정상 응답 처리를 완료한 deviceId에만 기록한다. 요청 도착·pairing·401/403·조회 오류·단독 파일 다운로드로 갱신하지 않는다. 이것은 호스트가 확인한 최근 정상 통신이며 멤버의 UI 반영 완료나 사용자의 실제 조작을 보증하지 않는다.
- host 프로세스 메모리에 마지막 정상 확인의 단조 시각과 표시용 벽시계를 기록한다. `경과 <= 10초`이고 호스트 공유가 정상이며 승인이 유효한 경우만 연결됨이다. 날짜/시간 변경으로 만료가 늘어나지 않는다. 응답 완료 callback은 현재 호스트 세대·권한을 다시 확인한다.
- 늦어도1초 이내에10초 초과를 표시하는 만료 타이머를 둔다. 패널이 열려 있지 않아도 상태를 만료시키고, 전체 목록을 조회할 때도 경과를 재계산한다. 패널이 열린 동안 별도의 수동 새로고침은 필요 없다. 승인 취소·삭제·IP 변경·호스트 중지/오류·절전 시 해당 상태를 즉시 무효화한다. 복귀/재시작 후 새 통신 전에는0명이다.
- 마지막 시각은 접속 분석 이력이 아니라 현재 실행 세대의 표시용 값이다. 재시작/공유 재개 시 과거 기록을 연결 근거로 복구하지 않는다. 등록·승인은 영속 유지한다. 같은 PC의 여러 요청은 deviceId로 한 명만 센다. 멤버에게 다른 멤버의 IP/접속 목록을 전송하지 않는다.
- 기존 멤버의2초 주기를 재사용하므로0.8.0/0.8.1도 새 호스트의 접속 목록에 표시할 수 있다. 새 프로토콜이나 별도 heartbeat는 추가하지 않는다. 최신 호스트의 표시 기준10초와 기존 멤버의 내부 freshness7초는 서로 다른 화면 판정이며 일치한다고 보장하지 않는다.

## 자동 실행 트레이 메뉴

시작 조회는 창 표시·DB 준비를 기다리게 하지 않는 비동기 사전 조회다. 우클릭에서는 실제 Windows 등록과 사용 중지 상태를 새로 읽고 결과가 확정된 메뉴를 한 번만 연다. 조회 중 잘못된 미체크 메뉴를 먼저 띄우거나, 열린 메뉴를 자동으로 닫았다 다시 열지 않는다. 사전 캐시는 진행 중 조회를 공유하는 데 쓸 수 있지만 우클릭의 최신 조회를 영구 생략하지 않는다.

기존10초 조회 상한을 유지하고 실패/기한 초과 시 체크박스 대신 비활성 일반 항목 ‘자동 실행 상태 확인 불가’를 표시한다. 전체 알림 끄기·Open·Exit·나머지 메뉴는 계속 사용할 수 있다. 실제 전역 무음 상태도 미확인/오류면 임의의 체크 해제로 표시하지 않는다. Windows에서 사용 중지했다면 미체크가 올바른 상태이며 이번 수정이 이를 강제로 켜지 않는다.

중복 우클릭 조회는 하나로 합치고 마지막 요청만 메뉴를 표시한다. 우클릭 후 앱/트레이 종료 또는 왼쪽 클릭으로 창 열기가 발생하면 늦은 응답으로 메뉴를 띄우지 않는다. 메뉴 토글 처리 중에는 설정 쓰기와 조회를 직렬화해 오래된 결과가 새 값을 덮어쓰지 않게 한다. 실패 안내는 앱 안에서 제공하며 전체 무음과 무관하다. 개발 실행의 자동 실행 등록 금지는 유지한다.

## 호환·실패 처리·구현자 재량

- 새 호스트에서도 구버전 멤버의 인증·동기화·업데이트 다운로드 경로를 유지한다. 새 Windows 업데이트 알림과 전체 무음 UI는 해당 코드를 포함한 멤버 버전부터 동작한다. 호스트 업데이트만으로 기존0.8.0에 생기지 않는다.
- SQLite migration은 개인 자료·수신 캐시·알림 설정·자격을 보존한다. 실패 시 원본을 보존하고 기존 차단/오류 정책을 따른다. 무음/중복 방지 이력은 알림용이며 업데이트 보안/설치 허가를 대신하지 않는다.
- 세부 테이블/IPC 타입명, 모듈 분리, 기존 스타일 안에서 배지의 정확한 색과 간격은 구현자가 정한다. 새 라이브러리·배포 서버·OS 정책 변경은 요구하지 않는다. UI 문자열/기능 범위와 무음 재개 규칙을 바꾸는 선택은 다시 협의한다.
- 버전 번호와 실제 구현 계획은 아직 정하지 않았다. 지금 문서 검토/승인이 앱 구현 승인까지 의미하지 않는다.
