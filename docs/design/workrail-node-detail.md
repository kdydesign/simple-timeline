## NodeRail

[현재 버전 패널 4안](mockups/workrail-detail-panel.png) · [검색 필드 4안](mockups/workrail-detail-search.png)

| 요청 | 선택지와 수용 기준 |
| --- | --- |
| 1. 환경 다시 검사 | 명시적으로 누른 검사 동안 현재 버전 패널의 상단 보더 안쪽에 2px 진행선을 표시한다. 기존 공식 목록의 1.1초 진행선과 같은 재질을 쓰고 레이아웃 높이를 유지한다. 목록 갱신은 목록 보더만 사용한다. |
| 2. 배지 배치 | 제목 오른쪽에 환경, 관리자 순으로 배치한다. 예: 현재 사용 버전 / Windows / NVM 1.1.11 설치. WSL에서는 기본 버전 / 배포판·기본 사용자 / nodenv 실측 버전. 좁으면 배지 묶음이 다음 줄로 흐른다. 확인 실패나 기존 Node만 있는 경우 이전 관리자 버전을 현재 값처럼 표시하지 않는다. |
| 3. N 위치 | 현재 버전 패널의 장식 N만 기준선에서 3px 올린다. 메뉴 아이콘과 버튼 클릭 영역은 기존 위치를 사용한다. |
| 4. 패널 시안 | A 기본형은 제목·배지 아래에 큰 버전을 둔다. B는 둘째 줄에 버전과 동작을 정렬한다. C는 정보와 동작을 선으로 나눈다. D는 환경·관리자 배지를 한 쌍으로 묶는다. |
| 5. 버전 검색 | A 얇은 테두리, B 캡슐, C 밑줄, D 상단 반사. 입력 가능 상태에 옅은 반투명 면과 선명한 돋보기·글자를 쓴다. 네 안 모두 키보드 포커스에는 강조 윤곽선을 준다. 필터·정렬·검색 동작은 기존 계약을 따른다. |
| 6. 설치된 버전 | 제목을 스크롤 컨테이너 바깥의 고정 행에 놓고 목록 부분만 스크롤한다. 제목은 공식 표 헤더와 같은 테마 토큰의 배경색·알파·블러를 사용한다. 투명 헤더 뒤로 행이 비치지 않게 스크롤 경계를 제목 아래에 둔다. 목록 상단/하단, 긴 목록/빈 목록, 다크/라이트에서 제목 좌표와 두 패널 하단을 비교한다. |
| 10. 최신 관리자 링크 | NodeRail의 관리자 배지 옆에 ‘최신 릴리스 ↗’ 링크를 둔다. Windows 환경이면 공식 nvm-windows, WSL이면 공식 nodenv 페이지를 기본 브라우저에서 연다. 미설치라도 선택 환경이 명확하면 공식 안내를 제공한다. 미선택 상태에서는 먼저 환경을 선택한다. 자동 설치나 버전 호환 판정을 수행하는 동작과 구분한다. |

설치된 버전 제목은 목록의 스크롤 영역 위에 고정하고 공식 목록 헤더의 테마 재질을 공유한다. [레이아웃](../../src/renderer/workrail.css) · [테마 재질](../../src/renderer/forest-crystal.css)

버전 패널에서 환경명과 관리자 배지를 제목 옆에 배치한다. 수동 검사만 상단 진행선을 사용하고, 포커스 복귀 조회와 목록 새로 고침은 이 선을 켜지 않는다. 같은 요청을 중복 실행하지 않고 성공·실패·대상 변경·언마운트 때 해당 요청의 표시를 끝낸다. 상태 설명과 aria-busy를 제공하며 모션 감소 시에는 정지한 선을 쓴다. [NodeRail](../../src/renderer/workrail/NodeScreen.tsx) · [상태 훅](../../src/renderer/workrail/useNodeManagement.ts)

링크는 Main에서 선택한 종류별 고정 HTTPS 주소로 연다. 렌더러에서 URL이나 셸 명령을 전달하지 않는다. 확인 시점의 최신 태그는 각각 v2.0.1과 v1.6.2다. UI에는 고정 버전 번호 대신 항상 최신 릴리스로 연결되는 주소를 쓴다. [nvm-windows](https://github.com/nvm-windows/nvm/releases/latest) · [nodenv](https://github.com/nodenv/nodenv/releases/latest)

## Home

[전환 전·중, 오늘의 일정, 폴더 버튼 시안](mockups/workrail-detail-home.png)

**7. Node 작업 레이어.** Home은 작업 직전 목록과 위젯 크기를 보존하고 해당 위젯 전체를 반투명 레이어로 덮는다. ‘24.22.2 사용’ 아래 실제 단계 안내를 표시한다. 진행 중인 위젯은 중복 클릭과 키보드 진입을 차단하되 다른 패널과 메뉴는 사용할 수 있다. 접근 가능한 상태 안내는 inert 영역 밖에 둔다. 가능한 WSL 취소·로그 동작을 레이어에서 유지한다. 실제 성공 확인 후 최신 목록을 보여주고, 실패는 오류와 복구 동작으로 전환한다. 종료 불명은 성공으로 닫거나 끝없는 스피너만 보여주지 않고 ‘다시 확인’을 제공한다. 메뉴를 바꿔도 같은 작업 상태를 사용한다.

**8. 남은 일수 — 결정.** ‘오늘의 일정’에 이미 포함된 각 행 오른쪽, 공유/개인 배지 다음에 일수를 표시한다. 오늘 종료는 ‘오늘 마감’, 내일은 ‘1일 남음’이다. 휴일을 포함한 달력 일수로 계산한다. 기존 업무 날짜의 `toOrdinal(endDate) - toOrdinal(today)`를 사용하고 로컬 날짜가 바뀌면 갱신한다. 현재 필터·순서·조회 권한을 따르며 만료 일정을 새로 추가하지 않는다. 금요일→월요일은 3일, 월말·윤일·연말과 DST 경계에서도 날짜 차이가 동일해야 한다. 좁은 창에서 이름이 길면 보조 정보를 줄바꿈하고 두 배지는 읽을 수 있어야 한다.

**9. 관리자 폴더 — 지원 범위 결정.** ‘내 개발 환경’ 헤더 우측 폴더 아이콘은 Windows nvm과 이미 실행 중인 WSL의 nodenv를 지원한다. 툴팁과 접근성 이름으로 열 대상을 알린다. 선택한 목적지는 **설치된 Node 버전들이 있는 관리자 데이터 루트**다. Windows 1.x는 검증된 설정 root, 2.x는 InstallRoot, WSL은 선택된 배포판 기본 사용자의 확인된 nodenv root를 탐색기에서 연다. 사용자 AppData·사용자명·.nodenv 경로를 추정하지 않는다. 2.x에서는 nvm.exe 위치와 관계없이 확인된 InstallRoot를 연다.

현재 선택 ID와 검사 상태만 전달하는 제한된 IPC를 두고 Main에서 환경·기본 사용자·디렉터리 소유와 실재 여부를 다시 확인한다. 렌더러 입력 경로, 임의 UNC 호스트, 사용자 셸 명령은 받지 않는다. WSL은 등록한 배포판의 검증된 경로만 탐색기용 경로로 변환한다. 종료 배포판은 버튼을 비활성화하고 ‘환경 시작 후 열 수 있습니다’로 안내한다. 선택이 바뀌었거나 작업 중·검사 실패·관리자 없음이면 실행하지 않는다. 폴더 열기 실패를 인라인으로 표시한다. WSL의 외부 동시 종료 경합은 기존 환경 계약에 따른 실기 검증 항목이다.

## 아이콘과 CI

제품의 [ICO](../../resources/icon.ico)에 승인된 9개 크기를 담았다. Windows 창·작업 표시줄·트레이와 NSIS 설치 프로그램에서 같은 리소스를 참조한다. 16·20px은 별도 벡터를 사용한다. [아이콘 원본 및 크기](../../resources/icon-NOTICE.md)

기준 main f5e2af4의 Windows Application은 E2E 115/116에서 중단했다. 500px 창에서 ‘외 2명’을 찾지 못했다. Windows 실측 참여자 영역의 너비 또는 실제 접힌 수는 실패 로그만으로 확정하지 못했다. Windows 설치·패키지 검증과 배포 업로드는 미실행이다. Ubuntu 앱과 두 OS 하네스는 통과했다. [실패한 Windows 작업](https://github.com/kdydesign/simple-timeline/actions/runs/44460706286/job/135346501145) · [하네스](https://github.com/kdydesign/simple-timeline/actions/runs/44460706727)

Windows footer E2E는 참여자 영역 실측 너비를 기준으로 창을 조절한다. 참여자 영역의 실측 폭, 계산된 표시 수, 알림·배지 경계를 실패 증거로 남긴다. 임계값 사이에 충분한 여유를 둔 영역 너비로 전체·일부·전부 접힘을 재현하고, 전체 인원 = 표시 + 접힘, 긴 버전·알림 비중첩, 키보드 전체 목록을 양 OS에서 검증한다. 실제 레이아웃 결함이면 제품을, 이전 창 너비 가정만 문제면 해당 테스트를 수정한다. 기존 타임아웃과 assertion 범위를 유지하고 같은 SHA의 Windows 설치·업데이트 및 WorkRail artifact 생성까지 확인한다.

## 적용과 검증 순서

1. 선택된 패널 A·검색 D·Home 시안과 버전 저장 폴더를 구현 기준으로 삼는다.
2. 공통 헤더 재질·수동 검사 상태·검색 및 Home 위젯을 연결한다. 다크/라이트, 작은 창, 키보드, 동작 감소를 확인한다.
3. 폴더·공식 릴리스 전용 IPC를 검증한다. 임시 루트와 가짜 opener에서 다른 대상·중지 WSL·잘못된 경로 거절을 검사하고 실제 Windows/WSL 탐색기 동작은 별도 확인한다.
4. footer 실패에 대한 검증을 함께 보정한다. 일회성 프로필과 sandbox로 전체 앱 검사 및 repository harness를 순차 실행한다.

설계와 구현 비교는 이 문서에서 관리한다. 실행 명령과 권한 범위에 변경이 없어 루트 AGENTS.md를 유지한다. 별도 ADR은 작성하지 않고 기존 환경 설계에 이번 선택을 연결한다.
