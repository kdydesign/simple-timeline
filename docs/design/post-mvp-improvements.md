# MVP 이후 개선·오류 대응 — 확정 설계

> 2026-11-05 [Planrail 승인 설계](planrail-improvements.md)가 명시한 선택 날짜·탐색·배율·트레이·화면 변경은 이 문서의 이전 해당 항목보다 우선한다. 구현 상태와 검증은 [Planrail 기록](../implementation/2026-11-05-planrail.md)을 따른다.

승인일: 2026-11-04 (한국 시간). 기준 구현: `3dc20f69932ac7db2c3d7ae590cd27f62f6fcae2`.
상태: **요구사항·상호작용 설계 승인 완료**. 후속 구현 요청에 따라 구현·검증을 진행했다.
현재 결과와 남은 실기 확인은 [구현 기록](../implementation/2026-11-04-post-mvp-improvements.md)을 따른다.
사용자는 프로젝트 [grill-me](../../.agents/skills/grill-me/SKILL.md)와
[grilling](../../.agents/skills/grilling/SKILL.md)의 Q1~Q20에 답한 뒤 최종 정리를 확정하고 문서만 반영하도록 지시했다.

이 문서가 이번 후속 변경의 기준이다. 아래 변경 항목에서는 기존 MVP 설계를 대체한다.
나머지 [도메인 규칙](domain-rules.md), [구조](architecture.md), [저장](storage.md),
[화면](experience.md), [시각화](visualization.md), [배포 정책](../release/policy.md)은 유지한다.
스테이지 1~7의 완료·인수 결과는 과거 MVP의 근거로 보존하며 새 기능의 구현 완료로 해석하지 않는다.

## 테마·아이콘·설치

- **Q1·Q3 — 테마:** 라이트·다크 수동 전환만 제공한다. 초기값은 라이트이며 마지막 선택을 재실행 후에도 유지한다.
  시스템 설정 자동 추종은 선택하지 않았다.
- **Q2 — 아이콘:** 달력과 간트 막대를 표현한 Simple Timeline 전용 시안을 만들고 사용자가 검토해 선택한다.
  선택한 디자인을 설치 파일·앱·작업 표시줄·바로가기에 일관되게 적용한다.
  최초 설계 승인에서는 이미지가 미정이었다. 후속 구현 중 사용자가 **B — 남색 배경의 간결한 간트**를 선택했다.
  최종 자산은 [PNG](../../resources/icon.png)와 [Windows ICO](../../resources/icon.ico)다.
- **Q4 — 설치 완료:** 완료 화면에 기본 체크된 `Simple Timeline 실행`과 `마침` 버튼을 제공한다.
  실행 체크를 해제하고 마치면 앱을 실행하지 않는다. 기존 사용자별 설치·업데이트/제거 후 DB 보존을 유지한다.
  MVP 구현의 one-click·설치 후 실행 끔 방침은 이 완료 화면 요구로 대체한다. 구체 NSIS 설정과 검증 결과는 구현 기록을 따른다.

## 시작 지연의 현상과 목표

**Q5·Q13 사용자 관측:** 설치된 앱의 시작 메뉴 바로가기를 누르면 주 창이 보이기까지 체감 약 40초가 걸린다.
종료 후 재실행해도 같고, 사용자는 프로젝트·일정 개수와 무관하다고 보고했다.
이는 사용자 보고이며 해당 PC에서 측정·재현하거나 원인을 확인한 결과가 아니다.

설계 확정 당시 [bootstrap](../../src/main/bootstrap.ts)은 저장소 초기화 이후 창을 만들고,
[window](../../src/main/window.ts)는 ready-to-show에서 표시한다. 이 순서만으로 DB 검사를 지연 원인으로 단정하지 않는다.
해당 사용자 PC의 40초 원인은 아직 미확인이다. 후속 구현에는 구간별 시작 기록을 추가했다.

**Q20 승인 목표:** 정상 재실행 시 실행 요청부터 주 창 표시까지 **3초 이내**,
일정 조회·편집 가능까지 **5초 이내**를 우선 개선 목표로 삼는다.
같은 Windows PC·같은 데이터에서 반복 측정하고 두 시간을 따로 확인한다.
최초 실행·DB 복구·마이그레이션은 별도로 기록한다. 아직 달성·검증된 수치가 아니다.
기존 Linux 대량 fixture와 달력 집계 벤치마크는 이 설치본 시작 시간의 증거로 사용하지 않는다.

## 날짜 클릭과 편집 패널

**Q7·Q14:** 간트와 달력의 날짜 클릭은 기존 일정 추가 패널을 연다.
시작일·종료일은 모두 클릭한 날짜로 넣는다. 별도 추가 팝업은 만들지 않는다.

- 간트 날짜 눈금과 행의 빈 날짜 영역에서도 추가할 수 있다.
- 프로젝트/일정 행 안에서는 해당 행의 프로젝트를 우선한다.
- 달력이나 간트 날짜 눈금처럼 프로젝트 맥락이 없는 곳에서는 실행 중 최근 선택한 프로젝트를 미리 선택한다.
  선택 이력이 없으면 첫 프로젝트를 사용하고, 패널에서 변경할 수 있다.
- 프로젝트가 없으면 먼저 프로젝트 추가를 안내한다.
- 일정 막대 클릭은 기존 일정 편집이다. 날짜 클릭 진입도 기존 미저장 입력 보호를 따른다.

**Q15 — 날짜 선택기:** 시작일·종료일 클릭 시 해당 입력 옆에 한국어·월요일 시작 달력을 연다.
연·월을 직접 바꿀 수 있고, 날짜 선택 시 입력에 반영한 뒤 닫는다.
기존 YYYY-MM-DD 직접 입력과 0001~9999년 지원을 병행한다.
날짜를 선택한 것만으로 저장하지 않으며 기존 저장 버튼을 사용한다.

## 간트 계층과 고정 헤더

**Q8:** 일정은 프로젝트 아래 한 단계 들여쓴다. 프로젝트 이름 왼쪽 화살표로 접고 펼친다.
처음에는 모두 펼치고 프로젝트별 접힘 상태를 재실행 후에도 기억한다.
이름 클릭은 프로젝트 편집을 유지한다. 접힘은 표시 상태이며 해당 일정은 달력과 전체 날짜 범위에 계속 포함한다.

**Q12:** 상단 전체 도구 모음(모드·연월·프로젝트 목록·프로젝트 추가·일정 추가)을 고정한다.
그 아래 간트 월/일 눈금과 달력 요일도 세로 스크롤 중 계속 보이게 한다.
헤더 높이와 여백을 줄인다. 정확한 픽셀 높이는 이번에 확정하지 않았다.

## 드래그 이동·기간 조절

**Q9:** 간트·달력 모두 양 끝 손잡이는 시작일/종료일을 변경하고, 몸통은 기간을 유지하며 날짜를 이동한다.
소속 프로젝트는 바꾸지 않는다. 드래그 중 예상 날짜를 표시하고 놓으면 한 번 저장한다.
예: 11/1 하루 일정의 오른쪽 끝을 11/3에 놓으면 11/1~11/3의 3일 일정,
몸통을 이틀 이동하면 11/3 하루 일정이다. 저장 전 미리보기와 실제 저장 완료를 구분한다.

**Q16:** 실제 시작·종료일이 보이는 조각에만 해당 끝의 손잡이를 표시한다.
12/1~12/20 일정의 첫 주 끝인 12/6은 실제 종료가 아니므로 종료일 손잡이를 표시하지 않는다.
중간 조각 몸통도 원 일정 전체를 같은 일수만큼 이동한다.
화면 밖 시작·종료는 날짜 입력이나 해당 월로 이동해 수정한다. 간트의 화면 잘림도 실제 일정 끝으로 취급하지 않는다.

**Q10 — 화면·월 경계:** 간트 가장자리에서 자동 스크롤하고 필요한 날짜 범위를 임시로 확장한다.
달력 인접 월 날짜에도 놓을 수 있고, 이전/다음 월 이동 영역에 잠시 머물면 월을 전환한다.
이 월 변경은 드래그 중 명시적 탐색에 따른 것이며 일반 CRUD가 선택 월을 바꾸는 규칙으로 확대하지 않는다.

**Q17 — 편집 충돌:** 패널에 미저장 변경이 있으면 드래그를 막고 먼저 저장하거나 변경을 버리도록 안내한다.
변경이 없는 패널은 둔 채 드래그를 허용한다. 같은 일정 패널이 열려 있다면 저장 결과로 날짜를 갱신한다.

**Q18 — 한계·취소:** 끝을 반대 끝 너머로 끌면 최소 1일에서 멈춘다.
몸통 이동은 기간을 유지하면서 지원 날짜 범위 끝에서 멈춘다.
Escape·유효 날짜 영역 밖 드롭·포인터 입력 중단은 날짜 변경을 취소한다.
취소 시 드래그로 탐색한 월은 유지하고 일정 데이터는 원래 상태로 둔다.
저장 실패·응답 소실·저장 성공 후 재조회 실패는 기존 오류 계약을 유지한다.
저장 결과가 불명인데 DB 변경이 취소됐다고 단정하거나 같은 변경을 자동 재전송하지 않는다.

## 오늘 이동과 표시 범위

**Q6:** `현재 월`과 `선택 월로 이동`을 `오늘` 버튼 하나로 통합한다.
선택 연월을 PC 현지 현재 월로 바꾸고 달력은 오늘을 강조하며, 간트는 오늘을 화면 중앙에 표시한다.
오늘이 전체 일정 범위 밖이면 이번 달까지 표시 범위를 넓혀 실제 오늘을 보여준다. 전체 일정도 계속 포함한다.

**Q19:** 오늘로 넓힌 범위는 실행 중 유지하고 재실행 시 전체 일정 기준으로 다시 계산한다.
드래그 중 추가 확장은 임시이며 저장되면 변경된 일정 전체 범위를 반영한다.
취소 시 드래그 임시 확장은 해제하되 기존 오늘 확장은 유지한다.
범위 확장은 조회 동작이며 일정 날짜 자체를 바꾸지 않는다.

기존 `선택 월로 이동 미동작`은 사용자 보고다. 현재 코드는 선택 월 변경 시 이미 이동하거나,
전체 폭이 화면보다 작거나, 범위 끝으로 제한된 상태이면 추가 클릭에 화면 변화가 없을 수 있다.
보고한 현상을 재현해 원인을 확정한 것은 아니며, 후속 검증에서는 위 오늘 이동 계약을 확인한다.

## 알림과 유지하는 규칙

**Q11:** 기존 성공 문구·영역을 제거하고 추가·수정·삭제 성공을 우측 하단 토스트로 **2초** 표시한다.
입력 오류는 해당 필드에, 저장 실패·결과 불명·DB 오류 등 조치가 필요한 안내는 해결 전까지 남긴다.
성공 토스트는 실제 저장 확인 후 표시하며 저장 성공 후 재조회 실패를 정상 완료로만 표시하지 않는다.

날짜의 양 끝 포함·최소 1일·0001~9999년, 겹친 일정 허용, 동일 이름의 ID 구별,
저장 commit 후 성공 반영·원본 보존, 기존 CRUD·키보드 접근과 편집 경로는 유지한다.
테마·접힘의 영구 유지와 달리 최근 프로젝트는 실행 중 선택 이력이다.
선택 연월은 기존대로 재실행 시 현재 월로 시작한다.

## 검증 기준과 미검증 상태

아래는 구현 후 확인할 기준이며 이번 문서 반영으로 통과한 항목이 아니다.

| 대상 | 확인 기준 |
| --- | --- |
| 테마·접힘 | 초기값, 두 테마 전환, 프로젝트별 접기/펼치기, 재실행 후 마지막 설정 유지; 접어도 달력·전체 범위 유지 |
| 설치·아이콘 | 완료 화면의 체크/해제에 따른 실행, 사용자별 설치·DB 보존 회귀, 선택된 아이콘의 각 위치 적용 |
| 시작 속도 | 실제 같은 Windows PC·같은 데이터의 반복 측정, 창 표시/편집 가능 시간 분리, 정상 재실행 3초/5초 목표 확인 |
| 날짜 추가·선택기 | 두 화면에서 같은 클릭 날짜, 행 프로젝트 우선/최근/첫 프로젝트, 프로젝트 없음 안내, 직접 입력과 달력 선택, 저장 전 입력 보존 |
| 드래그 | 하루·장기·겹침·주/월/연도 경계, 실제 끝과 잘린 조각 구별, 기간 보존, 한 번 저장, 두 화면 결과 일치 |
| 실패·취소 | 미저장 패널 보호, 날짜 경계, Escape/영역 밖/입력 중단, 저장 실패/결과 불명/재조회 실패와 원본·입력 보존 |
| 오늘·범위 | 오늘이 범위 안/밖, 전체 일정 포함, 현재 월/오늘 위치, 실행 중 확장 유지·재실행 초기화·드래그 확장 취소 |
| 화면·알림 | 2초 성공 토스트와 지속 오류, 높이를 줄인 고정 헤더·날짜 눈금, 좁은 창·키보드·포커스와 기존 CRUD 회귀 |

설계 확정 당시 아이콘 이미지·시작 지연 원인·설정 저장 방식·날짜 선택기 구현 수단·NSIS 설정을 후속 작업으로 남겼다.
이번 문서는 사용자 동작과 목표를 확정하며 새 의존성·DB 스키마·IPC 변경을 확정하지 않는다.
신규 설계 구현·자동 검증은 구현 기록에 분리하며, 사용자 Windows PC 시작 시간 실측은 아직 미실행이다. 기존 MVP 인수 범위는 [사용자 인수 기록](../release/user-acceptance.md)을 따른다.

- 변경 범위는 `docs/`의 Markdown뿐이다. 제품 코드·테스트·의존성·배포 설정은 변경하지 않았다.
- 앱 빌드·제품 테스트·Windows 설치/시작 시간 검증은 실행하지 않았다. 이 결과는 문서 검증만 증명한다.


## 2026-11-04 데스크톱 화면 후속 요청

기존 동작을 유지하면서 다음 표시 규칙을 적용한다.

- 빈 프로젝트의 `일정 없음`은 날짜 격자가 아닌 프로젝트 메타데이터 안에 표시한다.
- 간트의 오늘 열과 달력의 오늘 날짜에 옅은 배경을 표시한다. 가리킨 날짜에도 옅은 배경을 표시하며,
  프로젝트 막대 색상과 클릭·드래그 동작을 유지한다.
- 헤더의 보이는 `선택 연월` 글자만 제거한다. 월 입력·이전/다음 달·오늘 기능과 접근성 이름은 유지한다.
- 달력은 요일뿐 아니라 월간 달력 제목과 이전/다음 달 버튼도 함께 고정한다.
- 데스크톱의 글자 크기·여백·정렬과 라이트/다크 색상 일관성을 정리한다. 모바일 개선은 범위 밖이다.

실제 화면 근거·색상 규칙·검증 범위는 [데스크톱 화면 정리 기록](../implementation/2026-11-04-desktop-polish.md)에 둔다.


## 2026-11-04 전체 화면 재설계 선택

사용자가 네 시안을 검토하고 상단 프로젝트 팝오버 C안을 선택했다. 크기는 시안대로 유지하고
항목이 늘면 내부 목록에만 스크롤을 적용한다. Flat·앱 내부 반투명, 커스텀 창 버튼, 아이콘·툴팁,
입력 팝오버의 상세는 [C안 확정 설계](flat-glass-redesign.md)를 따른다.
현재 제품 코드는 앞선 데스크톱 개선까지 구현되어 있으며, C안은 별도 구현이 필요한 설계다.
