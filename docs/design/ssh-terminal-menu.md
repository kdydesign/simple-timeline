# TermRail SSH 터미널 설계

2026-11-19 사용자가 네 번째 시안(커밋 `549d756`)의 화면과 사용자 동작을 승인했다. 공통 메뉴 크기, 서버 등록·수정·로그인, 탭과 별도 창, 분할 조절·닫기, 레이아웃 전체 저장·교체는 아래 표를 기준으로 한다. 승인 이후 제품 구현과 인수 범위는 [구현·검증 기록](../implementation/2026-11-19-termrail-and-windows-zip.md)에서 확인한다. [승인 시안](mockups/termrail-v4.html) · [관련 ZIP 설치·아이콘 설계](windows-node-zip-all-versions.md)

## 사용자 요구

- Home·PlanRail·NodeRail과 함께 SSH 터미널을 사용하는 새 메뉴를 추가한다.
- 서버 접속 정보를 입력하고 연결해 PuTTY처럼 터미널을 사용한다.
- SuperPuTTY처럼 여러 터미널을 열고 레이아웃을 구성·저장한다.
- 터미널 공간을 확보하도록 해당 메뉴의 버튼·입력 폼을 작게 구성한다.
- 메뉴 이름과 구체적인 기능을 협의하고 화면 시안을 확인한다.

## 현재 구조와 설계 방향

설계 시작 시 Electron·React 앱에는 SSH·터미널 엔진 의존성이 없었다. 메인 창은 sandbox·contextIsolation을 사용하며 renderer의 Node 접근은 꺼져 있다. 기존 공유 자격 정보에는 Electron safeStorage 기반 저장 기능이 있다. TermRail은 아이디와 비밀번호를 연결할 때마다 입력받는다. [현재 의존성](../../package.json) · [창 설정](../../src/main/window.ts) · [공유 비밀정보 저장](../../src/main/sharing/secrets.ts)

검토 방향은 앱 내부 터미널 화면과 메인 측 연결 관리를 결합하는 방식이다. 외부 PuTTY 창을 관리하는 방식, 내장 터미널에서 SSH 라이브러리를 사용하는 방식, OS의 SSH 실행 파일을 연결하는 방식의 기능·배포·인증·사내 보안 환경 차이를 조사한 뒤 구현 방식을 확정한다. 구현에서는 Electron 메인 프로세스에 ssh2를, 화면에 xterm.js를 적용했다. 호스트 키 확인과 운영체제 창의 수명은 [구현·검증 기록](../implementation/2026-11-19-termrail-and-windows-zip.md)에 기록한다.

설계에서 아래 개념을 구분한다. 용어는 협의를 위한 초안이다.

| 개념 | 의미 |
| --- | --- |
| 접속 프로필 | 이름·호스트·포트 등 서버에 다시 연결하는 데 쓰는 설정 |
| 터미널 세션 | 한 번 연결해서 실행 중인 SSH 접속과 그 화면 |
| 레이아웃 | 탭·분할 방향·비율·프로필 연결 관계, 별도 창 위치와 크기를 함께 담는 배치 |

저장된 레이아웃을 열면 창 배치를 복원하고 각 서버에 새 SSH 세션을 연다.

## 승인된 화면과 레이아웃 전환

[직접 조작하는 시안](mockups/termrail-v4.html) · [서버 선택 메뉴 화면](mockups/termrail-v4.png)

Home·PlanRail·NodeRail·TermRail은 WorkRail 공통 메뉴의 CSS와 20px 아이콘을 사용한다. 기본 메뉴 버튼은 최소 높이 36px이며 행 위아래 여백은 각 7px다. TermRail 페이지 안에서 서버 행 20px, 작업 탭 23px, 터미널 제목 19px를 사용한다. 서버 목록 폭은 88~128px, 본문 글자 크기는 13px다.

| 사용 위치 | 동작 |
| --- | --- |
| 왼쪽 ‘서버’ 오른쪽 ‘＋ 추가’ | 서버 이름·호스트·포트(기본 22)를 입력해 저장한다. 목록에는 이름이 한 줄로 나타난다. |
| 서버 이름 우클릭 → 서버 수정 | 이름·호스트·포트를 편집한다. 레이아웃은 고정 프로필 ID로 서버를 참조한다. 이름 변경은 목록과 세션 제목에 표시하고, 주소·포트 변경은 다음 접속부터 적용한다. 취소하면 기존 설정을 유지한다. |
| 작업 탭의 ＋ | 메뉴 첫 항목은 ‘새 터미널…’이며 그 아래에 저장된 서버를 나열한다. 새 터미널에서 서버 이름·호스트·포트(기본 22)를 입력한 뒤 ‘저장하고 연결’을 누르면 프로필을 저장하고 새 작업 탭에서 해당 서버에 접속한다. 취소하면 입력을 버린다. 저장된 서버를 선택하면 바로 새 탭에서 접속을 시작한다. Esc 또는 바깥 클릭으로 메뉴를 닫을 수 있다. |
| 서버 이름 더블클릭 | 새 작업 탭에 그 서버의 터미널을 열고 로그인 입력을 받는다. |
| 서버를 빈 탭 또는 터미널 가장자리에 드롭 | 빈 탭 전체 또는 미리 표시된 왼쪽·오른쪽·위·아래 영역에 새 터미널을 연다. |
| 두 터미널 사이의 분할선 | 좌우로 나뉜 영역은 경계를 좌우로, 상하로 나뉜 영역은 경계를 위아래로 드래그한다. 중첩 분할에서는 잡은 경계의 두 영역이 크기를 나눠 갖는다. 시안에서는 포커스한 경계를 방향키로도 조절할 수 있다. |
| 작업 탭 우클릭 → 별도 창으로 열기 | 해당 탭의 분할 배치 전체를 다른 모니터로 옮길 수 있다. |
| 터미널 제목 오른쪽 × | 해당 세션을 닫고 같은 분할의 이웃 터미널 또는 이웃 분할 전체가 남은 공간을 채운다. 다른 분할의 비율은 보존한다. 마지막 터미널이면 해당 탭 또는 별도 창을 닫는다. 저장본은 사용자가 다시 저장할 때 갱신한다. |
| 왼쪽 ‘레이아웃’ 제목 옆 ‘저장’ 또는 작업 탭 우클릭 → 레이아웃 저장 | 현재 TermRail 전체의 작업 탭과 순서, 활성 탭, 별도 창의 위치·크기, 각 창의 분할 트리와 서버를 이름을 붙여 저장한다. 각 분할은 방향과 첫 영역의 비율을 저장한다. 예를 들어 2열에서 왼쪽을 60%로 조절했다면 복원할 때 그 창의 가용 폭을 60 대 40으로 나눈다. |
| 왼쪽에 저장된 레이아웃 클릭 | 현재 TermRail 탭·별도 창과 그 SSH 세션을 모두 닫고 저장된 구성으로 다시 연다. 같은 서버도 새 연결을 시작하며 각 터미널에서 로그인한다. 서버 하나의 실패는 해당 터미널에 표시한다. |

복원 대상 프로필과 배치 정보를 먼저 확인하고 전환을 한 번에 수행한다. 이전 창의 닫힘 처리가 새 작업 탭을 추가하지 않도록 한다. 같은 레이아웃을 다시 선택해도 동일한 교체 규칙을 적용한다. 실제 제품에서는 SSH 세션의 터미널 행·열 수도 조절한 영역에 맞춰 갱신한다.

시안은 브라우저 로컬 저장소에 서버 프로필과 배치를 보관하고 예시 로그인 화면을 연다. 별도 창을 여러 개 여는 것은 브라우저 팝업 설정의 영향을 받는다. 제품의 SSH 연결 및 실제 다중 모니터 복원은 구현 단계의 검증 대상이다. [이전 두 번째 시안](mockups/termrail-v2.html)

## 로그인과 레이아웃 열기

서버 이름·호스트·포트를 저장해 선택하고, 터미널에 `login as:`와 비밀번호 입력 흐름을 표시한다. SSH 인증 전에 사용자명이 필요하므로 로그인 입력 UI를 연결 엔진이 제공해야 한다. 비밀번호는 화면·스크롤백·클립보드·로그·저장 프로필·레이아웃에 기록하지 않으며 인증 처리가 끝나면 불필요한 메모리 참조를 해제한다. 사용자명도 다음 연결을 위한 저장 대상으로 삼지 않는다.

레이아웃을 열면 모든 대상의 접속을 시작하고 각각 입력을 기다린다. 접속 시작·호스트 키 확인·로그인 대기·인증 완료·실패를 구분하며 한 서버의 입력 대기나 실패가 나머지 서버의 접속 시작을 막지 않게 한다. 활성 터미널의 로그인 입력은 그 세션에만 전달한다. 비밀번호를 저장하지 않는 조건에서 모든 서버의 인증 완료에는 각 서버의 사용자 입력이 필요하다.

서버 최초 연결과 호스트 키가 변경된 경우의 확인 절차는 후속 협의 대상이다.

## 전체 개선 재검토에서 확인한 세션 동작

- 메인 창을 트레이로 숨기면 SSH 연결을 유지한다. 창을 다시 열면 같은 세션을 표시한다. 명시적인 앱 종료 시에는 세션을 정리한다.
- 별도 창의 Windows 제목 표시줄 ×를 누르면 분할 배치와 연결을 유지한 채 메인 창의 작업 탭으로 돌아간다. 터미널 제목의 ×는 해당 세션을 종료한다. 레이아웃 교체로 별도 창을 닫을 때는 전체 교체 규칙이 우선한다.
- 인수 검사에서 장시간 출력 중인 세션으로 창 이동·트레이 복귀를 실행해 재로그인 횟수와 출력 연속성을 확인한다. 브라우저 시안의 창 이동은 화면 동작의 근거이며 실제 SSH 연결 수명은 제품에서 확인한다.
- 승인 문서는 기존 연결을 종료하기 전에 복원 대상 검사를 요구한다. 시안의 `openLayout`은 별도 창부터 닫는다. 제품 인수 사례에는 프로필 참조가 유실된 배치를 열 때 기존 세션이 유지되는 경우와, 유효한 배치에서 한 서버의 인증이 실패해도 다른 서버가 연결되는 경우를 각각 포함한다. [시안의 복원 처리](mockups/termrail-v4.html)

## 후속 검토 항목

SSH 엔진·Windows 패키징 등 기술 선택과 추가 기능 후보를 기록한다.

- 서버 호스트 키의 최초 확인·변경 처리.
- 직접 SSH 연결에서 접속 실패·인증 취소·주소 변경 시의 안내.
- 탭·분할 복제의 지원 범위, 별도 창 최대화 상태와 모니터 구성이 달라진 경우의 복원 방식.
