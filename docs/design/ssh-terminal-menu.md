# SSH 터미널 메뉴 설계 협의

2026-11-19 사용자 요청으로 협의 시작. 메뉴 이름·인증 범위·창 구성이 결정 전이며 제품 구현은 별도 승인 후 진행한다. Windows ZIP 설치 통일과 앱 아이콘 축소를 포함한 후속 개선 묶음으로 검토한다. [ZIP 설치·아이콘 설계](windows-node-zip-all-versions.md)

## 사용자 요구

- Home·PlanRail·NodeRail과 함께 SSH 터미널을 사용하는 새 메뉴를 추가한다.
- 서버 접속 정보를 입력하고 연결해 PuTTY처럼 터미널을 사용한다.
- SuperPuTTY처럼 여러 터미널을 열고 레이아웃을 구성·저장한다.
- 터미널 공간을 확보하도록 해당 메뉴의 버튼·입력 폼을 작게 구성한다.
- 메뉴 이름과 구체적인 기능을 협의하고 화면 시안을 확인한다.

## 현재 구조와 설계 방향

현재 Electron·React 앱에는 SSH·터미널 엔진 의존성이 없다. 메인 창은 sandbox·contextIsolation을 사용하며 renderer의 Node 접근은 꺼져 있다. 기존 공유 자격 정보에는 Electron safeStorage 기반 저장 기능이 있다. SSH 인증 정보의 보관 여부와 기존 저장 기능의 재사용 범위는 별도 결정한다. [현재 의존성](../../package.json) · [창 설정](../../src/main/window.ts) · [공유 비밀정보 저장](../../src/main/sharing/secrets.ts)

검토 방향은 앱 내부 터미널 화면과 메인 측 연결 관리를 결합하는 방식이다. 외부 PuTTY 창을 관리하는 방식, 내장 터미널에서 SSH 라이브러리를 사용하는 방식, OS의 SSH 실행 파일을 연결하는 방식의 기능·배포·인증·사내 보안 환경 차이를 조사한 뒤 구현 방식을 확정한다. 실제 라이브러리와 버전은 아직 선택하지 않았다.

설계에서 아래 개념을 구분한다. 용어는 협의를 위한 초안이다.

| 개념 | 의미 |
| --- | --- |
| 접속 프로필 | 이름·호스트·포트·사용자·인증 방법 등 다시 연결하는 데 쓰는 설정 |
| 터미널 세션 | 한 번 연결해서 실행 중인 SSH 접속과 그 화면 |
| 레이아웃 | 탭·분할 방향·비율·프로필 연결 관계, 별도 창을 지원하면 창 위치와 크기까지 담는 배치 |

레이아웃 복원과 서버 재접속은 각각 동작을 정한다. 실행 중인 원격 명령을 앱 재시작 후 복원할 수 있는지와 화면 배치를 복원하는 기능도 구분해 설명해야 한다.

## 화면 검토 기준

기존 Forest Crystal·Steel Blue 테마를 따른다. 어두운 테마의 페이지 `#202225`, 표면 `#2b2e31`, 본문 `#f1f2f3`, 보조 문구 `#c0c5cb`, 강조 `#8bc1eb`를 기준으로 기존 CSS 변수를 재사용한다. 밝은 테마도 기존 변수 체계를 따른다. 바깥 여백은 공통 14px이며 작은 조작부는 SSH 메뉴 내부에 한정한다. [테마](../../src/renderer/forest-crystal.css) · [공통 화면 여백](../../src/renderer/workrail.css)

작성자 제안은 높이 28~30px의 조작부, 12~13px의 UI 글자, 접을 수 있는 접속 목록, 얇은 탭과 드래그 가능한 분할선이다. 터미널 글자는 별도 고정폭 글꼴과 크기 조절을 제공하는 방향으로 검토한다. 본문 가독성을 위해 터미널 배경의 투명도는 조작부와 별도로 정한다. 활성 세션·키보드 포커스·연결 상태를 작은 공간에서도 식별할 수 있어야 한다.

시안은 사용자가 Q2의 창 범위를 고른 뒤 작성한다. 접속 전 입력 화면, 여러 터미널 사용 화면, 레이아웃 저장·복원 화면을 포함한다. 별도 창을 선택하면 다중 모니터와 모니터 제거 후 창 위치 복원도 포함한다.

## 다음 협의와 조사

선행 답변에 맞춰 질문을 구체화한다. 아래 항목의 권장안은 아직 사용자 결정으로 간주하지 않는다.

- 인증 방식에 따른 개인키 형식·암호·SSH agent·다단계 인증 필요 여부, 비밀번호·키 암호 저장 범위와 서버 호스트 키의 최초 확인·변경 처리.
- 직접 연결 외 점프 호스트·SSH 프록시·포트 포워딩 필요 여부. NodeRail의 HTTP 프록시 설정과 SSH 연결 설정의 관계.
- 탭과 분할의 이동·닫기·복제, 별도 창으로 이동할 때의 연결 유지, 최대화·다중 모니터 처리.
- 레이아웃에 저장할 정보, 자동 저장과 이름을 붙인 저장, 재시작 시 배치 복원 및 자동 연결 여부, 연결 실패한 일부 세션의 표시.
- 메뉴 전환·창 닫기·트레이·앱 종료 시 연결 수명, 끊김·재접속·keepalive 및 원격 실행 작업 안내.
- 복사·붙여넣기, 한글 입력·문자 인코딩, 터미널 단축키·검색·스크롤백·세션 로그, 여러 세션 동시 입력 요구 여부.
- SFTP 파일 전송, 로컬 셸, WSL 셸, 기존 PuTTY 프로필 가져오기 등 인접 기능의 초기 포함 여부.
- 접속 프로필·레이아웃의 PC별 보관과 내보내기·공유 요구 여부. PlanRail의 호스트·멤버 역할과의 관계.
- 엔진 선택 전 실제 터미널 프로그램·크기 변경·긴 출력·다중 세션·호스트 키 확인·인증 취소를 검증할 방법, Windows 패키징과 사내 보안 제품의 검증 범위.

## 협의 완료 기준

이름·기능 범위·인증·연결 수명·레이아웃 저장/복원·화면 시안·기술 방식·검증 기준을 정리하고 사용자에게 전체 설계 확인을 받는다. Windows ZIP 설치와 아이콘 변경은 각각의 설계와 승인 상태를 함께 확인해 구현 범위를 확정한다.
