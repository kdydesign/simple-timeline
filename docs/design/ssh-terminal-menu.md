# TermRail SSH 터미널 메뉴 설계 협의

2026-11-19 사용자 요청으로 협의 시작. Q1~Q6에서 TermRail, 탭·분할·별도 창·다중 모니터, 매번 로그인 입력, 레이아웃 열 때 전체 서버 접속 시작, 직접 SSH 연결을 선택했다. 세부 설계는 협의 중이며 제품 구현은 별도 승인 후 진행한다. Windows ZIP 설치 통일과 앱 아이콘 축소를 포함한 후속 개선 묶음으로 검토한다. [ZIP 설치·아이콘 설계](windows-node-zip-all-versions.md)

## 사용자 요구

- Home·PlanRail·NodeRail과 함께 SSH 터미널을 사용하는 새 메뉴를 추가한다.
- 서버 접속 정보를 입력하고 연결해 PuTTY처럼 터미널을 사용한다.
- SuperPuTTY처럼 여러 터미널을 열고 레이아웃을 구성·저장한다.
- 터미널 공간을 확보하도록 해당 메뉴의 버튼·입력 폼을 작게 구성한다.
- 메뉴 이름과 구체적인 기능을 협의하고 화면 시안을 확인한다.

## 현재 구조와 설계 방향

현재 Electron·React 앱에는 SSH·터미널 엔진 의존성이 없다. 메인 창은 sandbox·contextIsolation을 사용하며 renderer의 Node 접근은 꺼져 있다. 기존 공유 자격 정보에는 Electron safeStorage 기반 저장 기능이 있다. TermRail은 아이디와 비밀번호를 연결할 때마다 입력받는다. [현재 의존성](../../package.json) · [창 설정](../../src/main/window.ts) · [공유 비밀정보 저장](../../src/main/sharing/secrets.ts)

검토 방향은 앱 내부 터미널 화면과 메인 측 연결 관리를 결합하는 방식이다. 외부 PuTTY 창을 관리하는 방식, 내장 터미널에서 SSH 라이브러리를 사용하는 방식, OS의 SSH 실행 파일을 연결하는 방식의 기능·배포·인증·사내 보안 환경 차이를 조사한 뒤 구현 방식을 확정한다. 실제 라이브러리와 버전은 아직 선택하지 않았다.

설계에서 아래 개념을 구분한다. 용어는 협의를 위한 초안이다.

| 개념 | 의미 |
| --- | --- |
| 접속 프로필 | 이름·호스트·포트 등 서버에 다시 연결하는 데 쓰는 설정 |
| 터미널 세션 | 한 번 연결해서 실행 중인 SSH 접속과 그 화면 |
| 레이아웃 | 탭·분할 방향·비율·프로필 연결 관계, 별도 창을 지원하면 창 위치와 크기까지 담는 배치 |

레이아웃 복원과 서버 재접속은 각각 동작을 정한다. 실행 중인 원격 명령을 앱 재시작 후 복원할 수 있는지와 화면 배치를 복원하는 기능도 구분해 설명해야 한다.

## 터미널 중심 배치 · 두 번째 시안

[직접 조작하는 시안](mockups/termrail-v2.html) · [1280×760 화면](mockups/termrail-v2.png)

사용자는 서버 이름만 한 줄로 나열하는 좁은 왼쪽 목록과 작은 작업 탭·터미널 제목을 요청했다. 새 연결·좌우 분할·상하 분할·별도 창 버튼과 이들을 담던 툴바를 제거한다. 시안에서 목록 폭은 88~128px, 서버 행은 20px, 작업 탭과 ＋는 높이 23px, 터미널 제목은 높이 19px다. 이 수치는 시안 검토값이다. 본문은 고정폭 13px로 유지한다.

| 사용자 동작 | 설계 동작 |
| --- | --- |
| 서버 이름 더블클릭 | 새 작업 탭에서 해당 서버의 터미널을 열고 로그인을 기다린다. 같은 서버를 다시 열어도 독립 세션이다. |
| 서버 이름을 끌어 놓기 | 빈 탭이면 전체 공간에 연다. 기존 터미널 위에서는 포인터에 가까운 왼쪽·오른쪽·위·아래 절반을 미리 표시하고, 놓으면 표시된 자리에 새 터미널을 연다. 여러 번 분할해 배치를 구성한다. |
| 작업 탭 우클릭 → 별도 창으로 열기 | 우클릭한 탭의 전체 분할 배치를 별도 창으로 옮긴다. 제품 설계에서는 기존 세션을 이어서 사용한다. |
| 작업 탭 우클릭 → 레이아웃 저장 | 시안에서 제안하는 저장 위치다. 해당 탭의 배치에 이름을 붙이고 왼쪽 하단 목록에서 다시 연다. |
| 저장된 레이아웃 열기 | 기존 연결을 유지하며 새 작업 탭에 배치를 추가한다. 모든 서버에 접속을 시작하고 각 터미널에서 아이디·비밀번호를 새로 입력한다. |

드롭 영역은 놓을 때까지 미리보기로만 표시한다. 시안에서는 저장한 배치를 현재 브라우저 페이지에서 다시 열 수 있다. SSH 연결과 앱 재시작 후 복원은 제품 구현 단계의 검증 대상이다.

## 로그인과 레이아웃 열기

서버 이름·호스트·포트를 저장해 선택하고, 터미널에 `login as:`와 비밀번호 입력 흐름을 표시한다. SSH 인증 전에 사용자명이 필요하므로 로그인 입력 UI를 연결 엔진이 제공해야 한다. 비밀번호는 화면·스크롤백·클립보드·로그·저장 프로필·레이아웃에 기록하지 않으며 인증 처리가 끝나면 불필요한 메모리 참조를 해제한다. 사용자명도 다음 연결을 위한 저장 대상으로 삼지 않는다.

레이아웃을 열면 모든 대상의 접속을 시작하고 각각 입력을 기다린다. 접속 시작·호스트 키 확인·로그인 대기·인증 완료·실패를 구분하며 한 서버의 입력 대기나 실패가 나머지 서버의 접속 시작을 막지 않게 한다. 활성 터미널의 로그인 입력은 그 세션에만 전달한다. 비밀번호를 저장하지 않는 조건에서 모든 서버의 인증 완료에는 각 서버의 사용자 입력이 필요하다.

서버 최초 연결과 호스트 키가 변경된 경우의 확인 절차는 후속 협의 대상이다.

## 다음 협의와 조사

선행 답변에 맞춰 질문을 구체화한다. 아래 항목의 권장안은 아직 사용자 결정으로 간주하지 않는다.

- 서버 호스트 키의 최초 확인·변경 처리.
- 직접 SSH 연결에서 접속 실패·인증 취소·주소 변경 시의 안내.
- 탭과 분할의 이동·닫기·복제, 별도 창으로 이동할 때의 연결 유지, 최대화·다중 모니터 처리.
- 레이아웃에 저장할 정보, 자동 저장과 이름을 붙인 저장, 재시작 시 배치 복원 및 자동 연결 여부, 연결 실패한 일부 세션의 표시.
- 메뉴 전환·창 닫기·트레이·앱 종료 시 연결 수명, 끊김·재접속·keepalive 및 원격 실행 작업 안내.
- 복사·붙여넣기, 한글 입력·문자 인코딩, 터미널 단축키·검색·스크롤백·세션 로그, 여러 세션 동시 입력 요구 여부.
- SFTP 파일 전송, 로컬 셸, WSL 셸, 기존 PuTTY 프로필 가져오기 등 인접 기능의 초기 포함 여부.
- 접속 프로필·레이아웃의 PC별 보관과 내보내기·공유 요구 여부. PlanRail의 호스트·멤버 역할과의 관계.
- 엔진 선택 전 실제 터미널 프로그램·크기 변경·긴 출력·다중 세션·호스트 키 확인·인증 취소를 검증할 방법, Windows 패키징과 사내 보안 제품의 검증 범위.

## 협의 완료 기준

이름·기능 범위·인증·연결 수명·레이아웃 저장/복원·화면 시안·기술 방식·검증 기준을 정리하고 사용자에게 전체 설계 확인을 받는다. Windows ZIP 설치와 아이콘 변경은 각각의 설계와 승인 상태를 함께 확인해 구현 범위를 확정한다.
