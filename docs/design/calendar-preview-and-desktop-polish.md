# 달력 드래그 미리보기와 데스크톱 동작 개선

작성: 2026-11-10. 상태: **Q1~Q9 및 전체 설계 승인 완료. 사용자 “진행해”에 따라 구현 진행.**

## 목적과 범위

달력의 일정 이동·기간 조절을 화면에서 확인하고, 닫기 동작을 직접 선택하며,
넓은 창에서도 간트 작업 공간을 활용한다. About과 포커스·툴팁 오류도 함께 다룬다.
공유 호스트·PC 간 동기화, 설치 화면 DPI, 시작 성능, DB 변경은 이번 범위 밖이다.
완료된 MVP 지도는 다시 열지 않는다.

이 설계의 해당 변경만 [Planrail 설계](planrail-improvements.md)와
[이전 드래그 설계](post-mvp-improvements.md)에 우선한다. 나머지 날짜·저장·알림 계약은 유지한다.

## 선택한 접근과 대안

- 달력은 원본을 없애고 예상 막대만 옮기는 방식 대신 원본 흔적과 별도 미리보기를 선택했다.
  기존 위치와 결과를 비교할 수 있고 주변 일정의 재배치를 피한다.
  드래그 중 행을 늘리는 대안 대신 겹치는 미리보기를 선택했으므로 주변 막대를 잠시 가릴 수 있다.
- 종료는 선택 기억 대신 매번 선택하며, 명시적인 트레이 종료에는 동일 선택을 반복하지 않는다.
- 창은 마지막 크기 저장 대신 새로운 기본 크기를 사용한다. 기본값 적용은 기존처럼 매 새 프로세스 실행이며 트레이 복원에는 적용하지 않는다.
- 툴팁은 마우스만 지원하는 대안 대신 키보드 탐색도 유지한다.
- 가로 이동은 최대화 때만 고정하는 대안 대신 모든 창 크기에서 간트 영역 하단에 고정한다.

## 달력 미리보기 계약

- 몸통은 기간 유지 이동, 실제 시작·끝 손잡이는 해당 끝 변경. 기존 드래그 시작 임계값과 최소 1일·날짜 범위를 유지한다.
- 드래그 중 snapshot과 일반 막대 배치·더 보기 개수는 변경하지 않는다. 원본의 보이는 조각만 흐리게 표시한다.
- 미리보기는 화면의 주별로 분할한다. 일반 3줄 제한과 독립적으로 표시해 드래그 대상이 숨지 않게 한다.
  날짜 칸과 주 경계를 정확히 따르며 표시 범위 밖으로 이어지면 계속 방향을 표시한다.
- 보이는 이전·다음 달 날짜에도 미리보기를 그린다. 기존 650ms 월 이동과 이동 후 드래그 유지를 보존한다.
  드래그를 마치면 기존 선택 월 안의 일정 표시 규칙으로 돌아간다.
- 포인터 근처 시작·종료일 안내와 미리보기는 포인터 입력을 가로채지 않는다. 기존 상태 안내는 접근성을 위해 유지한다.
- 유효 영역 밖에서는 마지막 유효 미리보기를 구분해서 표시하고 놓으면 취소임을 안내한다. 영역 밖 drop, Escape, pointercancel, 창 포커스 이탈은 기존처럼 취소한다.
- 놓기 전에는 저장하지 않는다. 유효한 변경을 놓았을 때 한 번 저장하며 실패·결과 불명은 기존 저장 보호 흐름을 따른다.
  미리보기는 드래그 종료 시 정리하고 저장 확인 전 성공을 표시하지 않는다.
- 미저장 편집이 있으면 드래그 차단, 취소해도 탐색한 월 유지, 프로젝트 유지 등 기존 계약은 변경하지 않는다.

## 창 닫기·About

- X·Alt+F4에서 세 가지 선택창을 하나만 연다. 중복 닫기 요청으로 선택창을 쌓지 않는다.
- 트레이로 보내기는 미저장 입력·진행 중 저장·알림 처리를 유지한다. 최소화 버튼 동작은 그대로다.
- 완전 종료는 진행 중 저장을 기다리고 미저장 입력을 버릴지 기존 확인을 거친다. 취소하면 입력과 창을 유지한다.
  완전히 종료하면 일정 알림이 제공되지 않음을 선택창에서 안내한다.
- 트레이 생성 실패 시 트레이로 보내기는 제공하지 않고 완전 종료·취소만 제공한다.
- About 메뉴는 열기 / About / 종료 순서로 둔다. 버전은 main의 실제 app.getVersion() 값을 사용한다.
  설명은 ‘오프라인 프로젝트 일정 관리 프로그램’, 개발자는 daeyong, 저작권은 합의한 2026 문구다.
  패키지 author나 앱 ID·저장 위치·아이콘 자산을 이 표시 변경 때문에 바꾸지 않는다.
- About은 앱이 숨겨져 있어도 열 수 있으며 편집 입력·저장에 영향을 주지 않는다. 반복 선택 시 정보창을 중복 생성하지 않는다.
  About을 닫는 것은 정보창만 닫으며 앱 종료 선택창을 띄우지 않는다.

## 창 크기·간트 하단·툴팁

- 새 프로세스 기본 크기는 1707×820 DIP. 초기 표시 모니터의 작업 영역에 너비·높이를 제한하고 창이 영역 안에 놓이도록 한다.
  150% 배율에서는 물리 픽셀과 다르며 목표 너비보다 작은 창이 정상일 수 있다. 크기·위치 영속화는 추가하지 않는다.
- 간트는 헤더 아래 남은 작업 높이를 채우고 배율·가로 이동 영역을 하단에 둔다. 일정 본문만 필요한 세로 스크롤을 갖는다.
  행이 적음/많음, 편집기 열림/닫힘, 일반/최대화/복원에서 동일하며 마지막 행이 하단 영역에 가려지지 않는다.
- 기존 range 탐색기의 배율·포인터 기준 날짜·Space 이동 기능은 유지한다. 달력 스크롤 구조는 이 수정을 이유로 바꾸지 않는다.
- 패널을 연 위치로 포커스 복귀를 유지한다. 그 요소가 사라졌으면 일정 편집은 일정 추가, 프로젝트 편집은 프로젝트 추가 등 의미에 맞는 대체 대상을 사용한다.
- 자동 focus로 툴팁을 열지 않는다. 이후 실제 hover 또는 Tab 탐색은 정상 표시하고 Escape·클릭·이탈 시 닫는다.
  기존 툴팁 허용 버튼 목록과 접근성 이름·키보드 조작을 유지한다.

## 구현자 재량과 검증 기준

미리보기의 세부 투명도·겹침 행 위치·테두리, 포인터 안내의 화면 경계 보정, 종료·About의 native 또는 앱 UI 선택은 구현자 재량이다.
기존 라이트/다크·디자인·보안 경계를 따르고 입력·포커스·저장 보호를 보존한다. 새 DB·의존성이 필요하다고 전제하지 않는다.

| 검증 | 수용 기준 |
| --- | --- |
| 달력 | 포인터를 놓기 전 이동·좌우 resize 막대 좌표/폭/예상 날짜 변화. 주/월 경계·인접 월·하루·장기·3줄 초과 겹침에서도 미리보기 보임 |
| 저장 | 미리보기 중 저장 0회, 실제 변경 drop 1회. 취소/무변경은 0회. 실패 시 성공 표시 없음 |
| 종료 | 세 가지 선택·Escape·중복 요청·dirty·저장 중·트레이 직접 종료·트레이 실패. 숨김 후 복원 시 입력 유지 |
| About | 실제 버전·아이콘·개발자·문구, 숨긴 앱에서 열기, 중복 방지, dirty 입력 유지 |
| 툴팁 | 상단 버튼/간트 날짜/달력 날짜에서 일정 추가 후 닫기 시 유령 툴팁 없음. 올바른 포커스 복귀, 이후 hover·Tab은 정상 |
| 창/간트 | 큰/작은 작업 영역, 100/150/200% 배율, 최대화/복원·짧은 창·편집기·행 개수별 하단 위치와 마지막 행 접근 |

설계 문서는 하네스 verify와 경로 검사를 수행한다. 구현 후에는 관련 회귀 검사 및 verify:app을 수행하고,
실제 Windows 배율·트레이·창 검증은 자동 검사와 분리해 실행 여부를 보고한다.
현재 제품 테스트·실제 화면 검증은 미실행이며 이 문서는 구현 완료나 검증 통과의 근거가 아니다.

설계 검토 결과: 독립 검토에서 구현 계획을 막는 추가 질문 없음. 하네스 verify 7개 검사 통과,
이 문서와 탐색 인덱스의 상대 링크 45개 대상 존재 확인. 제품 코드는 변경하지 않았다.
