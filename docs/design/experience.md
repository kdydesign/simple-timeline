# 화면과 상호작용 설계

작성일: 2026-11-03. 스테이지 3. 사용자 승인 설계.
기준 main: `a773f88a9ca3747ed712dd1985eea095a6b71ba4`.
[도메인 규칙](domain-rules.md)·[IPC 계약](architecture.md)·[저장 설계](storage.md)는 승인 상태를 유지한다.
날짜 좌표·구간 분할·사례의 기준은 [시각화 설계](visualization.md)다.

## 목적·범위와 접근 선택

Windows 개인용 오프라인 앱에서 같은 프로젝트·일정을 간트와 월간 달력으로 조회하고 편집한다.
간트의 전체 범위, 선택 연월 유지, 빈 프로젝트 표시와 실제 저장 성공 후 반영을 지킨다.
날짜·저장 규칙 재설계, 제품 구현, 의존성 설치, 드래그 편집·진행률·의존성·검색·필터·공유는 범위 밖이다.
저장 실패를 성공·빈 데이터로 보이거나, 긴 기간과 겹친 일정을 조용히 누락시키지 않는다.

| 접근 | 장점·비용 | 선택 |
| --- | --- | --- |
| 넓은 조회 화면 + 오른쪽 편집 패널 | 간트 가로 공간을 쓰고 조회 맥락을 유지한다. 패널을 열면 조회 폭이 줄어든다. | 사용자 선택 |
| 상시 프로젝트 목록 + 중앙 조회 + 편집 모달 | 관리 목록 접근이 빠르나 목록이 상시 가로 공간을 차지하고 편집창이 조회를 가린다. | 미선택 |

사용자는 `1a 2a 3a 4a`로 목업 사용, 첫 접근, 월요일 시작, 기본 3줄·날짜별 더 보기를 선택했다.
후속 Q5~Q7에는 권장 탐색·월 경계·편집 동작을 선택했다.
나머지 배치 수치·접근성·정렬 알고리즘은 에이전트의 구체화이며 문서 전체 승인 대상으로 제시한다.

## 공통 화면

- 상단: 앱 제목, 간트/달력 전환, 선택 연월, 이전/다음 달, 현재 월, 프로젝트 목록 버튼,
  프로젝트 추가, 일정 추가. 선택 연월은 연도 4자리·월 직접 입력도 제공해 먼 연도로 이동할 수 있다.
- 기본 모드는 간트다. 선택 연월은 승인된 대로 재실행 시 현지 현재 월, 실행 중 전환·CRUD 시 유지한다.
- 간트에는 `선택 월로 이동`과 전체 범위 날짜를 추가한다. 달력에서는 이 이동 버튼을 숨긴다.
- 프로젝트 목록 버튼은 생성 순서의 이름·색상·참여자·일정 개수와 편집/일정 추가 진입점이 있는
  닫을 수 있는 목록을 연다. 달력에서도 일정 없는 프로젝트를 여기서 표시한다. 일정 색상 범례만으로 대신하지 않는다.
- 프로젝트 이름 중복은 `이름 · #프로젝트ID`, 같은 프로젝트 안 일정 이름 중복은 `이름 · #일정ID`로 구별한다.
  이름을 변경하거나 중복을 거부하지 않는다. 축약한 이름은 상세 패널·키보드 포커스 설명에서 전문을 확인한다.
- 오른쪽 편집 패널은 한 번에 하나다. 넓은 창에서는 약 360px로 조회 화면 옆에 배치한다.
  좁은 창/확대에서는 오른쪽 overlay로 전환하고 조회 화면을 덮는 동안 모달 포커스를 적용한다.
  고정 Windows 최소 해상도 요구를 새로 만들지 않는다. 툴바는 줄바꿈하고 패널은 자체 세로 스크롤한다.
- 초기 시각 스타일은 밝은 배경, 중립 텍스트, 프로젝트 색상 강조다. 테마 전환·다크 모드 설정은 추가하지 않는다.

## 간트 조회·탐색

- 왼쪽 프로젝트·일정 이름 열과 상단 월/일 눈금은 스크롤해도 고정한다. 행은 프로젝트와 개별 일정이다.
  프로젝트는 생성 순, 일정은 승인된 시작일·종료일·생성 순을 따른다. 그룹 접기는 MVP에 추가하지 않는다.
- 프로젝트 행에 이름·색상·참여자, 일정 추가를 둔다. 빈 프로젝트에는 `일정 없음`과 첫 일정 추가를 둔다.
- 일정 행에 이름·시작/종료 날짜를 표시한다. 막대와 이름 버튼 모두 같은 편집 패널을 연다.
  하루짜리·화면에 조금만 걸친 막대도 이름 버튼으로 접근한다.
- 1일 28 CSS px 고정이며 월/일 눈금, 가로·세로 스크롤을 제공한다. 자동 맞춤 축소·줌은 MVP에 추가하지 않는다.
- 연월 직접 선택·이전/다음 달·현재 월은 선택 연월을 변경하고, 간트에서는 해당 월 첫날로 이동한다.
  `선택 월로 이동`은 값을 바꾸지 않고 다시 이동한다. 전체 일정 범위를 필터링하지 않는다.
- 선택 월이 범위 밖이면 가까운 처음/끝으로 이동하고 `선택 월은 전체 일정 범위 밖입니다`를 안내한다.
  선택값과 전체 범위는 유지한다. 최초 간트 위치에도 이 규칙을 적용한다.
- 모드 전환 시 마지막 간트의 가로·세로 위치를 메모리에 유지한다. 달력에서 선택 월을 바꾼 후 간트로 돌아오면
  변경된 선택 월로 이동하고, 바꾸지 않았다면 이전 스크롤을 복원한다.
- CRUD 후에는 현재 왼쪽 기준 날짜·세로 기준 항목을 가능한 한 보존한다. 범위 축소 시 유효 끝으로 제한한다.
  기준 항목 삭제 시 다음 행, 없으면 앞 행으로 맞춘다. 마지막 일정 삭제 시 선택 월 한 달로 돌아간다.

## 달력 조회·겹친 일정

- 월요일~일요일 순서, 선택 월에 필요한 4~6주를 표시한다. 주마다 동일한 기본 높이를 사용한다.
  인접 월 날짜는 흐린 숫자만 보이며 일정·추가 버튼은 표시하지 않는다. 인접 월 숫자로 자동 이동하지 않는다.
- 일정은 선택 월과 겹친 부분을 주마다 나눠 연속 막대로 배치한다. 구간 밖으로 계속되는 방향에 표시를 둔다.
  하루짜리 일정도 한 날짜 칸의 막대로 표시한다.
- 기본 3줄만 표시한다. 숨겨진 막대가 해당 날짜에 있으면 그 날짜에 `+N 더 보기`를 제공한다.
  열리는 날짜 목록에는 보이는 일정까지 포함해 그날의 **전체** 일정을 표시한다. 각 항목은 편집 패널로 연결한다.
  목록은 내부 스크롤을 사용하며 개수 제한으로 자르지 않는다.
- 막대·목록의 전문은 프로젝트명/일정명·전체 시작일/종료일·기간을 포함한다. 프로젝트 색상만으로 구별하지 않는다.
  여러 주로 나뉜 막대는 같은 일정 ID로 연결된다. 주마다 줄 위치가 달라질 수 있다.
- 날짜 숫자 자체는 조회 표시다. 일정을 추가하려면 공통 일정 추가 또는 프로젝트 목록의 일정 추가를 사용한다.
  날짜 클릭 추가·주간/일간 모드·드래그 이동은 추가하지 않는다.

## 프로젝트·일정 편집

| 패널 | 입력·초깃값 |
| --- | --- |
| 프로젝트 추가/편집 | 이름, 색상, 선택 참여자 이름별 입력 행. 추가 시 기본 `#2563EB`, 참여자 빈 목록. 색상 선택기와 `#RRGGBB` 직접 입력 제공 |
| 일정 추가 | 프로젝트 선택(프로젝트에서 진입하면 미리 선택), 이름, 시작일·종료일. 날짜 둘 다 선택 월 1일, 미입력 이름은 빈 값 |
| 일정 편집 | 소속 프로젝트 읽기 전용, 이름·시작일·종료일. 프로젝트 이동 기능은 만들지 않음 |

- 이름·참여자 정리는 승인 규칙을 따른다. 참여자는 입력 행 추가/삭제로 편집하며 쉼표 등 구분자로 분해하지 않는다.
  정규화 후 참여자 중복 제거는 오류가 아니며 저장된 결과를 표시한다.
- 날짜는 `YYYY-MM-DD` 입력을 제공하고 0001~9999 전체 범위를 지원한다. 날짜 선택기는 보조 수단이다.
  플랫폼 선택기의 제약으로 텍스트 입력이나 날짜 범위를 제한하지 않는다. 두 날짜가 유효할 때 포함 기간을 보여준다.
- 필수·형식·역전 기간 오류를 해당 필드와 연결하고 첫 오류로 포커스를 이동한다. 잘못된 날짜를 자동 보정하지 않는다.
- 저장 버튼으로 제출한다. Enter는 일반 텍스트 입력에서 폼 제출, 참여자 행의 버튼은 제출을 일으키지 않는다.
  한 요청을 보내는 동안 저장·삭제·중복 제출과 패널 닫기/교체를 막고 `저장 중`을 표시한다.
- 미저장 입력이 있으면 닫기·취소·다른 항목 선택 시 `변경 버리기 / 계속 편집`을 확인한다.
  모드·월 조회 변경만으로 패널을 닫거나 입력을 버리지 않는다. 새 일정의 기존 입력 날짜도 자동 변경하지 않는다.
- 저장 성공 후 패널은 닫고 최신 snapshot으로 두 모드를 갱신한다. 생성 항목/수정 항목의 이름 버튼으로 포커스를 돌린다.
  현재 달력에 없는 일정이면 일정 추가 버튼으로 복귀하고 `저장됨 · 현재 월 표시 대상 아님`을 안내한다.
- 프로젝트 삭제는 `프로젝트명과 하위 일정 N개를 함께 삭제합니다`를 확인한다. 참여자도 함께 삭제되며 되돌리기 기능은 없다.
  일정 삭제도 이름·전체 기간을 확인한다. 기본 포커스는 취소다. 삭제 성공 후 다음 항목, 없으면 추가 버튼으로 복귀한다.

## 로딩·빈 상태·오류

| 상태 | 표시·가능 동작 |
| --- | --- |
| 시작/읽기 중 | 로딩 안내, 완료 전 빈 달력/데이터 없음으로 단정하지 않음. 최초 CRUD 비활성 |
| 정상 읽기, 프로젝트 0개 | 선택 월 그리드와 프로젝트 추가 안내. 일정 추가는 프로젝트 먼저 만들도록 안내 |
| 프로젝트만 존재 | 간트의 빈 프로젝트, 달력의 선택 월 빈 상태·프로젝트 목록 유지 |
| 선택 월에 일정 없음 | `이번 달 일정 없음`. 다른 월의 데이터나 간트 범위를 삭제/변경하지 않음 |
| 저장·삭제 실패 | 패널·입력·마지막 정상 데이터 유지, 원인 안내·수동 재시도. 성공 알림 없음 |
| 저장 commit 성공 후 조회 실패 | `저장은 완료했지만 새로고침에 실패했습니다`. 패널을 저장 완료 상태로 두고 재저장 방지, 조회 재시도 제공 |
| IPC 응답 소실 | `저장 결과를 확인할 수 없습니다`. 동일 create 자동 재전송 금지. 조회 확인 전 재제출 차단 |
| 일반 조회 실패, 캐시 있음 | 마지막 정상 화면에 `최신 데이터가 아닐 수 있습니다`. 조회 재시도 전 CRUD 차단 |
| 최초 조회 실패, 캐시 없음 | 읽기 실패 표시·재시도. 빈 프로젝트 안내로 대체하지 않음 |
| DB 초기화/손상/고버전 오류 | 편집 차단 화면. 보존 정책과 오류 원인·DB 경로·종료/재실행 안내. 초기화/DB 삭제/복원 버튼 없음 |

DB 경로 안내는 main의 초기화 실패 안내창에서 제공한다. renderer에 경로 조회·파일 접근 API를 추가하지 않는다.
업무 오류 코드는 [IPC 계약](architecture.md)의 분류를 사용한다. SQL·스택을 사용자에게 표시하지 않는다.
저장 결과 불명 상태는 snapshot 재조회 성공 후 결과를 보여주고 편집을 다시 허용한다.
전송이 끊긴 create의 새 행을 화면이 임의 매칭·자동 재생성하지 않는다. 입력은 조회 후에도 사용자가 확인할 수 있도록 유지한다.
윈도우 닫기에서도 미저장 확인을 같은 정책으로 제공한다. renderer의 beforeunload와 main의
닫기 확인창/진행 중 작업 관리로 처리하며 범용 IPC나 파일 권한을 추가하지 않는다. 정상 종료 요청 중 저장 요청이 진행 중이면
그 요청이 끝난 뒤 종료 확인을 처리한다. 강제 종료/OS 종료에서 미저장 입력 보존은 보장하지 않는다.

## 키보드·접근성

- 모든 모드 전환·추가·프로젝트/일정 열기·더 보기·저장·삭제는 Tab과 Enter/Space로 가능하다.
  간트 스크롤 영역에 포커스가 있을 때만 좌우 키로 하루, PageUp/Down으로 화면 폭,
  Home/End로 전체 처음/끝을 이동한다. 입력 필드의 기본 키 동작을 가로채지 않는다.
- 패널 열기 시 첫 입력으로 이동한다. 모달 overlay·확인창은 포커스를 내부로 제한하고 닫으면 호출 요소로 복귀한다.
  고정 옆 패널은 비모달이며 다른 조회 컨트롤로 이동할 수 있다. Escape는 닫기/미저장 확인,
  중첩된 날짜 목록·확인창이 있으면 최상위 하나만 닫는다.
- 날짜별 더 보기 목록은 열 때 제목/첫 항목으로 포커스 이동, 닫을 때 호출 버튼으로 복귀한다.
  목록에서 일정을 열면 목록을 닫고 편집 패널로 이동한다. 편집 종료 후 해당 날짜의 더 보기로 복귀한다.
- 포커스 테두리, 읽을 수 있는 레이블, 오류 `aria-describedby`, 로딩/저장/실패 상태 읽기를 제공한다.
  막대 클릭 영역은 최소 24×24px를 목표로 하며 기간 좌표를 늘려 잘못 표시하지 않는다. 좁은 조각은 이름 버튼을 보조 경로로 쓴다.
- 프로젝트 색상 위 글자는 검정/흰색 중 명암비가 높은 쪽을 사용하고, 선택 테두리·이름·날짜로도 구분한다.
  긴 이름은 시각적으로 줄여도 접근성 이름과 패널에는 전문·ID·날짜가 남아야 한다.
