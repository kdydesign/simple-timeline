# DeviceRail · 장비 접속 상태와 SSH 작업

제품 변경 전 검토 문서다. 아래의 사용자 선택과 제안은 구분해서 기록한다. [장비 화면 4안](mockups/device-monitor/page.png) · [Home 위젯 4안](mockups/device-monitor/home.png) · [조작 시안](mockups/device-monitor/index.html)

## 요청과 합의

새 메뉴 이름은 **DeviceRail**로 확정했다. 장비 메뉴는 **A · 장비 표와 상세**로 확정했다. 왼쪽 표에서 SSH와 제품 서비스 상태를 비교하고, 행을 선택하면 오른쪽에 해당 장비의 정보와 SSH 열기·매크로 버튼을 표시한다. Home 위젯은 **B · 즐겨찾는 장비**로 확정했다. 즐겨찾는 장비별로 SSH 상태와 제품 서비스 상태를 한 행에서 확인한다. [선택한 Home 시안](mockups/device-monitor/index.html#home-2)

- 사용자가 **수동 등록한 장비**만 대상으로 한다. 장비와 장비별 이름 있는 매크로는 각 사용자의 PC에 저장한다.
- 한 장비의 **SSH 접속 상태**와 **제품 서비스 상태**를 따로 표시한다. 한쪽이 실패해도 다른 쪽의 성공을 표시한다.
- 대화형 접속은 TermRail을 사용한다. 저장 서버가 없으면 현재 작업 동안 쓸 임시 연결을 연다.
- 장비 매크로는 사용자가 선택한 장비에서 버튼을 눌러 시작한다. TermRail 탭과 독립적으로 실행한다. 첫 매크로 실행에서 로그인한 뒤 해당 장비의 인증을 이번 앱 세션에서 재사용한다.
- 아래 시안은 로컬 예시다. 장비 등록, 네트워크 검사 및 명령 실행 대화상자는 동작을 설명하는 미리보기다.

## 장비 등록과 관측 제안

장비 레코드에 고유 ID, 표시 이름, 주소, SSH 포트, 선택적 위치·설명, 제품 서비스 검사 설정을 둔다. 장비 수정·삭제는 상세 메뉴에서 처리한다. 서비스 미설정과 실제 장애를 구분한다. 사용자가 기입한 설명과 WorkRail이 관측한 시간·결과를 별도 영역으로 둔다.

| 검사 축 | 무엇을 뜻하는가 | 구분할 사례 |
| --- | --- | --- |
| SSH | 등록한 주소·포트가 SSH 프로토콜에 응답함. 주기적 검사는 로그인 전에 끝낸다. | 연결 거부, 시간 초과, SSH 외 서비스, 이름 해석 실패 |
| 제품 서비스 | 장비에 지정한 제품 검사 대상이 응답 기준을 충족함 | 연결 성공이지만 HTTP 503, TLS 검증 실패, 검사 미설정 |
| 관측 시각 | 해당 축의 마지막 검사 시각과 마지막 성공 시각 | 처음 등록, PC 절전·네트워크 단절 후 오래된 결과 |

제품 서비스는 장비별로 TCP 포트 또는 HTTP(S) 상태 URL을 지정하는 방식을 제안한다. TCP 성공은 그 포트의 접속까지만 뜻한다. HTTP(S)는 기본 2xx를 제안하며 401/403은 인증 요구로 구분한다. 검사 주기·트레이 중 검사 정책·제품별 성공 기준은 협의 대상이다. 재검사 중에는 직전 결과와 시각을 유지한다. 주소를 수정한 뒤 이전 주소에서 늦게 도착한 응답은 새 결과에 적용하지 않는다. Home과 메뉴는 동일한 관측 결과를 읽는다. 한 장비에서 두 축이 모두 실패해도 장애 장비 합계는 한 대다.

## TermRail 연결 제안

기존 ‘새 터미널’은 프로필을 저장하고 연결한다. 저장 서버를 여는 경로는 새 작업 탭과 세션을 만든다. 프로필·레이아웃은 로컬에 저장하고 SSH 호스트 키 승인과 시작 파일은 메인 프로세스에서 처리한다. [TermRail 진입점](../../src/renderer/termrail/TermRail.tsx) · [작업 탭과 레이아웃 저장](../../src/renderer/termrail/useWorkspace.ts) · [호스트 키](../../src/main/termrail/ssh-host-keys.ts)

- 장비 행 클릭은 상세 보기, **SSH 열기**는 TermRail 새 작업 탭으로 이동하도록 제안한다. 주소·포트가 일치하는 저장 서버가 여러 개면 사용자가 프로필을 선택한다. 기존 프로필의 자동 로그인이나 시작 파일은 해당 프로필의 명시적 동작을 따른다.
- 일치하는 서버가 없으면 장비 이름·주소·포트로 임시 탭을 만들고 기존 호스트 키 승인 및 수동 로그인 흐름을 사용한다. 메뉴를 오가거나 창을 분리해도 열려 있는 연결을 유지하고, 탭을 닫거나 앱을 종료하면 임시 탭 정보는 폐기한다. 신뢰한 호스트 키와 개인 장비 목록은 각자의 저장 규칙을 유지한다.
- 기존 레이아웃은 저장된 프로필 ID로 복원한다. 임시 탭을 포함해 저장하려 할 때는 해당 탭을 알려 주고, 포함하려면 사용자가 명시적으로 서버를 저장하도록 제안한다. 기존 저장 서버를 몰래 만들거나 같은 이름의 다른 장비에 연결하지 않는다.

## 장비별 매크로 제안

각 장비의 상세 화면에서 이름과 여러 줄의 명령을 작성·수정하고 실행할 버튼을 만든다. 실행은 사용자가 선택한 장비 한 대와 매크로 하나에 결합한다. 실행 직전에 장비명·주소·매크로 본문을 확인할 수 있게 한다. 첫 사용 또는 지문 변경 시 호스트 키를 확인하며, 매크로 로그인은 TermRail 시작 파일과 별도로 처리한다.

**추천 방식은 로그인 연결을 재사용하고 실행마다 새 셸 채널을 여는 것이다.** 한 매크로의 줄들은 같은 셸에서 처리하므로 한 줄에서 바꾼 디렉터리가 다음 줄에 적용된다. 다음 매크로는 독립된 작업 상태로 시작한다. 지원되는 비대화형 셸 장비에서는 명령 묶음의 종료 상태와 표준 출력·오류를 받는다. 챌린지나 대화형 장비 CLI처럼 프롬프트를 기다려야 하는 경우는 별도 실행 방식을 협의한다. 고정된 시간 간격으로 키 입력을 흉내 내면 장비 부하나 확인 질문에 따라 다음 줄이 잘못 입력될 수 있다.

- 첫 로그인 후 인증된 연결은 메인 프로세스 메모리에 장비 주소·포트·계정·호스트 키별로 유지한다. 연결이 끊기면 재로그인을 요청하는 방식을 제안한다. 장비 삭제·주소 변경·연결 해제·앱 종료 때 해당 연결을 정리한다.
- 이름 옆에 상태를 표시하고, 실행 상세에서 대상, 시각, 출력과 종료 근거를 확인한다. 첫 오류에서 중지할지, 대화형 입력을 어떻게 다룰지, 중복 클릭 시 재실행을 어떻게 처리할지 확정한다. 기본 제안은 같은 장비의 중복 실행 방지와 첫 오류 시 중지다.
- 재시작처럼 명령 직후 연결이 끊어지는 작업은 ‘연결 종료 · 결과 확인 필요’로 남긴다. 이후 SSH·서비스 상태 변화와 명령 자체의 성공은 별도로 취급한다. 중간에 연결이 끊긴 매크로는 자동 재전송하지 않는다.
- 장비 감시와 매크로는 독립적이다. 상태 검사 또는 Home 위젯 열기가 매크로를 실행하지 않는다. Home에서 장비를 선택하면 해당 장비 상세로 이동하는 방식을 제안한다.

## 구현 전 확인 시나리오

1. SSH만 성공, 서비스만 성공, 양쪽 실패, 서비스 미설정, 오래된 결과를 각각 재현한다. Home 집계와 메뉴 결과가 일치해야 한다.
2. 저장 서버가 있는 장비와 없는 장비를 번갈아 연다. 임시 탭을 닫고 앱을 재시작한 뒤 저장 서버 목록과 저장 레이아웃이 보존되는지 확인한다.
3. 같은 장비에서 한 매크로의 작업 디렉터리 변화가 다음 줄에 적용되는지, 별도의 실행에는 이어지지 않는지 확인한다. 계정과 대상 장비가 섞이지 않아야 한다.
4. 실행 도중 연결이 끊기거나 앱을 닫은 경우, 실행 전 확인에서 취소한 경우, 지문이 바뀐 경우를 일회성 장비로 검증한다.
