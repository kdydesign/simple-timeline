# 휴일 기간 입력과 날짜 표시

2026-11-17 사용자 Q1~Q3, 수정 시안과 구현 진행 승인.

- 기존 일정 시작일과 같은 DatePicker·입력 재질·아이콘을 사용한다. 공유 설정 안에서도 월 목록이 잘리거나 다른 레이어 뒤로 숨지 않아야 한다.
- 시작일·종료일·이름·취소·추가(수정 시 저장)는 데스크톱에서 한 줄이다. 두 날짜는 오늘로 초기화하고 취소/저장 후 오늘로 돌아간다.
- 양 끝 포함 기간 한 항목을 저장·수정·삭제한다. 하루 휴일은 시작=종료다. 날짜는 0001~9999년이고 역전은 차단한다.
- 등록된 다른 휴일과 하루라도 겹치면 해당 이름·기간을 안내하고 저장하지 않는다. 반복 요일과의 겹침은 허용한다.
- 간트: **최종 수정 승인에 따라** 프로젝트/일정 제목과 나란한 상단 날짜 눈금 왼쪽 위에만 작은 삼각형을 표시한다. 일정 행에는 표시하지 않는다.
- 달력: 날짜 칸 왼쪽 위 삼각형, hover/키보드 focus 때 등록된 휴일 이름을 표시한다. 휴일 이름을 상시 표시하지 않는다.
- 반복 휴일은 옅은 배경만 남긴다. 삼각형/반복 이름은 표시하지 않는다. 일정 계산·알림·드래그는 변경하지 않는다.

## 저장과 호환

기존 JSON의 dates 항목에 선택적 endDate를 추가한다. date는 시작일이며 누락된 endDate는 date와 같다. 한 날짜에 하나의 이름이라는 계약으로 시작일을 항목 키로 사용한다. 하루 항목은 기존 모양을 유지한다. 기존 SQLite JSON 저장을 원자적으로 교체하며 새 테이블은 필요하지 않다.

기존 제한인 등록된 날짜 총 1,000일을 유지한다(기간을 펼친 일수 합계). 구버전 동기화 크기를 유지하기 위한 제한이며 초과 시 입력 오류로 안내한다. 반복 요일은 이 제한에 포함하지 않는다.

새 클라이언트는 `/v1/holidays/ranges`을 요청하고 404일 때 기존 `/v1/holidays`로 재시도한다. 새 호스트는 기본 경로에 범위를 펼친 기존 스키마를 반환한다. 확장 경로만 endDate를 포함하며 인증·ETag·원자적 캐시·회수·무알림 규칙은 같다. 새 클라이언트가 구버전 호스트에서 받은 하루 항목을 임의로 하나의 기간으로 합치지 않는다.

## 디자인

현재 다크 그레이·스틸 블루를 유지한다. 삼각형 6px, 옅은 분홍색, 입력 간격 10px, 시작/종료 입력 동일 너비. 호스트 관리 팝업만 입력 한 줄이 들어갈 폭으로 늘리고 작은 작업 영역에서는 넘치지 않도록 줄바꿈한다. 월 목록은 가장 가까운 모달 소유 컨테이너에 portal하여 clipping과 focus trap을 함께 지킨다.
