# 호스트·멤버 역할 전환

2026-11-18. 상태: **사용자 선택 반영, 전체 설계 확인 대기·제품 구현 전**.
[화면 정리 v3](workrail-screen-polish.md)의 공유 설정 개선에 연결되는 동작 설계다. 기존 [LAN 공유 Q21](lan-project-sharing.md)의 역할 고정 정책을 변경하는 후속 제안이며, 현재 제품은 여전히 역할 변경을 막는다.

## 목적과 선택

설정에서 호스트로 지정한 뒤 멤버로 돌아갈 수 없는 문제를 해결한다. 한 PC는 한 번에 한 역할만 수행하고, 개인 자료와 이전 호스트 원본을 잃지 않아야 한다.

| 협의 항목 | 사용자 선택 | 비교한 대안과 이유 |
| --- | --- | --- |
| 전환 방향 | 호스트↔멤버 양방향 | 한 방향만 열면 반대 역할에 다시 고정됨 |
| 이전 호스트 원본 | 보존·조회만 허용 | 삭제 또는 멤버 상태에서 편집하는 안 대신 원본을 보관 |
| 등록·공유 대상·승인 | 보관 후 호스트 복귀 시 재사용 | 모든 참여자의 재등록을 요구하지 않음. 공유·업데이트 배포는 자동 재개하지 않음 |
| 보관 원본 노출 | 별도 ‘중지된 공유 자료’ 조회만 | 현재 호스트의 자료와 섞이지 않도록 Home 오늘 일정·간트·달력·일정 알림에서 제외 |
| 멤버→호스트 | 수신 공유 자료·공유 알림·접속 자격 정리, 멤버 복귀 시 재승인 | 수신 자격을 휴면 보관하지 않음. 개인 일정·개인 휴일·이 PC의 호스트 원본은 유지 |

현재 연결을 끊는 것과 역할 전환은 다른 명령이다. ‘공유 중지’만으로 역할을 바꾸거나 승인을 폐기하지 않는다. 역할 전환은 다른 호스트 PC로의 이관·복제·자동 연결이나 동시 역할 수행을 포함하지 않는다.

## 설정 흐름

공유 설정의 현재 역할 옆에 **역할 변경**을 둔다. 펼친 호스트/멤버 선택 후 영향 설명과 취소/전환 확인을 표시한다. 라디오 선택만으로 자료를 정리하지 않는다.

- 호스트→멤버: 공유 제공과 업데이트 배포를 중지하고 원본·등록·승인을 보관한다는 안내. 전환 완료 후 멤버 연결 설정을 보여 주며 연결은 별도 클릭으로 시작한다.
- 멤버→호스트: 연결 해제, 수신 자료·알림·자격 정리와 재승인 필요를 안내. 완료 후 호스트 설정을 보여 주되 공유와 업데이트는 중지 상태다.
- 미저장 일정·설정이 있으면 기존 저장/폐기 확인을 먼저 해결한다. 저장 실패 시 전환하지 않는다. 진행 중 저장·승인·자료 변경·업데이트 설치 인계와 충돌하면 전환을 보류하고 이유를 표시한다.
- 진행 중에는 중복 전환·연결·공유 시작을 막는다. 취소는 실행 전까지 가능하며, 이미 정리가 시작된 뒤 완료되지 않은 상태를 성공이나 단순 취소로 표시하지 않는다.
- 개인 전용 상태에서 처음 역할을 설정하는 기존 진입과 기존 연결 해제 동작은 유지한다. ‘개인 전용’으로의 새로운 역할 전환 기능은 이번 범위에 추가하지 않는다.

## 자료와 알림의 경계

| 자료 | 멤버로 전환한 동안 | 호스트 복귀 |
| --- | --- | --- |
| 개인 프로젝트·일정·개인 휴일 | 현재 화면에서 계속 사용·편집 | 그대로 유지 |
| 이 PC가 제공하던 공유 프로젝트·일정 | 중지된 공유 자료에서 조회만 | 원본·공유 지정·등록을 복원해 편집 가능, 공유 시작은 별도 |
| 이 PC의 호스트 공통 휴일 | 호스트 원본으로 보존, 현재 멤버 워킹데이에서 제외 | 다시 호스트 공통 휴일로 사용 |
| 등록 참여자·대상·승인 | 휴면 보관, 서버가 권한을 제공하지 않음 | 동일 PC의 기존 등록·승인을 재사용 |
| 외부 호스트에서 수신한 자료·공통 휴일·공유 알림·자격 | 연결한 호스트의 규칙으로 사용 | 멤버→호스트 완료 전에 정리 |
| 호스트 업데이트 후보·보관 파일 | 보존하되 제공 중지 | 명시적 배포 시 현재 파일·버전·서명/해시 조건 재검증 |

중지된 공유 자료는 공유 설정의 조회 버튼으로 진입한다. 프로젝트·일정·당시 공통 휴일을 읽기 전용으로 제공하고 수정·추가·삭제·공유 대상 변경·알림 설정을 노출하지 않는다. 별도 새 최상위 메뉴는 만들지 않는다. 현재 일정 검색·카운트·Home 오늘 일정·간트/달력·일정 알림 대상으로도 섞이지 않게 한다.

알림 예약과 표시 대기 건도 같은 자료 경계를 따른다. 보관 중인 원본에서 새 알림을 보내지 않으며 역할 변경 도중 큐에 있던 이전 역할 알림도 전환 완료 후 발송하지 않는다. 기존 전송 이력은 중복 방지를 위해 유지한다. 복귀 시 과거 보관 기간의 알림을 일괄 재전송하지 않는 것을 구현 기본값으로 제안한다.

이 PC가 호스트 제공을 중단해도 다른 멤버 PC의 캐시가 즉시 삭제되지는 않는다. 멤버 측에는 기존 연결 단절·마지막 확인 규칙이 적용된다. 보관된 승인의 재사용은 상대의 자격과 등록이 여전히 유효한 경우에 한하며, 자격이 폐기된 멤버를 자동 재승인하지 않는다.

## 코드 조사와 구현에 필요한 경계

- [SharingSettings.tsx](../../src/renderer/components/SharingSettings.tsx), [service.ts](../../src/main/sharing/service.ts), [store.ts](../../src/main/db/sharing/store.ts)는 현재 roleHistory로 반대 역할을 거부한다. UI 제한만 풀거나 roleHistory만 초기화해서는 안 된다.
- [repository.ts](../../src/main/sharing/repository.ts)의 호스트 원본 분류는 현재 역할과 독립적이다. 보관된 원본의 읽기 전용·조회/알림 제외를 main과 저장소 경계에서도 보장해야 한다. renderer 버튼 숨김만으로 처리하지 않는다.
- 로컬 호스트의 주소·인증서·서비스 식별과 멤버의 원격 주소·호스트 ID·신뢰 지문을 분리 보관한다. 역할 전환으로 이 PC의 식별자를 재발급하거나 원격 신뢰를 로컬 인증서에 덮어쓰지 않는다.
- 현재 disconnect는 수신 캐시·알림·접속 자격 정리를 하되 역할 이력·원격 호스트 바인딩을 남긴다. 재승인은 새 접속 자격을 받는 절차이며 임의의 다른 호스트로의 신뢰 변경 허용을 뜻하지 않는다. 기존 지문 확인과 바인딩 제한을 유지한다.
- 역할 변경 세대를 갱신하고 이전 서버·클라이언트·진행 중 요청을 정리해 늦게 도착한 snapshot/승인/알림이 새 역할로 들어오지 않게 한다. 단일 실행 잠금과 진행 기록을 둔다.
- DB·OS 자격 저장소·네트워크 종료 전체를 하나의 원자적 transaction이라고 가정하지 않는다. 재시작 가능한 전환 단계를 기록하고 정리 실패 시 ‘전환 미완료’와 복구 동작을 제공한다. 접속 자격 정리를 마치기 전에 새 역할 성공을 표시하지 않는다.
- 재시작 시 미완료 전환을 복구하기 전 공유 서버·업데이트 배포·멤버 연결을 자동 시작하지 않는다. 이전 역할로의 되돌림은 데이터·자격 상태를 확인할 수 있을 때만 허용하며, 멤버 연결 실패를 이유로 호스트를 자동 재개하지 않는다.

위 실패 복구·큐 경계는 선택한 자료 보존 정책을 지키기 위한 엔지니어링 제안이다. 구체적인 schema와 작업 단계는 후속 구현 계획에서 정한다.

## 인수 범위

일회성 프로필에서 양방향 전환·반복 전환·취소·미저장 변경·busy·정리 실패·재시작 복구를 검증한다. 원본 ID/등록/승인 유지, 보관 자료의 CRUD 거부, 현재 화면·워킹데이·알림 제외, 수신 자료/자격 정리, 재승인 필요, 공유/업데이트 자동 재개 없음, 늦은 snapshot 및 알림 차단이 핵심이다. 실제 Windows 자격 저장소·연결 복구 검증은 HTML 시안 검증과 별도다.

[v3 클릭형 시안](mockups/workrail-screen-polish-v3.html)은 설정 배치와 역할 확인 흐름만 재현한다. 저장·삭제·권한 변경을 실제 수행하지 않으며 중지된 자료의 전체 조회 화면·실패 복구 UI는 구현하지 않은 상태다. 전체 설계 승인은 아직 대기 중이다.

독립 설계 검토에서 역할 전환 구현 계획을 막는 중요한 미답 질문은 발견되지 않았다. 별도 화면 설계의 메뉴/앱 아이콘 선택은 남아 있다. 검토 결과를 실제 전환 코드·Windows 자격 정리·실패 복구가 검증된 것으로 간주하지 않는다.
