# WorkRail 통합 도구 확장 — 설계 협의 기록

후속 협의(2026-11-19): [환경별 Node 연동·Home 개선 초안](workrail-environments-and-home.md)은 아래 1.2.2 고정 구현을 기존 설치 nvm 우선·WSL nodenv 연동으로 확장하려는 설계다. 아직 최종 승인·구현 전이며 아래 초기 결정과 당시 구현 기록은 이력으로 유지한다.

2026-11-18. 상태: Q1~Q13 확정 후 구현을 진행했으며, 이후 사용자가 Q10 메뉴 배치를 **D 하단 도크형 → B 상단 탭형**으로 변경했다. 이번 변경은 설계에만 반영하며 제품 코드는 수정하지 않는다. 아래 구현 기본값과 과거 검증 기록은 당시 상태로 구분한다.
기준: 원격 main `05e972da7282046f2fd2bee584c9ceee7beba007`의 Planrail 0.8.8 문서와 코드. 최초 조사 기준 `c5fa387fe9e0ed8b31ca7af6612bec120f6e815d` 이후 변경을 2026-11-18에 대조했다.
초기 협의 체크아웃은 `17ccfd0`이었으며 최신 원격 객체를 읽어 조사했다. 구현 작업 공간은 원격 `05e972d`를 기준으로 생성했다. 이후 구현은 최신 원격 기준의 `/workspace/workrail` 작업 공간에서 진행하며 기존 협의 작업 트리는 보존한다.

사용자는 최근 작업 맥락으로 `Stage 2 Electron SQLite 설계 확정` 채팅(`codex://threads/01a1a039-9315-7047-ba7a-7fb20b20c098`)을 지정했다. 현재 도구로 해당 채팅 본문은 읽지 못했으며, 원격 저장소에 기록된 변경만 확인했다. 최신 두 커밋은 격리 Electron E2E 프로세스 종료 정리와 관련 검증 기록 보완이며 제품 코드·버전 변경은 없다. WorkRail의 Q1~Q12 결정과 충돌하는 변경은 이 차이에서 발견하지 못했다. 최신 SHA의 CI 성공 여부는 이번 조회로 확인하지 않았다.

## 목적

추가 화면 협의: [Home·PlanRail·NodeRail 화면 정리](workrail-screen-polish.md)는 메뉴 이름, Node 목록의 진행·정렬·패널 높이, PlanRail 하단 상태, Home 배지·제목 및 N 아이콘을 다룬다. 사용자 요청과 Q1~Q4 선택을 반영했으며 전체 문서·시안 확인 전이다. 제품 코드 변경은 하지 않았다.

후속 확정 설계: [기존 Node 제거와 nvm 설치](node-conflict-removal.md)는 Q8의 수동 정리 안내를 사용자 클릭에 따른 공식 MSI 제거 지원으로 확장한다. Q1~Q6를 확정했으며 개발 실행에서는 독립 관리 창으로 이어간다. 사용자가 코드 수정을 금지했으므로 제품 구현 전이다. 아래 원래 결정은 당시 기록으로 유지한다.

Planrail을 팀용 통합 데스크톱 도구의 첫 번째 메뉴로 편입한다. 상위 앱 이름은 WorkRail이며 일정 도구 이름은 Planrail로 유지한다. 두 번째 메뉴는 Node 버전 관리이며, 이후 다른 도구를 추가할 수 있도록 경계를 설계한다. DevOps라는 표현만으로 CI/CD·배포 서버·계정 관리 기능이 승인된 것으로 해석하지 않는다.

Wayfinder로 결정 순서를 정리하고 Superpowers로 접근 방식·설계를 구체화한다. 저장소의 grill-with-docs에 따라 grilling과 domain-modeling을 적용한다. 기존 완료된 MVP 지도는 다시 열지 않는다. 새 지도의 목적과 첫 결정 범위가 정리되면 별도 지도 구조를 정한다.

## 검토한 접근

- 제품 전환: 별도 앱 병행 설치와 기존 앱의 후속 제품 전환 중 사용자는 후자를 선택했다. 기존 사용자의 일정·설정·승인을 이어 쓰는 방향이다.
- 적용 범위: 프로젝트별 독립 환경, 앱에서 연 터미널만 적용, 기존 터미널 연동 중 기존 터미널 연동을 선택했다.
- Node 관리 엔진: 독립 설치·전환 구현과 nvm-windows UI 연동 중 후자를 선택했다. 팀이 이미 사용하는 nvm 및 CLI와 결과를 함께 유지하려는 선택이다.
- 권한: 통합 앱 전체를 관리자 권한으로 실행하는 정책은 승인하지 않았다. 선택한 것은 필요한 작업에 한정된 권한 요청이다.

## 공식 자료에서 확인한 사실

- [nvm-windows](https://github.com/coreybutler/nvm-windows/blob/master/README.md)는 [nvm-sh](https://github.com/nvm-sh/nvm/blob/master/README.md)와 별개다. 기존 제품 대상인 Windows 11 x64를 조사 기준으로 삼았으며 다른 OS 확장은 아직 결정하지 않았다.
- nvm-windows는 PATH에 등록된 단일 심볼릭 링크의 대상을 바꾼다. 그 경로를 사용하는 후속 Node 실행에 적용되며 프로젝트별 병렬 버전 격리는 기본 모델이 아니다. 최초 설치로 PATH가 바뀌면 터미널 재시작이 필요할 수 있다.
- 공식 사용 안내는 install/use에 보통 관리자 권한이 필요하다고 설명한다. 기존 Node의 PATH 우선순위나 실제 디렉터리가 전환을 방해할 수 있다. 기존 설치를 자동 제거할 권한은 이번 결정에 포함되지 않는다.
- [공식 배포 목록](https://nodejs.org/dist/index.json)은 version/date/files/npm/lts/security 등을 제공하며 사전 공개 버전도 포함한다. 최신 항목을 무조건 추천 버전으로 취급하지 않는다.
- 공식 버전별 ZIP과 SHASUMS256.txt가 존재한다. [Node 검증 안내](https://github.com/nodejs/node#verifying-binaries)는 서명된 checksum 검증 절차도 설명한다. UI의 목록 출처와 nvm의 실제 다운로드·검증 경로는 별도로 확인해야 한다.

## 이름·메뉴·Node 화면·홈 — 선택 결과와 비교 기록

사용자는 **NW 웹개발팀**이라는 팀 맥락을 제공한 뒤 처음에는 **WorkRail / 메뉴 D / Node A / 홈 B**를 선택했다. 이후 메뉴 배치만 **B 상단 탭형**으로 변경했다. 현재 확정 조합은 **WorkRail / 메뉴 B / Node A / 홈 B**다. 아래 비교표는 변경 이력을 포함하며 별도의 선택 이유는 답변에 없으므로 추정하지 않는다.

### 상위 앱 이름 검토 이력

| 후보 | 의미와 고려점 |
| --- | --- |
| NW Dock — 당시 추천 | 팀의 도구가 모이는 공간. 일정과 개발 환경을 함께 포괄하며 새 메뉴를 추가하기 쉽다. |
| NW Workbench | 개발팀의 작업대라는 의미가 명확하다. 이름이 상대적으로 길다. |
| NW Hub | 팀의 중심 공간이라는 짧은 이름. 다른 서비스와 구별되는 인상은 약하다. |
| NW Rail | Planrail의 이름을 이어 간다. 상위 앱과 일정 도구의 구분은 덜 선명하다. |

이름·상표·도메인의 사용 가능 여부는 아직 조사하지 않았다. 이름 선택과 내부 설치 식별자 변경은 별개 결정이다.

### 메뉴 배치 4안

기존 딥 그레이·스틸 블루 글래스 재질을 유지하며 같은 Planrail 예시 화면으로 비교한다. 메뉴 이름과 위치만 비교하며 현재 제품 화면을 그대로 재현한 것은 아니다.

| 안 | 구성 | 장점과 비용 |
| --- | --- | --- |
| A 왼쪽 펼침형 — 당시 추천 | 도구 이름을 항상 표시하는 사이드바 | 이후 메뉴가 늘어나도 찾기 쉽다. 간트의 가로 공간을 사용한다. |
| B 상단 탭형 — 현재 선택 | 제목 표시줄 아래에 도구 탭 | 간트의 가로 공간을 확보한다. 도구 수가 늘면 탭이 혼잡해진다. |

### Q10 변경 반영 기준 — 상단 탭 B

사용자가 기존 비교 시안의 B를 직접 선택했으므로 새 메뉴 유형을 설계하거나 다시 선택을 요청하지 않는다.

- 위치: 제목 표시줄 바로 아래, 각 도구 콘텐츠 위의 공통 영역이다. 제목 표시줄의 창 제어·드래그 영역과 구분한다.
- 구성: **Home / PlanRail / NodeRail** 순서의 상단 탭을 세 도구 화면에서 공통으로 사용한다. 후속 화면 정리 요청의 메뉴 이름이며 하단 도크와 중복 배치하지 않는다.
- 스타일: 기존 딥 그레이·스틸 블루, 글래스 투명도·테두리·선택 강조를 유지한다. 새 색상 테마나 사이드바로 변경하는 요청이 아니다.
- 콘텐츠: 탭 아래에 도구 화면을 배치해 메뉴와 화면 조작부가 겹치지 않게 한다. 추후 구현 시 하단 도크용 여백을 정리하고 상단 탭 높이를 반영하되 간트·Node 목록의 스크롤과 입력을 보존한다.
- 동작: Q7의 작성 중 입력·선택 날짜·스크롤 보존과 공유·알림·Node 작업 지속 정책은 유지한다. Q11 Node 목록 A, Q12 통합 현황 홈 B, WorkRail 이름은 유지한다. 앱 아이콘은 후속 Q13 변경으로 F WR 모노그램을 따른다.
- 검증: 추후 구현 시 세 도구에서 탭 전환·선택 표시·키보드 접근·좁은 창의 겹침·제목 표시줄 조작·상태 보존을 확인한다. 이 문서 변경 자체는 화면 구현이나 시각 검증 완료를 뜻하지 않는다.

현재 제품과 기존 조합 시안은 하단 도크 D 상태다. 이번 요청은 B 상단 탭으로 변경할 설계만 확정하며 코드·시안 HTML·기존 검증 캡처는 수정하지 않았다.

메뉴 배치와 Node 화면은 독립적으로 선택했다. 최초 Node 비교 시안의 왼쪽 메뉴 A는 비교를 위한 공통 틀이었으며, 당시 선택 조합 시안에는 하단 도크 D를 적용했다. 현재 메뉴 선택은 B로 변경됐지만 Node 화면은 목록 중심 A를 유지한다. 버전 번호·분류·npm·설치 상태는 모두 예시이며 실제 공식 배포 목록이나 사용자 PC 조회 결과가 아니다. 검색·필터·설치·전환 버튼은 브라우저 메모리에서만 동작하는 모의 기능이다.

### 홈 화면 3안

| 안 | 구성 | 장점과 비용 |
| --- | --- | --- |
| A 도구 시작 화면 — 당시 추천 | Planrail과 Node 관리 진입 카드, 작은 상태 요약 | 도구가 두 개인 현재 범위에서 시작점이 명확하다. 실제 작업까지 한 번 더 이동한다. |
| B 통합 현황 — 선택 | 오늘의 일정, 내 Node 환경, 공유·진행 작업 요약 | 실행 직후 업무 상태를 볼 수 있다. 집계 범위와 갱신 규칙을 추가로 정해야 한다. |
| C 마지막 메뉴 복원 | 별도 시작 화면 없이 마지막 사용 도구로 진입 | 반복 작업에 빠르게 복귀한다. 첫 실행과 복원 실패 시 기본 화면을 정해야 한다. |

미선택 C안은 앱 재실행 시 진입 위치에 대한 제안이었다. 이미 승인된 Q7의 실행 중 메뉴 전환 상태 보존과 별개이며, 미저장 입력을 앱 종료 후에도 복구하는 기능까지 승인한 것은 아니다. C의 안내 배너는 시안 설명용이다.

### 검토용 산출물

독립 HTML과 11개 화면, 세 종류 비교 이미지는 이 채팅 작업공간의 `/workspace/output/nw-tool-concepts/`에 있다. 진입 파일은 `index.html`이며 HTML을 브라우저에서 열어 상단 분류와 하단 A/B/C/D로 비교한다. 이 경로는 저장소에 포함된 배포 자산이 아니다.

당시 선택 조합은 같은 경로의 `workrail.html`에 별도로 반영했다. WorkRail 이름, 하단 도크 D, 목록형 Node 화면, 통합 현황 홈을 함께 확인할 수 있다. 이 조합 시안은 현재의 상단 탭 B 변경을 반영한 화면이 아니며 기존 비교 산출물과 함께 검토 이력으로 보존한다. 로고, 홈의 개별 요약 항목·문구와 상세 동작은 여전히 시안이며 화면 선택만으로 전부 승인된 것은 아니다. 당시 시안 단계에서는 제품 구현·설치·배포 변경을 하지 않았다. 이후 사용자가 구현 진행을 명시했다.

## 후속 상세 검토 항목

- 홈 일정의 집계 범위·정렬·갱신 기준, Node 미설치·조회 실패·오프라인 표시.
- 공통 메뉴의 세부 동작·확장, 앱 공통 설정과 Planrail 전용 설정의 경계. 현재 메뉴 위치는 Q10 변경으로 상단 탭 B다.
- 메뉴 전환 시 상태 보존을 구현할 서비스/화면 경계, 다운로드의 수명주기와 앱 종료 처리.
- 기존 설치본에서 상위 앱으로 이어지는 설치·업데이트·프로필 호환 방식.
- 지원하는 nvm-windows 버전, 기존 설치 탐색, 설치 취소·실패·재시작 처리.
- standalone Node/PATH 충돌의 진단 항목·안내, 기존 nvm 저장소와 권한, CLI의 동시 변경 처리.
- Node 목록의 LTS/Current/사전 공개/EOL 표시, 검색·필터·아키텍처와 삭제 범위.
- 실제 사용 버전의 확인, 권한 취소·다운로드 중단·검증 실패의 처리.
- 프록시·인터넷 제한·오프라인 사용과 Node 다운로드의 검증 책임.
- 1계획(통합 앱)과 2계획(Node 메뉴)의 단계별 인수 기준과 검증.

이 항목의 초기 상태는 미결정이었다. 구현 요청 이후 아래 기본값을 적용하며 검증 중 드러난 경계는 구현 기록에 남긴다. 삭제·다른 OS 확장 등 새 제품 범위는 추가하지 않는다. 이 설계 문서 자체가 검증 성공을 뜻하지 않는다.

## 구현 기본값과 경계 (에이전트 판단)

사용자는 확정 화면·색상·스타일을 유지한 구현을 요청했다. 구현 세부사항은 다음과 같이 정하며 실제 검증 범위와 구분한다.

- 홈은 오늘을 포함하는 조회 가능한 개인·공유 일정과 공유 연결 상태, 로컬 Node 상태를 요약한다. 앱 실행은 홈에서 시작하며 모듈은 숨겨도 살아 있게 유지한다. Node 실패가 일정 사용을 막지 않는다.
- 공식 nvm-windows 1.2.2 Windows x64 연동을 지원하며 최초 설치 지원은 공식 1.2.2 설치본을 사용한다. 다른 버전은 감지·안내하고 자동 교체하지 않는다. 다른 OS에서는 지원 범위를 명확히 표시한다. 공식 Node 목록을 조회하고 LTS/설치됨 검색을 제공한다. 미설치 Node는 설치, 설치된 Node는 사용을 별도 동작으로 제공한다. 삭제·프로젝트별 격리·동시 설치는 추가하지 않는다.
- nvm 최초 설치는 공식 설치 파일을 사용자 동작으로 연다. 앱 전체를 승격하지 않고 install/use에만 Windows 권한 확인을 요청한다. 취소·실패는 성공 표시하지 않으며 설치 후 반드시 재조회한다. 충돌은 진단과 수동 해결 안내로 처리한다.
- 임의 명령·다운로드 URL·경로를 renderer에서 받지 않는다. main frame 발신자 검사, 명령 허용 목록, 버전 형식·실제 목록 검증, 작업 직렬화를 적용한다. nvm의 공식 Node 미러 설정을 확인한다.
- Node 작업은 메뉴 이동 중 계속 진행된다. 실제 앱 종료/업데이트 시 진행 작업을 보호하고 종료 후 복구는 결과 재조회로 판단한다. 오프라인에서는 설치된 버전을 표시하고 목록 조회 오류·재시도를 제공한다.
- 기존 appId·프로필·DB·승인 PC·업데이트 프로토콜은 유지한다. 사용자 표시 이름·제목·아이콘은 WorkRail로 바꾸되 일정 모듈은 Planrail이다. 설치/업데이트 관련 내부 파일명은 호환성을 우선한다.
- 빌드·로컬 검증과 Windows UAC/nvm/설치 실기는 별개다. 이 세션에서는 원격 push·게시를 하지 않는다.
