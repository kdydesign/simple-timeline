# 간트·달력 시각화 계약

작성일: 2026-11-03. 스테이지 3. 사용자 승인 설계.
[화면 동작](experience.md)과 [승인 도메인](domain-rules.md)을 따른다.
이 문서는 좌표·구간의 승인 계약과 기대 결과다. 현재 구현과 실행 증거는 마지막 절에 연결한다.

## MVP 이후 변경의 기준

2026-11-04 승인된 [후속 개선 설계](post-mvp-improvements.md)가 오늘 이동·표시 범위 확장,
간트 접기/들여쓰기, 날짜 클릭·드래그 편집과 고정 헤더의 기준이다. 아래는 기존 MVP의 계산·배치 계약이며,
해당 변경 항목에서는 후속 설계를 우선한다. 날짜 계산·28px 눈금·달력 구간 분할은 유지하고,
드래그 손잡이는 잘린 조각의 경계가 아닌 실제 일정 시작·끝을 따른다. 후속 기능의 구현·검증은 [실행 기록](../implementation/2026-11-04-post-mvp-improvements.md)을 따른다.

## 공통 날짜 계산

- 업무 날짜는 0001~9999 그레고리력 실제 날짜, 양 끝 포함이다. 파싱 후 연·월·일 정수로 계산한다.
  현지 자정 Date/밀리초 차이, UTC 변환으로 업무 날짜를 만들지 않는다. 00~99년 자동 보정도 허용하지 않는다.
- 날짜의 순번 `O(y,m,d)`는 0001-01-01을 1로 두고,
  `365*(y-1) + floor((y-1)/4) - floor((y-1)/100) + floor((y-1)/400)`에
  해당 해 이전 월들의 일수와 `d`를 더한다. 최대 유효 순번은 3652059다.
- 기간은 `O(end)-O(start)+1`. 좌표의 오른쪽 경계는 날짜가 아닌 정수 `O(end)+1`이다.
  9999-12-31 다음을 표현하려고 지원 밖 날짜 10000-01-01을 생성하지 않는다.
- 선택 연월 이전/다음은 0001-01과 9999-12에서 각각 비활성이다. 잘못된 직접 입력은 거부하고 기존 선택을 유지한다.
  주 격자에서 범위 밖 날짜가 필요한 칸은 빈 비활성 칸이다. 연도 0000·10000을 표시/저장하지 않는다.

## 간트 범위와 좌표

- 일정이 있으면 전체 최솟값의 시작 월 첫날을 `Rstart`, 전체 최댓값의 종료 월 마지막 날을 `Rend`로 둔다.
  빈 프로젝트는 범위를 제공하지 않는다. 전체 일정 0개면 선택 연월 한 달이다.
- 일당 폭 `p=28` CSS px. 논리 날짜 영역의 폭은 `(O(Rend)-O(Rstart)+1)*p`다.
  왼쪽 이름 열 폭·바깥 여백은 날짜 영역의 원점에 포함하지 않는다.
- 일정의 논리 시작 `x=(O(start)-O(Rstart))*p`, 논리 폭 `w=(O(end)-O(start)+1)*p`.
  실제 그리기는 `[x,x+w)`와 현재 가로 뷰포트의 교집합이다. 두 날짜가 같아도 폭은 28px다.
  막대 내부 여백·테두리 때문에 논리 기간을 늘리거나 짧은 일정을 여러 날로 표시하지 않는다.
- 월 눈금 폭은 실제 월 일수×28이다. 중간 빈 월도 포함하며 평일만 집계하거나 모든 월을 같은 폭으로 만들지 않는다.
  프로젝트 행에는 기간 막대를 만들지 않는다. 각 일정은 독립 행이며 프로젝트 색상을 상속한다.

## 긴 범위·스크롤·초기 위치

전체 유효 범위는 약 365만 일, 논리 폭은 최대 102257652px다.
이 폭의 DOM 요소나 전체 날짜 칸을 한 번에 만들 수 있다고 가정하지 않는다.
수치상 전체 범위는 유지하되 렌더링은 보이는 날짜·월과 여유 구간만 사용한다.
좌표는 현재 뷰포트 근처의 기준일로 재설정해 물리적인 거대 CSS 좌표/브라우저 스크롤 한계에 의존하지 않는다.
세로 행도 필요하면 가상화하되 스크롤·키보드로 모든 항목에 접근 가능해야 한다.
날짜·일정 개수의 업무 제한을 추가하거나 먼 일정을 조용히 잘라내지 않는다.

가로 이동은 전체 논리 폭에 대응하는 스크롤바/드래그 손잡이와 키보드 이동을 제공한다.
손잡이 위치는 0~`max(0, 전체 논리 폭-뷰포트 폭)`의 논리 오프셋에 대응한다.
보이는 날짜를 접근성 값으로 설명하고 실제 렌더 구간을 넘어 계속 이동할 수 있어야 한다.
현재는 별도 가상화 라이브러리 없이 [viewport 함수](../../src/visualization/viewport.ts)와 React 상태로 구현한다.
극단 범위를 검증하되 일반 노트북·사용자 Windows PC의 응답 시간/최대 데이터 규모를 보장하지 않는다.

선택 월로 이동할 때 목표는 그 월 첫날의 논리 x다. 실제 오프셋은 위 유효 범위로 제한한다.
그 월이 전체 범위 밖일 때만 범위 밖 안내를 한다. 전체 폭이 화면보다 작으면 오프셋은 0이다.
최초 위치·모드 전환·CRUD 이후 기준 유지 규칙은 [화면 설계](experience.md)를 따른다.
현재 월/오늘 강조는 현지 날짜를 기준으로 하는 장식이며 업무 날짜 값·기간 계산을 바꾸지 않는다.

## 달력 격자와 구간 분할

- 월 첫날의 월요일 기준 요일은 `(O(first)-1) mod 7`이다. 격자 시작은 그만큼 앞선 월요일이다.
  필요한 주 수는 `ceil((첫날 요일 + 월 일수)/7)`로 4~6이다.
- 먼저 일정과 선택 월의 교집합 `[max(start,monthFirst), min(end,monthLast)]`을 구한다.
  교집합이 없으면 표시하지 않는다. 이후 각 월~일 주와 다시 교차해 주별 조각을 만든다.
- 조각의 시작 열은 해당 주 월요일과의 순번 차이(0~6), 칸 수는 조각의 포함 일수다.
  원 일정 시작이 조각 시작보다 이르면 왼쪽 계속 표시, 원 일정 종료가 조각 끝보다 늦으면 오른쪽 계속 표시를 둔다.
  월 경계와 주 경계 모두 같은 규칙이다. 각 조각은 원 일정 ID를 유지한다.
- 인접 월 칸에는 일정 조각을 그리지 않는다. 격자가 인접 월 숫자를 보여준다고 선택 월 바깥 일정까지 끌어오지 않는다.

## 주별 줄 배치·더 보기

다음은 에이전트가 구체화한 결정적 배치 알고리즘이다. 업무 정렬을 변경하지 않는다.

1. 각 주의 조각을 **원 일정 시작일 → 원 일정 종료일 → 프로젝트 ID 수치 → 일정 ID 수치** 오름차순으로 정렬한다.
2. 앞에서부터 이미 배치된 조각과 날짜 칸이 겹치지 않는 가장 낮은 줄(0부터)에 배치한다.
   같은 날짜를 포함하면 충돌이다. 다음 날 시작하는 일정은 같은 줄을 재사용할 수 있다.
3. 줄 0~2를 표시하고, 줄 3 이상은 막대를 숨긴다. 같은 일정의 줄 번호는 다른 주에서 달라질 수 있다.
4. 날짜 `d`의 숨김 개수는 숨긴 조각 중 `d`를 포함하는 **서로 다른 일정 ID 수**다.
   숨김 수가 양수일 때만 그 날짜에 `+N 더 보기`를 만든다. 주 전체 합계를 모든 날짜에 반복하지 않는다.
5. 더 보기 목록은 원본 snapshot에서 `start <= d <= end`인 전체 일정을 위 정렬로 표시한다.
   보이는 3줄의 일정도 포함한다. 같은 ID를 중복 나열하거나 이름이 같다는 이유로 합치지 않는다.

세 줄은 배치 줄 제한이지 ‘하루 일정 최대 3개’ 제약이 아니다. 줄의 연속성을 위해
하루에 겹친 수보다 높은 줄에 배치될 수 있으며, 이 경우도 날짜별 더 보기가 접근 경로를 제공한다.
선택·포커스는 일정 ID로 유지한다. 가상화·snapshot 재조회 후 키보드 포커스 항목을 임의 제거하지 않는다.
