# 설치본 피드백 · NodeRail과 TermRail

2026-11-20 협의안. 비교한 제품 커밋은 `1803f49`다. 사용자가 선택한 상단 탭 단위는 **작업 탭**이다. 아래의 색상, 상세 상호작용과 인수 기준은 검토 제안이다. [기존 TermRail 설계](ssh-terminal-menu.md) · [Windows ZIP 설계](windows-node-zip-all-versions.md)

## NodeRail

### 1. 간헐적인 ZIP 설치 권한 오류

사용자 PC에서 Node 26.13.1 설치 이력에 `install · 26.13.1 · zip-permission`이 한 번 표시됐고 이후 설치가 성공했다. 현재 코드는 파일 시스템의 접근 거부와, nvm 2.x 저장 폴더의 권한 규칙 불일치, 권한 정보를 읽는 검사 자체의 실패에 같은 코드를 사용할 수 있다. 당시 어느 단계가 실패했는지는 기존 이력만으로 복원할 수 없다. [Windows 설치 어댑터](../../src/main/node-management/windows.ts) · [ZIP 배치](../../src/main/node-management/zip-install.ts) · [작업 이력](../../src/main/node-management/service.ts)

설계 제안은 사용자에게 최초 실패 단계와 다음 행동을 함께 표시하는 것이다. 예를 들어 디렉터리 생성 중 접근 거부가 확인되면 “임시 설치 폴더를 만들 수 없습니다”, 권한 정보를 읽지 못했다면 “설치 폴더의 권한 정보를 확인할 수 없습니다”라고 안내한다. 진단 이력에는 작업 시각, 대상 버전, 관리자 계열, 실패한 폴더의 역할(저장 루트·임시·대상), 단계와 확인된 OS 오류 코드를 남긴다. 정리 실패는 최초 오류와 별도로 남기고 다음 성공 뒤에도 두 결과를 구별할 수 있게 한다. 프록시 자격 정보와 계정 경로는 진단 복사에서 제외한다. 검증에는 임시 폴더 생성, 권한 조회, 최종 이동, 실패 뒤 재검사와 다음 정상 설치를 각각 포함한다.

### 2. 공식 배포 목록의 작업과 상태

| 현재 상태 | 상태 열 | 작업 열 |
| --- | --- | --- |
| 미설치 | 회색 빈 원 | 파란 글래스 **설치** |
| 설치됨 | 파란 보관함 | 초록 글래스 **사용** |
| 사용 중 | 초록 체크 원 | **사용 중**, 실행 불가 |
| 확인 불가 | 호박색 경고 삼각형 | **다시 확인** |

기존 아이콘 형태, 버튼 글자, 마우스·키보드 툴팁을 유지한다. 밝은 테마와 어두운 테마에서 글자 대비 4.5:1, 상태 아이콘 대비 3:1을 확인한다. 작업 중 잠긴 버튼에서도 상태 열로 설치 여부를 읽을 수 있어야 한다. [현재 상태·작업 셀](../../src/renderer/workrail/NodeVersionControls.tsx)

## TermRail

### 3–4. 로그인 입력과 다른 메뉴에 터미널이 보이는 문제

제품 CSS를 적용한 Chromium 최소 재현에서 포커스된 로그인 입력의 테두리는 0px였지만 TermRail 공통 포커스 윤곽선은 2px였다. 로그인 프롬프트에서만 사각 윤곽선을 없애고, `login as:` 바로 뒤에 대비가 충분한 입력 커서를 표시한다. 여러 서버를 동시에 열어도 현재 선택한 터미널만 포커스를 받는다. 비밀번호는 화면 출력과 스크롤 기록에 남기지 않는다. [입력 규칙](../../src/renderer/termrail/termrail.css) · [로그인 프롬프트](../../src/renderer/termrail/TerminalPane.tsx)

비활성 메뉴의 부모는 `visibility: hidden`이고 연결된 터미널 본문은 `visibility: visible`을 직접 지정한다. 위 Chromium 재현에서 부모를 비활성화해도 자식의 실제 표시 상태가 참이었다. 메인 창에서 다른 메뉴를 열면 TermRail의 전체 표시 영역과 입력 포커스를 함께 제외한다. SSH 연결·출력 버퍼는 유지하고 별도 창의 표시 여부는 그 창에서 관리한다. 검증은 연결 후 Home·PlanRail·NodeRail 각각에서 본문과 커서가 그려지지 않는지, 입력이 숨은 터미널로 전송되지 않는지, 복귀 후 같은 세션에서 화면 크기와 그 사이의 출력이 복원되는지 확인한다. 기존 E2E는 Home 복귀 후 출력 보존을 검사한다. [메뉴 표시](../../src/renderer/termrail/TermRail.tsx) · [기존 E2E](../../tests/e2e/termrail-ssh.spec.ts)

### 5. 서버별 로그인 후 준비

사용 목적은 서버 로그인 뒤 해당 서버의 작업 모드에 들어가는 명령을 매번 직접 입력하는 수고를 줄이는 것이다. 제안은 서버 추가·수정에서 선택적으로 UTF-8 텍스트 파일의 한 줄을 가져와 내용을 미리 보고 프로필에 보관하는 방식이다. 파일은 이 PC에서 읽고 서버로 보내는 내용은 확인한 한 줄이다. 대상 서버와 호스트 키 확인, 사용자 로그인과 대화형 셸 준비가 끝난 해당 세션에서 한 번 수행한다. 추가 인증은 사용자가 해당 터미널에서 입력한다. 기존 세션의 메뉴 이동·탭 이동·창 복귀로 다시 수행되지 않아야 한다. 준비 단계가 실패해도 로그인된 터미널에서 수동으로 계속할 수 있게 한다. SSH 셸 채널이 열렸다는 이벤트와 서버가 모드 전환 명령을 받을 준비가 된 시점은 다를 수 있다. 배너가 늦게 도착하거나 추가 입력을 요구하는 경우까지 확인하며, 준비가 불명확하면 사용자가 해당 세션에서 전송 시점을 선택하는 안을 검토한다.

### 6–7. 새 터미널, 서버 목록과 입력 검증

새 터미널의 현행 폭과 창 크기를 기준으로 제목·입력·동작 영역의 정렬과 재질을 다듬는다. 서버 이름은 한 줄 전체 폭에 두고 호스트와 짧은 포트 입력은 한 행으로 묶는다. 확보한 행을 선택 파일의 이름과 작은 가져오기 버튼에 쓴다. 기존 테마의 얇은 테두리와 반투명 표면, 주요 동작 하나에 파란 강조를 사용한다. 서버 목록은 한 줄에 서버 이름 하나를 유지하고, 평상시 행 배경은 투명하게, 포커스된 행은 얇은 파란 표시로 구분한다. 마우스·키보드·드래그 동작과 상단 공통 메뉴의 크기는 유지한다.

현재도 제출 시 이름 중복·호스트·포트를 검사한다. 새 안은 입력 중에는 방해하지 않고 필드를 떠나거나 제출하면 해당 위치에 이유를 표시한다. 공백 이름·중복 이름, 호스트명·IPv4·IPv6, URL이나 포트까지 붙인 주소, 포트 1–65535 범위와 정수 여부를 구분한다. IPv6 주소의 콜론을 포트 구분자로 오판하지 않아야 한다. 저장하고 연결할 때는 첫 오류로 포커스를 옮기고 입력값을 보존한다. 잘못된 입력에서 저장이나 접속 요청이 발생하지 않는지, 기존 프로필 수정에도 같은 기준이 적용되는지 확인한다. [현재 대화상자](../../src/renderer/termrail/WorkspaceControls.tsx)

기존 저장 데이터는 이전 버전에서 허용한 호스트 표기를 포함할 수 있다. 그런 항목도 목록에서 열어 수정할 수 있게 하고 새 연결 시 문제가 있는 필드를 안내한다. 예전 프로필 하나 때문에 정상 서버나 저장 레이아웃 전체가 사라지지 않는지 확인한다.

### 8–9. 작업 탭, 저장 레이아웃과 닫기

사용자가 선택한 모델에서 상단 탭은 항상 **작업 탭**이고 그 안의 각 칸이 **터미널**이다. 터미널 하나면 탭 제목은 서버명, 분할하면 작업 이름과 터미널 수를 표시한다. **저장 레이아웃**은 모든 작업 탭·분할 비율·별도 창을 담는 복원 단위다. 현재 탭의 우클릭으로 작업 전체의 배치를 저장할 때도 메뉴 문구에서 이 범위를 드러낸다.

예를 들어 단일 탭 `dev-api`에 두 번째 서버를 드롭하면 `작업 1 · 2`가 되고, 이름을 붙이면 `개발 점검 · 2`가 된다. 마지막 한 칸으로 돌아오면 서버명을 표시하고 이전 작업 이름은 다음 분할을 위해 보관하는 안을 제안한다. 기존 저장 레이아웃도 열 수 있어야 한다.

탭 우클릭의 **작업 탭 닫기**는 그 탭 안의 모든 세션을 종료한다. 터미널 제목의 ×는 그 칸 하나만 닫는다. 다른 작업 탭·독립 창·저장 레이아웃은 각각 유지한다. 살아 있는 세션이 여러 개면 “개발 점검의 터미널 2개를 종료할까요?”처럼 범위를 먼저 보여주는 안을 제안한다. 마지막 탭을 닫으면 새 터미널을 열 수 있는 빈 화면으로 돌아간다. [현재 작업 탭과 레이아웃 처리](../../src/renderer/termrail/useWorkspace.ts)
