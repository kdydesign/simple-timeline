# Windows Node 설치의 공식 ZIP 통일

2026-11-19 사용자 요청에 따른 후속 설계 초안. 설치 방식 변경은 사용자 지정 사항이며 아래 세부 절차와 아이콘 축소율은 검토안이다. 제품 구현은 별도 요청 후 진행한다. 현재 배포 구현은 nvm 1.1.10·1.1.11에 ZIP을 적용한다. [이전 설계와 검증](noderail-zip-recovery-shell-icons.md)

## 결정과 배경

Windows에서는 nvm 버전에 관계없이 WorkRail이 공식 Node ZIP을 다운로드하고 실제 버전 저장 루트에 설치한다. 설치 과정의 PowerShell 실행이 사내 보안 제품에 의해 차단된 사용자 사례가 변경 배경이다. 사용자가 지정한 직접 ZIP 설치를 공통 경로로 삼고, 기존 nvm은 환경 확인·설치 목록 확인·사용 버전 전환에 활용한다. WSL2의 nodenv/node-build는 기존 설계를 따른다. 이번 Windows 아키텍처 범위는 기존 x64다.

선택한 방식은 공통 다운로드·검증·압축 해제 처리와 nvm 저장 구조별 연동을 조합한다. 버전별로 `nvm install`을 유지하는 방식은 사용자가 이번에 교체하도록 지정했다. 모든 버전에 같은 AppData 경로를 적용하는 방식은 사용자 지정 루트와 2.x의 별도 저장 위치를 처리하지 못한다.

## 버전과 저장 구조의 처리

설치 방법을 `1.1.10`, `1.1.11` 같은 버전 문자열로 선택하는 분기를 제거한다. nvm 1.2.2와 2.0.1에도 같은 ZIP 설치 절차를 적용한다. 이후 버전은 확인된 저장 구조와 필요한 기능이 호환되면 같은 절차를 적용한다. 버전 숫자가 새롭다는 이유만으로 설치 기능을 제한하지 않는다.

| 환경 | 설치 위치 확인과 등록 |
| --- | --- |
| nvm 1.x | 기존 설정의 `root`를 해석하고 `<root>\v<version>`에 배포본 내용물을 설치한다. `NVM_HOME`과 버전 저장 루트를 구분한다. |
| nvm 2.x | 유효 설정의 `InstallRoot`와 정책 우선순위를 확인하고 버전 폴더를 결정한다. 현재 코드상 폴더 형식은 `v<version>`이며 실제 CLI의 목록·shim/link 전환으로 검증한다. 실행 파일 폴더나 `.shim`에 ZIP을 풀지 않는다. |
| 추가 버전 | 공식 배포본의 신뢰 확인, 설정 해석, 실제 저장 구조 및 목록 조회 능력을 판별한다. 확인된 구조의 연동을 재사용한다. 구조가 달라 판별할 수 없으면 구체적인 이유와 경로 확인 방법을 표시한다. |

현재 실행 파일 신뢰 판정도 네 버전의 고정 해시에 의존한다. 구현 시 공식 배포 자료에 근거한 신뢰 확인을 확장해, 버전 허용 목록을 넓히는 작업 없이 호환 구조를 인식할 수 있도록 해야 한다. 신뢰 판정과 저장 구조 호환성은 각각 검사하며, 파일 해시 검증을 단순 제거하는 방식으로 처리하지 않는다. 미래의 미확인 구조까지 검증됐다는 의미로 모든 버전 지원을 표시하지 않는다.

현재 2.x의 설치 버전 0개 상태에서 적용하는 설치 제한도 ZIP 경로에 맞춰 해제한다. 저장 루트 생성 권한과 경로를 확인하고 첫 설치를 허용하며, 첫 설치 후에도 활성 버전 미지정 상태를 지원한다. 별도 ‘사용’ 요청에서 활성화한다.

## 설치 순서

1. 선택한 Windows 환경, nvm 실행 파일, 유효 설정, 버전 저장 루트, x64 배포 파일 존재와 쓰기 권한을 확인한다. Home과 NodeRail은 같은 작업 서비스를 호출한다.
2. nvm에 저장된 인증정보 없는 HTTP(S) 주소·포트 프록시를 WorkRail 다운로드 계층에서 사용한다. 1.x 설정과 2.x 유효 설정을 각각 해석한다. TLS와 조직의 네트워크 정책을 적용한다. 미러 설정을 바꾸지 않고 이번 기능의 다운로드 출처를 공식 Node 배포 서버로 명시한다. 조직 정책과 충돌하면 이유를 표시한다.
3. `https://nodejs.org/dist/v<version>/node-v<version>-win-x64.zip`과 해당 릴리스의 서명된 해시 자료를 받는다. 신뢰하는 Node 릴리스 키와 정확한 파일명의 SHA-256을 검증한다.
4. 최종 저장 위치와 같은 볼륨에 작업별 임시 폴더를 만들고 압축을 해제한다. 경로 이탈·링크·재분석 지점·비정상적 해제 크기 검증과 Node/npm 패키지 완전성 확인을 재사용한다.
5. 게시 직전에 환경과 설정을 재확인하고 완성된 임시 폴더를 최종 버전 경로로 원자적으로 이동한다. 정상적인 기존 동일 버전은 다시 설치할 필요가 없으며, 불완전한 기존 폴더는 경로와 복구 안내를 표시한다.
6. 실제 nvm의 설치 목록에서 버전을 확인한 뒤 완료로 표시한다. 전환은 별도의 ‘사용’ 요청에서 수행한다. 설치 전후 활성 버전·shim·링크·PATH가 유지되는지 검증한다.

Windows의 다운로드·압축 해제·배치 과정은 앱의 파일 처리 기능을 사용한다. 실패 시 `nvm install`이나 PowerShell 설치 스크립트로 재시도하는 경로를 두지 않는다. 쓰기 권한이 부족하면 해당 경로와 필요한 조치를 안내한다. 현재 환경 감지와 ‘사용’에는 별도의 PowerShell 호출이 있으므로 ZIP 설치 변경만으로 앱 전체의 PowerShell 의존성이 사라졌다고 안내하지 않는다.

기존 환경 감지에서 사용자 지정 미러가 있다는 이유로 설치를 차단하는 조건도 재검토한다. 일반 사용자 미러 설정을 보존하면서 WorkRail의 공식 ZIP 출처를 안내한다. 2.x의 조직 강제 정책은 유효 설정의 출처까지 확인해 준수하고, 직접 다운로드와 양립할 수 없으면 해당 정책을 이유로 설명한다.

## 진행 상태와 실패 복구

양쪽 목록을 덮는 기존 진행 레이어에 환경 확인, 다운로드, 무결성 확인, 압축 해제, 설치 목록 확인 단계를 표시한다. 오류 문구는 실제 원인을 기준으로 다운로드·프록시·서명/해시·권한·보안 제품 차단·목록 확인 실패를 구분한다.

이번 작업의 임시 자료만 정리하고 기존 Node 버전은 보존한다. 폴더 등록 뒤 목록 확인이 실패하면 설치 상태 확인이 필요하다고 표시하고 재다운로드에 앞서 실제 폴더를 재검사한다. 작업 소유권과 종료를 확인해 잠금을 해제하며, ‘환경 다시 검사’로 실패 기록과 실제 설치 상태를 대조하는 기존 복구 절차를 재사용한다. 실행 중인 작업에는 새 설치·전환을 겹쳐 시작하지 않는다.

## 구현 전 확인과 인수 기준

- 1.1.10·1.1.11·1.2.2·2.0.1 각각에서 실제 공식 배포본으로 설치 목록 인식과 ‘사용’ 후 `node -v`·`npm -v`를 확인한다. 2.x는 shim/link 모드와 첫 Node 설치를 포함한다.
- 기본 경로와 사용자 지정 저장 루트, 공백·한글 경로, 직접 연결과 사내 프록시를 확인한다. 프록시 설정은 다운로드 처리에 전달되는지 검증한다.
- Windows 설치 진입점에서 버전에 관계없이 ZIP 경로를 선택하고 `nvm install`과 PowerShell 다운로드·압축 해제 실행이 발생하지 않는지 검증한다. 감지·전환 호출은 별도로 기록한다.
- 다른 버전 번호이면서 호환 구조인 경우의 기능 판정과, 알 수 없는 구조에 대한 설명을 검증한다. 공식 실행 파일의 신뢰 검증 방법과 추가 버전 검증 근거를 구현 기록에 남긴다.
- 잘못된 서명·해시, 연결 실패, 권한 부족, 보안 제품 차단, 기존 불완전 폴더, 등록 직후 조회 실패, 중복 요청, 앱 재시작 후 복구를 검증한다.
- 설치만으로 현재 사용 버전이 바뀌지 않아야 하며, 실패 후 재검사를 거쳐 다음 정상 작업을 실행할 수 있어야 한다.

## 앱 아이콘 로고 축소 시안

사용자는 내부 로고를 살짝 줄이도록 요청했다. 검토 시안은 기존 흰색·하늘색 레일 형태의 중심을 기준으로 가로·세로 약 92% 크기를 목표로 생성했다. 8% 축소는 작성자의 제안이다. 바깥 정사각형의 크기와 모서리·테두리·남색 배경을 기준으로 내부 여백을 늘린다. 이미지 생성 시안은 정확한 벡터 변환 결과와 구분한다. [시안 PNG](mockups/workrail-icon-smaller-logo-preview.png)

제품 적용 시에는 원본 SVG의 로고 두 path만 중심 기준으로 동일 비율 축소한다. 앱·작업 표시줄·트레이·설치 바로가기의 외곽 점유 크기를 유지하고, 16·20·24·32px에서 식별성과 여백을 확인한다. 이번에는 제품 `resources/icon.*`와 소형 아이콘을 교체하지 않았다.
