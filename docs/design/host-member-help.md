# 호스트·멤버 도움말 창

2026-11-16. 상태: **승인된 설계 — H1~H7 개별 결정 및 H8 화면 시안·문서 전체 확정, 구현 보류.** 사용자는 H8에서 ‘설계 확정·구현은 보류’를 선택했다. 제품 구현 시작과 출시 버전은 별도 요청 이후 정한다.

기준은 main `052ffe46f20eb767c8963cf4947f80ff4d85d0fb`의 0.8.1이다. 이번 변경은 설계와 검토용 시안뿐이다. [알림 제어·접속 상태 승인 설계](notification-controls-and-member-presence.md)는 별도 구현 보류 상태를 유지한다. 도움말을 추가한다고 그 기능들이 구현된 것으로 설명하지 않는다.

## 확정된 사용자 결정

| 항목 | 합의 |
| --- | --- |
| 진입점 | 주 창 최상단 최소화 버튼 바로 왼쪽에 물음표 아이콘. 접근 가능한 이름은 ‘도움말’ |
| H1 | 시작하기 / 호스트 사용법 / 멤버 사용법 / 문제 해결. 첫 연결, 프로젝트 공유, 동기화, 알림, 업데이트, 연결 문제 포함. 해당 출시 버전의 실제 동작만 설명 |

| H7 | 제품 코드를 수정하지 않는 화면 시안 검토 |
| H8 | 화면 시안과 기술 구체화를 포함한 문서 전체 확정. 기본 1120×800, 오프라인 콘텐츠·검색·이미지 확대, 읽기 전용 보안 구조 포함. 제품 구현은 보류 |

## 접근 방식과 결정

앱과 함께 배포하는 오프라인 도움말을 전용 BrowserWindow에서 제공한다. 사내 인터넷 접속 없이 검색·그림·이미지 확대를 사용할 수 있고 해당 앱 버전과 설명을 함께 관리할 수 있다. 외부 웹사이트는 사내 접속 제한과 버전 불일치, PDF는 역할별 진입·창 복원 연동을 충족하기 어려워 채택하지 않는 안이다.

아래 창 크기·검색 세부·콘텐츠 관리·기술 경계는 H1~H7을 구체화해 제안했고 H8 문서 전체 승인에 포함됐다. 설계 승인은 구현 시작을 의미하지 않는다. 새로운 업무 권한이나 공유 동작은 추가하지 않는다.

## 화면 설계

- [검토용 HTML 시안](mockups/host-member-help.html): 기존 딥 그레이·스틸 블루, 얇은 경계, 높은 본문 대비. 정보 화면은 장식과 배경 투과를 줄인다. 제품 화면 구현물이 아니다.
- 주 창 오른쪽은 `? / 최소화 / 최대화·복원 / 닫기`. 물음표는 드래그 영역에서 제외하며 마우스·키보드 포커스로 설명을 확인할 수 있다. 자동 포커스 복원만으로 툴팁을 띄우지 않는다.
- 도움말 기본 크기 1120×800 논리 픽셀, 열기 위치는 주 창 모니터 작업 영역 안으로 제한한다. 왼쪽 약 236px, 본문은 남은 폭을 사용한다. 창은 크기 조절 가능하며 글자는 14px, 단계 제목 16px, 문서 제목 24px를 기준으로 한다.
- 좁은 작업 영역·높은 Windows 배율에서는 목차 접기 기능과 본문 세로 스크롤로 모든 조작부에 접근한다. 별도 모바일 화면은 추가하지 않는다. 도움말의 제목 표시줄에도 최소화·최대화/복원·닫기를 제공한다.
- 목차와 본문은 각각 스크롤한다. 검색 결과에는 제목·소속 분류·본문 일치 부분을 표시한다. 공백을 정리한 검색어로 제목과 본문을 대소문자 구분 없이 검색하며 이미지 안의 글자 OCR은 하지 않는다. 결과가 없으면 검색어 변경 안내와 지우기를 제공한다. 검색은 도움말에만 적용하며 사용자 일정은 검색하지 않는다.
- 처음 여는 항목은 개인 전용=‘시작하기’, 호스트=‘호스트 사용법’, 멤버=‘멤버 사용법’. 이후 창을 닫아도 같은 실행 중에는 마지막 항목·본문 스크롤·검색어를 기억한다. 앱 재실행 후에는 현재 역할 기준으로 다시 시작한다. 도움말을 열어 둔 상태의 역할 변경은 읽던 항목을 강제로 바꾸지 않는다.
- 이미지 아래 ‘클릭하여 확대’와 대체 설명을 제공한다. 확대 보기는 화면 맞춤/확대/축소 버튼, 휠 확대 및 드래그 이동, 키보드 버튼·방향키 이동을 제공한다. 확대율은 50~300%, 첫 표시는 화면 맞춤이다. Escape/X 후 같은 위치와 이미지 버튼 포커스로 돌아온다. 검색 중 Escape는 확대 보기가 있을 때 먼저 확대 보기만 닫는다.
- 시안의 참여자 이미지는 기존 격리 E2E 산출물 `artifacts/participant-row/participants.png`에서 참여자 부분만 보이게 배치했다. ‘디자인 PC / 192.168.0.20’은 예시다. 현재 출시 화면의 최종 도움말 자산이 아니며, 실제 구현에서는 해당 출시 버전에서 새로 촬영한다. 원본의 테스트용 loopback·환경 IP 영역은 설명 이미지로 사용하지 않는다.

## 콘텐츠 구성과 근거

운영 설명의 기준은 기존 [사용 안내](../release/user-guide.md)다. 정책 결정은 그 문서가 연결한 설계에 두고, 도움말은 화면 중심의 사용 절차로 작성한다. 동일 규칙의 다른 사본을 별도 정책 문서로 만들지 않는다.

| 분류 | 포함할 설명 |
| --- | --- |
| 시작하기 | 개인·호스트·멤버 차이, 한 호스트와 승인 PC 관계 그림, 트레이 연결 상태에서 공유 설정 열기, 사내 주소·방화벽 준비 |
| 호스트 사용법 | 실제 LAN IPv4/포트 저장 → 공유 시작 → 참여자 이름/IP 등록 → 멤버 연결과 전체 지문 비교·승인 → 프로젝트 공유 전환/참여자-PC 연결. 승인 취소와 참여자 삭제 차이, 공유 중지·트레이·완전 종료, 업데이트 ZIP 등록·검사·배포 시작·중지 |
| 멤버 사용법 | 호스트 주소 입력·지문 확인·호스트 승인, 허용된 프로젝트 조회, 개인/공유 필터, 수동 동기화·상태, 자기 일정 알림, 공유 변경 알림, UPDATE 다운로드·검증·설치 대기·재시작, 연결 해제 |
| 문제 해결 | 빨간 연결 상태, 호스트 공유 중지·절전·종료, IPv4 변경·승인 취소, 같은 주소/포트 확인, Windows 방화벽과 회사 IT 문의, UPDATE 미표시/다운로드 실패/미저장 입력 대기, Windows 알림 설정 |

호스트 주소 `192.168.0.10`, 멤버 주소 `192.168.0.20`, 포트47831 등은 ‘예시이며 실제 PC 값으로 변경’이라고 명시한다. 127.0.0.1을 사내 연결 주소로 안내하지 않는다. 양쪽 전체64자리 지문 비교 절차를 축약하지 않으며 방화벽 전체 해제·보호 저장소 삭제·DB 초기화를 해결책으로 안내하지 않는다.

접속 멤버 수·전체 알림 끄기·업데이트 Windows 알림은 승인됐지만 아직 미구현이다. 이 기능을 함께 출시하기로 결정하고 실제 코드·화면 검증이 끝난 경우에만 해당 도움말 항목을 포함한다. 릴리스마다 도움말에 대상 앱 버전을 표시하며 원격 도움말 자동 갱신·온라인 검색·계정·사용 추적은 추가하지 않는다.

## 창 생명주기

| 사건 | 동작 |
| --- | --- |
| ? 첫 클릭/연속 클릭 | 생성 중에도 단일 창 유지. 생성 완료 후 표시. 이미 있으면 최소화/숨김 복원 후 포커스 |
| 도움말 X | 도움말만 닫고 현재 읽기 위치를 메모리에 유지. 주 창·동기화·입력에는 영향 없음 |
| 주 창 X, 트레이 숨김 | 열려 있는 도움말도 숨기고 ‘주 창과 함께 복원할 창’으로 기억. 닫혀 있던 도움말을 새로 만들지 않음 |
| 트레이 Open·바로가기·알림 클릭으로 주 창 표시 | 숨김 전 열려 있던 도움말을 함께 복원하되 주 창의 사용자 작업/알림 대상에 최종 포커스. ? 명시 클릭이면 도움말에 최종 포커스 |
| 창별 최소화 | 다른 창에는 영향 없음. 주 창을 단순 최소화해도 도움말은 유지 |
| Exit·업데이트 설치·수동 설치 종료 | 기존 앱 종료 절차 우선. 종료가 취소되면 도움말 유지. 종료가 확정되면 도움말도 파괴하며 별도 저장 확인 없음 |
| 도움말 로드 실패/renderer 종료 | 도움말 재열기 안내와 재시도 제공. 주 창·저장·공유는 계속 사용. 생성 중 플래그 해제, 반복 클릭으로 영구 차단되지 않음 |

트레이 생성 실패로 주 창의 종료/취소 확인이 뜨면 그 기존 흐름을 유지한다. 취소 시 도움말도 숨기지 않는다. 로그인 자동 실행은 도움말을 자동으로 열지 않는다. 도움말 검색어·읽기 위치는 데이터 편집이 아니므로 미저장 입력/업데이트 대기의 조건에 포함하지 않는다.

## 승인된 구현 경계

- 현재 [Titlebar](../../src/renderer/components/Titlebar.tsx)에는 도움말 버튼이 없고 [window](../../src/main/window.ts)는 주 창 생성만 담당한다. [About](../../src/main/about.ts)은 native 정보 대화상자이므로 도움말을 대체하지 않는다.
- main에서 단일 도움말 창과 세션 읽기 상태를 관리한다. 전용 renderer 진입점과 묶음 콘텐츠·이미지를 지연 로딩해 앱 초기 화면/동기화를 기다리게 하지 않는다. packaged/dev 모두 고정된 로컬 진입점만 허용한다.
- `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, `webviewTag: false`. 주 창의 데이터·공유·업데이트 API preload를 재사용하지 않는다. 도움말에는 자신의 창 조작과 허용된 읽기 상태 전달만 노출하고 IPC는 해당 창/메인 프레임/고정 출처를 검사한다. 주 창의 기존 신뢰 검사를 느슨하게 하지 않는다.
- 외부 탐색·새 창·권한 요청은 막고, 본문/그림/폰트/검색 색인은 로컬로 제공한다. 콘텐츠의 script·임의 HTML 실행을 허용하지 않으며 내부 링크는 정해진 문서 ID로만 이동한다. 도움말에서 공유 설정 변경이나 설치 다운로드를 직접 실행하지 않는다.
- 도움말 문서에는 안정적인 항목 ID·분류·제목·본문·이미지 대체 텍스트·단계 번호를 둔다. 빌드 때 항목 링크/이미지 경로/중복 ID/설치 버전 메타데이터를 검사한다. renderer 문구와 도움말이 바뀌면 같은 변경에서 설명·이미지를 함께 갱신한다.
- 테스트 화면은 격리된 가상 프로필에서 촬영하고 DB·접속 자격·실제 이름/IP를 배포 자산에 포함하지 않는다. PNG는 필요한 화면 부분을 선명하게 담고 원본 크기를 유지해 확대 시 읽을 수 있게 한다. 문서와 이미지의 버전·촬영 근거를 기록한다.

## 구현 이후 인수 기준

1. 설치 후 인터넷을 끊어도 모든 본문·그림·검색·이미지 확대가 동작한다. 검색 결과 없음/한글/본문 일치/키보드 탐색을 확인한다.
2. 역할별 첫 항목, 역할 간 목차 이동, 같은 세션 재열기 복원, 재실행 초기화를 확인한다.
3. ? 연속 클릭에서 창 하나, 도움말 X, 두 창 각각 최소화, 트레이 함께 숨김·복원, Exit 취소·실제 종료, 설치 대기·실제 재시작을 확인한다. 주 창 초안은 유지한다.
4. 이미지 확대·축소·이동·Escape·포커스 복귀 및 누락된 이미지의 대체 설명을 확인한다.
5. Windows100/150/200% 배율·작은 작업 영역·다중 모니터에서 조작부 잘림 없이 읽고 닫을 수 있다. 화면 읽기 도구로 이름·목차·단계·이미지 설명을 확인한다.
6. 도움말 renderer에서 DB/공유/설치 IPC 접근, 임의 경로/외부 탐색을 거부한다. 도움말 열기 전후 주 창 시작 시간을 따로 확인한다.
7. 도움말의 모든 절차를 해당 설치본의 가상 호스트·멤버에서 따라가며 버튼명·승인 순서·알림·업데이트 제한과 대조한다. 아직 미구현인 알림 제어 설계의 화면을 출시 도움말에 넣지 않는다.

## 이번 설계 검증

제품 구현과 Windows 도움말 창은 아직 없으므로 위 인수 기준은 **미검증**이다. HTML 시안은 브라우저에서 배치·검색·이미지 확대를 확인하기 위한 별도 검토물이며 Electron 창 생명주기 검증을 대신하지 않는다.

- Linux Chromium, 1280×960, sandbox 유지: 최종 시안 렌더링·이미지 확대·Escape 복귀·한글 검색·검색 결과 없음·검색 지우기 통과. 페이지 스크립트 오류 없음. `artifacts/help-window-preview.png`, `artifacts/help-window-zoom.png`를 확인했다. 기존 화면 캡처의 해상도 한계가 있으므로 출시용 이미지 선명도 검증은 별도다.
- 환경의 `file://` 탐색 제한으로 HTML 내용을 브라우저에 직접 주입해 확인했다. 임시 검증 스크립트의 같은 페이지 재주입은 전역 변수 충돌로 실패했으며, 새 페이지에서 최종 HTML을 다시 검사해 통과했다. 제품 설정이나 보안 정책은 바꾸지 않았다.
- 독립 builder 검토: 창 생명주기·보안·콘텐츠 경계에서 구현 계획을 막는 중요한 미결정 없음. 구현 보류 중인 알림 제어 설계와 충돌 없음.
- `node scripts/harness/run.mjs verify`, `git diff --check` 통과. 문서 상대 경로를 실제 대상과 대조했다. 제품 검사·Windows 도움말 실기는 실행하지 않았다.

H8 승인 후 설계·문서 인덱스·STATUS의 승인 상태만 갱신했다. 시안과 제품 코드는 변경하지 않았다. 다음 작업은 별도 구현 요청 이후 이 승인 문서를 기준으로 계획하며 기존 MVP 단계를 다시 열지 않는다.
