# PostRail 설계 재검토

2026-11-20 · Wayfinder 상태와 승인 커밋을 대조했다. Q12는 첫 버전의 범위와 화면 배치에 대한 승인이다. 이번 검토에서는 세 가지 추가 동작을 합의하고, 기존 화면에서 확인하기 어려웠던 실행 상태를 별도 시안에 담았다. 제품 구현은 후속 단계다. ## 승인 범위를 확인한 결과

| 승인 | 사용자에게 보이는 동작 |
| --- | --- |
| Q1~Q3 | 저장한 요청과 환경을 불러온다. 환경당 로그인 설정 하나를 두고 요청별로 인증을 켠다. 한 실행에서 한 번 로그인하며 토큰 추출에 실패하면 본 요청은 0건이다. 비밀번호는 선택한 경우에만 보호 저장하며 토큰은 실행 동안만 쓴다. |
| Q4 | 반복 POST는 한 건씩 전송한다. 4회차가 HTTP 409여도 5회차를 보낸다. 서버 반영 여부가 불명확한 시간 초과는 ‘결과 확인 필요’로 표시하고 자동 재시도하지 않는다. |
| Q5~Q7 | 저장한 요청별 첫 번호는 1이다. 환경 전환이나 재시작 후에도 다음 번호가 이어진다. 번호는 발송 직전에 예약·저장하고 실패해도 재사용하지 않는다. 5회차 전송 중 중지하면 그 한 건의 결과를 기다리고 6부터 이어간다. |
| Q8·Q11 | 횟수는 기본 1인 양의 정수이며 고정 상한이 없다. 인덱스를 쓰는 POST는 1회여도 번호를 소비한다. 인덱스가 없으면 반복해도 번호를 소비하지 않는다. |
| Q9 | 실제 HTTP 평문 대상을 미리 보여 준다. HTTPS는 Windows 신뢰 저장소를 따른다. 다른 주소로의 리디렉션을 자동으로 따라가지 않는다. |
| Q10·Q12 | 앱 전체에서 한 번에 한 실행을 진행한다. 현재 또는 마지막 실행의 요청명·환경·회차별 응답을 확인한다. 인덱스를 쓰려면 먼저 요청을 저장한다. 환경·저장 요청은 왼쪽, 요청·응답은 중앙, 회차 결과는 아래에 둔다. |

## 화면에서 확인할 흐름

[인터랙티브 시안](mockups/postrail-review.html) · [기본 화면 이미지](mockups/postrail-review.png) · [Q12 승인 당시 시안](mockups/postrail.html)

| 확인할 상황 | 시안에서 해볼 일 | 기대 결과 |
| --- | --- | --- |
| 개별 회차 오류 | 첫 화면에서 선택된 4회차를 확인하고 다음 페이지의 7회차를 선택한다. | 4회차는 409와 86 ms, 7회차는 201과 해당 응답을 표시한다. 응답 본문과 헤더를 전환할 수 있다. |
| 환경 변경 | 왼쪽 환경을 개발 장비에서 QA 장비로 바꾼다. | 편집기에는 QA의 실제 HTTP 평문 주소가 보인다. 최근 결과에는 실행 당시 개발 장비가 표시되며 같은 저장 요청의 다음 번호는 11이다. |
| 전송 중 중지 | ‘시안 보기’에서 실행 중을 고른 뒤 ‘진행 중지’를 누른다. | 5회차가 끝날 때까지 중지 대기를 표시한다. 이후 6~10회차는 미전송이고 다음 번호는 6이다. |
| 서로 다른 두 실패 | ‘실행 전 인증 실패’와 ‘결과 확인 필요’ 상태를 각각 연다. | 인증 실패는 본 요청 0건이며 번호를 소모하지 않는다. 시간 초과는 해당 회차가 발송되었고 서버 반영 여부가 불명확한 상태다. |
| 좁은 창 | 창 너비를 줄여 환경 관리와 저장 요청 선택을 확인한다. | 승인 당시 시안은 좁은 폭에서 왼쪽 영역이 사라졌다. 이번 시안은 환경과 요청을 위쪽에 배치해 선택을 유지한다. |

시안의 ‘시안 보기’는 상태 비교용이다. 모든 표시값과 응답은 로컬 예시 데이터이며 브라우저 밖으로 전송하지 않는다. 반복 횟수 10과 표의 페이지 크기 5는 표시 예시다.

## 추가 합의와 인수 기준

| 추가 합의 | 구현 시 확인할 동작 |
| --- | --- |
| 창의 ×로 트레이에 숨기면 실행을 계속한다. 명시적 앱 종료는 진행 중인 한 건까지만 기다린다. | 5회차를 보내는 동안 창을 숨겼다가 열면 같은 실행을 다시 볼 수 있다. 같은 시점에 앱 종료를 누르면 5회차의 응답 또는 시간 초과 후 종료하고 6회차는 보내지 않는다. 재실행 후 자동 발송하지 않는다. |
| 환경마다 토큰을 받을 API 주소 하나를 지정한다. 로그인 서버와 별도 주소를 쓸 수 있다. | 로그인 서버에서 받은 토큰을 설정된 API의 프로토콜·호스트·유효 포트가 모두 일치하는 대상에만 보낸다. 인증을 켠 요청이 다른 주소를 가리키면 보내기 전에 표시한다. 리디렉션으로 전달하지 않는다. |
| 공통 응답 대기 시간을 기본으로 쓰고 요청별로 조정할 수 있다. | 같은 환경의 보통 요청과 느린 요청에 서로 다른 대기 시간을 적용할 수 있다. 실행 도중 편집한 값은 다음 실행부터 적용한다. 시간 초과 후에는 같은 회차를 자동 재전송하지 않는다. |

공통 기본 시간의 숫자는 이번 협의에서 지정하지 않았다. 시안의 개별 요청에 표시한 60초는 예시다.
