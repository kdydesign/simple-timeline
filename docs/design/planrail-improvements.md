## 목표와 접근 선택

기존 오프라인 일정 관리 기능·데이터를 유지하면서 Planrail로 이름을 바꾸고,
날짜 탐색·간트 조작·창 종료·설치 경로 선택을 개선한다. 화면은 shadcn/ui를 사용해 재설계한다.

검토한 접근은 다음과 같다.

| 접근 | 차이·선택 결과 |
| --- | --- |
| C안 외형 유지, 공통 컴포넌트만 교체 | Q6에서 사용자가 외형 재설계를 선택하여 채택하지 않음 |
| C안 배치 유지, shadcn/ui 기반 새 외형 | Q7에서 선택. 프로젝트 탐색 위치를 유지하며 외형·조작 요소 개선 |
| 탐색 구조·배치까지 재설계 | Q7에서 채택하지 않음. 사이드바 등 새로운 탐색 구조를 추가하지 않음 |

외형은 두 시안을 비교했다. A Zinc는 중립 회색·인디고와 얇은 테두리,
B Mist는 청회색·청록과 채워진 입력이다. **Q12에서 A Zinc를 선택했다.**
이 문서의 승인된 변경 항목은 [C안 설계](flat-glass-redesign.md)와
[이전 개선 설계](post-mvp-improvements.md)의 해당 항목을 대체한다.
[날짜·도메인 규칙](domain-rules.md), [저장 계약](storage.md), 업무 CRUD 계약은 유지한다.

## 이름·설치·데이터 연속성

- 사용자에게 보이는 제품명·창 제목·실행 파일·설치 파일·바로가기·트레이 이름은 **Planrail**이다.
- 신규 기본 설치 위치는 `%LOCALAPPDATA%\Programs\Planrail`이며 단계형 설치에 경로 선택 화면을 넣는다.
  현재 사용자가 쓸 수 있는 위치를 선택한다. 쓸 수 없는 폴더에는 오류를 안내하며 관리자 승격하지 않는다.
- 기존 사용자 설치는 기존 설치 경로를 기본으로 재사용한다. 폴더 이름을 강제로 바꾸지 않는다.
  사용자가 다른 경로를 고른 업그레이드도 이전 앱·바로가기 정리와 데이터 보존을 검증한다.
- 완료 화면의 기본 체크된 실행 옵션과 제거 시 DB 보존 정책은 유지한다.
- **구현 구체화:** 설치 ID/AUMID `com.kdydesign.simpletimeline`, package 내부 식별자,
  `%APPDATA%\SimpleTimeline` 프로필 및 `simple-timeline.preferences.v1` 키를 유지한다.
  이는 이름 변경으로 기존 DB·테마·프로젝트 접힘 설정이 끊기지 않게 하기 위한 선택이다.
  GitHub 저장소 주소와 예전 실행 기록을 일괄 개명하지 않는다.
- 표시명과 별개인 DB 위치·스키마·보존 정책은 변경하지 않는다. renderer의 파일·DB 권한도 늘리지 않는다.
- **구현 구체화:** 배포 버전은 0.3.0으로 구분한다. 기존 0.2.1 → Planrail 업그레이드를 별도로 검증한다.
  같은 새 코드의 가상 다음 버전 설치만으로 이름 변경 업그레이드 검증을 대체하지 않는다.

## 날짜 선택과 탐색

앱이 공유하는 단일 선택 날짜를 상단 YYYY-MM-DD 입력, 간트 날짜 열, 달력 날짜 칸에 반영한다.
새 프로세스 실행 시 현지 오늘을 선택하고 해당 날짜를 보여준다. 트레이 복원은 선택·위치를 그대로 유지한다.
일정 막대를 편집하는 동작은 날짜 선택을 바꾸지 않는다. 선택일은 일정 데이터가 아닌 화면 상태다.
구현 계약 보정: 달력 일정 드래그 중 월 경계 탐색은 표시 월만 바꾸며 선택 날짜는 유지한다.
기존 드래그 취소 규칙대로 탐색한 월은 남기고, 다음 명시적 날짜 탐색에서 표시 월과 선택 날짜를 다시 맞춘다.

| 입력 | 결과 |
| --- | --- |
| 상단 입력 클릭 | 입력 옆 한국어·월요일 시작 날짜 팝오버 열기. 옆 ‘조회 연월 선택’ 버튼 제거 |
| 상단 달력에서 선택 / 올바른 직접 입력 확정 | 선택 날짜·조회 월 변경. 간트 왼쪽 정렬, 달력은 해당 월·날짜 강조. 일정 추가 패널은 열지 않음 |
| 오늘 | 현지 오늘 선택. 간트의 프로젝트 이름 열 바로 다음 날짜 영역 왼쪽에 오늘 칸 시작점을 맞춤 |
| 이전/다음 달 | 현재 일자를 최대한 유지하고 없는 날은 목표 월 말일. 예: 1월31일 → 2월28일 → 3월28일(비윤년) |
| 간트 날짜 눈금·빈 날짜 영역 / 달력 날짜 클릭 | 선택 날짜 강조와 기존 일정 추가 패널. 기존 프로젝트 우선·최근 프로젝트 규칙 유지 |

- 날짜 영역 클릭은 포인터 아래 화면 위치를 유지한다. 상단 입력·오늘·월 이동 같은 명시적 탐색에서만 왼쪽으로 정렬한다.
- 미저장 확인을 요구하는 기존 일정 추가 동작에서 ‘계속 편집’을 선택하면 기존 선택 날짜도 유지한다.
  편집 패널을 연 채 상단 날짜만 탐색할 때는 기존 입력을 보존한다.
- 다른 날짜를 선택할 때까지 강조를 유지하고 두 모드에서 공유한다. 호버·오늘·선택을 서로 식별할 수 있게 표시한다.
  일정을 추가하거나 패널을 닫았다는 이유로 선택 날짜를 해제하지 않는다.
- 직접 입력은 Enter/blur에서 기존 도메인 유효성을 확인한다. 잘못된 값은 적용하지 않고 안내한다.
  지원 범위 0001-01-01~9999-12-31과 시간대 없는 날짜 의미를 유지한다.
- 전체 일정 범위와 실행 중 탐색한 달 범위의 합집합을 표시한다. 최초 오늘도 이 탐색 범위에 포함한다.
  일정이 없어도 선택 날짜가 속한 달을 표시한다. 현재 실행에서 넓어진 탐색 범위는 저장하지 않는다.
- 오른쪽 끝 날짜도 정확히 왼쪽에 놓을 수 있도록 후행 화면 공간을 확보한다.
  지원 범위 밖 가짜 날짜·추가 가능한 칸은 만들지 않으며 끝 공간은 일정 날짜 범위로 계산하지 않는다.

## 간트 확대·축소와 가로 이동

- Ctrl+휠은 간트 날짜 눈금·날짜 본문 위에서만 날짜 간격을 바꾼다. 기본 28px, 최소14px, 최대84px다.
  페이지 전체 확대나 달력 확대가 아니다. 일반 세로 휠·기존 가로 휠·Shift+휠 기능은 유지한다.
- 확대 전 포인터 아래의 논리 날짜 위치가 확대 후에도 그 포인터 아래에 오게 offset을 보정한다.
  범위 양 끝에서는 유효 offset으로 제한한다. 마지막 배율을 기존 설정과 함께 보존한다.
- **구현 구체화:** 휠 deltaMode를 정규화해 연속 배율로 조절한다. 손상·범위 밖 저장 배율은 기본값으로 되돌린다.
  시안의 100%는 28px 기준 현재 배율 표시다. 별도의 확대 패널은 추가하지 않는다.
- 최소 배율에서도 날짜 클릭·1일 일정 양끝 조절이 가능해야 한다. 날짜 눈금 생략은 가능하나 클릭 날짜 계산은 생략하지 않는다.
- Space를 누른 상태에서 날짜 영역에 왼쪽 포인터 드래그를 시작하면 가로 이동을 우선한다.
  일정 막대 위에서도 일정 이동·기간 조절·날짜 추가 클릭을 발생시키지 않는다.
- 텍스트 입력·선택 목록·버튼의 키보드 Space 동작은 유지한다. 시작 시의 포인터 위치와 논리 offset으로 이동량을 계산한다.
  작은 클릭 흔들림을 이동으로 처리하지 않되, Space 탐색 제스처 뒤 일정 추가/편집 클릭은 억제한다.
- 현재 표시 범위에서 제한하며 패닝만으로 범위를 늘리지 않는다. 포인터 또는 Space를 놓으면 끝낸다.
  Escape·pointercancel·창 포커스 이탈도 현재 offset에서 끝내고 일정 데이터는 변경하지 않는다.
- **구현 구체화:** 일정 이동/기간 조절 중에는 확대·화면 패닝을 새로 시작하지 않는다.
  이미 시작한 일정 드래그는 기존 Escape 취소·저장 규칙을 유지한다.
- 표시·클릭·막대 길이·리사이즈 손잡이·드래그 미리보기·키보드 이동·가로 손잡이가 같은 day width와 offset을 사용한다.
  0001~9999년·10,000개 일정에서도 기존 가상화와 제한된 DOM 구조를 유지한다.

## 창 숨김·복원·종료

- 최초 실행은 주 창을 표시하고 트레이 아이콘을 만든다. Windows의 설정에 따라 알림 영역이나 숨겨진 아이콘에 나타난다.
- X/Alt+F4는 창을 파괴하지 않고 숨긴다. 미저장 폼·선택 날짜·스크롤·배율·진행 중 저장을 유지한다.
  트레이는 현재 프로세스를 유지하기 위한 것이며 로그인 자동 실행은 이번 범위에 추가하지 않는다.
- 트레이 메뉴는 ‘열기’, ‘종료’다. **구현 구체화:** 아이콘 클릭도 열기로 연결한다.
  최소화되었으면 복원하고 전면 포커스를 준다. 실행 파일을 다시 실행해도 기존 창을 복원하며 두 번째 프로세스를 유지하지 않는다.
- 최소화 버튼은 작업 표시줄 최소화다. 실제 종료는 별도 종료 의도로 처리해 다시 숨기는 루프를 막는다.
- ‘종료’는 진행 중 저장 완료를 기다리고 미저장 입력이 있으면 창을 먼저 복원해 기존 버리기 확인을 표시한다.
  취소하면 창·입력을 유지하고, 확정 시 IPC·DB·트레이를 정리한 뒤 프로세스를 종료한다.
- **구현 구체화:** 트레이 생성 실패 시 접근 불가능한 숨은 앱으로 남기지 않고 오류를 안내하고 기존 닫기 보호 경로를 사용한다.
  렌더러 실패·저장 상태 오류가 종료를 막는 경우에는 강제 저장 성공을 표시하지 않고 기존 보수적인 확인 경로를 유지한다.
- 설치/제거 전에 트레이에서 실제 종료하도록 안내한다. NSIS의 실행 중 앱 처리는 별도 검증한다.
  OS 강제 종료·전원 손실·설치기의 강제 프로세스 종료까지 미저장 폼을 보존한다고 보장하지 않는다.

## A · Zinc 외형과 shadcn/ui

상단 프로젝트 팝오버, 간트/달력 전환, 날짜 탐색, 오른쪽 편집 패널의 C안 배치를 유지한다.
프로젝트 팝오버는290×442px이며 목록만 스크롤하고 제목·추가 버튼은 고정한다. 짧은 창에서 최대 높이를 줄인다.
데스크톱과 높은 배율을 지원하며 기존 1100px 미만의 편집 오버레이·키보드 보호를 유지한다.

| 본문 | `#18181B` | `#FAFAFA` |

- 기존 오프라인 맑은 고딕·시스템 폴백을 유지한다. 제목18px, 본문13~14px, 보조12px를 기준으로 한다.
- 얇은 테두리·7~8px 모서리·평면 구획, 헤더/프로젝트 팝오버의 앱 내부 반투명을 사용한다.
  기존 앱 아이콘은 유지하며 OS 바탕화면 투명 효과·장식용 카드·외부 폰트·임의 애니메이션은 추가하지 않는다.
- **시안 구체화:** 프로젝트 행64px, 일정 행60px, 이름/날짜 영역 위아래 최소8px 여백을 기준으로 한다.
  행 높이와 가상화 prefix를 함께 바꿔 글자·선·날짜가 붙거나 일정 막대가 어긋나지 않게 한다.
- 프로젝트 색상 데이터는 유지한다. 막대는 프로젝트 색상의 얇은 선과 옅은 채움, 테마 본문색을 사용한다.
- shadcn/ui Button·Input·Select·Popover·Tooltip·확인 대화상자 등 필요한 구성 요소를 프로젝트 소스로 가져온다.
  단순 CSS 모방을 실제 shadcn 통합으로 보고하지 않는다. 새 의존성과 출처·라이선스를 기록한다.
- **구현 구체화:** Radix 기반 구성과 Tailwind의 필요한 부분을 사용하되 Vite·React·Electron 구조를 유지한다.
  버전 호환성과 전체 스타일 충돌은 설치·빌드·UI 검사로 확인한다. 외부 CDN 없이 번들에 포함한다.
- 날짜 선택기는 승인된 한국어·월요일 시작·직접 입력·전체 연도 범위를 보존한다.
  shadcn Popover/입력 외형을 적용하되 검증된 도메인 계산·날짜 격자를 재사용할 수 있다.
  예제의 JS Date 기본 동작으로 1~99년 또는 시간대 날짜를 바꾸지 않는다.
- Portal 도입 시 편집 패널·확인창·날짜 팝오버의 포커스 범위를 함께 설계한다.
  중첩 Escape는 안쪽부터 닫고, 팝오버가 폼을 밀지 않으며 화면 경계에서 위쪽 배치와 내부 스크롤을 제공한다.
- 일정 편집의 소속 프로젝트는 기존처럼 변경할 수 없다. 시안의 프로젝트 선택기는 일정 추가 화면의 예시다.

## 툴팁 수정

툴팁은 **헤더의 테마·프로젝트 추가·일정 추가·프로젝트 목록·간트·달력·오늘 버튼**에만 둔다.
창 버튼·이전/다음 달·편집기의 삭제/취소/저장·날짜 셀·일정 막대·프로젝트 항목에는 생성하지 않는다.
그 밖의 native `title` 툴팁도 제거하되 접근성 이름과 전체 일정 설명은 보존한다.
긴 이름은 편집 화면에서 확인할 수 있고 툴팁 유무와 무관하게 스크린리더 이름은 전체 문자열을 유지한다.

현재 오류는 모든 button에서 문구를 추론하는 전역 처리와 최대360px을 항상 예약하는 위치식에서 발생한다.
명시적으로 지정한 트리거와 shadcn Tooltip의 위치 계산으로 대체한다.
**구현 구체화:** hover250ms, 키보드 포커스 표시, 기본 버튼 아래8px·중앙 정렬,
화면 경계에서는 충돌 회피, Escape/클릭/포커스 이탈 시 닫기. 여러 툴팁을 동시에 남기지 않는다.

## 구현자가 검증할 완료 기준

- 날짜 클릭·상단 탐색·오늘·월말·윤년·0001/9999 경계·확장 범위·공유 강조·미저장 확인 취소를 검증한다.
- 14/28/84px에서 날짜 히트 테스트·드래그/리사이즈·포인터 앵커·가상화·가로 손잡이가 일치해야 한다.
  Space 이동이 클릭/일정 저장을 만들지 않고 입력 공백·키보드 접근을 깨지 않아야 한다.
- 실제 Electron에서 숨김→복원, 편집/저장 중 숨김, 트레이 종료 확인·취소·정리, 재실행 복원을 확인한다.
  UI 테스트의 종료 fixture를 새 숨김 동작과 혼동하지 않는다.
- shadcn 구성 요소의 라이트/다크·포커스·중첩 Escape·짧은 창·높은 배율을 확인한다.
  툴팁 허용/비허용 항목과 실제 좌표를 검사한다.
- Windows 설치 경로 선택 UI, 권한 없는 폴더 거부, 사용자별 설치, Planrail 이름·아이콘·바로가기,
  실제 구버전0.2.1 업그레이드와 새 버전 업데이트, 설치 경로 변경·제거·재설치·DB/설정 보존을 확인한다.
- 기존 CRUD·저장 실패 복구·날짜 규칙·오프라인·단일 인스턴스·보안 검사를 유지한다.
  `npm run verify:app`와 `node scripts/harness/run.mjs verify`를 실행하고 Windows CI 결과까지 확인한다.
- 실제 Windows11 사용자 PC의 배율·트레이 위치·시작 성능은 CI와 구분해서 미검증 여부를 기록한다.

## 시안 증거와 다음 단계

[A/B 비교 HTML](mockups/planrail-comparison.html)은 외부 리소스 없이 열 수 있는 디자인 전용 시안이다.
기본 표시는 선택한 A안이며 B안은 비교 기록으로 남겼다. 실제 데이터·API와 연결하지 않았다.
촬영 PNG·검증 결과는 Git 추적 밖의 `artifacts/design/planrail/`에 있다.
A/B 각각 간트/달력·라이트/다크, 추가 패널·날짜/프로젝트 선택기·긴 프로젝트 목록을 렌더링했다.
Chromium headless1440×960에서 목록290×442·내부 스크롤·고정 제목/추가,
헤더 툴팁 정렬·저장 버튼 툴팁 없음·문서 가로 넘침 없음·JS 오류 없음을 확인했다.
이는 제품 shadcn 통합·Windows 트레이·설치 검증의 증거가 아니다.

독립 구현 가능성 검토 결과 중요한 미결정 항목은 없었다. 이 문서의 최종 확정 뒤
Superpowers 구현 계획 → 실패 재현 검사 → 구현 → 회귀/Windows 검증 → main 커밋·push 순서로 진행한다.
기존 MVP 단계 지도는 다시 열지 않는다.
