기준 구현은 0.8.5, `f53b165beacd576ebd3e27c83c3e1f5aff780435`다. 기존 [LAN 공유](lan-project-sharing.md), [알림 제어·접속 상태](notification-controls-and-member-presence.md), [공유 변경 알림](shared-change-notifications.md), [저장 확인](release-notes-and-confirmations.md)의 대체하지 않은 계약은 유지한다. 아래 기술 구체화는 개별 사용자 답변과 구분해 제안했으며 문서 전체 승인에 포함됐다.

## 목표와 범위

호스트가 참여자의 마지막 실행 버전을 확인하고, 직접 정한 공통 휴일을 모든 승인 멤버에게 제공한다. 멤버가 확인 코드를 대조하고 승인을 기다리면 호스트에게 Windows 알림을 보낸다. 휴일 변경 자체는 알리지 않는다.

공식 공휴일 자동 수집·내장 자료, 프로젝트별 휴일, 휴일에 따른 일정 이동·기간 계산 변경, 원격 설치 프로그램 조사, 새 로그인 방식, 외부 서버, 종료된 앱 깨우기는 범위 밖이다. 공식 공휴일 자료 보류 결정은 유지한다. 호스트가 수동 등록한 날짜를 공식 검증된 공휴일로 표현하지 않는다.

## 코드 조사와 선택한 접근

- [WireSnapshot 검사](../../src/domain/sharing.ts)는 허용 키를 엄격히 검사한다. 기존 snapshot에 휴일 키를 추가하면 구버전 멤버가 거부한다.
- [공유 transport](../../src/main/sharing/transport.ts)와 [공유 타입](../../src/shared/sharing.ts)에 멤버 버전 보고는 없다. 업데이트 배포 서비스의 currentVersion은 호스트 버전이며 멤버 버전이 아니다.
- [호스트](../../src/main/sharing/host.ts)의 pending 목록에는 멤버 확인 전, 호스트 승인 후 자격 인계 중인 요청도 포함된다. onChange는 여러 단계에서 발생하므로 이를 그대로 알림 발송에 연결하면 중복·조기 알림이 된다.
- [휴일 표시의 기존 기반](../../src/visualization/weekends.ts)은 고정 토·일이다. 달력의 날짜 칸에도 새 공통 판정을 연결해야 한다.
- 접속 상태는 기존 인증된 정상 동기화가 최근 10초 내에 있었는지로 계산한다. 버전 표시 때문에 TCP 연결 수나 별도 사용자 활동 수집으로 바꾸지 않는다.

**선택 A:** 기존 프로젝트 응답은 유지하고, 버전 보고는 호환되는 요청 메타데이터로, 휴일은 별도 인증 조회로 추가한다. 기존 2초 동기화 수명주기를 사용한다. 기능별 성공 상태를 구분하는 비용이 있지만 순차 업데이트가 가능하다. Q10에서 선택했다.

**대안 B:** 모든 정보를 새 통합 프로토콜로 전달한다. 일괄 응답은 단순하지만 호스트·멤버 동시 업데이트가 필요해 선택하지 않았다.

## 멤버 버전 표시

새 멤버 main이 실제 Planrail 버전을 기존 인증된 snapshot/changes 요청의 선택적 헤더로 보낸다. 기존 요청/응답 본문의 키는 바꾸지 않는다. 호스트는 IP·활성 자격 검증과 정상 응답 완료 후에만 보고를 채택한다. 미승인 요청이나 임의 HTTP 요청은 버전 기록을 바꾸지 못한다.

기술 제안:

- 버전은 길이 제한된 정식 SemVer 문자열로 검증하며 실행 코드에서 정한 제품 버전을 사용한다. 개발 실행은 개발용임을 구분하고 Electron 런타임 버전을 Planrail 버전으로 기록하지 않는다. 버전은 멤버의 자기 보고이며 보안 권한이나 설치 증명이 아니다.
- device와 승인된 설치본에 버전·확인 시각을 묶어 저장한다. 같은 보고가 매 2초 도착할 때마다 SQLite 쓰기를 하지 않도록 최신 메모리 상태와 영속 갱신을 병합한다. 연결 확인 시각과 버전 확인 시각은 구별한다.
- 마지막 유효 보고는 호스트 재실행 후에도 남기되, 새 통신 전에는 현재 접속/현재 버전으로 단정하지 않는다. 보고가 없는 최신 통신은 ‘확인 불가’다. 옛 보고를 현재 버전으로 보여주지 않는다.
- 설치본 교체·재승인으로 바인딩이 바뀌면 이전 버전 기록을 재사용하지 않는다. 참여자 삭제 시 함께 삭제한다.
- 기존 이름·IP·수정/승인 취소/삭제 한 줄 배치는 유지하고, 기존 상태 정보 줄에 버전을 추가한다. 연결 중 `버전 0.8.5`, 단절 시 `마지막 확인 버전 0.8.5 · 확인 시각`, 미보고는 `버전 확인 불가`로 구분한다. 기존 승인 배지와 연결 상태는 유지한다.

## 휴일 데이터와 저장

호스트 main/SQLite가 공통 표를 소유한다. 반복 요일 집합, 날짜별 이름, 독립 revision을 저장한다. 멤버 main은 hostId/datasetId에 묶인 수신 캐시·revision·마지막 정상 수신 시각만 관리한다. renderer에는 제한된 조회와 호스트 전용 수정 API만 제공한다.

- 날짜는 기존 `YYYY-MM-DD`, 0001~9999년, 시간대 없는 날짜 검사 사용. 요일 값은 정해진 7개 중 중복 없는 집합이며 빈 집합도 유효하다.
- 휴일 이름은 앞뒤 공백 제거 후 필수이며 제어 문자와 과도한 길이를 거부한다. 구체적 길이/전체 항목 수/응답 크기 상한은 기존 입력·전송 제한에 맞춰 구현자가 정하고 UI와 main에 동일하게 적용한다.
- 날짜를 고유 키로 사용한다. 같은 날짜 추가는 기존 항목 수정 안내. 날짜 변경은 새 날짜 중복 검사를 포함해 원자적으로 반영한다.
- 호스트 편집은 반복 요일의 명시적 저장, 날짜 항목별 추가/수정 저장·삭제로 구성한다. 저장 중 중복 조작을 막고 commit 후에만 성공 표시한다. 필드 오류는 해당 입력 아래, DB 오류는 기존 지속 안내를 사용한다. 이 표 편집은 일정 저장 확인창 대상이 아니다.
- 동기화가 진행 중인 공유 설정의 호스트 입력 초안을 덮어쓰지 않는다. 멤버 표는 편집 컨트롤 없이 보여준다. 개인 전용은 기존 토·일 표시를 유지하며 새 휴일 편집 기능을 제공하지 않는다.
- 기존 DB에 비파괴 migration을 추가한다. 새 호스트 표는 토·일과 빈 날짜 목록으로 시작하며, 읽기 실패를 빈 기본 표로 저장하지 않는다.

## 동기화와 호환

기술 제안은 `GET /v1/holidays` 같은 별도 인증 endpoint다. 독립 schemaVersion, hostId/datasetId, revision, 반복 요일, 날짜 항목을 전송하고 ETag로 미변경 시 304를 사용한다. 최종 경로/타입명은 구현 계획에서 고정한다.

1. 기존 프로젝트 동기화 성공 후 같은 동기화 회차에서 휴일 변경을 확인한다. 자동 약 2초 주기·수동 동기화·재연결 모두 포함하며 중복 회차를 겹쳐 실행하지 않는다. 정상 사내망의 호스트 저장 후 5초 이내 표시를 검증 목표로 삼는다.
2. 호스트는 프로젝트 접근권과 별개로 승인된 활성 설치본·등록 IP를 검증한다. 공유 프로젝트가 0개여도 공통 표를 받을 수 있다. 응답에 참여자 목록이나 개인 프로젝트를 넣지 않는다.
3. 멤버는 기존 TLS pin/자격 검증 후 표 전체와 hostId/datasetId를 검사하고 한 transaction으로 교체한다. 일부 날짜만 적용하지 않는다. 수신 중 연결 해제·승인 취소·호스트 변경을 확인하면 늦게 도착한 응답이 캐시를 되살리지 못하도록 세대를 검사한다.
4. 구버전 호스트의 endpoint 404는 ‘호스트가 휴일 동기화를 지원하지 않습니다’로 표시하고 기본 토·일을 사용한다. unsupported는 해당 연결 세션에서 캐시하고 재연결/수동 동기화 시 다시 확인한다. 같은 호스트의 이전 수신 자료가 있더라도 현재 미지원 상태에서는 오래된 표를 최신 표처럼 적용하지 않는다.
5. timeout·서버 실패·잘못된 표는 미지원으로 위장하지 않는다. 마지막 유효 표를 보존하고 휴일 수신 실패·마지막 수신 시각을 안내한다. 프로젝트 동기화 성공을 되돌리지 않지만 ‘전체 동기화 성공’이라고 표시하지 않는다. 휴일 실패만으로 전체 연결 상태를 거짓 단절로 바꾸지 않는다.
6. 인증/승인 취소 응답은 기존 자격 회수 규칙을 우선한다. 승인 취소 확인이나 명시적 연결 해제 시 표와 관련 수신 상태를 제거한다. 일반 네트워크 실패만으로 삭제하지 않는다. 특정 프로젝트 공유 종료는 공통 표를 제거하지 않는다.
7. 휴일 revision은 프로젝트 변경 journal/cursor와 분리한다. 휴일만 변경했을 때 공유 변경 요약·일정 날짜 알림·업데이트 알림을 만들지 않는다. 정기 조회 횟수는 기존 서버 요청 제한 안에서 검증한다.

## 날짜 표시와 공유 설정 화면

공유 설정의 휴일 관리에는 반복 요일 월~일과 날짜·이름 목록을 둔다. 호스트는 추가/편집/삭제, 멤버는 읽기 전용이다. 멤버에게 정상 수신/마지막 수신 기준/미지원/실패를 문구로 구분하고 마지막 정상 수신 시각을 보여준다.

날짜별 이름이 있으면 그 이름, 없고 반복 요일에 해당하면 ‘매주 수요일 휴무’처럼 요일 이름을 사용한다. 주말 해제 시 빨간 휴일 강조도 해제한다. 다음 표시 규칙은 구현 제안이다.

- 간트는 날짜 눈금과 실제 gantt-track 행에만 옅은 붉은 배경을 적용한다. 프로젝트 행 아래 빈 공간으로 칠하지 않는다. 오늘·선택 날짜 표시와 일정 막대는 계속 구분한다.
- 좁은 간트 눈금은 너비를 늘리지 않고 hover/키보드 focus 시 휴일 이름을 보여준다. 스크린리더 날짜 설명에도 이름을 포함한다. 날짜 클릭·드래그의 기존 동작은 유지한다.
- 달력은 날짜 칸 배경과 날짜 아래 작은 휴일 이름을 사용한다. 긴 이름은 줄임 처리하고 전체 이름을 확인할 수 있게 한다. 기존 일정 3줄/더 보기의 수용량을 줄이지 않도록 휴일 이름 공간을 별도로 정한다.
- 휴일 이름은 평문으로 렌더링하고 HTML을 실행하지 않는다. 최대 날짜 범위를 전체 순회하거나 모든 반복 날짜를 DB에 저장하지 않고 화면에 필요한 날짜만 판정한다.

## 연결 승인 요청 Windows 알림

```text
등록 IP의 멤버가 연결 요청 → 양쪽 코드 표시
→ 멤버가 코드 확인 → 호스트 승인이 아직 필요함
→ 유효성·중복·1분 제한·전체 무음 검사
→ 호스트 Windows 알림 → 클릭 → 현재 승인 대기 목록
→ 호스트가 별도로 코드 확인·승인
```

발송 조건은 현재 유효한 요청에서 memberApproved가 false→true로 바뀌고 hostApproved가 false인 순간이다. 이미 호스트가 승인했다면 새 승인 행동이 필요 없으므로 알리지 않는다. confirm 재시도나 onChange 호출마다 알리지 않는다. 기존 연결 승인 자체의 코드 검증·만료·자격 인계는 바꾸지 않는다.

기술 제안:

- 요청별 처리 키는 host/device/pairId, 1분 제한 키는 IP 문자열이 아닌 등록 device다. 재요청으로 pairId가 바뀌어도 같은 PC 제한을 적용한다. 동일 IP 새 설치본은 기존 재승인 절차를 따라야 한다.
- OS 전달 직전에 요청의 최신성·만료·승인/취소·현재 전역 무음을 확인한다. 처리 이력과 발송 시도 시각을 먼저 기록하고 전송한다. 실패/결과 불명은 자동 반복하지 않는다. OS 표시 자체의 정확히 한 번은 보장하지 않는다.
- 60초는 직전 전송 시도부터 계산한다. 무음/제한으로 억제한 요청은 나중에 자동 재전송하지 않는다. 호스트가 재시작해도 직전 알림의 제한을 우회하지 않도록 최소 이력을 보존하되, 이미 사라진 승인 요청은 재생하지 않는다.
- 전역 무음 중에도 최신 승인 목록은 갱신한다. 이력 저장 오류면 OS 발송을 하지 않고 앱 안에 오류를 안내하며, 정상 연결 요청을 막거나 승인 자격 발급 성공으로 위장하지 않는다.
- 예시: 제목 `Planrail 연결 승인 요청`, 본문 `김멤버 · 192.0.2.21 — 연결 승인을 기다립니다.` 표시 이름은 호스트에 등록된 값을 사용한다. 코드·토큰·인증서 정보는 알림에 넣지 않는다. Windows 방해 금지·알림 정책은 존중한다.
- 클릭은 주 창을 복원하고 공유 설정의 최신 승인 대기 위치를 보여준다. 이미 승인/만료/교체/삭제됐다면 현재 상태를 안내하며 옛 요청을 승인하지 않는다. 공유 설정이 열려 있으면 입력을 보존한 채 해당 위치로 이동한다. 다른 모달 때문에 열 수 없으면 요청을 보류하고 종료 후 재확인한다. 편집 패널의 입력을 알림 클릭 때문에 버리지 않는다.
- 서버 중지/앱 종료 후 과거 OS 알림으로 앱을 실행하는 기능은 추가하지 않는다. 등록 참여자 삭제 시 불필요한 요청 이력도 정리한다.

격리된 두 프로필의 TLS 통합 검사, 단위/UI/Electron 검사, 저장소 하네스를 계획에 포함한다. 실제 Windows 알림 배너와 회사 LAN 지연은 사용자 PC 인수로 분리한다. 구현·격리 화면 검증 결과는 [구현 기록](../implementation/2026-11-17-member-holidays.md)을 따른다. 실제 회사 PC의 Windows 알림 인수는 별도다.

## 승인과 후속

Q1~Q11 및 검토 시안은 확정됐다. 독립 builder 검토 후 사용자가 ‘좋아 진행해’로 전체 설계와 구현을 승인했다. 기존 MVP 지도 완료 상태를 변경하지 않는다.

2026-11-17 독립 builder 검토 결과: 구현 계획을 막는 중요한 미정 사항 없음. 문서 단계의 저장소 하네스 검사는 통과했다. 제품 동작 검증이나 실제 Windows 인수 완료를 의미하지 않는다.
