## 비교한 대안

- 알림 설정 단위: 일정별 / 앱 공통 / 프로젝트별 중 일정별을 선택했다.
- 알림 방식: Windows 일반 알림 / 해제할 때까지 반복 알람 중 일반 알림을 선택했다.
- 실행 범위: 실행·트레이 유지 / 완전히 종료한 뒤에도 제공 중 실행·트레이 유지 범위를 선택했다.
- 계층 표현: A안의 행 배경 강조 / B안의 연결선 강조 중 A안을 선택했다. 두 안을 현재 앱의 격리된 테스트 프로필에서 임시 스타일로 비교했다. A안은 행 배경으로 그룹을 빠르게 훑을 수 있다는 추천 근거를 제시했으며, 사용자가 A안을 선택했다.
- 배율: 100%에서 자동 정지와 클릭 복귀 / 10% 단계와 클릭 복귀 / 연속 배율과 클릭 복귀 중 마지막 안을 선택했다. 자동 정지는 승인되지 않았다.
- 알림 시각: 앱 공통 설정 / 일정별 설정 / 오전 9시 고정 중 일정별 설정을 선택했다. Q11에서 일정별 초기값은 오전 9시로 확정했다.
- 놓친 알림: 오늘 것만 제공 / 과거 알림 전체 제공 / 놓친 알림 미제공 중 오늘 것만 제공하기로 했다.

## 화면과 조작

아래는 Q11의 입력 구조다. 0.6.3에서 사용자 요청으로 두 체크박스를 각각 시작일/종료일 스위치로 바꿨다.
별도 전체 알림 스위치는 추가하지 않는다. 기본 꺼짐·기존 저장 버튼으로 반영하는 규칙은 유지한다.

```text
종료일  [2026-11-30   달력]

알림
[ 2 ] 일 전     [09:00]
[스위치] 시작일 알림   [스위치] 종료일 알림

[삭제]                     [취소] [저장]
```

- 기존 shadcn 기반 입력·버튼과 라이트/다크 색상 체계를 사용한다. Radix 기반 알림 스위치는 레이블 클릭과 Tab·Space 조작을 지원한다.
- 일정 편집 패널 안에서 스크롤하며 작은 창에서도 저장·취소·삭제에 접근할 수 있다. 입력 변경은 기존 미저장 보호에 포함한다.
- 기술 제안: 시각은 분 단위 24시간제 `00:00`~`23:59`, N은 정수로 검증한다. 비활성 상태에서도 형식이 잘못된 입력은 저장하지 않고, 날짜 범위 이전 여부는 켜진 알림에 대해서만 검사한다.
- 간트의 참여자 요약과 ‘참여자 없음’만 제거한다. 빈 프로젝트의 ‘일정 없음’, 프로젝트 목록 팝오버의 참여자 표시, 참여자 편집은 유지한다.
- A안의 프로젝트 배경과 15px/700, 일정 13px/400을 적용한다. 행 높이는 [Forest Crystal 후속 기준](forest-crystal.md#063-행-밀도알림-조작-보정)을 따르며 날짜 정렬·긴 이름의 말줄임·접근성 이름은 유지한다.
- 편집 패널 삭제 버튼은 라이트·다크 모두 붉은 배경과 읽기 쉬운 밝은 글자로 바꾼다. 삭제 확인 흐름은 유지한다.
- 배율 숫자는 키보드로도 실행 가능한 버튼으로 바꾸고 접근성 이름은 ‘간트 배율 100%로 초기화’로 한다. 새 툴팁은 추가하지 않는다. 기술 제안: 복귀할 때 현재 왼쪽 날짜와 그 날짜 안의 위치를 유지하며 기존 범위에서 경계를 보정한다. 일정 드래그·화면 이동 제스처 중에는 복귀를 막는다.

## 알림 시점과 재평가

이 절의 세부 경계 처리는 Q15 전체 설계 승인에 포함한다.

- 알림 날짜는 대상 시작/종료일에서 N을 빼는 순수 달력 연산이다. 일정 날짜 자체에 시간대를 저장하거나 변환하지 않는다.
- 시각은 PC 현지 벽시계 기준이다. 시간대가 바뀌면 현재 현지 날짜·시각으로 다시 평가한다. DST로 없는 시각은 그날 시계가 해당 시각을 지난 첫 평가에서 처리하고, 반복되는 시각은 이력으로 중복을 막는다.
- 실행·절전 복귀·저장 commit 후 재평가하고, 실행 중에는 최대 30초 간격으로 현재 시각을 확인한다. 오래 남은 알림을 긴 단일 타이머로 기다리지 않는다. OS 스케줄링·절전·부하에 따른 지연은 가능하며 초 단위 정확성을 보장하지 않는다.
- 오늘 이전 알림은 제공하지 않는다. 오늘 새로 켠 알림의 시각이 이미 지났으면 commit 후 평가한다. 저장 전 초안은 알림 실행에 영향을 주지 않는다.
- 알림을 끄거나 일정·프로젝트를 삭제하면 아직 전송하지 않은 후보를 제외한다. 큐에서 꺼낼 때 현재 DB 상태를 다시 확인한다. 이미 Windows에 전달된 알림의 회수는 보장하지 않는다.
- 간트·달력 드래그로 날짜를 바꾸는 경우도 같은 검증·재평가를 적용한다. 알림 날짜가 지원 범위를 벗어나면 날짜 변경 전체를 거부하고 기존 일정·알림을 보존한다. 알림을 먼저 조정하도록 오류를 안내한다.
- 알림 내용의 ‘오늘’·‘N일 후’는 실제 전달 시점의 현지 날짜와 대상 날짜로 계산한다. 프로젝트/일정 이름은 전달 직전 최신 저장값을 사용한다.

## 저장·실행 구조

기존 main 소유 SQLite와 제한된 preload 계약을 유지하는 구현자 제안이다. renderer 타이머는 창 수명에 의존하며, OS 예약 작업은 완전 종료 후 실행을 추가하므로 이번 구조로 선택하지 않는다.

- main이 알림 설정·실행·처리 이력을 소유한다. renderer는 설정 편집과 알림 클릭 후 탐색만 담당한다. 임의 알림 전송 API나 파일·DB 권한은 노출하지 않는다.
- schema v2의 순차 마이그레이션으로 일정별 N·현지 시각·시작/종료 활성화를 저장한다. 기존 일정은 2일 전·09:00·둘 다 꺼짐으로 이관하며 기존 ID·날짜·이름·참여자는 보존한다.
- 알림 설정은 일정과 같은 트랜잭션에서 저장한다. 기존 백업·버전 검사·실패 시 원본 보존·편집 차단 계약을 유지한다. 구버전 앱이 v2를 읽을 수 있다고 보장하지 않는다.
- 처리 이력은 일정 ID·시작/종료 종류·대상 날짜·N·시각의 조합을 식별한다. 이름·활성화 스위치·현재 시간대는 식별에 포함하지 않는다. 조합 A를 처리한 뒤 B로 변경했다가 A로 돌아와도 A는 반복하지 않는다.
- 시작·종료는 각각의 처리 이력을 유지한다. 둘 다 같은 시각에 미처리라면 한 Windows 알림으로 합치고 두 항목을 처리한다. 하나만 미처리라면 해당 의미만 알린다. 시작을 먼저 알린 뒤 종료를 새로 켜면 새 종료 알림을 허용한다.
- 삭제 시 관련 설정·처리 이력을 함께 제거한다. 임의의 짧은 기간으로 이력을 지워 중복 기준을 깨지 않는다. 실제 테이블·인덱스 이름은 구현 계획에서 정한다.
- 일정 DTO/CRUD 검증을 확장한다. 날짜만 바꾸는 드래그 업데이트는 기존 알림 설정을 보존하며, 최종 합성된 일정·알림을 main에서 검증한다.
- 알림 큐는 main에서 직렬 처리하며 긴 작업으로 시작·CRUD를 막지 않는다. 중복 타이머·resume 이벤트·창 재로딩에도 한 후보를 동시에 전송하지 않는다.

## 전송 결과와 한계

아래 기술 처리 방침과 한계는 Q15 전체 설계 승인에 포함한다.

- Windows에 알림을 요청한 것과 사용자가 배너를 보거나 읽은 것은 다르다. 방해 금지·앱 알림 차단·관리 정책을 우회하지 않는다.
- 중복 억제를 우선해 전송 시도 전에 DB에 후보를 선점하고 commit한다. 그 뒤 네이티브 API를 호출하고 요청 결과를 기록한다. DB와 OS 사이에는 원자적 commit이 없어 정확히 한 번 표시를 보장할 수 없다.
- DB 선점 후 전송 전 앱이 비정상 종료하면 알림이 누락될 수 있다. 전송 결과가 불명확한 항목은 자동 재전송하지 않으며, 다음 실행에 ‘알림 전송 결과를 확인하지 못했습니다’ 안내를 남긴다. 정상 종료·재실행은 이미 처리한 알림을 반복하지 않는다.
- 명확한 API 실패는 실패 상태와 지속 안내를 남기고 무한 자동 재시도하지 않는다. 안내에서 사용자가 재시도를 선택한 경우에만, 여전히 활성 상태이고 오늘 예정인 실패 항목을 다시 평가한다. 결과 불명 항목은 이 재시도 대상에 넣지 않는다.
- 알림 처리 이력 DB 쓰기에 실패하면 알림을 보내지 않고 오류를 안내한다. 일정 저장 commit이 성공한 뒤 알림 전송만 실패했다면 일정 저장 실패로 표시하거나 데이터를 되돌리지 않는다.
- 알림 클릭은 main이 기존 창을 복원하고 제한된 이벤트로 일정 ID를 전달한다. renderer는 준비 후 최신 snapshot으로 일정 존재를 확인하고 기존 미저장·저장 중 보호를 거친다. 이름이나 알림 문자열을 코드·URL로 실행하지 않는다.
- 앱을 완전히 종료했다가 과거 알림 센터 항목을 누르는 콜드 실행은 이번 보장 범위 밖이다. 실행 중인 프로세스에서의 알림 클릭을 검증한다.
