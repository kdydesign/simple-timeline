# 설정 탭·개인 휴일·워킹데이

2026-11-18. 상태: Q1~Q9 협의 반영, 전체 설계 승인 대기. 제품 코드는 변경하지 않았다. 구현 담당자의 제안은 아래 별도로 구분한다.

## 요청 범위

- 반복 휴일 선택 및 호스트/멤버 역할 선택의 붉은 활성 표시 복구. 새 휴일표는 토·일 기본값, 기존 저장 선택은 보존.
- 제목 표시줄: 릴리즈노트·도움말 | 설정 아이콘 | 최소화·최대화·닫기. 기존 트레이 연결 상태에서 열던 공유 설정을 설정 팝업으로 이동.
- 설정 팝업은 기본 설정·공유 설정 탭. 호스트/멤버 권한은 유지하고 개인 전용·호스트·멤버의 개인 휴일 관리 추가.
- 프로젝트가 없을 때 `먼저 프로젝트를 추가해 주세요.` 고정 영역 대신 토스트.
- 개발용 `dev:member` 명령 및 기존 호스트와 분리된 개발 데이터 폴더.
- 일정 추가·편집의 기간 표시를 `총 기간: xx일, 워킹데이: xx일`로 변경. 워킹데이는 붉은 글씨. 일정 시작·종료일을 포함하는 총 기간에서 적용 휴일을 제외한다.
- 구현 후 이번 릴리즈노트와 전체 기능 도움말을 코드에 맞춰 점검·갱신. 누락된 기존 기능과 실제 화면 이미지도 포함.

## 현재 코드 확인

- 공통 `.sharing-settings button:not(.date-picker button)`가 휴일/역할의 `[aria-pressed]` 규칙보다 구체적이어서 배경·테두리·색상을 덮는다. 실제 화면 회귀 검사로 검증할 예정.
- 공통 휴일표와 멤버 수신 캐시만 존재하며, 개인 휴일표와 워킹데이 계산은 없다.
- 빈 날짜 클릭의 `addDate`가 일반 formError에 안내를 저장한다. 기존 4초 warning toast 경로를 재사용할 수 있다.
- 기존 기간은 양 끝 포함, 0001~9999년 범위를 지원한다. 새 계산도 날짜 전체를 순회하지 않는 방식이 필요하다.
- 일반 dev는 사용자 운영 프로필을 사용한다. 이전 안내는 실제 코드에 적용되지 않았으며, 개발 전용 프로필 옵션은 이번 구현 범위다.

## 첫 협의 질문

- Q1 확정: 호스트의 업데이트 배포는 기본 설정에만 배치한다. 기본 설정에는 업데이트 배포·공통 휴일 관리, 공유 설정에는 주소·공유 시작/중지·참여자·연결 승인을 둔다. 공유 설정에 업데이트 배포를 중복 배치하지 않는다.
- Q2 확정: 멤버 PC의 간트·달력과 워킹데이는 공통 휴일과 개인 휴일의 합집합을 개인·공유 일정 모두에 적용한다. 겹치는 날짜는 한 번만 제외한다. 다른 PC와 일정 날짜는 바꾸지 않으며, 같은 공유 일정의 워킹데이가 PC마다 달라질 수 있다.
- Q3 최초 합의: 개인 전용 사용자와 멤버는 개인 휴일을 관리하고 호스트는 공통 휴일만 관리. 이후 Q8 피드백으로 호스트도 개인 휴일을 관리하도록 변경했다.

후속 Q8~Q9는 앞선 호스트 개인 휴일 제한보다 우선한다.

## 두 번째 협의 질문

- Q4 확정: 개인 휴일은 연결 해제·승인 취소 후에도 보존하고 자동 공유하지 않는다. 첫 호스트 공통 휴일은 토·일 기본값이다. 최초 합의의 ‘호스트 모드에서 개인 휴일 미적용’은 Q8~Q9로 대체되어 호스트에서도 개인 휴일을 적용한다.
- Q5 확정: 공통/개인 휴일 사이의 겹침을 허용하고, 삼각 표시 hover/focus에서 `공통: 창립기념일 / 개인: 연차`처럼 출처별 이름을 함께 표시한다. 개인 휴일끼리 겹침은 금지하고, 반복 요일은 배경만 표시한다.
- Q6 확정: 탭 이동은 미저장 입력을 유지하며 자동 저장하지 않는다. 팝업 X/Escape 닫기는 미저장 입력을 확인 없이 폐기한다. 저장된 설정은 유지한다.
- Q7 확정: 호스트·멤버 설정 탭, 붉은 활성 버튼, 워킹데이 표시를 제품 구현 전 시안으로 검토한다.
- Q8 수정 요청: 날짜별 휴일 삭제는 휴지통 대신 붉은 계열의 `삭제` 텍스트 버튼으로 표시한다. 호스트도 기본 설정에서 공통 휴일과 개인 휴일을 별도로 관리한다. 개인 날짜별 휴일 소제목에는 `날짜별 휴일 (개인)`을 표시한다. 시안 전체의 무조건 승인은 아니며 수정본으로 검토한다.
- Q9 확정: 호스트도 공통 휴일과 자신의 개인 휴일을 간트·달력·워킹데이에 합산한다. 개인·공유 일정 모두에 적용하고, 멤버에게는 공통 휴일만 제공한다. 기존에 보관한 개인 휴일도 호스트에서 다시 적용한다.

## 검토용 화면과 구현 제안

시안은 기존 다크 그레이·스틸 블루 재질을 유지한다. 기본 바탕 #202225, 패널 #2b2e31, 본문 #f1f2f3, 보조 #c0c5cb, 일반 강조 #8bc1eb, 선택/워킹데이 #ffd0d0을 사용한다. 기존 시스템 글꼴과 13px 본문·15px 영역 제목, 기존 한 줄 휴일 입력을 유지한다. 붉은 선택은 반복 요일·역할 선택에만 적용하고, 저장/설정 탭 전체를 붉게 만들지 않는다.

시안의 날짜·PC·버전은 가상 예시다. 멤버의 예시 일정 2026-11-23~29는 총 7일, 토·일 및 공통 휴일 11/25·개인 휴일 11/26을 제외하면 워킹데이 3일이다. 동일한 휴일을 가진 호스트도 Q9에 따라 워킹데이 3일이다. 앞서 수정 시안에서 잠시 숨긴 호스트 기간 예시도 구현에서는 이 기준을 사용한다. 실제 Windows 투명 효과나 제품 구현 검증 결과로 간주하지 않는다.

개발 실행 조사: CLI 인자 전달은 electron-vite가 지원하지만 아직 dev:member 구현은 없다. 새 격리 프로필은 개인 전용에서 기존 멤버 연결·코드 확인·호스트 승인 절차를 밟아야 하며 역할 값만 강제로 바꾸지 않는다. 운영 DB뿐 아니라 현재 공통 경로를 사용하는 updater 캐시도 격리 대상이다. 개발 실행에서 실제 설치 인계는 차단하는 방안을 제안한다. 제품 설정/승인 흐름을 우회하지 않고 별도 개발 프로필을 재사용한다. Windows 설치 호스트와 동시 실행은 구현 후 실기 검증 대상이다.

## 호스트 개인 휴일의 기능 검토

2026-11-18 사용자 요청: 호스트 개인 휴일은 화면 추가만이 아니라 실제 기능으로 설계한다. 아래는 Q9 합산 적용 결정을 반영한 코드 조사와 구현 제안이며, 전체 설계 승인은 별개다. 이 검토에서 제품 코드는 변경하지 않았다.

### 현재 구조와 변경 필요성

- `src/main/db/sharing/extras.ts`의 `sharing_holidays`는 호스트 공통 원본, `sharing_holiday_cache`는 멤버 수신 자료다. 개인 휴일 저장소는 없다. 기존 `saveCalendar`는 호스트만 허용하고 공통 revision을 변경한다. 이를 개인 저장에도 그대로 쓰면 개인 내용이 공통 자료에 섞일 수 있다.
- `src/main/sharing/service.ts`의 `holidayState()`는 역할에 따라 한 표만 반환한다. `createSharingHost`에는 `extras.hostCalendar`만 전달하고, `host.ts`는 이를 인증된 `/v1/holidays` 및 `/v1/holidays/ranges`로 제공한다.
- `App.tsx`는 한 표를 간트·달력에 전달한다. `namedHoliday()`와 `HolidayDateTooltip`은 한 이름만 반환·표시하므로 출처가 다른 같은 날짜의 이름을 함께 표현하도록 확장해야 한다.
- `EditorPanel.tsx`는 현재 총 기간만 계산한다. 개인 저장 기능과 별개로 워킹데이 계산 및 적용 휴일 연결이 필요하다.

### 저장·권한·전송 경계

1. 개인 휴일은 동일 PC의 SQLite에 독립 저장한다. 기존 공통 원본 및 수신 캐시는 유지하며, DB migration으로 개인 표를 추가한다. 최초 개인 표는 토·일, 날짜별 휴일 없음으로 시작하고 재실행·업데이트 시 저장된 선택을 덮어쓰지 않는다. 기존 공통 휴일을 개인 표로 복사하지 않는다.
2. 공통 저장 명령은 호스트 전용으로 유지한다. 개인 저장 명령은 개인 전용·호스트·멤버가 자신의 PC에서 사용할 수 있다. 역할·입력 검증은 main에서 수행하며 UI 숨김에만 의존하지 않는다. 공유 중지·네트워크 단절·원격 승인 취소가 개인 수정 권한을 막지 않아야 한다. 단, 앱 종료/설치 인계의 저장 차단과 DB 오류는 정상적으로 적용한다.
   현재 `HolidaySettings`의 `host` boolean은 편집 권한·문구·dirty 처리를 함께 결정하므로, 공통/개인 출처와 해당 표의 편집 권한을 분리한다. 구형 호스트의 휴일 미지원이나 원격 통신 오류 때문에 로컬 개인 휴일의 조회·저장 결과까지 실패로 취급하지 않는다.
3. 개인 저장은 공통 revision·ETag·프로젝트 변경 기록을 변경하지 않는다. LAN의 두 휴일 엔드포인트에는 공통 원본만 제공한다. 합쳐진 표시용 결과를 동기화 원본이나 전송 DTO로 사용하지 않는다. 개인 이름·날짜·반복 요일은 멤버에게 전달하지 않는다.
4. 개인/공통 각각 날짜 형식·기간 순서·필수 이름·동일 표 내 기간 겹침·기존 총 1,000일 제한을 검증한다. 공통과 개인 사이의 겹침은 허용한다. 서로 겹칠 수 있는 표시용 합집합을 단일 원본 검증기에 넣지 않는다.
5. 저장은 트랜잭션 성공 후 반영한다. 실패하면 기존 저장 자료와 편집 입력을 보존하고 오류를 표시한다. 두 영역의 미저장 입력은 독립 관리하며 한쪽 저장·동기화 수신으로 다른 쪽 초안을 초기화하지 않는다. 탭 전환은 유지, 설정 닫기는 폐기한다.

### 화면·계산·알림

- 호스트 기본 설정에 공통/개인 각각 반복 요일, 날짜별 기간 추가·수정·삭제·저장을 제공한다. 개인 날짜 목록은 `날짜별 휴일 (개인)`, 삭제는 텍스트 버튼이다. 멤버는 수신 공통 표를 조회만 하고 개인 표는 편집한다.
- 표시용 휴일은 출처를 유지한다. 호스트·멤버 모두 공통+개인 합집합을 모든 일정에 적용한다. 겹친 날짜는 한 번만 제외하고 이름은 공통/개인 둘 다 보여준다. 반복 요일은 배경만 표시한다.
- 합집합 방식에서는 공통 토요일을 해제해도 개인 토요일이 선택되어 있으면 해당 PC에서는 여전히 휴일이다. 개인 표로 공통 휴일을 근무일로 덮어쓰지 않는다. 이 규칙을 설정 안내와 도움말에 명시한다.
- 워킹데이는 시작·종료일 포함, 주 단위 산술과 날짜별 휴일의 중복 제거로 계산한다. 윤년·월/연도 경계·0001~9999·전 요일 휴일(0일)을 다룬다. 저장된 휴일표를 기준으로 갱신하며 작성 중인 휴일 초안은 계산에 반영하지 않는다.
- 휴일을 추가/수정/삭제해도 일정 날짜·기간을 이동하거나 시작/종료 알림 날짜를 조정하지 않는다. 개인·공통 휴일 변경 알림은 발송하지 않는다.
- 명시적 연결 해제·승인 취소 확인은 공통 수신 캐시만 제거하고 개인 표는 유지한다. 일시 단절은 마지막 공통 표와 개인 표를 유지한다. 역할 선택에 따라 개인 표를 자동 공유하거나 삭제하지 않는다. 기존 역할 전환 제한은 이번 기능에서 별도로 해제하지 않는다.

### 구현 인수 검증

- 호스트 개인 휴일 저장·수정·삭제·재실행 보존, 멤버/개인 전용에서도 동일 개인 저장 사용.
- 공통/개인의 독립 저장 및 저장 실패 롤백, migration 전후 기존 프로젝트·일정·공통 휴일 보존.
- 실제 LAN 응답 두 종류에서 개인 휴일이 없고 공통 ETag도 바뀌지 않음. 구버전 멤버는 기존 공통 자료만 계속 수신.
- 공통/개인 겹침의 이름 출처 표시, 중복 없는 워킹데이, 반복 요일 조합과 전 요일 휴일, 전체 지원 날짜 범위 계산.
- 단절·공유 중지 중 개인 저장 가능, 연결 해제/승인 취소 후 개인 보존, 재연결로 개인 표를 덮어쓰지 않음.
- 휴일 변경으로 일정 날짜/알림 설정/전송 이력/공유 변경 알림이 달라지지 않음.
- UI에서 두 휴일 영역 초안 독립, 탭 전환 보존 및 닫기 폐기, 개인 삭제 텍스트·필드 오류·붉은 선택 상태 확인.

현재는 정적 코드 검토이며 위 기능 검증은 아직 실행하지 않았다.

## 선택한 접근과 범위

공통 원본·멤버 수신 캐시·개인 원본을 분리하고 표시용 조회에서 합친다. 사용자 Q2·Q5·Q9의 합산·출처별 표시·개인 비공개 요구를 충족하는 접근이다. 단일 표로 병합 저장하는 대안은 출처·동기화 경계가 불명확하고, 프로젝트 종류별로 개인 휴일을 적용하는 대안은 Q9에서 선택하지 않았다. 제품 구조·프레임워크는 유지한다. 기능 추가에 필요한 저장/IPC/화면 연결과 회귀 검사까지 포함하며 단순 시안 복제에 그치지 않는다.

이번 작업에서 Windows 시작 지연·도움말 초기 렌더링 성능, 공식 공휴일 자동 수집, 역할 자유 전환, 새로운 공유 권한은 변경하지 않는다. 날짜는 0001~9999년 양 끝 포함이며 renderer에 파일·DB 권한을 추가하지 않는다.

## 설정 진입과 화면 계약

| 역할 | 기본 설정 | 공유 설정 |
| --- | --- | --- |
| 개인 전용 | 개인 휴일 관리 | 기존 호스트/멤버 연결 시작 절차 |
| 호스트 | 업데이트 배포 → 공통 휴일 관리 → 개인 휴일 관리 | LAN 주소·포트·공유 시작/중지·참여자·승인·접속/버전 |
| 멤버 | 개인 휴일 관리, 공통 휴일 조회 | 기존 주소·연결·개별 공유 변경 알림·연결 해제 등 |

아래 세부 사항은 요청과 기존 동작을 연결하기 위한 구현 담당자 제안이며 전체 승인에서 함께 검토한다.

- 제목 표시줄 설정 아이콘은 no-drag 영역이며 마우스/키보드 접근과 설명 툴팁을 제공한다. 릴리즈노트·도움말 | 설정 | 창 조작의 두 구분선을 사용한다. 기존 창 조작·트레이 숨김·닫기 정책은 유지한다.
- 설정 버튼으로 처음 열면 기본 설정을 표시한다. 닫았다가 열면 기본 설정으로 시작하며, 열려 있는 동안 탭 전환은 입력을 보존한다. 기존 공유 설정 요청 이벤트는 새 설정 팝업의 공유 설정 탭으로 연결한다. 승인 요청 알림은 해당 탭의 승인 목록으로 이동시키고 다른 탭의 초안을 버리지 않는다.
- 트레이 연결 상태 항목은 상태 표시로 남기고 설정 진입 클릭은 제거한다. 설정 버튼이 일반 진입점이며, 승인 요청 알림 등의 기능상 바로가기는 유지한다.
- 기존 팝업 높이 제한 `calc(100vh - 160px)`·내부 스크롤·15px 외곽 패딩·10px 스크롤 패딩을 유지한다. 상단 제목/탭은 보이고 내부 내용이 스크롤된다. 호스트의 두 휴일 관리 영역은 구분선으로 분리하고 날짜 입력은 일정 DatePicker를 재사용한다. 월 선택 포털과 날짜 선택기 z-index도 회귀 검사한다.
- 각 영역의 편집 초안·오류·저장 기준값을 독립 관리한다. 일반 탭 전환은 저장하지 않고, 서버 상태 갱신은 미저장 입력을 덮지 않는다. 저장 성공한 영역만 기준값을 갱신한다. 팝업 종료 시 초안은 무확인 폐기하며, 이미 시작한 저장은 기존 안전한 완료/실패 처리 정책을 따른다.
- 기본 토·일은 새 표의 초기값이다. 기존에 저장한 반복 요일을 렌더링 또는 앱 재실행 때 토·일로 강제 복구하지 않는다. 개인 전용 및 승인 취소/명시적 연결 해제로 공통 표가 사라진 경우에는 개인 표만 적용한다. 멤버의 첫 수신 전/구형 호스트 미지원 상태는 기존 공통 기본 토·일 안내를 유지하고 개인 표를 함께 적용한다. 일시 단절/수신 실패는 마지막 정상 공통 표를 유지한다.

## 빈 프로젝트 안내 및 활성 스타일

- 편집 가능한 프로젝트가 없어 일정 추가를 진행하지 못할 때 기존 formError 영역에 안내를 넣는 경로를 제거하고, 기존 우측 하단 경고 토스트로 4초 표시한다. 반복 호출은 표시 시간을 갱신한다. 간트/달력 보기 전환 자체는 막지 않으며 기존 빈 상태 설명은 유지한다. 필드 검증·DB/통신 실패 메시지는 이 토스트 전환 범위가 아니다.
- 역할 선택과 반복 요일 버튼의 활성 상태는 `aria-pressed`와 실제 상태를 기준으로 붉은 배경·테두리·글자색을 적용한다. 공통 버튼 스타일보다 우선하는 범위 지정으로 수정하고 hover/focus/disabled에서도 선택 상태가 구분되는지 검사한다. 역할 확정 또는 휴일 저장 전에 상태를 임의 확정하지 않는다.

## dev:member 구현 제안

- `npm run dev:member`는 electron-vite의 앱 인자로 개발 전용 실행을 표시한다. `!app.isPackaged` 및 development 조건에서만 플래그를 처리한다. 설치본은 이 플래그로 프로필이나 권한을 변경하지 않는다.
- 사용자 데이터 경로는 `%APPDATA%\PlanrailDev\member`로 지정하고 DB·비밀 저장소·업데이트 임시/캐시 경로를 이 프로필 아래로 분리한다. 프로필 설정 후 단일 인스턴스 잠금을 얻는다. 운영 `%APPDATA%\SimpleTimeline`은 변경하지 않는다. 같은 개발 프로필 재실행은 기존 승인·데이터를 유지한다.
- 최초에는 새 개인 전용 프로필에서 멤버 선택을 기본으로 보여주며, 사용자가 실제 LAN 호스트 주소를 입력하고 코드 확인/호스트 승인을 거친다. 설치 호스트와 같은 PC에서 시험하면 호스트에 실제 접속 LAN IP를 등록한다. 인증·IP 검사를 우회하지 않는다. 기존 개발 버전 `-dev` 보고를 유지한다.
- 이 개발 실행에서 실제 앱 업데이트 설치 인계와 Windows 자동 실행 등록은 제공하지 않는다. 별도 설치본의 호스트 + 개발 멤버 한 개가 기본 시험 구성이다. 일반 dev와 dev:member 두 개발 서버의 동시 실행을 위한 별도 포트 체계는 이번 범위에 추가하지 않는다.
- README/검증 안내에 실행·프로필 보존·운영 데이터 분리·승인 절차·제한을 기록한다. 자동 검증은 운영 프로필을 실행하지 않으며 일회성 프로필과 mock/native 테스트를 사용한다. Windows 동시 실행 실기는 별도 결과로 보고한다.

## 도움말·릴리즈·최종 검증

- 구현 완료 버전의 릴리즈노트에 Feat(설정 탭·개인 휴일·dev:member·워킹데이), Fix(활성 상태·토스트)를 실제 결과에 맞춰 작성한다. 버전 번호는 구현 시 현재 main 기준의 다음 패치로 정하고 다른 변경이 선행되면 충돌 없이 조정한다.
- 기존 모든 도움말 항목을 실제 UI/동작과 대조한다. 시작하기·프로젝트/일정·간트 조작·달력·기간/휴일·알림·창/트레이·설치·오류·도움말 자체·호스트/멤버 연결·참여자/권한·동기화·업데이트·연결 해제·문제 해결을 포함한다. 트레이 진입 설명을 설정 버튼으로 교체하고 공통+개인 합산·출처·워킹데이 차이·개인 비공개 규칙을 추가한다. 기존 빠진 기능은 실제 구현 근거가 있는 것만 보충한다.
- 스크린샷은 가상 데이터의 격리 실행으로 재촬영하고 도움말 이미지 버전/라벨 검사를 맞춘다. 실제 운영 PC 데이터는 사용하지 않는다.
- 날짜 단위 검사, SQLite migration/실패 복구, 두 LAN 휴일 API의 개인정보 제외, IPC 권한·입력 검증, 설정 탭/초안/알림 바로가기, 실제 계산 갱신, 스타일·레이아웃·포털, 격리 개발 인자/프로필을 검증한다. 이어 하네스 및 순차 verify:app, Windows CI 빌드/설치 검사를 수행한다. Linux 시안·앱 화면 확인과 Windows 설치/사내망 실측을 구분한다.
- 이 문서는 전체 승인 대기이며 제품 구현·런타임 기능 검증 완료를 뜻하지 않는다.
