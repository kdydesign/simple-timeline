## 목표와 범위

현재 딥 그레이·스틸 블루 글래스 재질을 유지하면서 Node 목록의 읽기·정렬·진행 표시를 정리하고 일정 관련 상태를 해당 화면에 배치한다. 기존 이름 Planrail과 Node 관리의 **현재 사용자 화면 표기**를 PlanRail·NodeRail로 통일한다. 과거 기록이나 설치 식별자·프로필·실행 파일·업데이트 파일명 변경은 포함하지 않는다.

## 코드·시안 대조

- [ToolDock.tsx](../../src/renderer/workrail/ToolDock.tsx)는 현재 홈 / Planrail / Node 관리와 Lucide `Hexagon`을 사용한다. N은 CSS에 가려진 것이 아니라 경로 자체가 없다. 기존 검토 시안 `/workspace/output/nw-tool-concepts/index.html`에는 육각형과 N 경로가 있다.
- [NodeScreen.tsx](../../src/renderer/workrail/NodeScreen.tsx)의 새로고침 중 문구와 최초 로딩의 빈 상태 문구는 두 곳에 있다. 둘 다 제거 대상이다. 오류·빈 결과·설치 진행 문구는 별개다.
- [workrail.css](../../src/renderer/workrail.css)는 표 기본 정렬을 start, 작업 열을 end로 두며 행 버전은 th다. 컬럼별 정렬 명령은 없다. 설치 패널은 `align-items: start`인 grid에서 내용 높이만 차지한다.
- [SavingOverlay.tsx](../../src/renderer/components/SavingOverlay.tsx)는 진행 바 외에 화면 입력 차단·포커스 이동도 한다. 목록 조회에는 이 차단 동작을 복제하지 않는다. [forest-crystal.css](../../src/renderer/forest-crystal.css)의 2px 진행 선, accent 색, 1.1초 흐름과 reduced-motion 표현만 재사용한다.
- [App.tsx](../../src/renderer/App.tsx)는 PlanRail일 때만 Titlebar에 공유 상태를 준다. 현재 Home에는 상단 역할 배지가 없다. 이번 설계는 PlanRail 상단 배지를 없애고 Home 카드와 PlanRail 하단에 상태 표현을 모으는 변경이다.
- [Home.tsx](../../src/renderer/workrail/Home.tsx)의 ‘일정 공유’에는 역할·연결 설명·마지막 정상 확인·오류가 이미 있다. ‘작업 현황’과 날짜가 같은 행에 있다.
- 현재 NodeScreen은 메뉴 선택에 따라 조건부 마운트되므로 검색·필터가 화면을 떠날 때 사라질 수 있다. 이번 설계의 검색·필터·정렬·스크롤 보존은 상태 수명을 별도로 정리해야 하며 기존 구현이 이미 충족한다고 가정하지 않는다.
- 트레이의 전체 무음은 main의 [notifications.ts](../../src/main/db/notifications.ts)에 저장된다. [reminder-api.ts](../../src/shared/reminder-api.ts)는 현재 무음 값을 제공하지 않는다. 오류 개수 0이나 공유 변경 알림 스위치로 무음을 추정해서는 안 된다.
- 기존 비교 시안의 하단 ‘일정 공유 연결됨 / 일정 알림 켜짐’은 고정 예시다. 제품에는 실제 상태에 따른 표현이 필요하다.

## NodeRail 목록

### 진행 표시

- 테이블 프레임을 최초 로딩·빈 결과·조회 실패에서도 유지한다. 첫 조회와 새로고침 모두 프레임의 상단 보더에 진행 선을 표시한다. 문구 제거로 테이블 위치나 높이가 움직이지 않게 한다.
- 진행률을 알 수 없는 조회이므로 숫자 퍼센트는 만들지 않는다. PlanRail의 색상·두께·흐름 표현을 재사용하되 NodeRail 목록 영역에만 적용한다.
- 이전 목록이 있으면 조회 중에도 유지한다. 데이터가 없을 때는 헤더 아래 빈 공간과 진행 선으로 표시하며, 아직 로딩 중인 상태를 ‘버전 없음’으로 단정하지 않는다.
- 화면의 로딩 문장은 제거하되 스크린리더에는 목록 조회 중/완료 상태를 알리고 테이블 영역의 aria-busy를 설정한다. reduced-motion에서는 움직이지 않는 선으로 표시한다.
- 중복 새로고침만 막는다. 메뉴 전환·검색·필터·정렬은 허용하되 기존 Node 설치·사용의 busy 및 신뢰 가능한 목록 조건은 그대로 따른다. 저장용 차단 overlay를 사용하지 않는다.
- 조회 실패 시 진행 선을 끝내고 실제 오류·재시도·마지막 목록 안내를 유지한다. 설치·전환 진행과 오류를 숨기는 변경이 아니다.

### 정렬 규칙

- 헤더·본문의 모든 셀과 버튼을 가로 가운데 정렬하고 행 안에서 세로 중앙을 맞춘다. 헤더의 정렬 아이콘 공간을 양쪽 대칭으로 확보해 제목 중심과 데이터 중심이 어긋나지 않게 한다.
- 기본은 Node 버전 내림차순이다. Node와 npm 버전은 각 숫자 구성요소로 비교한다. 한 번에 한 컬럼만 정렬하며 같은 헤더를 다시 누르면 방향을 반전한다.
- 새 컬럼의 첫 방향은 Node/npm 최신순, 분류는 LTS 우선, 상태는 사용 중 우선으로 제안한다. 분류는 LTS 그룹 → 일반 그룹, 같은 그룹은 코드명 순으로 비교한다. 상태 순서는 사용 중 → 설치됨 → 미설치다.
- 값이 없거나 확인되지 않은 npm·분류·상태는 두 방향 모두 맨 뒤다. 같은 정렬값의 타이는 Node 버전 내림차순으로 고정해 행 순서가 흔들리지 않게 한다.
- 현재 화면에 표시하는 상태와 같은 기준으로 정렬한다. 오래된 설치 목록·연결 오류를 최신 정상 상태로 바꾸지 않는다.
- 전체 조회 목록에 검색·필터·정렬을 적용한 뒤 표시 개수를 제한한다. 기존 ‘버전 더 보기’는 테이블 스크롤 영역 안에서 유지한다. 필터·검색·정렬 변경 시 표시 개수를 초기값으로 되돌리고 목록 스크롤을 위로 이동한다.
- 메뉴 이동·목록 새로고침에서는 선택한 검색·필터·정렬을 유지한다. 재조회 결과가 바뀌면 같은 규칙으로 재정렬한다. 앱 재시작 후 정렬 복원은 범위 밖이다.
- 헤더는 키보드로 동작하는 버튼과 aria-sort를 사용한다. 현재 방향은 색뿐 아니라 화살표로도 구분한다. 작업 열은 제목·버튼 가운데 정렬만 적용한다.

### 패널 높이

- 넓은 화면에서는 공식 목록 프레임과 설치된 버전 패널의 위·아래 경계를 같은 grid 행에 맞춘다. 목록 제목·검색 도구는 이 공통 행 위에 둔다. 표 아래 출처·시안 문구와 해당 문구만을 위한 여백은 제거한다.
- 앱 창에서 제목 표시줄·상단 메뉴·현재 환경·충돌 안내·검색 영역을 제외한 공간을 사용한다. 목록 프레임과 설치 패널을 각각 내부 스크롤하며 헤더는 내용에 가려지지 않도록 유지한다.
- 새로고침·검색 결과 0건·설치 버전 0건에서도 두 프레임 높이는 유지한다. 설치 항목이 적다고 오른쪽 패널만 줄이지 않는다.
- 좁은 폭에서는 기존 반응형의 단일 열 전환을 유지하고, 세로로 쌓인 두 패널의 하단 일치를 강제하지 않는다. 낮은 창이나 긴 오류 안내에는 최소 읽기 공간을 보장하며 페이지 스크롤을 허용한다. UI를 잘라 고정 높이를 지키지 않는다.

### 제목과 현재 환경

- ‘Node 버전 관리’ 제목과 그 아래 ‘Windows x64 · 공식 nvm-windows 1.2.2 지원’ 문구를 모두 제거한다. 현재 환경 카드부터 시작하고 페이지의 접근 가능한 이름은 NodeRail로 유지한다. 미지원 OS·비호환 설치 등 사용자의 조치가 필요한 상태별 안내는 유지한다.
- 현재 버전 옆에 반복하던 nvm 배지와 버전 설명을 정리한다. 카드 좌측에는 Node 아이콘·현재 사용 버전만 두고, 우측에는 ‘nvm-windows 사용 중’ 배지와 환경 다시 검사 버튼을 나란히 둔다. 좁은 화면에서는 우측 묶음이 다음 줄로 이동할 수 있다.
- 사용 중 배지는 최신 검사에서 현재 Node가 nvm 관리 경로를 사용한다고 확인한 경우에만 표시한다. nvm 파일이 있거나 이전 결과가 남아 있다는 이유만으로 사용 중이라고 표시하지 않는다. 비호환 버전·설정 충돌·조회 실패의 실제 정보는 해당 안내 영역에서 제공한다.

## 메뉴와 아이콘

- 상단 B 메뉴의 라벨은 **Home / PlanRail / NodeRail**이다. 이동 버튼·현재 화면 접근성 이름·새 도움말 등 현재 UI에서 도구를 지칭하는 표기도 맞춘다. Node.js·npm·nvm-windows라는 기술 이름은 바꾸지 않는다.
- 기존 시안은 육각형 안 N을 사용한다. v3에서 [메뉴 4안](mockups/workrail-menu-icons-v3.html)을 추가 비교한다. A 라운드 라인 / B 솔리드 듀오톤 / C 레일 심벌 / D 레터 타일이며 NodeRail의 N 식별은 모든 안에 유지한다. 선택·비선택·포커스 상태와 17px 메뉴 크기를 함께 확인한다. N은 텍스트 폰트에 의존하지 않는 벡터 경로다.
- [앱 아이콘 4안](mockups/workrail-app-icons-v3.png)은 A 병렬 W 레일 / B 접힌 W 리본 / C 연결 레일 / D 육각 W다. 이는 이전 비교 기록이다. 최신 선택은 아래 E/F이며 실제 SVG/ICO/PNG와 16~256px 대비·투명 가장자리 검증은 별도로 필요하다. 현재 제품 리소스를 교체한 결과가 아니다.
- 같은 도구를 나타내는 Home 개발 환경 카드와 NodeRail 현재 환경 아이콘도 같은 심벌을 재사용한다. 메뉴 텍스트가 있으므로 아이콘 자체는 중복 낭독하지 않는다.

### 최신 아이콘 선택 — 메뉴 E / 앱 F

사용자는 추가 비교의 [메뉴 E~H](mockups/workrail-menu-icons-v4.png)에서 **E 모듈형**, [앱 E~H](mockups/workrail-app-icons-v4.png)에서 **F WR 모노그램**을 선택했다. 이전 앱 A W 레일형 선택을 대체한다. 아이콘 선택을 전체 화면 설계 승인이나 제품 구현 요청으로 확대하지 않는다.

- Home: 크기가 다른 둥근 사각 모듈 네 개. 통합 현황과 여러 도구가 모이는 공간을 표현한다.
- PlanRail: 세로 연결선과 어긋난 가로 일정 막대 세 개. 일정·작업의 관계를 표현한다.
- NodeRail: 굵은 N과 파란색 사각 단말 모듈. 작은 크기에서도 N의 대각선과 모듈 간 간격을 유지한다.
- 앱: 짙은 네이비 글래스 타일 위 옅은 파란색 WR 결합 심벌. WorkRail 전체를 나타내며 NodeRail N과 구분한다.
- 기존 차콜·스틸 블루·흰색 팔레트와 글래스 스타일을 유지한다. 메뉴 선택은 아이콘 색만으로 구분하지 않고 기존 탭 배경·테두리·텍스트 상태를 함께 사용한다.

BrandKit의 모노그램·모듈 구조·색상 절제 원칙으로 [선택 조합 확인용 보드](mockups/workrail-selected-identity.png)를 작성했다. 보드는 선택한 심벌의 조합을 보여 주는 이미지이며 실제 메뉴 크기·배율의 검증 자료가 아니다. 하단 띠는 아이콘 적용 예시이며 **제목 표시줄 아래 B 상단 탭**으로 확정한 레이아웃을 변경하지 않는다. 추가 폰트·팔레트·레이아웃 변경은 포함하지 않는다.

후속 자산 제작에서는 선택한 실루엣을 기준으로 작은 크기의 틈·두께·광학 정렬을 보정한다. SVG의 N/WR은 글꼴에 의존하지 않고, 16/20/24/32px 메뉴·타이틀바와 16~256px 앱 아이콘, 선택/비선택/포커스·고대비·Windows 배율에서 확인한다. 밝은 글래스 하이라이트가 심벌 가독성을 떨어뜨리지 않게 한다. 생성 이미지의 작은 썸네일만으로 검증 완료를 주장하지 않는다. 이번에는 제품 리소스·설치 아이콘·ICO를 생성하거나 교체하지 않았다.

## PlanRail 하단 상태 바

- PlanRail 화면에만 콘텐츠 아래의 독립된 상태 바를 둔다. 상단 B 메뉴와 함께 사용하며 하단 도크를 되살리지 않는다. 간트·달력의 가로 스크롤·편집 패널·알림을 덮지 않게 실제 레이아웃 공간을 확보한다.
- 읽기 전용 요약이다. 역할 배지 + 공유 상태, 일정 알림 정책을 표시한다. 새로운 설정 토글·재시도 버튼·승인 기능을 추가하지 않는다. 자세한 오류와 기존 조작은 원래 UI에서 유지한다.
- 공유 상태는 [sharingDescription](../../src/shared/sharing-status.ts)과 같은 실제 상태를 사용한다. 호스트는 ‘공유 제공 중’, 멤버 정상은 ‘연결 정상’, 개인은 ‘공유 미설정’으로 구분한다. 중지·연결 확인·승인 대기·단절·승인 취소·오류를 정상으로 표시하지 않는다. null/조회 실패는 확인 불가다.
- role과 연결 상태는 별개다. 연결이 끊겨도 마지막 역할은 멤버일 수 있다. 마지막 정상 확인 시간은 툴팁/접근 가능한 설명에 표시하며 현재 정상 연결의 근거로 쓰지 않는다.
- 연결 아이콘은 실제 상태가 connected인 호스트·멤버에만 초록색으로 표시한다. 연결 중·승인 대기·단절·중지·취소·오류·미설정·확인 불가는 빨간색이며, 정상으로 확인되지 않았다는 의미다. 개인 전용을 오류라고 바꾸지는 않고 ‘공유 미설정’이라는 정확한 문구를 유지한다. 색만으로 판단하지 않도록 정상 체크/비정상 표시와 텍스트를 함께 제공한다.
- 일정 알림 문구 앞에는 기존 [Icon.tsx](../../src/renderer/components/Icon.tsx)의 bell 아이콘을 재사용한다. 켜짐은 초록 종, 무음은 회색의 사선이 있는 종, 조회 중은 회색 종, 확인 불가는 빨간 종이다. 색뿐 아니라 무음 심벌·정확한 문구로 구분하며 새 알림 토글은 추가하지 않는다.
- 트레이의 전체 무음=true면 ‘전체 알림 무음’, false면 ‘일정 알림 켜짐’을 표시한다. 초기 조회 중은 ‘알림 상태 확인 중’, 읽기 실패는 ‘알림 상태 확인 불가’다. 개별 일정 알림 설정·Windows 방해 금지·배너 수신 여부를 뜻하지 않는다는 설명을 제공한다.
- 무음 해제 직후의 공유 권한 재확인과 기존 실패/결과 불명/기록 오류는 원래 진단 영역에서 계속 알린다. 하단의 정책 요약을 알림 성공 판정으로 쓰지 않는다.
- 새 제한된 읽기 상태와 변경 통지를 main/preload/shared 계약에 추가해야 한다. main이 실제 저장소 조회 결과를 제공하고 트레이 변경이 성공한 뒤 통지한다. 초기/재포커스/오류 복구 시 재조회한다. renderer에 DB·파일 권한이나 무음 변경 명령을 새로 열지 않는다.

## Home

- ‘작업 현황’ 글자만 제거하고 오늘 날짜는 유지한다. 빈 제목 자리를 남기지 않고 기존 패널 간격을 유지한다. 페이지의 접근 가능한 이름은 Home으로 제공한다.
- 기존 ‘일정 공유’ 패널 제목을 **PlanRail 상태**로 바꾼다. 역할 배지(개인 전용·호스트·멤버), 공유 연결 상태 배지, 마지막 정상 확인·실제 오류를 모은다.
- PlanRail 상태는 내용 크기에 맞춘 작은 위젯으로 제공한다. 카드 너비를 상위 그리드 열 전체로 늘리지 않고, 제목·배지·마지막 정상 확인에 필요한 높이만 사용한다. 긴 오류는 제한된 폭 안에서 줄바꿈하며 숨기거나 잘라내지 않는다. Node 작업 요약과 나란히 배치할 수 있고 좁은 창에서는 자연스럽게 줄바꿈한다.
- 내 개발 환경은 첨부한 홈 B안의 내부 구성을 유지한다. 상단 제목 왼쪽·N 아이콘 오른쪽, ‘현재 사용 중인 Node’ 라벨, 큰 버전 숫자, 작은 nvm 사용 배지, 가로 구분선, ‘설치된 버전’과 우측 개수, 전체 폭의 ‘NodeRail 열기’ 버튼 순서다. v3 요청에 따라 오늘의 일정과 같은 grid 행 높이를 사용하며 위·아래 경계를 맞춘다. 일정이 많을 때 목록을 내부 스크롤하고 개발 환경의 하단 정보·버튼을 아래에 유지하는 것을 제안한다. 좁은 단일 열에서는 내용 높이로 배치한다. 기존 딥 그레이·글래스 재질과 스틸 블루 버튼을 유지한다.
- Home의 nvm 사용 배지도 확인된 현재 상태에만 표시한다. 사용 버전·설치 개수가 불명확하면 기존 확인 불가/마지막 확인 안내를 유지하며 실제 데이터 대신 예시를 넣지 않는다.
- 공유 상태의 의미와 데이터는 PlanRail 하단과 동일하다. 상단 제목 표시줄에서는 역할·연결 배지를 모든 메뉴에서 제거한다. UPDATE·설정·도움말·릴리즈노트·창 제어는 유지한다.
- 오늘의 일정·내 개발 환경·Node 작업 패널은 유지한다. NodeRail 화면에 일정 상태 배지를 따로 추가하지 않는다.

## 설정 페이지

- 기존 기본 설정/공유 설정 탭과 글래스 모달을 유지한다. 업데이트 배포는 설명 문단을 길게 쌓지 않고 현재 배포·보관 파일·배포 후보·상태를 짧은 항목표에 묶는다. 가져오기·배포·중단은 작은 우측 버튼으로 둔다. 실패·재시도·진행 정보는 실제 상태에 맞춰 유지하며 좁은 폭에서는 항목표가 줄바꿈한다.
- 휴일 관리 (공통), 휴일 관리 (개인) 제목 안에 **반복 휴일**과 **날짜별 휴일**을 별도 테두리 영역으로 나눈다. 반복 영역은 ‘매주 반복되는 휴무 요일’, 날짜 영역은 ‘특정 날짜 또는 기간에만 적용’ 설명과 각 저장 동작을 둔다. 넓은 화면은 요일/날짜를 좌우로, 좁은 화면은 위아래로 배치한다.
- 호스트는 공통·개인을 편집한다. 멤버는 개인을 편집하고 공통은 조회만 하며 ‘호스트 제공 · 조회 전용’을 표시한다. 공통 편집 버튼을 비활성화된 채 채워 두지 않고 숨긴다. 반복/날짜 구분 개선은 양 역할에 동일하게 적용한다.
- 기존 날짜 규칙·미저장 초안 보호·검증 오류·입력 보존을 유지한다. 배경 상태 갱신으로 편집 중 초안을 덮어쓰지 않는다.
- 공유할 LAN IP·포트 아래 우측에 **호스트 주소 저장 / 공유 시작(또는 중지)**을 한 줄로 묶는다. 두 버튼은 별개 동작이며 새 주소 저장 없이 공유 시작을 누를 때 미저장 주소가 적용된 것으로 오인시키지 않는다. 저장 필요 상태는 시작을 막고 먼저 주소를 저장하도록 알린다. 멤버의 연결/해제 동작은 역할에 맞게 표시한다.
- 역할 변경은 [별도 동작 설계](sharing-role-switch.md)를 따른다. 확인 전에 영향 안내, 완료 후 공유/배포 중지, 수신 자료 정리와 보관 자료 조회 경계를 함께 반영한다.

## 검토용 시안과 인수

최신은 [수정 클릭형 시안 v3](mockups/workrail-screen-polish-v3.html)다. Home 카드 높이·알림 색상·제목 제거와 설정 기본/공유 탭·호스트/멤버 전환 확인을 추가했다. 상단 검토 도구 또는 설정 아이콘으로 설정을 열 수 있다. 모든 자료와 전환은 예시이며 실제 저장·연결·설치·역할 변경을 하지 않는다. 중지된 공유 자료의 전체 조회 화면과 전환 실패 복구 화면은 아직 재현하지 않았다. 아이콘 선택은 아래 확인용 보드에 반영했다. 클릭형 v3 HTML에는 이전 아이콘이 남아 있으며 실제 벡터 자산 적용 결과가 아니다. 아이콘의 기준은 최신 E/F 선택이다.

[수정 클릭형 시안 v2](mockups/workrail-screen-polish-v2.html)를 제품과 분리된 HTML로 작성했다. [이전 시안 v1](mockups/workrail-screen-polish.html)은 검토 이력으로 남긴다. Home·PlanRail·NodeRail 탭, 목록 정렬·새로고침 진행, 두 패널 스크롤, 역할·연결·무음 상태를 예시 데이터로 확인할 수 있다. 실제 공식 목록 조회·Node 설치/삭제·DB·알림 전송은 수행하지 않는다. 설치·사용·창 제어 등 범위 밖 동작은 예시 안내만 표시한다. 레이아웃·상태 표현 검토용이며 기존 제품의 전체 기능을 재현한 것은 아니다.

작업공간의 `/workspace/output/workrail-screen-polish/`에 Home·PlanRail·NodeRail 및 로딩·실패·좁은 폭 캡처와 `checks.json`을 보관했다. Chromium sandbox를 유지한 검토에서 1440×1000의 두 패널 위·아래 차이는 각각 0px, 페이지 JavaScript 오류는 0건이었다. 숫자 정렬·검색·메뉴 전환 시 예시 상태 유지·최초/재조회/실패·640px 폭의 가로 넘침 없음·reduced-motion을 확인했다. 이 결과는 시안 검증이며 제품 앱의 테스트 결과가 아니다.

v2 캡처와 검사 기록은 같은 폴더의 `v2/`에 별도 보관했다. 1440×1000에서 PlanRail 상태 위젯은 약185px, 내 개발 환경 카드는340×337px였으며 목록/설치 패널의 상·하단 차이는0px였다. 두 설명 문구 제거, nvm 배지 이동, 정상/비정상 연결5개 예시의 초록/빨강, 기존 bell 경로 재사용, 정렬·검색·로딩 상태, 640px에서 Home과 NodeRail의 가로 넘침 없음 및 reduced-motion을 확인했다. JavaScript 오류는0건이다. 실제 제품이나 Windows 연결·알림 실행 검증은 수행하지 않았다.

초기 독립 설계 검토에서는 구현 계획 수립을 막는 미답 질문과 코드 사실의 모순을 발견하지 않았다. NodeScreen 상태 수명과 무음 읽기/변경 통지는 후속 구현에 필요한 실제 변경으로 확인했다. 이후 사용자 요청에 따른 v2 수정은 해당 검토의 실기 검증 결과로 간주하지 않으며 전체 설계와 수정 시안의 최종 사용자 확인은 아직 대기 중이다.

v3 독립 설계 검토에서는 역할 전환 계획을 막는 중요한 미답 질문이 없고 메뉴/앱 아이콘 선택만 남았다고 확인했다. 이는 제품 코드 검증이 아니다. v3 브라우저 검사 기록은 `/workspace/output/workrail-screen-polish/v3/`에 보관한다. Home 두 카드 높이, Node 두 패널 경계, 알림 3개 상태색, 예시 역할 양방향 전환과 멤버 공통 휴일 조회 전용, 좁은 설정 화면을 확인한다. 첫 검사에서는 새 설정의 휴일 표까지 검색 개수에 포함하는 시안 검사 selector 오류가 있었으며 공식 목록 영역으로 범위를 수정했다.

최종 v3 Chromium sandbox 검사에서 1440×1000의 Home 두 카드 높이는 각각337px, Node 양쪽 패널 상·하단 차이는0px였고 JavaScript 오류는0건이었다. 640px 폭의 Home/NodeRail/설정 페이지 가로 넘침 없음, 기존 정렬·검색·상태 보존·로딩/실패·reduced-motion도 통과했다. Linux Node24.22.1에서 작업 트리의 문서 하네스7개 검사를 통과했다. 전체 앱·Windows 실제 역할 전환 검증은 수행하지 않았다.

- NodeRail: 최초 조회/재조회/실패/0건에서 상단 선과 표 위치, 헤더/셀 가운데 정렬, 4개 정렬키·숫자 비교·빈 값·타이·필터 후 정렬, 넓은/좁은/낮은 창, 독립 스크롤.
- 메뉴: 상단 B·정확한 라벨·N 가독성, 키보드·고대비·reduced-motion, 메뉴 이동 후 입력·날짜·스크롤·정렬 유지.
- PlanRail: 개인/호스트/멤버 및 연결의 모든 상태, 무음 on/off·조회 중/실패·트레이 변경 전파, 기존 오류 안내 유지, 상태 바가 간트·달력·편집·팝업을 가리지 않음.
- Home: 제목 문구 제거·날짜 유지, 카드명·배지·오류·마지막 확인, 기존 오늘 일정·개발 환경 정보 유지.
- 전체: 설치 식별자·버전은 이번 이름/화면 정리로 변경하지 않음. 추가된 역할 전환의 자료·공유·알림 변경은 별도 역할 설계를 따른다. 실제 구현 시 타입·단위/UI·Electron 통합·앱 전체 검사를 변경 범위에 맞춰 실행한다.

현재는 설계·시안 검토 단계다. 전체 설계 승인과 제품 구현 요청을 구분한다.
