## 현재 코드에서 확인한 사실

- `src/main/node-management/discovery.ts`의 기존 검증은 특정 nvm-windows 실행 파일을 전제로 한다. 이를 단순 제거하는 방식은 새 버전 지원 설계가 아니다.
- `src/renderer/workrail/Home.tsx`의 activeSource 분기와 manager 상태가 별개여서 관리자 미지원 상태와 기존 Node 출처 표시를 구분해야 한다.
- `PlanRailStatus.tsx`는 알림 정책에 관계없이 동일 툴팁을 사용한다.
- `SharingState`에는 devices, memberPresence, deviceVersions, pendingPairs가 있다. 등록 수는 연결 수가 아니며 version=null은 버전 확인 불가이다. 멤버가 호스트 실행 버전을 받는 경로는 현재 없다. 업데이트 배포 버전과 혼용하지 않으며 아래 선택적 메타데이터 설계를 따른다.
- `workrail.css`는 버전 숫자에 별도 monospace를 지정한다. Home 공유 배지는 별도 workrail-tag이다.
- `.github/workflows/app.yml`의 3개 artifact 표시 이름은 Planrail 접두어이다. 과거 Planrail 설치본 마이그레이션 테스트 이름은 역사적 제품명이다.

## 아키텍처 대안과 선택

1. **모든 버전에 동일 명령 실행:** 구현은 짧지만 1.x/2.x의 설정·권한·전환 구조 차이를 숨긴다. 채택하지 않는다.
2. **환경 실행기 + 관리자별 adapter:** Windows/WSL 실행 경로와 nvm 1.x/nvm 2.x/nodenv 기능을 분리한다. 기존 설치 존중과 환경 확장에 적합하여 통합 설계에 채택했다.
3. **WorkRail 관리형 설치만 허용:** 검증 범위는 좁지만 기존 도구를 쓰겠다는 사용자 요구를 충족하지 않는다.

환경 식별자와 검사 결과에 관리자 종류·버전·경로·사용자·마지막 검사 시각·기능별 가능/불가 이유를 포함한다. 오래된 조회 결과를 새 환경 결과로 재사용하지 않는다. 작업 시작 시 환경과 관리자를 고정하고, 실행 직전 재검증한다. 진행 중에는 아래 세부안에 따라 환경 변경을 잠근다.

WSL 실행은 `wsl.exe`에 배포판과 사용자를 명시한다. Windows UAC 기반 처리와 Linux 권한을 혼용하지 않는다. 사용자가 입력한 배포판·경로를 shell 문자열에 그대로 연결하지 않는다. nodenv 실행 경로와 `NODENV_ROOT` 등 실제 설정을 확인한다. nodenv 설치 기능은 node-build 플러그인 유무·정의를 별도 확인하고, 배포 목록에 있는 버전이 해당 환경에서 설치 가능한지 구분한다. WSL에서는 Windows용 Node ZIP을 설치하지 않는다. WSL의 PATH에는 Windows 경로가 포함될 수 있으므로 Node가 발견되었다는 이유만으로 nodenv 정상으로 판정하지 않는다. 실제 Linux 실행 경로와 선택 사용자의 관리 경로를 확인한다.

nvm-windows 2.x는 사용자별 설치와 shim/link 모드를 지원하므로 1.x의 symlink·설정·권한 가정을 재사용하지 않는다. 프로젝트 파일을 인식하는 환경에서는 기본 버전과 프로젝트 실행 버전이 다를 수 있다. `nvm pin` 같은 프로젝트 파일 변경은 기본 버전 전환과 별도 기능이다.

Windows 1.x, 2.x, WSL nodenv 각각 조회/설치/전환/취소/실패를 검증해야 하며, 모든 과거·미래 버전 지원은 보장하지 않는다. 실제 실행 파일 신뢰·설정 검증과 호환 기능 판정을 구분한다. Q3에 따라 기능별 지원을 제공하며 구체적인 신뢰 검증·기능 탐지 기준은 구현 설계에서 구체화한다.

## 질문 기록

- **Q1 확정:** 선택한 WSL 사용자의 기본 버전만 변경한다. 프로젝트 `.node-version`은 수정하지 않는다. 화면에 기본 버전임을 표시하고 프로젝트/셸 우선순위를 설명한다.
- **Q2 확정:** 종료된 WSL 배포판은 선택만으로 실행하지 않는다. 사용자가 `환경 시작` 버튼을 누른 뒤 조회한다. 시작 전에는 버전 확인 전 상태이며, 지난 결과를 현재 상태처럼 표시하지 않는다.
- **Q3 확정:** 기존 nvm을 기능별로 확인하고 가능한 기능을 제공한다. 최신 버전 설치를 강제하지 않고, 조회·설치·전환 중 확인하지 못한 기능만 제한 이유를 표시한다. 실행 파일·설정 신뢰 검증은 유지한다.
- **Q4 확정:** 바이너리 우선, 필요한 경우 소스 컴파일도 지원한다. 빌드 도구 존재 확인과 진행 안내를 제공하며 도구를 임의 설치하지 않는다. 바이너리 전용이라는 이전 추천은 기술 조사와 사용자 선택으로 대체했다.
- **Q5 수정 요청:** Home의 PlanRail 상태와 Node 작업 정보 구성은 유지하되 작은 위젯 크기로 줄인다. 오늘의 일정 공유 배지는 실제 PlanRail 배경과 일치시킨다. 이후 Q12에서 수정 시안까지 포함한 통합 설계를 확정했다.
- **Q6 확정:** 환경 자동 감지와 조건부 선택. 하나면 자동 선택, 여러 개면 마지막 선택 복원과 작은 `환경 변경` 버튼, 처음 여러 환경을 발견하면 최초 선택. 종료된 WSL은 `환경 시작` 클릭 뒤 내부 조회. 사용자가 이 방향으로 설계 진행을 요청했다. 아래 세부 처리와 기존 미결 항목 전체 승인으로 확대하지 않는다.
- **Q7 확정:** 각 WSL2 배포판의 기본 Linux 사용자만 관리한다. 다른 사용자 지정·동시 관리는 이번 범위 밖이다.
- **Q8 확정:** WSL의 nodenv/node-build 미설치는 공식 안내만 제공하며 자동 설치하지 않는다. node-build만 없으면 가능한 기존 버전 조회·전환은 유지한다.
- **Q9 확정:** Actions artifact와 실제 설치 EXE·업데이트 ZIP 이름 모두 WorkRail로 통일한다. 내부 앱 ID·실행 파일명·프로필 경로는 유지한다.
- **Q10 확정:** 메뉴별 마지막 도움말 글·스크롤을 유지한다. 전체 검색 결과에는 소속 메뉴를 표시한다.
- **Q11 확정:** 호스트 footer는 한 줄로 유지하고 `외 N명`에서 전체 목록을 연다. 기존 최근 정상 동기화 기준을 재사용한다.
- **Q12 확정:** 사용자가 “이 내용으로 설계 확정”을 선택했다. 16개 개선과 Q1~Q11, compact Home 시안, 14px 공통 여백, Node 최대 3개·참여자 최대 2명 후 전체 목록 연결, 작업 중 환경 변경 잠금, 구버전 호스트 버전 확인 불가 처리를 포함한 통합 설계를 확정한다. 제품 구현 시작은 별도 요청 범위다.

## 환경 자동 감지와 선택 — Q6

### 선택한 접근

상시 드롭다운은 전환 위치를 쉽게 찾지만, 환경이 하나인 사용자에게 불필요한 조작을 노출한다. 완전 자동 선택은 화면은 단순하지만 Windows와 WSL이 공존할 때 사용자의 작업 대상을 추측하게 된다. 사용자는 **자동 감지 + 필요한 경우에만 선택**을 선택했다. WorkRail이 실행되는 OS와 Node 관리 대상 환경은 서로 다르다.

| 상황 | 화면과 동작 |
| --- | --- |
| 환경 하나, 유효한 이전 선택 없음 | 자동 선택하고 환경명·확인한 관리자 버전을 표시. 변경 버튼 숨김 |
| 여러 환경, 유효한 이전 선택 있음 | 마지막 선택 복원. `Windows · NVM 1.1.11` 또는 `WSL2 · Ubuntu · 사용자`와 작은 `환경 변경` 버튼 |
| 여러 환경, 최초 실행 | 선택 화면을 열어 사용자가 지정. 선택 전 설치·사용 작업 없음 |
| 종료된 WSL 선택/복원 | 배포판 이름·종료 상태 표시. 관리자·Node 버전은 확인 전. `환경 시작` 클릭 뒤 내부 조회 |
| 실행 중 WSL 선택 | 선택 사용자의 관리자·Node 정보를 조회하고 기능별 지원을 표시 |

환경 선택은 관리 대상만 바꾼다. Node 버전 전환, 관리자 설치, WSL 종료를 함께 수행하지 않는다. Home의 개발 환경·Node 작업과 NodeRail은 같은 선택을 사용한다. 현재 관리 대상은 항상 보이며, 선택 목록은 버튼을 눌렀을 때만 열린다. 검토 시안 상단의 시나리오 선택 컨트롤은 제품 UI가 아니다.

### 감지 범위와 세부 처리

다음은 Q6의 의도를 구체화하여 Q12 통합 설계 확인에 포함한 세부 처리다.

- 먼저 Windows와 등록된 WSL2 배포판의 존재·실행 상태만 조회한다. 종료된 배포판 내부에 명령을 보내거나 기본 사용자·nodenv 버전을 알아내려고 실행하지 않는다. 조회 직전 상태가 바뀌는 경합도 검증 대상으로 둔다.
- Windows는 관리자 미설치여도 관리 대상이다. WSL 역시 관리자 미확인을 환경 부재로 취급하지 않는다. 따라서 Windows와 종료된 WSL2가 있으면 복수 환경이다.
- 기본 Linux 사용자가 아직 확인되지 않았다면 `기본 사용자 · 확인 전`으로 표현하고 시작 후 실제 사용자를 식별한다. Q7에 따라 사용자 선택 UI는 제공하지 않는다. 기본 사용자가 달라지면 이전 사용자의 목록을 버리고 대상 변경을 알린 뒤 다시 조회한다.
- 감지 중·조회 실패를 `환경 0개`나 `하나뿐`으로 처리하지 않는다. 불완전한 목록에 근거한 자동 선택을 피하고 `다시 확인`을 제공한다.
- 이전 선택의 배포판이 삭제되거나 접근 불가하면 다른 환경으로 자동 대체하지 않는다. 이전 대상이 없음을 알리고 다시 선택하게 한다. 관리자가 사라진 경우도 다른 관리자로 조용히 전환하지 않는다.
- 설치·사용 전환 중에는 대상 환경을 고정하고 환경 변경 버튼을 잠근다. 작업 종료 또는 취소 확인 후 전환한다. 지연된 응답은 이전 환경 결과로 식별하여 새 환경 목록에 섞지 않는다.
- 환경 선택을 저장하되, 설치·시작·Node 전환 명령 자체를 재실행하지 않는다. WSL 종료는 WorkRail에서 자동 수행하지 않는다.

## 전체 재검토로 보완한 계약

아래는 설계자가 제품 요구를 구체화한 세부안으로 Q12에서 통합 승인받았다. 원래의 제안 출처를 유지하며, 구현 계획에 맡긴 내부 기술 상세까지 이미 구현·검증됐다는 뜻은 아니다.

### 기존 관리자와 Node 작업

- 환경 실행기와 관리자 adapter를 분리한다. Windows nvm 1.x, nvm 2.x, WSL2 nodenv/node-build의 명령·설정·권한 차이를 adapter 내부에서 처리한다. 임의의 다른 관리자까지 이번 범위를 확대하지 않는다.
- 파일 경로·소유권·서명 또는 공식 배포 해시 등의 신뢰 근거를 먼저 확인한 뒤 버전·읽기 전용 기능을 탐지한다. 버전 문자열 자체를 무결성 증명으로 쓰지 않는다. 현재의 1.2.2 단일 해시를 무조건 통과시키는 우회는 하지 않는다. 구체적인 신뢰 목록 구성·배포 해시 취득·플랫폼별 검증 코드는 구현 계획에서 결정한다.
- UI 모델은 관리자 식별(종류·실측 버전·경로), 활성 Node 출처, 기능별 지원(조회/설치/사용), 검사 신선도를 구분한다. `nvm 미지원`을 `기존 Node.js 충돌`로 변환하지 않는다. 관리자 식별 성공은 옅은 초록 배지로 표현하고 검증 실패나 제한은 별도 이유로 표시한다.
- 동일 환경에서 관리자 후보가 여러 개면 기존 실행 경로 우선순위와 실제 Node 소유 경로가 일치하는지 확인한다. 대상이 모호하면 변경 작업을 막고 경로 정리 안내를 제공한다. 관리자 사이 자동 이관·선택 UI는 이번 범위에 추가하지 않는다.
- `설치`와 `사용`을 분리한다. 설치 성공만으로 기본 버전을 바꾸지 않는다. 변경 후 실제 목록·기본/활성 버전을 재조회해 성공을 판정한다. Windows 1.x 전환은 공통 symlink를 사용하며 WSL nodenv 전환은 해당 기본 사용자의 global 설정이다. 기존 프로젝트 파일이나 열린 셸 환경변수는 변경하지 않는다.
- 설치·전환은 한 번에 하나만 수행하고 Home/NodeRail 모두 같은 진행 상태를 표시한다. 환경 변경은 작업 동안 잠근다. 다운로드·압축 해제·컴파일·최종 확인을 구분하고 측정 근거 없는 퍼센트는 표시하지 않는다.
- 소스 빌드에 필요한 도구가 없으면 설치하지 않고 필요한 준비를 안내한다. 로그를 보존하며 실패·취소·결과 불명을 구분한다. 취소는 WorkRail이 시작한 작업에 한정하고 배포판 전체를 종료하거나 다른 셸을 정리하지 않는다. 취소 후 재조회 전 완료·미설치를 단정하지 않는다.
- WSL nodenv 초기화나 PATH가 잘못되면 필요한 설정을 안내하되 shell 설정 파일을 자동 수정하지 않는다. Q8의 수동 설치 안내와 같은 범위이다.
- Windows에서 관리자가 없는 경우의 기존 설치 진입점 및 공식 MSI 제거·독립 복구 흐름은 유지한다. 이번 요구는 기존 관리자 활용 확장이며 Windows 신규 설치 기본 버전의 자동 변경을 포함하지 않는다. 기존 1.2.2 설치 안내를 현재 도구의 호환 조건으로 재사용하지 않는다.

### Home·footer의 정보와 범위

- Home은 현재 선택 환경의 상태만 보여준다. 정상은 설치 목록, 진행은 작업 진행, 실패는 오류 요약/상세 진입, 확인 전은 조회 상태를 표시한다. 확인 실패를 버전 0개로 표시하지 않는다.
- 작은 위젯을 유지하도록 Node 목록은 현재 사용/기본 버전을 먼저, 나머지는 최신순으로 최대 3개 표시하고 `전체 N개`로 NodeRail에 연결한다. 호스트 위젯은 연결 참여자 최대 2명과 나머지 수를 표시하고 전체 목록으로 확장한다. 설치 버전이나 참여자가 많아져도 위젯 전체가 계속 커지지 않도록 한다.
- footer와 Home 연결 목록은 승인되고 취소되지 않은 기기의 `memberPresence`를 재사용한다. 현재 구현의 연결 판정은 최근 10초 이내 정상 동기화이며 로그인·영구 소켓 연결을 뜻하지 않는다. 등록 수와 연결 수는 별개다. 버전 미수신은 `버전 확인 불가`, 연결 0명은 `연결된 참여자 없음`으로 표시한다.
- Q11의 `외 N명`은 이름·버전·연결 상태를 읽을 수 있는 접근 가능한 목록을 연다. 긴 이름은 축약하되 전체 이름은 툴팁/목록에서 제공한다. 화면 폭이 좁으면 참여자 목록을 먼저 접고 알림 상태를 가리지 않는다.
- 멤버의 호스트 실행 버전은 새 선택적 메타데이터가 필요하다. 인증된 공유 응답의 선택적 헤더 등으로 호스트 실행 버전을 전달하고 연결 대상과 함께 보관한다. 엄격한 기존 snapshot 스키마에 필드를 무조건 추가하지 않는다. 구버전 호스트가 정보를 주지 않으면 `확인 불가`로 유지하고 동기화는 계속한다. 업데이트 배포 manifest 버전을 호스트 실행 버전으로 대신 표시하지 않는다.
- 알림 툴팁은 실제 on/muted/unknown/loading별로 다르게 표시한다. 켜짐은 초록 종, 무음은 회색 무음 종, 불명은 빨간 상태, 조회 중은 중립색으로 구분한다. 기존 전체 무음 저장값을 사용하며 OS 알림 허용 여부를 추정하지 않는다.

### 화면·공식 목록·도움말

- 공통 콘텐츠 프레임은 좌우/위/아래 14px로 맞추고 내부 툴바·표의 여백과 구분한다. PlanRail footer가 있는 경우 콘텐츠 영역에서 해당 높이를 제외한다. 각 메뉴에 서로 다른 margin을 더해 이중 여백을 만들지 않는다.
- 기존 글래스 색·재질·아이콘은 유지한다. 버전 숫자도 본문 font-family를 상속하고 숫자 폭 정렬만 선택적으로 적용한다. Home 상단 두 패널 높이 일치, 하단 compact 위젯, 실제 `.sharing-badge`, 선택 메뉴와 같은 CTA 스타일, flat 비선택 메뉴를 함께 검증한다.
- 분류는 `LTS · 코드명` / `비 LTS` / `확인 불가`. LTS의 장기 지원 계열 의미와 코드명 예시를 헤더 설명·도움말에 제공한다. 코드명만 보고 현재 지원 중·보안 권장을 보장하지 않으며 이번 범위에 별도 Current/EOL 판정을 추가하지 않는다.
- 상태/작업은 `사용 중: 체크·비활성 사용 중`, `설치됨: 보관함·사용`, `미설치: 빈 원·설치`, `미확인: 경고·다시 확인`. 작업 진행은 별도 진행 표시이며 미확인 상태에서 설치를 추측해 실행하지 않는다. 기능 제한은 버튼 옆 설명 또는 접근 가능한 툴팁으로 표시한다.
- 공식 목록에 있어도 해당 환경의 아키텍처·node-build 정의에서 설치 가능한지는 별도다. 지원되지 않는 버전은 이유를 표시한다. 공식 목록에 없는 설치 버전도 설치된 목록에서 유지한다. 정렬은 기존 4개 데이터 열과 숫자 기반 버전 비교를 유지하며 상태 아이콘의 색만으로 정렬하지 않는다.
- 표 상단 진행 선·가운데 정렬·달력 제목과 같은 헤더 투명도·헤더 hover 배경 없음·양쪽 패널 하단 일치/내부 스크롤 등 기존 승인 사항은 유지한다. 상태 아이콘 툴팁은 마우스·키보드 모두 제공한다.
- 도움말은 Home / PlanRail / NodeRail / 공통 설정으로 분리한다. 메뉴 ID를 제한된 열거형으로 IPC에 전달한다. 최초에는 해당 메뉴 첫 글, 이후에는 Q10에 따라 해당 메뉴 마지막 글·스크롤을 복원한다. 검색어는 메뉴별로 기억하고 전체 검색 결과에는 메뉴명을 표시한다. 역할별 글은 PlanRail 내부에서 구분한다. 기존 오프라인 자산·관련 글 링크·접근성·도움말 창 재사용은 유지한다.
- 도움말의 1.2.2 고정 호환 설명을 기능별 지원·환경 선택·기본 버전 범위로 바꾼다. Windows 신규 설치 안내는 기존 설치 흐름과 별도로 설명해 모든 환경에 1.2.2를 요구하는 것처럼 보이지 않게 한다.

### 배포 이름과 업데이트 호환

Q9는 Actions 3개 artifact 이름뿐 아니라 `electron-builder.yml`의 artifactName, `scripts/release/update-bundle.mjs`의 배포 ZIP 이름에도 적용한다. EXE·blockmap·해시 파일·latest.yml의 path/url·manifest 파일명/해시 참조를 함께 일치시킨다. 버전·소스 SHA·unsigned·UPDATE-TEST-ONLY 표시는 유지한다.

`appId`, `UPDATE_APP_ID`, 설치된 실행 파일명 `Planrail`, DB/프로필 경로, 자동 실행 등록은 유지한다. 역사적인 Planrail 0.8.0 설치본 이름은 바꾸지 않는다. 새 파일명이어도 기존 설치본의 데이터 보존·수동 업그레이드·자동 업데이트가 이어져야 한다.

현재 workflow에서 Windows 설치 artifact에는 실제 `*-update.zip`이 있고, LAN-UPDATE artifact에는 EXE·blockmap·metadata 등의 구성 파일이 있다. GitHub가 다운로드 시 만드는 artifact ZIP과 앱이 만드는 업데이트 ZIP은 구분해 문서화한다. 이름 변경만으로 artifact 내용을 재배치하지 않는다.

정적 미리보기: [호스트 Home](mockups/workrail-home-host-v2.png) · [멤버 Home / WSL](mockups/workrail-home-member-v2.png) · [NodeRail](mockups/workrail-environment-auto.png). 정적 화면의 환경은 실행 중으로 가정한다. 아이콘 툴팁은 시안에서 title로 표시하며 실제 제품은 기존 접근 가능한 Tooltip 컴포넌트로 구현해야 한다.

## 문서 유지와 검증

agents-md의 기존 진입점·명령·문서 분리 원칙에 따라 루트 지침은 확대하지 않고 domain 인덱스와 STATUS에 이번 설계를 연결한다. 기존 설계와 달라지는 정책과 Q12 최종 승인을 이 문서에 기록했다. 기존 ADR 디렉터리가 없으므로 동일 결정을 별도 ADR로 중복 생성하지 않는다.

현재 문서는 요구 추적과 Q1~Q12 승인 결정을 담은 확정 설계다. 제품 테스트·Windows/WSL 실기는 수행하지 않았으며 구현 완료 증거로 사용하지 않는다.

중간 검토: 독립 공식 자료 검토에서 nvm 2.x shim/link·프로젝트 설정, WSL의 Windows PATH 혼입, node-build 소스 빌드 범위 누락을 지적받아 보완했다. Chromium sandbox를 유지한 정적 시안 렌더링에서 이미지 로드·메뉴/역할/환경/테마 전환·WSL 시작 표현을 확인했다. 1280px 다크 및 800px 라이트에서 가로 넘침과 JS 오류가 없었다. 제품 연동 검증은 아니다. 문서 변경의 하네스 verify 7개 검사를 통과했다.


### Home 수정 시안 v2

사용자는 하단 두 패널의 구성을 유지하면서 작은 위젯처럼 보여 달라고 요청했다. 위젯 너비를 PlanRail 상태 최대 400px, Node 작업 최대 360px로 제한하고 왼쪽부터 나란히 배치한다. 내부 패딩은 13px/14px, 행 간격은 5px로 줄이며 내용 길이에 따라 높이는 자연스럽게 늘어난다. 좁은 화면에서는 세로 배치한다. 오늘의 일정과 내 개발 환경의 동일 높이는 유지한다.

공유 배지의 이전 파란 스타일은 잘못된 시안이었다. `src/renderer/forest-crystal.css`의 실제 `.sharing-badge`를 직접 재사용한다. 배경 `#ab75632b`, 테두리 `#dc9b7d8c`, 글자 `#f4d4c2`, 반경 4px, 폰트 10px/행 높이 16px, 좌우 패딩 4px로 제품 PlanRail과 일치시킨다. 제품 코드 변경은 없다.

수정 시안 검토: 1280px 화면에서 호스트 위젯 콘텐츠 높이 191px/183px, 멤버·WSL 위젯 193px/211px를 확인했다(테두리 제외). 800·600·390px에서 가로 넘침과 브라우저 JS 오류가 없었다. 공유 배지의 계산된 배경·테두리·폰트가 실제 `.sharing-badge` 규칙과 일치함을 확인했다.

Q6 시안 검토: sandbox를 유지한 Chromium에서 단일 환경의 변경 버튼 숨김, 최초 복수 환경의 선택 전 작업 목록 숨김, 선택 후 목록 표시, 종료 WSL의 시작 버튼과 관리자 확인 전 표시, Windows로 복귀를 확인했다. 600px 화면에서 가로 넘침과 JS 오류가 없었다. 실제 환경 감지·WSL 시작 검증은 아니다.

전체 설계 독립 검토: 구현 계획 수립 관점에서 16개 요구·Q1~Q11·호환성·실기 수용 경계를 재검토했으며 중요한 추가 제품 결정 질문은 없었다. 통합 설계는 이후 Q12에서 확정했으며 신뢰 검증/명령 파서 등의 내부 기술 세부는 구현 계획에서 다룬다. 검토 결과가 제품 구현·호환성 테스트 완료를 의미하지 않는다.
