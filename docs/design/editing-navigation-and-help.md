# 편집 흐름·간트 탐색·전체 기능 도움말 개선

2026-11-16. 상태: **Q1~Q8 설계 전체 확정·구현 승인. 0.8.4 구현·로컬 검증 완료.** 기준 main `a060eb6955f898939c6be541413aab83a55a5e38` (0.8.3).

## 목적과 범위

미저장 입력 폐기 확인의 반복을 없애고, 간트 스크롤 조작 뒤 Space 이동을 복구한다. 행동 차단 경고는 작업 영역을 밀지 않는 토스트로 표시한다. 도움말 열기 지연을 조사·개선하고 실제 Planrail의 모든 사용자 기능을 안내한다. 제목 표시줄에서 공유 역할을 구분한다. 기존 날짜·공유 권한·데이터 보존·Windows 알림 정책을 재설계하지 않는다.

## 코드에서 확인한 현재 상태

- [GanttNavigation](../../src/renderer/components/GanttNavigation.tsx)의 가로 스크롤은 range input이다. [탐색 훅](../../src/renderer/state/useGanttNavigation.ts)은 모든 input을 편집 입력으로 분류하므로 스크롤에 포커스가 남으면 Space-pan 준비가 되지 않는다. 배율 range도 같은 분류에 걸린다. 이 경로는 코드로 확인했으며 실제 사용자 PC의 기본 Space 스크롤 반응은 미실측이다.
- [App](../../src/renderer/App.tsx), [공유 설정](../../src/renderer/components/SharingSettings.tsx), [bootstrap](../../src/main/bootstrap.ts)에 각각 폐기 확인이 있다. 프로젝트 삭제·참여자 삭제 같은 별도 작업 확인은 이번 ‘미저장 변경 폐기 확인 제거’와 구분한다.
- [도움말 창](../../src/main/help-window.ts)은 클릭 때 BrowserWindow를 생성하고 ready-to-show까지 숨긴다. X는 창을 파괴하고 다음 열기에서 새 renderer를 만든다. 이미 열린 창은 복원 경로를 사용한다. 명시적인15초 대기 코드는 없다.
- 도움말에는 창 생성/로드/본문 준비 시간을 나눠 기록하는 계측이 없다. renderer 기동·파일 접근·회사 보안 프로그램·본문 준비 중 어느 부분이 병목인지는 미확정이다. PNG URL의 eager import만으로 모든 이미지가 동시에 decode된다고 판단하지 않는다.
- [도움말 콘텐츠](../../src/shared/help-content.ts)는 공유 중심14개 글이다.0.8.3 접속 상태·전체 무음·업데이트 알림 설명은 이미 존재한다.

## 접근 방식

폐기 확인은 각 UI의 승인 단계를 제거하되 공통 저장 중/결과 불명 보호를 유지하는 방향이다. 행동 경고만 토스트로 옮기며 데이터 오류까지 잠깐 보였다 사라지게 하지 않는다. Space 문제는 간트의 탐색 range와 실제 문자 입력을 구분해 수정한다. 전역 입력 예외를 없애는 방식은 텍스트 공백 입력과 키보드 조작을 훼손하므로 사용하지 않는다.

도움말 성능은 두 안을 제시했고 **Q6에서1안을 선택**했다.

1. 선택: 주 화면 조회·편집 준비 뒤 유휴 시점에 도움말을 미리 준비하고 재사용. 최초 클릭 응답 개선 가능, 사용하지 않아도 메모리/백그라운드 준비 비용이 발생한다.
2. 미선택: 첫 클릭에 준비한 뒤 재사용. 사용 전 자원 비용이 적지만 최초 새 창/renderer 준비 지연이 남을 수 있다.

어느 안도 빈 창만 빨리 띄운 것으로 성능 목표를 달성했다고 판정하지 않는다. 클릭→창 표시와 클릭→본문 조작 가능을 각각 측정하며 메인 창 시작 성능을 함께 확인한다. 반복 오류 시 무한 사전 재시작은 하지 않는다. 오류 안내와 명시적 재시도 경로는 보존한다.

## 구현 시 보존할 경계와 제안

- 저장 전의 초안만 폐기한다. 이미 저장된 데이터와 시작된 DB 트랜잭션을 임의 롤백·강제 중단하지 않는다. 저장 실패/결과 불명 상태의 처리와 UPDATE 설치는 확정 규칙에 따라 구분한다.
- 토스트는 기존 성공 안내와 다른 경고 표시를 사용하되 새로운 영구 레이아웃을 만들지 않는다. 반복 동작은 동일 경고의 시간을 갱신하고 누적 창을 만들지 않는 방식을 제안한다. 기존 성공 토스트2초는 변경하지 않는다.
- 간트 가로/배율 스크롤 조작 뒤에도 날짜 영역에서 Space+왼쪽 드래그가 동작해야 한다. 텍스트의 공백 입력, 버튼 Space/Enter, range 화살표/PageUp/PageDown/Home/End는 유지한다. Space만 누를 때 불필요한 페이지 이동을 막되 일반 버튼 키보드 실행을 훼손하지 않는다. 기존 Escape/blur/Space·포인터 해제 종료와 날짜 변경 없는 pan을 유지한다.
- 도움말은 독립 창 하나, 오프라인 콘텐츠, 읽기 전용 preload, sandbox/contextIsolation, 외부 탐색 금지, 주 창 초안 보존을 유지한다. 사전 준비 창은 자동으로 표시하거나 포커스를 가져오지 않는다.
- ‘실제로 사용자가 열어 둔 도움말’과 ‘숨겨진 준비 창’을 구분한다. 주 창 트레이 복원 때 준비만 된 창이나 사용자가 X로 닫은 창을 임의로 열지 않는다. Exit/업데이트 종료 때 모두 정리한다. 역할별 첫 항목은 실제 첫 열기 시점의 역할을 기준으로 하며 이후 읽던 항목·검색·스크롤 복원을 유지한다.
- 역할 배지는 연결 성공을 뜻하지 않는다. 텍스트로 역할을 읽을 수 있게 하고 클릭 가능한 공유 설정 진입점으로 임의 확장하지 않는다. 로딩/오류 중 개인 역할로 잘못 표시하지 않는다. 배지 세부 재질은 기존 작은 태그와 조화되도록 구현자가 정한다.

## UPDATE 자동 설치와 폐기 경계

Q5는 [기존 업데이트 설계](lan-app-updates.md)의 미저장 초안 때문에 설치를 대기하고 다시 누르게 하는 조건을 대체한다. 다운로드 시작은 기존대로 사용자가 UPDATE를 누를 때다. 다운로드 중 편집은 허용하고, 검증 완료 후 설치 준비에 들어가면 새 편집·저장을 차단하고 기존 저장을 안전하게 마무리한다. 프로젝트·일정·공유 설정·빠른 알림뿐 아니라 날짜/연월 입력의 아직 확정하지 않은 텍스트도 저장하지 않는다. 자동 blur로 입력을 확정하거나 저장을 만들어내지 않는다.

구현자 제안: renderer의 설치 준비 응답은 dirty 여부가 아니라 입력 차단과 진행 중 저장의 종료 여부를 확인하도록 바꾼다. main의 mutation barrier·현재 배포/자격/파일 검증·앱 정상 종료 계약은 유지한다. 저장이 반영되지 않았다는 안전한 실패 결과가 확정된 경우에는 초안을 저장하지 않고 종료를 진행할 수 있다. 반면 renderer 무응답, 저장 종료 시간 초과·결과 불명, DB/공유 정리 실패를 ‘폐기 동의’로 간주하지 않고 설치를 중단해 오류와 명시적 재시도를 제공한다. Q5는 강제 프로세스 종료나 DB 쓰기 강제 중단의 승인이 아니다.

설치 준비가 실패해 앱이 계속 열려 있으면 아직 메모리에 남은 초안을 불필요하게 먼저 삭제하지 않는 방식을 제안한다. 실제 앱 종료 때 미저장 초안은 없어지며 복구/자동 저장은 제공하지 않는다. 사용자 안내에는 다운로드 완료 후 편집 중에도 자동 재시작하고 미저장 입력이 사라진다는 점을 정확히 쓴다.

변경 요청이 없는 기존 계약: 앱을 완전히 종료했다 다시 열었을 때 보관된 설치 대기 파일은 자동 설치하지 않고 ‘설치 후 재시작’으로 진행한다. 평소 Exit만으로 업데이트를 설치하지 않는다. 다운로드 취소, 배포 철회/교체·권한 회수 확인 시 취소, 검증 완료 파일의 기존 오프라인 설치 조건은 유지한다. 업데이트 자동 설치 시점의 초안 보호만 Q5로 대체한다.

## 도움말 성능 측정과 창 재사용

구현자 제안: 주 renderer가 조회·편집 준비 완료를 알린 뒤 유휴 작업으로 사전 준비를 한 번 예약한다. 로그인 자동 실행으로 트레이에 시작하면 도움말은 절대 표시하지 않는다. 사용자가 사전 준비 전/도중 도움말을 누르면 같은 준비 작업을 사용해 단일 창을 연다. main이 역할/버전/읽기 상태를 안전하게 전달하는 기존 IPC 출처 검사는 유지한다.

사용자 X/Alt+F4는 도움말을 숨기고 사용자가 닫은 상태로 기록한다. 트레이 함께 숨김과 구별하여 복원할 창만 복원한다. 종료 중에는 숨김으로 가로채지 않고 실제 파괴한다. 닫아 둔 도움말 renderer가 실패하면 캐시를 버리고 다음 명시적 열기에서 재시도하며, 사전 준비 실패 때문에 주 창 작업을 중단하지 않는다.

측정은 도움말 클릭 수신·창 생성 시작/완료·load 요청·dom-ready·첫 화면 준비·show·본문 준비를 같은 실행 내 시간축으로 기록한다. 본문 준비는 역할에 맞는 글/목차/검색 이벤트가 사용 가능한 시점이며 빈 창 표시는 구분한다. 이미 열린 창 재호출도 별도 유형으로 기록한다. 가상 데이터로 기존/변경 후 동일 환경을 비교하고, 주 창 시작 시간·유휴 준비 자원 사용도 확인한다. 회사 PC 실측은 별도로 남기며 목표 미달을 통과로 쓰지 않는다. 진단 기록에 이름·IP·일정·검색어·토큰은 넣지 않는다. 기록 경로·용량 제한은 구현 계획에서 구체화한다.

이미지는 실제 출시 코드의 격리된 가상 자료로 촬영하고 번호·본문 설명을 일치시킨다. 실제 이름·IP·일정·접속 자격은 사용하지 않는다. 구현하지 않은 백업/복원·서비스 실행·역할 이관 등을 가능한 기능처럼 소개하지 않는다. 모든 사용자 기능을 코드·사용 안내·도움말 항목에 매핑해 누락을 점검한다.

## 검증 계획

- 초안 있는 각 패널/팝업의 X·취소·Escape·바깥 클릭·전환 및 Exit에서 확인창 없이 폐기. 주 창 트레이 숨김의 입력 보존과 저장 중/실패 경계 검증. UPDATE는 미저장 초안·미확정 날짜 입력이 있어도 안전한 저장 종료 후 설치하는지, renderer 무응답/저장 결과 불명 시 중단·재시도와 재실행 후 보관 파일의 명시적 설치를 검증.
- 미저장 입력이 있는 드래그/빠른 작업 차단,4초 경고 토스트, 반복 안내, 필드/시스템 오류 지속, 기존 성공 토스트 검증.
- 실제 가로 스크롤·배율 range에 포커스가 남은 상태에서 Space+드래그. 일반 입력·버튼·키보드 range·일정 드래그 회귀.
- 도움말 첫 열기/재열기/기존 창 재호출/생성 중 연속 클릭/트레이/Exit/로드 실패/역할 변경을 검증. 생성·로드·첫 화면·본문 준비의 구간과 주 창 시작 시간을 분리 기록. 회사 Windows PC 성능은 CI와 구분.
- 모든 도움말 항목의 경로/관련 링크/이미지/단계/버전, 오프라인 검색·이미지 확대, 새 역할 배지와 제목 표시줄 잘림 검증.
- 구현 승인 후 typecheck·전체 verify:app·harness 및 실제 가능한 화면 검증. Windows CI·실기 미검증을 구분해 기록.

## 설계 검토 기록

- 독립 builder 검토: Q1~Q7, 기존 승인 설계와 명시된 구현자 제안으로 계획 수립 가능. 중요한 미결정 사항 없음.
- 상대 링크10개 모두 실제 경로 확인. `node scripts/harness/run.mjs verify`, 공백 검사 통과. 제품 구현·성능 개선은 아직 없으며 목표 달성은 미검증이다.
- 문서 전체 승인 시에는 사용자 개별 결정과 구분한 구현자 제안(동일 토스트 갱신, 안전한 설치 중단/재시도, 재실행 보관 파일의 명시적 설치 유지, 숨겨진 도움말의 생명주기·계측, 기존 태그에 맞춘 배지)을 함께 검토한다.
