# NodeRail 사내 프록시와 설치·사용 진행 화면

**설계 확정 · 2026-11-19.** Q4에서 Q1~Q3의 선택과 두 헤더의 불투명도를 포함한 설계를 승인했다. 제품 구현은 후속 작업이다. 요청 범위는 프록시가 필요한 기존 Windows nvm과 WSL2 nodenv 환경에서의 설치, Home과 동일한 작업 레이어, 두 목록 헤더의 불투명도다. [이전 화면 계약](workrail-node-detail.md) · [클릭 가능한 시안](mockups/noderail-proxy-loading.html)

## 설치와 네트워크

- Windows nvm-windows 1.1.11에서 사내 프록시 설정 후 CLI 설치가 성공하고 NodeRail은 미러 충돌을 보고했다. 현재 1.x는 settings.txt의 proxy, 2.0.1은 레지스트리 Proxy를 미러·설치 소스 판단에 포함한다. [1.x 검사](../../src/main/node-management/discovery.ts) · [2.x 검사](../../src/main/node-management/modern-manager.ts)
- 공식 미러 주소는 다운로드 출처이고 프록시는 그 출처에 연결하는 경로다. 유효한 기존 HTTP(S) 프록시만으로 설치를 제한하지 않는다. 공식 Node·npm 출처, 관리자 실행 파일과 설정의 무결성, TLS 정책, 설치 후 검증은 계속 적용한다. 비지원 프록시, 미러 변경, 서버 응답 실패에는 각각 원인을 안내한다. 설정값을 변경하거나 화면·로그에 인증 정보를 남기지 않는다. Windows 지원 범위는 사용자명·비밀번호가 없는 주소·포트 방식이다. 예를 들어 `http://proxy.example:8080`을 허용한다. 인증 정보가 포함된 URL은 설치를 시작하기 전에 해당 방식의 지원 범위를 안내한다. 안내에는 입력값을 되풀이하지 않는다.
- WSL2는 사용자가 시작한 배포판의 기본 사용자 로그인 환경에서 nodenv와 node-build를 사용한다. 배포판별 기본 사용자의 로그인 환경에 export된 HTTP(S) 프록시와 NO_PROXY(소문자 포함)를 각 다운로드 도구가 지원하는 방식으로 상속한다. Windows 설정을 배포판에 복사하거나 중지된 배포판을 기동하지 않는다. 바이너리 다운로드와 소스 빌드, 작업 로그 및 취소를 포함해 확인한다. [로그인 셸](../../src/main/node-management/wsl-host.ts) · [설치](../../src/main/node-management/wsl-guest.ts)
- 공식 배포 목록은 Windows·WSL 모두 Electron Main의 net.fetch로 읽는다. 목록 조회, nvm 설치, node-build 다운로드 실패를 구별한다. WSL 출력은 화면과 저장 로그로 분기되기 전에 프록시 인증정보를 제거한다. 공개할 진단에는 주소·계정·비밀번호 예시로 실제 팀 값을 쓰지 않는다.

현재 [NodeScreen](../../src/renderer/workrail/NodeScreen.tsx)은 상태 문구를 목록 위에 별도 출력한다. 설치·사용 중에는 이를 한 번만, Home의 반투명 면·진행 표시·두 줄 텍스트로 표시한다. 현재 버전 카드와 메뉴는 계속 보인다. 작업 전 목록·스크롤·포커스 위치를 보존하고, 시작 버튼의 중복 입력과 키보드 재진입을 막는다. 좁은 창에서도 상태와 허용된 동작이 보이도록 한다. 명시적 환경 검사와 목록 새로 고침의 기존 상단 진행선은 각 영역에서 유지한다.

Windows는 확인 가능한 권한·작업 대기 상태를 표시한다. WSL은 실제 단계와 가능한 취소·로그만 표시한다. 완료 후 재조회해 버전과 목록을 갱신하며 실패는 해당 원인과 복구 동작을 보여 준다. 종료 여부 불명은 기존 잠금과 다시 확인을 유지한다. 메뉴를 이동해도 작업은 이어진다. 상태 안내는 스크린 리더에서 한 번 읽고 동작 감소 설정을 따른다.

## 헤더

현재 공식 목록 thead와 설치된 버전 h3는 모두 transparent이고, 공식 목록은 스크롤할 때 뒤의 행과 별도 blur가 결합한다. 같은 CSS 선언만 비교하면 실제로 보이는 차이를 놓친다. 두 헤더에 테마별로 같은 반투명 배경 재질과 blur를 적용한다. 표의 현재 외관을 기준으로 색과 알파를 정하고 행이 비치지 않는 고정 제목에서도 배경 면이 읽히게 한다. 투명도는 글자에 적용하지 않는다. 공통 달력 스타일에 영향이 가지 않게 NodeRail에 한정한다. 다크·라이트, 스크롤 전후, 빈 목록·긴 목록에서 두 헤더의 실제 화면과 고정 위치를 확인한다. ## 인수 시나리오

| 조건 | 구현 후 확인할 결과 |
| --- | --- |
| Windows nvm 1.1.11·1.2.2·2.0.1, 공식 미러, 유효한 주소·포트 프록시 | 프록시만으로 충돌이 발생하지 않는다. 다른 설치 조건도 충족하면 기존 nvm으로 설치하고 설치된 목록에서 결과를 재확인한다. |
| Windows 인증정보 포함 프록시 또는 비공식 미러 | 원인별 안내가 구분된다. 프록시 주소나 자격 증명을 출력하지 않는다. |
| WSL2에서 서로 다른 프록시를 쓰는 두 배포판 | 선택한 배포판 기본 사용자의 기존 설정과 예외 목록을 따른다. 이전에 선택한 배포판의 프록시가 다음 작업에 적용되지 않는다. |
| Home 또는 NodeRail에서 설치·사용 시작 | NodeRail 두 목록 위에 레이어 하나가 표시된다. 완료·실패·종료 불명, WSL 취소 가능 여부가 실제 작업 상태와 일치한다. |
| 다크·라이트에서 공식 목록과 설치 목록을 독립 스크롤 | 두 고정 헤더의 배경 농도와 글자 가독성을 실제 화면으로 비교한다. |
