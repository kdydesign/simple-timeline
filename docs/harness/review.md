## 현재 상태

Codex의 진입점은 루트 `AGENTS.md`, 단계별 결정과 인수인계는 `docs/wayfinder/`에 있다.

## 확인과 수정

| 관점 | 발견한 문제 | 조치 |
| --- | --- | --- |
| 다음 세션의 문맥 | 완료 티켓이 지도에 없어도 검사기가 성공해 결정의 진입점을 놓칠 수 있었다. | 완료 티켓마다 지도 `Decisions so far`의 링크를 검사한다. 미완료·없는 티켓이 색인되면 오류다. |
| 단계 추적 | `open`에 assignee가 있으면 오류 없이 착수 가능한 목록에서도 사라졌다. | 미착수 티켓은 assignee를 `null`로 제한하고, 착수 시 티켓과 상태 표를 함께 갱신하도록 안내한다. |
| CI 피드백 | 깨끗한 체크아웃의 `git diff --check`는 이미 커밋된 공백 오류를 검사하지 않았다. | CI는 최근 커밋과 부모 간 차이를 검사하고 merge 커밋의 부모도 확인한다. |

완료 지도 누락과 미착수 claim은 실패 테스트로 재현한 후 수정했다.
임시 Git 저장소에서 공백 오류를 커밋해 CI와 같은 Git 명령이 오류를 발견하는지도 확인했다.

## 보장 범위와 후속 작업

- 검사 성공은 **문서 구조와 참조의 일관성**을 뜻한다. 실제 사용자 승인, 인수인계의 충실도,
  플러그인 실행, 제품의 품질을 자동으로 증명하지 않는다.
- 각 채팅이 이전 대화를 기억한다고 가정하지 않는다. 작업 종료 시 근거와 미해결 사항을
  인수인계에 남기고, 다음 채팅이 읽을 수 있는 원격 커밋의 반영 결과를 확인한다.
- 제품 코드가 도입되면 스테이지 4~5에서 실행·테스트·빌드 명령을 확정하고 CI에 연결한다.
  SQLite 데이터 보존과 IPC 경계는 실제 구조가 생긴 뒤 자동 검증한다.
- 간트·달력의 시각적 정확성, 설치형 앱 실행, 오프라인 동작은 별도 검증 경로가 필요하다.
  지금의 Windows CI는 문서 검사기의 Windows 호환성만 확인한다.
- Codex 계정의 프로젝트 생성이나 환경 등록은 저장소 변경과 별개다.

## 실행 흐름 재점검

앞선 수정은 문서의 구조적 일관성에 집중했다. 그러나 새 세션에서 필요한 문서를 찾는 일,
검사 명령을 빠짐없이 실행하는 일, 결과를 다음 세션에 전달하는 일은 여전히 수동이었다.
또한 closed 단계의 인수인계는 파일 존재만 검사해 빈 파일로도 다음 단계가 열렸다.

다음 실행 경로를 추가했다.

1. `node scripts/harness/run.mjs context`: 진행 중인 단계 재개를 우선하고,
   담당자·승인 대기 상태·선행 인수인계와 읽을 문서를 출력한다. 차단 단계 요청은 거부한다.
2. `node scripts/harness/run.mjs verify`: 로컬·CI에서 같은 검사를 실행하고
   Git 커밋·작업 트리·OS·Node 버전과 검사별 결과를 JSON 및 로그에 남긴다.
3. 성공·실패 양쪽의 보고서를 CI artifact로 보존한다. 증거의 저장 위치와 보관 기간은
   [검증 안내](validation.md)를 기준으로 한다.
4. 완료 인수인계에 결과·승인 사항·산출물 링크·검증·다음 작업이 채워져 있는지 확인한다.
   이 구조 검사가 사용자 승인이나 결과의 진실성을 대신하지는 않는다.

새 세션·차단 단계·중단 단계 재개·선행 인수인계·빈 완료 문서에 대한 회귀 검증을 추가했다.
임시 저장소에서 고의로 테스트를 실패시켜 비정상 종료와 실패 보고서 보존도 확인했다.
개별 PASS 이벤트 대신 최종 테스트 요약으로 판정해 뒤늦은 비동기 오류와 전부 skip된 실행을 거부한다.
새 실행 시작 때 이전 latest 보고서를 미완료 상태로 바꿔 중단 시 과거 성공을 재사용하지 않도록 했다.

검증 근거: 회귀 테스트 22개와 통합 verify를 실행했다. 별도 임시 저장소에서 정상·assertion 실패·
뒤늦은 예외·모두 skip인 네 실행의 종료 코드와 JSON 판정이 일치함을 확인하고,
실패 로그에 원인 메시지가 남는 것을 확인했다. 실행을 강제 중단한 경우 latest가 running/false로 남았다.
중단·테스트 오류 재현은 실제 프로젝트의 소스나 단계 상태를 변경하지 않는 복사본에서 수행했다.
제품 코드는 추가하지 않았고 스테이지 1은 계속 미착수다.
