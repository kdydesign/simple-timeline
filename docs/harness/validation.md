# 검증 안내

## 현재 실행할 검사

| 명령 | 검사 범위 |
| --- | --- |
| `node scripts/harness/check.mjs` | 필수 진입 문서, Markdown 파일 상대 링크, 스테이지 메타데이터·선행 관계·완료 인수인계 |
| `node --test scripts/harness/check.test.mjs` | 검사기가 끊어진 링크·잘못된 단계 상태를 실제로 거부하는지 확인 |
| `git diff --check` | 미커밋 변경의 공백 오류 |

체커는 실패 시 파일과 문제를 출력하고 종료 코드 1을 반환한다.
읽기 전용이며 날짜·상태·승인 내용을 자동으로 수정하지 않는다.
착수 가능한 스테이지도 출력하지만 사용자 승인이나 실제 작업 결과를 대신 판단하지 않는다.

## 한계

- Markdown의 인라인 링크 중 로컬 파일 대상만 검사한다. 코드 블록·인라인 코드의 예시,
  URL·앵커·참조형 링크·HTML 링크와 외부 사이트의 유효성은 검사하지 않는다.
- 티켓 메타데이터와 완료 인수인계 파일의 존재는 검사하지만 사용자의 실제 승인·검증의 진실성은 판단하지 않는다.
- 티켓 메타데이터는 문서 시작부터 첫 `##` 제목 이전에 둔다. 중복 필드는 오류다.
- STATUS 표와 티켓의 open/in_progress/closed 상태도 대조한다. 상세 문장의 의미는 사람이 검토한다.
- 현재 하네스 검사는 Electron 실행·SQLite 동작·UI·보안·Windows 설치 테스트가 아니다.

앱 명령이 도입되면 이 문서·AGENTS.md·CI를 같은 변경에서 갱신한다.
실제 Windows 검증 대기는 해당 스테이지를 완료하지 않고 차단 사유로 남긴다.
