## 환경과 요청 인증

**환경**에는 변수와 로그인 방법을 저장한다. **이 요청의 인증**은 선택한 환경의 토큰을 이 요청에 붙일지를 결정한다. **실행 환경**은 왼쪽 작업 패널에서 선택한 환경이다. **토큰**은 로그인 성공 후 메인 프로세스의 메모리에 보관하는 값이다.

- **협의 완료**. 새 요청은 인증 없이 시작한다. 그룹명 / 요청명 행의 요청명 바로 오른쪽에 항상 ‘인증 없음’ 또는 ‘환경 로그인 사용’을 표시한다. 누르면 인증 탭으로 이동한다. 인증 탭에는 두 선택지와 효과를 표시한다. 직접 헤더에 입력한 인증값은 ‘인증 없음’에서도 보낼 수 있다. 기존 요청의 선택과 ‘변경 저장’ 동작을 유지한다.
- 환경 관리에는 넓은 2단 창을 사용한다. 왼쪽 목록 위에 ‘환경 추가’, 오른쪽 상단에는 항상 편집 가능한 환경 이름을 둔다. 변수와 로그인 설정은 탭으로 나눈다. 그룹·요청 등 다른 팝업은 기존 크기를 사용한다. **대안**은 기존 340px 팝업에서 환경 선택과 편집을 별도 단계로 나누는 방식이다. 작은 화면에서는 좁은 창이 잘 맞지만, 로그인 본문과 API 주소를 함께 대조하기에는 편집 폭이 부족하다.
- 목록에서 고른 환경은 편집 대상이다. 선택만으로 작업 화면·Home의 실행 환경을 바꾸거나 네트워크 요청을 보내지 않는다. 이름 변경 시 같은 환경 ID와 요청을 유지한다. 최초 환경 생성 후에는 새 환경으로 바로 보낼 수 있다. 현재 실행 환경을 삭제하면 남은 유효한 환경을 표시하고, 마지막 환경을 삭제하면 ‘환경 없음’ 상태를 표시한다.
- ‘변수’에서 이름·값·휴지통 구성은 유지하고, 추가 ＋를 **마지막 행 아래 우측**에 놓는다. 누르면 새 행의 이름으로 포커스를 옮긴다. 중복 이름, 빈 이름, 예약어 오류는 해당 행에 표시한다.
- ‘로그인 설정’ 첫 묶음은 **로그인 요청**이다. 로그인 URL(POST), 여러 줄을 편집할 수 있는 JSON 본문, 보호 비밀번호, ‘이 PC에 저장’을 둔다. 두 번째는 **발급 토큰 사용**이다. 응답에서 값을 꺼낼 경로와 토큰을 받을 API 주소를 나란히 표시한다. 헤더 이름·접두어와 사용자 지정 로그인 헤더는 ‘고급 헤더 설정’에 둔다. 빈 값과 기본값을 구분한다. 접두어 끝의 공백을 보존한다. JSON 오류와 미등록 변수는 해당 필드에서 찾을 수 있도록 한다.
- 인증 설정이 없는 환경도 변수만으로 저장·전송할 수 있다. 환경 로그인 방식이 선택됐지만 설정이 부족한 요청에는 빠진 항목과 ‘환경 관리 열기’를 제공한다. 로그인 실패로 본 요청을 보내기 전에 중지된 경우와 본 요청이 서버로부터 401을 받은 경우를 구분한다.
- 환경 삭제는 대상을 명시하고 확인을 받는다. 편집을 취소하면 초안을 폐기한다. 하단 ‘저장’은 이 창에서 변경한 모든 환경의 추가·수정·삭제를 한 번에 적용한다. 입력 검증이나 저장에 실패하면 일부만 반영하지 않고 초안을 유지해 수정할 수 있게 한다. 실행 환경이 계속 존재하면 같은 ID를 유지한다. 미저장 변경을 닫을 때는 변경된 환경을 알리고 폐기 여부를 확인한다. 비밀번호·토큰을 로그 또는 미리보기에 노출하지 않는다.
- 현재 ‘로그아웃’은 인증 서버에 요청을 보내는 동작이 아니다. 제품은 해당 환경의 토큰을 폐기하며 실행 중인 해당 환경의 인증 반복은 현재 회차 후 중지한다. ‘저장된 토큰 비우기’는 편집 중인 환경에 유효한 토큰이 있을 때만 표시한다. 확인하면 그 환경의 세션에 즉시 적용한다. 이후 편집을 취소해도 비운 토큰을 복원하지 않는다. 다른 환경의 토큰은 계속 사용할 수 있다. 활성 반복에 미치는 영향도 확인창에 표시한다. 이후 인증 요청에서 다시 로그인한다. 자동 만료·401 처리와 환경별 토큰 재사용은 기존 계약을 따른다.

## 작업 화면

| 항목 | 화면과 동작 |
|---|---|
| 1. 응답 | 상태·회차·소요 시간은 상단에서 한 번 읽는다. 본문은 첫 문자부터 응답 데이터로 시작한다. JSON은 두 칸 들여쓰기, 긴 문자열은 자동 줄바꿈 없이 가로 스크롤, 세로는 패널 안에서 스크롤한다. 본문 수신 중단, 시간 초과, 빈 응답은 상태에서 설명한다. |
| 2. 드롭다운 | 환경·HTTP 메서드 모두 PlanRail 일정 추가의 ‘소속 프로젝트’ 선택 컨트롤을 기준으로 트리거·메뉴·선택 항목·키보드 동작을 맞춘다. 각 컨트롤의 현재 높이와 폭을 유지한다. GET 녹색, POST 황색, DELETE 적색을 선택값과 옵션에 유지한다. |
| 3. 변수 표기 | URL, 요청 헤더·본문, 로그인 URL·헤더·본문, 토큰 수신 API 주소 등 템플릿을 지원하는 입력란에서 `${BASE_URL}` 참조 전체를 연한 적색으로 표시한다. 미등록 변수에는 오류 문구를 함께 제공한다. 예약 변수는 유효한 위치에서만 사용한다. 입력·복사·선택·IME·스크롤 시 원문을 보존한다. 서버에서 받은 문자열은 템플릿으로 해석하지 않는다. |
| 4. 포커스 | URL·요청 헤더·회차별 결과 버튼 및 로그를 마우스로 선택해도 추가 테두리가 생기지 않는다. 편집 커서와 텍스트 선택을 유지한다. 키보드 탐색에는 대비가 확보된 포커스 표시를 제공한다. |
| 5. 요청 인증 | 요청명 오른쪽 배지와 ‘이 요청의 인증’ 선택을 연결한다. 첫 로그인·재사용·인증 미설정을 구분한다. |
| 6. 즐겨찾기 | 선택한 별의 내부만 금색으로 채운다. 버튼 외곽선과 배경은 바뀌지 않는다. 스크린리더에는 눌림 상태를 제공한다. |
| 7. 그룹 추가 | 공통 스타일의 작은 팝업에서 ‘그룹 이름’과 이름 입력란을 한 줄에 배치한다. 오류가 있으면 입력란 아래에 표시한다. |
| 8. 그룹 간 이동 | 모든 메서드의 요청 행을 펼친 그룹·접힌 그룹·미분류에 드롭할 수 있다. 대상만 강조하고, 성공하면 같은 요청을 목적 그룹에서 선택한다. 빈 미분류도 유효한 드롭 대상으로 제공한다. ID·즐겨찾기·다음 반복 번호·미저장 요청 본문을 보존한다. 저장 실패 시 원래 위치를 유지한다. 키보드에서는 기존 ‘요청 수정 → 그룹’을 쓸 수 있다. |
| 9. 환경 관리 | 위의 환경·요청 인증 설계와 별도 시안을 따른다. |
| 10. console | footer 높이를 유지하고 ‘회차별 결과’ 옆의 `console`로 같은 위치에 연다. 둘 중 하나만 열린다. 회차 결과는 회차별 성공·상태·인덱스를 조회하고, console은 로그인 시작·발급/재사용·전송·응답·오류를 시간순 일반 텍스트로 기록한다. 에러는 빨간 글자와 ERROR로 구분한다. 요청명·환경명·메서드·회차·경과 시간·상태 코드만 사용하고, 전송 URL의 쿼리나 헤더·본문 값과 자격 정보는 담지 않는다. 자유 입력 실행창은 없다. 메인 프로세스의 앱 세션 전체에서 최근 1,000줄을 시간순으로 보관한다. 1,001번째 줄부터 가장 오래된 줄을 버린다. 메뉴·환경 전환과 트레이 숨김 동안 유지하고 완전 종료 후 다시 시작하면 빈 상태로 연다. 반복 실행 중에는 화면 갱신을 묶고, 위쪽을 읽는 중에는 자동으로 끝으로 이동하지 않는다. |
| 11. 요청/응답 분할 | URL 입력행과 footer를 뺀 편집 높이에서 처음 30%가 요청, 70%가 응답이다. 경계선을 위아래로 드래그한다. 키보드 화살표로 조절하고 더블클릭으로 기본 비율을 복원한다. 최소 높이를 보장하고 drawer를 열 때에도 입력 내용과 읽던 응답을 유지한다. 시안의 비율은 화면을 여는 동안 유지된다. |


## 헤더 입력과 응답 본문 도구

- **요청 헤더**는 기존 요청과 새 요청 모두 Key / Value 표로 연다. 쿼리 표처럼 사용 체크, 이름, 값, 행 추가·삭제를 제공한다. raw 탭에서는 한 줄에 `이름: 값`을 입력하고 첫 콜론만 구분자로 쓴다. 두 보기는 같은 헤더 초안을 편집한다. 사용 해제한 행은 raw와 전송에서 제외하고 표로 돌아오면 원래 순서에 복원한다. 유효하지 않은 줄이나 대소문자만 다른 중복 이름이 있으면 그 위치를 표시하고 초안을 유지한다. 해결한 뒤 저장·전송하거나 표로 돌아갈 수 있다. `Content-Type`은 본문 설정과 공유하며 금지 헤더·환경 인증 헤더 충돌에 대한 기존 검사를 유지한다.
- **응답 본문 편집**. 수신한 본문에 기존 비밀값 마스킹을 적용한 뒤 편집본을 연다. 완전한 JSON의 첫 화면은 두 칸 들여쓰기다. 일반 텍스트와 불완전한 JSON도 받은 형식에서 바로 편집할 수 있다. 편집은 해당 응답의 화면 초안에만 적용한다. 서버 응답 기록·회차별 결과·console은 수신 당시 값을 유지한다.
- **본문 툴바**. 제목 아래 한 줄에 ‘포맷 정렬’, ‘원문’, 복사 아이콘, 포함 검색을 둔다. ‘포맷 정렬’은 현재 입력한 JSON의 공백·들여쓰기만 정리한다. 키 순서·중복 키·큰 정수·문자열을 보존한다. 문법 오류면 입력한 텍스트를 유지하고 짧게 알린다. ‘원문’은 마스킹된 수신 내용을 읽기 전용으로 열고 ‘편집본’으로 돌아오면 수정 내용이 복원된다. 복사는 편집 중에는 수정된 전체 텍스트, 원문을 보는 중에는 그 원문 전체를 사용한다. 검색 강조·상태·응답 헤더는 복사에서 제외한다. 응답 헤더 탭을 오가도 같은 초안을 유지하고 새 응답이 도착하면 그 응답의 편집본으로 시작한다.
- **본문 검색**은 현재 표시한 본문에서 대소문자를 구분하지 않고 입력한 문자열 그대로 찾는다. 일치 위치를 강조하고 현재/전체 건수를 표시한다. Enter와 Shift+Enter로 다음·이전 결과를 순환한다. 검색 중에도 전체 본문을 유지한다. 빈 응답에서는 도구를 비활성화하고 긴 줄은 가로로 스크롤한다.
- **요청 제목**은 그룹명과 글자 크기를 맞추고 요청명만 굵게 표시한다. 인증 배지는 그 오른쪽에 놓고 누르면 요청 인증 탭을 연다.
- **왼쪽 목록** 상단은 요청 이름 검색과 우측 ＋ 메뉴가 한 줄이다. 검색 대상은 요청 이름 하나이며, 대소문자 구분 없는 부분 일치를 사용한다. 일치하는 요청이 속한 그룹을 임시로 펼치고 검색을 지우면 기존 접힘 상태를 복원한다. 결과가 없어도 오른쪽에서 편집 중인 요청·초안과 ＋ 메뉴를 유지한다.

## 요청 파라미터와 POST 본문

사용자는 쿼리·경로·POST 폼을 모두 입력하고, 서버에 맞춰 이름·값과 전송 타입을 지정하는 범위를 선택했다. 파일은 **같은 PC에서 선택한 위치를 기억하고 파일이 없으면 다시 선택**한다. 본문 타입과 MIME의 결합 방식은 아래와 같이 제안한다. 현재 제품은 URL에 직접 입력한 쿼리를 보내고 요청 본문으로 JSON 객체를 지원한다. 이 절은 후속 설계다.

### Postman에서 가져올 동작

Postman의 공식 Collection SDK는 URL의 쿼리 목록과 경로 변수를 분리하고, 본문을 raw·urlencoded·formdata·file 등으로 구분한다. 공식 Runtime은 raw의 언어에서 기본 Content-Type을 정하되 명시한 헤더를 우선하며, multipart의 각 파트에도 MIME을 지정할 수 있다. PostRail에서도 **전송 방식 선택**과 **실제 내용 직접 입력**을 분리한다. 예를 들어 XML은 raw를 선택해 본문을 입력하고 Content-Type을 `application/xml`로 지정한다. |---|---|---|
| 파라미터 → 쿼리 | `q = phone`, `limit = 10` | `GET /products/search?q=phone&limit=10` |
| 파라미터 → 경로 | URL `/products/:id`, `id = 1` | `GET /products/1` |

| 본문 → form-data | Text 파트 `title`, File 파트 `attachment` | 하나의 multipart 본문에 텍스트와 파일 바이트를 담는다. 같은 키의 파일도 여러 행으로 전송할 수 있다. |
| 본문 → raw / binary | XML 텍스트 / 파일 하나 | 직접 입력한 텍스트 또는 선택한 파일 자체를 본문으로 보낸다. |

- **쿼리**. GET·POST·DELETE 모두에서 URL과 같은 쿼리를 행으로 편집한다. 이름·값·사용 체크·행 추가와 삭제를 제공한다. 사용 해제한 행은 요청에 보관하고 실제 주소에서 제외한다. 기존 URL을 열 때 이름 중복·순서·빈 값과 변경하지 않은 인코딩을 보존한다. 같은 행을 URL과 표 양쪽에서 중복 전송하지 않는다. 환경 변수를 먼저 해당 값에 대입한 후 구성요소별로 인코딩한다. `A&B`, 공백, 리터럴 `+`, 한글이 하나의 값으로 도착하는지 검사한다. 기존 URL에서 구분자까지 포함하는 환경 변수를 사용한 경우, 편집 전후의 실제 주소가 조용히 바뀌지 않도록 기존 URL 전송을 보존한다.
- **경로**. URL의 한 경로 조각 전체가 `:id`이면 같은 이름의 값 입력란을 만든다. `${BASE_URL}`은 환경 변수다. `:id`의 값에 환경 변수를 쓸 수 있다. 한 값은 한 조각이 되도록 인코딩하며 값이 비면 전송 전에 해당 칸을 표시한다. URL의 호스트·포트·쿼리를 경로 변수로 해석하지 않는다. 기존에 문자 그대로 `:id`를 사용한 저장 요청은 명시적으로 경로 변수를 설정하기 전까지 기존 주소를 유지한다.
- **본문 방식**. POST는 없음·기존 JSON·이름/값 폼·multipart·raw·binary를 선택한다. 모드를 전환하면 그 모드의 초안을 복원하고 선택한 방식만 보낸다. GET은 본문 없이 동작하고 기존 DELETE의 JSON 편집을 유지한다. 이번 확장 대상은 일반 API 요청이다. 환경의 자동 로그인 본문은 기존 JSON 계약을 따른다.
- **Content-Type**. 본문 설정과 헤더 탭은 명시한 헤더 한 개를 공유한다. 직접 지정하지 않으면 전송 방식의 기본값을 사용한다. MIME 입력은 직렬화 방식을 바꾸지 않는다. 예를 들어 raw로 `application/vnd.team+json`을 보낼 수 있다. multipart의 외부 헤더는 실제 바디와 같은 boundary를 전송기가 생성한다. 사용자가 다른 형식이나 boundary를 명시해서 충돌하면 전송 전 설명하고 자동값 복원 또는 raw 전환을 안내한다. 각 파트의 이름·값·Text/File·MIME은 직접 지정할 수 있다.
- **파일**. OS 파일 선택으로 받은 원본 경로는 메인 프로세스에서 이 PC의 요청과 연결하고, 화면에는 파일 이름을 표시한다. 저장 후 재실행하면 같은 위치의 파일을 사용한다. 파일이 없거나 읽을 수 없으면 로그인·인덱스 예약·API 호출 전에 해당 행에서 다시 선택하도록 한다. 임의의 경로 텍스트나 환경 변수에서 파일을 열지 않는다. 전송·반복·Home 즐겨찾기에서 같은 검증을 사용한다. 파일 내용·전체 경로·쿼리값은 console에 기록하지 않는다.
- **호환 및 검증**. URL·JSON으로 저장한 기존 요청은 이전 동작으로 열린다. 저장·복제·Home 실행 시 선택 모드, 파라미터와 사용 여부를 보존한다. 인덱스는 기존 JSON 문자열의 `${index}`에서만 소비한다. 일반 반복 전송은 새 본문 방식에서도 명시한 횟수를 따른다. 토큰을 보낼 수 있는 origin, URL에 넣을 수 없는 보호 변수와 비밀 키 검사는 파라미터가 모두 반영된 실제 주소에도 적용한다. 같은 PC에서 파일이 사라진 경우, 한 요청에서 같은 이름의 파일 파트 둘, 폼 값이 URL에 섞이지 않는 경우, 직접 지정한 MIME과 생성된 multipart boundary가 일치하는 경우를 인수 검사에 포함한다.

## 인수 시나리오

1. 서로 다른 두 환경에서 토큰을 발급받고, 실행 환경과 다른 쪽을 편집한다. 비우기를 취소하면 두 토큰이 유지된다. 확인하고 창을 닫으면 편집한 환경에서만 버튼이 사라진다. 그 환경의 다음 인증 요청은 새로 로그인하고 다른 쪽은 기존 토큰을 재사용한다.
2. Home과 PostRail에서 실행한 요청의 로그를 합쳐 1,001줄을 만든다. console에는 마지막 1,000줄만 남고 회차별 결과의 기존 페이지는 그대로 조회된다. 트레이에 숨겼다가 복원한 뒤에는 로그가 남고 WorkRail을 완전히 종료해 다시 열면 0줄이다.
3. 새 GET은 요청명 오른쪽에 ‘인증 없음’을 표시한다. 환경 로그인을 켜서 저장한 기존 GET을 다시 열면 ‘환경 로그인 사용’을 표시한다. 환경 관리에서 다른 환경을 열어 이름·로그인 설정을 편집하는 동안 두 요청의 인증 선택은 보존된다.
4. 기존 헤더를 표로 열고 한 행을 끈다. raw에서 `X-Note: a:b`를 추가한 뒤 표로 돌아오면 값은 `a:b`이고 끈 행은 여전히 꺼져 있다. raw에 중복 이름을 넣으면 오류 줄을 수정할 수 있다.
5. 응답의 값을 수정하고 검색한 뒤 복사하면 수정된 전체 본문이 복사된다. ‘포맷 정렬’ 전후 모두 큰 정수와 중복 키가 보존된다. 닫는 괄호를 지워 정렬하면 오류를 표시하고 수정·복사가 가능하다. ‘원문’에서 수신값을 확인하고 ‘편집본’으로 돌아오면 입력한 내용이 남는다. 다시 보내 새 응답을 받으면 새 편집본을 연다.
6. 그룹명이나 URL에만 있는 단어를 입력하면 결과가 없다. 요청명의 일부를 입력하면 해당 행만 보이고 필터를 지우면 이전 그룹 상태와 요청 초안이 유지된다.

## 구현 전 확인할 계약

- JSON의 표시 형식을 정리할 때 키 순서·중복 키·큰 정수·숫자 표기와 문자열 자체를 보존한다. 기존 마스킹을 거친 응답의 표시 복사본만 다룬다. 단순 객체 역직렬화 후 재직렬화하면 이 값들이 바뀔 수 있다. 잘린 JSON, 일반 텍스트·HTML과 본문 수신 중단은 받은 그대로 보여 준다. 대형 본문은 주 UI를 멈추지 않도록 기존 65,536 UTF-16 단위 구문 강조 제한과 별도로 포맷 비용을 제한한다.
- console에 전체 본문이나 서버의 임의 문자열을 그대로 넣지 않는다. 자격 정보가 없는 고정 이벤트로 구성한다. 실패 원인은 ‘로그인 HTTP 401, 본 요청 미전송’, ‘인증 없이 전송한 본 요청 HTTP 401’, ‘환경 토큰을 붙인 본 요청 HTTP 401, 캐시 폐기’로 구별한다. 사용자가 선택한 실행 환경을 중간에 바꿔도 로그의 요청·환경은 실행 당시의 값이다.
- 401 → 요청 인증 켜기 → 로그인 성공 → GET 성공 → 같은 환경에서 두 번째 요청의 토큰 재사용을 검증한다. 64비트 ID·불완전 JSON·긴 한 줄·빈 204, 접힌 그룹으로 이동 및 취소, 작은 창·150% 배율·키보드·한글 입력을 검증한다.
- HTML은 동작을 비교하기 위한 예시다. 보내기·토큰·로그는 모의 데이터이며 데이터는 탭 안에서만 유지한다. [console 예시](../../design/mockups/postrail-editor/console.png) · [그룹 추가](../../design/mockups/postrail-editor/group.png) · [메서드 선택](../../design/mockups/postrail-editor/method.png)
