# Simple Timeline — 전체 설계 기준

작성일: 2026-11-03. 스테이지 0 초안에서 시작한 전체 요구사항 인덱스다.
세부 규칙은 아래 연결된 승인 설계를 따른다. 현재 MVP는 기본 설치 인수 범위로 완료됐으며,
구현·검증의 근거는 [현재 상태](../../wayfinder/STATUS.md)와 [사용자 인수 기록](../../release/user-acceptance.md)을 따른다.

## MVP 이후 승인된 변경

2026-11-04 [개선·오류 대응 확정 설계](../../design/post-mvp-improvements.md)에 테마·설치 완료 화면·
아이콘 선택 절차·시작 속도 목표·날짜 클릭/선택기·간트 계층·드래그·오늘 이동·토스트·고정 헤더를 확정했다.
해당 항목에서는 아래 MVP 요구와 제외 범위를 대체하며, 제품 구현과 검증 결과는 [실행 기록](../../implementation/2026-11-04-post-mvp-improvements.md)에서 구분한다.
원래 스테이지의 설계·계획·인수 기록은 당시 근거로 유지한다.

## 목적

정기 릴리즈, 핫픽스, 기타 프로젝트의 기간을 간트와 월간 달력으로 확인한다.
Windows에 설치해 인터넷 없이 실행·조회·편집·저장하는 개인용 프로그램이 MVP다.

## 사용자가 확정한 사항

- Electron + React + SQLite를 사용한다.
- Windows 설치형 프로그램을 먼저 만든다. 모바일은 지원 범위에서 제외한다.
- 기본 기능은 오프라인으로 동작해야 한다. 사용자 간 공유는 없다.
- Microsoft Teams 앱 등록은 낮은 우선순위의 후속 작업이다.
- 참여자는 우선 이름 목록이다. Microsoft 계정 연동은 추후 검토한다.
- 프로젝트에 일정이 없어도 표시한다. 일정은 반드시 한 프로젝트에 속한다.
- 프로젝트 삭제 시 소속 일정도 함께 삭제하며, 삭제 전 확인을 제공한다.
- 일정 간 기간 중복을 허용하고 단계 순서·의존성을 강제하지 않는다.
- 같은 날 시작·종료하는 일정은 하루짜리 일정이다.
- 간트는 전체 일정의 가장 이른 시작 월부터 가장 늦은 종료 월까지 표시한다.
  예: 2026-11-01~2026-12-22이면 11월·12월 전체가 표시된다.
- 달력은 월별이다. 두 모드는 같은 데이터를 사용하고 선택한 연월을 유지한다.
- 다시 실행해도 데이터가 유지되어야 한다.

## 검토한 접근 방식

| 방식 | 이점 | 비용 및 선택 |
| --- | --- | --- |
| 브라우저 + LocalStorage | 빠른 단일 브라우저 시제품 | Windows 설치형이라는 사용 목적에 부합하지 않아 제외 |
| Electron + React + SQLite | UI 구현 생태계와 향후 Teams 화면 재사용 가능성 | 실행 자원·패키지 크기가 커질 수 있음. 사용자 선택 |
| Tauri + React + SQLite | 비교적 작은 패키지 | Rust·Windows 빌드 도구 관리가 추가됨. 미선택 |

## 기능과 데이터

프로젝트: `id`, `name`, `color`, `participants`, `createdAt`, `updatedAt`.
일정: `id`, `projectId`, `name`, `startDate`, `endDate`, `createdAt`, `updatedAt`.
프로젝트명·색상, 일정명·시작일·종료일은 필수이며 색상 기본값을 제공한다.
참여자는 선택이다. 업무 날짜는 `YYYY-MM-DD`로 관리한다.

프로젝트와 일정 각각의 추가·조회·수정·삭제, 프로젝트별 일정 조회가 필요하다.
기간 막대와 달력 일정을 클릭하면 상세·수정 화면을 연다.
수정·삭제의 성공은 실제 저장 성공 후 화면 상태에 반영한다.
읽기·쓰기 실패를 빈 데이터나 성공으로 표현하지 않는다.

## 화면의 기능적 계약 — 스테이지 3 승인 설계 참조

화면·폼·탐색·키보드·빈 상태·실패 처리는 [화면 설계](../../design/experience.md),
간트 좌표·긴 범위·달력 주 경계·겹침과 사례는 [시각화 설계](../../design/visualization.md)를 따른다.
[설계용 목업](../../design/mockups/stage-03.html)은 시각 자료이며 제품 코드로 재사용하지 않는다.

## 기술 경계 — 스테이지 2 승인 설계 참조

프로세스 책임·제한된 IPC·오류 계약은 [승인된 구조 설계](../../design/architecture.md),
드라이버·스키마·수명주기·백업 제외 선택은 [승인된 저장 설계](../../design/storage.md)를 따른다.
아래 UI 재사용 방향은 향후 가능성이며 서버·Teams 구현 승인이 아니다.

업무 날짜 계산은 시간대에 따라 하루가 이동하지 않도록 date-only 규칙으로 분리한다.
생성·수정 시각은 업무 날짜와 별개다. 스테이지 1의 날짜·정렬·입력·조회 규칙은
[도메인·날짜 규칙](../../design/domain-rules.md)을 따른다. 해당 문서에 사용자 답변과 문서 승인 상태를 기록한다.
날짜 계산·간트 배치·달력 구간 분할은 UI 및 Electron과 독립적인 함수로 설계한다.

React 화면은 승인된 저장 인터페이스를 통해 데이터를 사용한다.
향후 Teams에서 UI 일부를 재사용할 여지는 두되, 지금 서버·인증·동기화 계층을 구현하지 않는다.
Teams는 Windows 설치 파일을 업로드해 실행하는 방식이 아니며 로컬 DB 접근도 자동 제공되지 않는다.

## 후속 스테이지에 맡기는 결정

- 스테이지 1: [도메인·날짜 규칙](../../design/domain-rules.md)에 정리. 이 목록을 미결정으로 재질문하지 않는다.
- 스테이지 2: [구조](../../design/architecture.md)·[저장](../../design/storage.md) 설계로 확정. 이 목록을 미결정으로 재질문하지 않는다.
- 스테이지 3: [화면](../../design/experience.md)·[시각화](../../design/visualization.md) 설계로 확정. 이 목록을 미결정으로 재질문하지 않는다.
- 스테이지 4: [승인 구현 계획](../plans/2026-11-03-simple-timeline-implementation.md)에 파일·의존성·검증·구현 순서를 확정했다.
- 스테이지 7: Windows 지원 버전·CPU 아키텍처, 설치 방식, 서명·배포 조건과 실제 검증.
  MVP에서는 자동 업데이트·원격 업데이트 확인을 기본 요구사항으로 넣지 않는다.

세부 라이브러리 버전과 패키징 도구의 승인 기준은 [구현 계획](../plans/2026-11-03-simple-timeline-implementation.md)을 따른다.
문서상 버전 조합 검토는 실제 설치·빌드 호환성 검증을 대신하지 않는다.
구현 담당자가 관례적인 내부 코드 스타일·함수명 등 되돌리기 쉬운 사항은 판단할 수 있다.
기능 범위·데이터 소실 가능성·사용 환경에 영향을 주는 변경은 사용자와 확정한다.

## 기존 MVP의 범위 밖

드래그 편집과 성공 토스트는 위 후속 설계에서 추가 승인했다. 나머지 제외 범위는 유지한다.

작업 계층, 진행률, 의존성, 지연 분석, 리소스 분석, 드래그 편집,
복잡한 권한·승인, 알림, 자동화, 외부 이슈 연동, 로그인, 사용자 간 공유,
Teams 구현과 PC 간 동기화, 모바일.

## 검증과 완료 기준

1. `1.1.1 핫픽스` 프로젝트의 색상·참여자를 설정한다.
2. 개발 2026-11-11~12-11, QA 12-12~12-17, 운영 배포 12-18 일정을 만든다.
3. 간트에 11월·12월이 표시되고 각 일정 위치·기간이 정확하다.
4. 달력으로 전환해 같은 일정과 색상을 확인한다.
5. 일정을 수정하면 두 모드에 반영된다.
6. 개별 일정 삭제와 확인 후 프로젝트·하위 일정 일괄 삭제가 동작한다.
7. 프로그램을 종료하고 재실행해 저장된 데이터가 유지된다.
8. 네트워크를 끊은 Windows 설치본에서도 위 기능이 동작한다.

날짜 경계·윤년·일일 일정·겹친 일정·프로젝트 삭제 트랜잭션은 자동 검증 대상으로 삼는다.
클라우드에서 가능한 검증과 Windows 설치본 실행 검증을 구분한다.
클라우드 빌드 성공만으로 Windows 설치·실행·오프라인·데이터 보존 성공을 선언하지 않는다.

### 2026-11-04 MVP 사용자 인수 범위 조정

위 제품 동작 요구는 유지한다. 스테이지 7에서 실제 Windows Server 설치 lifecycle 자동 검증을 통과했고,
사용자는 각 설치본 해시·설치/실행·업데이트·제거/재설치와 데이터 보존을 확인했다.
사용자가 기본 설치 관련 검증으로 이번 MVP를 마무리하고 상세 개선·오류 사항은 별도로 진행한다고 밝혔다.
이에 따라 사용자 PC의 오프라인 전체 시나리오·배율/Narrator·물리 오류 경로 등은 미확인/미실행인 후속 항목으로 남긴다.
기본 설치 인수를 전체 상세 검증의 통과로 간주하지 않는다. 근거와 경계는 [사용자 인수 기록](../../release/user-acceptance.md)을 따른다.
