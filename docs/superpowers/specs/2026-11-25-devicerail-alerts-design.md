# DeviceRail 장비 이상 알림

WorkRail 1.2.0 · 승인 설계. 장비를 등록하거나 수정하는 사람이 해당 PC에서 받을 Windows 알림을 선택한다. 기존 [장비 상태 검사](../../design/device-monitor.md)를 사용한다.

## 합의한 동작

- 장비별 스위치 하나로 SSH와 설정된 제품 서비스의 이상 알림을 켠다. 제품 서비스 미설정 장비는 SSH만 대상이다.
- 같은 항목이 두 번 연속 실패하면 알린다. 같은 항목의 실패가 계속되면 한 번만 알리고, 정상 결과를 받은 항목은 다시 두 번 연속 실패해야 새로 알린다.
- 같은 장비의 SSH와 제품 서비스가 같은 검사 회차에 기준에 도달하면 한 건에 묶는다. 먼저 SSH 장애를 알린 뒤 다른 회차에서 서비스가 기준에 도달하면 제품 서비스 장애를 별도로 한 번 알린다.

SSH만 보거나 항목별 스위치를 두는 안도 검토했다. 한 스위치로 장비를 등록하고 두 검사 결과는 각각 판정하는 안을 선택했다. 첫 실패에 바로 보내는 방식보다 한 회차 늦게 통지해 일시적인 단절을 거른다.

## 등록·수정 화면

장비 등록·수정 창의 제품 서비스 설정 아래에 ‘알림’ 영역을 두고, 종 아이콘·스위치·‘장비 이상 알림’ 레이블을 한 줄에 놓는다. [PlanRail 일정 알림](../../../src/renderer/components/ReminderFields.tsx)의 아이콘, 스위치, 간격, 키보드 포커스를 재사용한다. Home 즐겨찾기는 독립 설정이다. 새 장비와 기존 저장 레코드의 기본값은 꺼짐이다. 저장해야 적용되고 취소하면 기존 설정을 유지한다.

## 발송과 무음

검사가 실제로 완료될 때 메인 프로세스에서 판정한다. 등록한 장비 하나의 한 회차에서 수행하는 검사가 끝나면 새로 기준에 도달한 항목을 모아 Windows 알림을 보낸다. 리렌더링이나 진행 중인 검사를 공유한 재검사 요청으로 같은 결과를 두 번 세지 않는다. 다른 장비의 응답은 기다리지 않는다. 창이 트레이에 있어도 같은 기준을 쓴다.

알림 제목은 ‘장비 이름 · 장비 이상’, 본문은 ‘제품 서비스 · HTTP 503’처럼 새로 실패 기준에 도달한 항목과 원인을 표시한다. 화면의 상태는 첫 검사 결과부터 갱신한다. 정상 복구는 화면에 반영한다. 트레이의 ‘전체 알림 끄기’를 적용하되 상태 검사는 계속한다. 무음을 풀었을 때 이미 복구된 장애는 건너뛰고, 계속 실패 중인 미통지 장애만 다음 검사에서 알린다.

알림을 보낸 항목은 앱을 다시 열어도 같은 장애로 반복 통지하지 않도록 장비와 검사 대상별로 기억한다. 절전으로 취소된 검사와 변경 전 주소에서 도착한 결과는 실패 횟수에 포함하지 않는다. 장비 알림을 끄거나 검사 대상을 변경하면 해당 알림 판정을 초기화한다.

## 확인할 사례

| 검사 순서 | 기대 결과 |
| --- | --- |
| SSH 한 번 실패 → 정상 | 알림 0건 |
| SSH 한 번 실패 → 다음 회차는 서비스만 실패 | 알림 0건 |
| 두 항목 모두 두 회차 연속 실패 → 같은 장애 지속 | 두 항목을 적은 알림 1건 |
| SSH 장애 알림 후 서비스도 두 번 연속 실패 | 서비스 알림 1건 추가 |
| SSH는 계속 실패, 서비스는 복구 후 다시 두 번 연속 실패 | 서비스 알림만 1건 추가 |
| 무음 중 장애 발생 후 복구 → 무음 해제 | 알림 0건 |
| 장애 통지 후 앱 재시작 → 같은 항목 계속 실패 | 중복 알림 0건 |
| 기존 장비 열기, 설정 변경 후 취소, 트레이 검사 | 꺼짐 기본값·기존 저장값·백그라운드 판정 확인 |
