# NodeRail 사내 프록시와 작업 레이어 구현 계획

[승인 설계와 화면 A](../../design/noderail-proxy-and-loading.md)를 기준으로 기존 Windows 설치 검사, WSL 기본 사용자 로그인 환경, Home·NodeRail에서 공유하는 작업 상태를 사용한다.

| 작업 | 구현 위치 | 확인 기준 |
| --- | --- | --- |
| Windows 설치 | discovery 및 modern-manager에서 인증정보 없는 HTTP(S) 프록시와 미러를 각각 검사한다. | 실제 nvm 설정 형식, 오류 안내의 값 비노출, 미러·TLS 제한 및 기존 버전 사용 |
| WSL 설치 | WSL 실행기와 서비스의 환경 전달·출력 저장 경로를 점검한다. | 배포판별 프록시·예외 상속, Windows 설정 미복사, 자격정보가 저장 로그와 화면에 기록되지 않음 |
| Node 작업 | NodeScreen에 두 목록을 덮는 레이어 A를 연결하고 Home의 작업 표시를 재사용한다. | 이전 목록·스크롤 유지, 중복 입력 방지, 작업 종료·불명·오류, WSL 취소와 로그 |
| 목록 헤더 | NodeRail 테마에 색·알파·블러를 지정한다. | 다크와 라이트의 두 헤더가 실제 반투명 배경을 공유하고 독립 스크롤, 다른 달력과 메뉴 간격 유지 |
| 통합 | 집중 회귀 검사 후 일회성 프로필로 전체 앱과 하네스를 검증하고 사용 안내에 반영한다. | 검증 SHA·운영체제와 실제 사내망 인수 범위를 구분한다. |
