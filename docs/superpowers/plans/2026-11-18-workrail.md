# WorkRail Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for the independent backend and UI tasks, with review gates. Parent coordinates integration and validation.

**Goal:** Deliver the approved WorkRail shell, integrated home, preserved Planrail module and usable nvm-windows manager.
**Architecture:** Existing Electron main/preload security boundaries remain. Node management is a separate typed capability and service; React shell retains Planrail state across navigation.
**Tech Stack:** Electron, React, TypeScript, SQLite, existing CSS, nvm-windows.
**Spec:** [WorkRail design](../../design/team-tool-expansion.md)

## Global Constraints

- Preserve existing dark grey / steel blue glass styling and Planrail data/sharing/reminders.
- WorkRail title, bottom dock D, Node list A, home B, W rail icon A.
- Keep appId/profile/DB/updater identities compatible. Never expose arbitrary shell commands or filesystem paths to renderer.
- Only user-triggered official installer and version operations; per-operation elevation, never whole-app elevation; Windows x64 support.
- No push, deployment, destructive profile changes, or real nvm operations in automated tests.

## Review Focus

- Invalid IPC sender, shell injection, malicious catalog/version/mirror input: refuse before process launch.
- Missing/conflicting Node, UAC cancellation, child exit failure, offline catalog: actionable errors without false success.
- App exit/update during operation: do not strand operation or report clean readiness.
- Hidden Planrail editor and ongoing sharing/reminders: preserve state and notification navigation.
- Existing installation/profile/update compatibility and small icon readability.

## Task 1: Node service and secure IPC

Files: create src/shared/node-management.ts, src/main/node-management/*; integrate preload/global and bootstrap. Tests: tests/unit/node-management.test.ts and IPC tests.
Interfaces: typed NodeManagementApi with getState(), refreshCatalog(), install(version), use(version), installManager(), onChange(callback). Node state includes platform/support, manager status, active/installed/catalog, busy/error/conflicts and checked time. Renderer passes versions only.
