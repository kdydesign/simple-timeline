# WorkRail 화면 피드백 구현 계획

[승인 설계](../../design/workrail-log-home-termrail-help.md)의 Q1~Q3과 마지막 아이콘·색상 선택을 기존 Electron, React, TypeScript 구조에 반영한다. 작업별 회귀 검사를 먼저 실행하고, 일회성 프로필을 사용하는 전체 앱 검사는 한 번에 하나만 실행한다.

| 순서 | 구현 단위 | 코드와 검증 기준 |
| --- | --- | --- |
| 1 | Node 작업 로그 | 작업 완료와 환경 조회를 구분하고 환경별 닫기 상태를 공유한다. NodeVersionControls, 서비스와 useNodeManagement에서 같은 오류의 새 실패, 메뉴 이동, 재검사, 진단 복사·WSL 로그 경로를 검사한다. |
| 2 | 버전 표시와 Home | 공통 NodeVersionAction에 세 상태를 적용한다. Home, SharingMembers 및 메뉴 이동에서 5개 경계, 팝업 전체 목록, 같은 환경의 설치 목록으로 포커스 이동을 검사한다. |
| 3 | TermRail 파일 선택 | WorkspaceControls, useStartupFile 및 메인 저장소에서 임시 선택과 저장 시 대상 결합을 분리한다. 빈 폼 가져오기, 검증 실패 후 재저장, 취소와 기존 서버 주소 변경을 검사한다. |
| 4 | TermRail 컨트롤 | 서버·레이아웃 팝업에 표준 입력과 액션 간격을 적용하고 사이드바 추가·저장 버튼을 작은 글래스 버튼으로 구분한다. 좁은 창·키보드 사용·터미널 배치를 확인한다. |
| 5 | 도움말 | help-content와 목차를 공통, Home, PlanRail, NodeRail, TermRail 순서로 편집한다. 현재 메뉴 진입, 기존 읽기 위치와 검색 및 예시 화면의 적합성을 검사한다. |
| 6 | 통합 검증과 문서 | 설계와 제품을 대조하고 구현 기록, 사용자 안내, AGENTS 진입점을 점검한다. 저장소 하네스와 전체 앱 검사를 실행하고 로컬 결과와 Windows 원격 검증을 구분한다. |

작업 로그 닫기는 진행 중인 작업에 영향을 주지 않는다. 시작 파일 내용·인증 정보는 메인 프로세스에서만 취급한다. 환경 선택과 버전 활성화는 전체 목록 보기와 독립적이다.
