# PostRail 1.1.0 구현 계획

[승인 설계와 인수 시나리오](../specs/2026-11-20-postrail-editor-design.md)를 기준으로 기존 Electron main·preload·React 경계를 유지한다.

1. 저장 요청에 선택 필드를 추가한다. 이전 JSON 요청, 헤더·쿼리 행, 경로와 파일 참조가 저장·복제·실행을 거쳐 유지되는지 확인한다.
2. 요청 편집, 환경 일괄 저장, 목록 이동과 필터, 응답 편집과 검색, 세션 console을 제품 메뉴에 연결한다. 환경별 토큰, 파일 접근, 전송 전 오류는 메인 프로세스에서 처리한다.
3. Home의 단건·명시적 반복, 결과 이동, 두 편집 영역의 크기 조절을 통합하고 단축키·포커스·진행 상태를 검증한다.
4. 버전·도움말·릴리즈노트·작업 지침을 갱신한다. 관련 단위·UI 테스트 후 저장소 하네스와 앱 전체 검사를 실행한다.

## 1.1.0 설치 후 피드백

1. 빈 쿼리와 헤더 표에 즉시 입력할 행을 두고, 첫 입력 전에는 저장·전송에 포함하지 않는다. 기존 URL 양방향 편집과 명시적인 행 추가를 검사한다.
2. 응답 본문 상단에 편집본과 원문을 고정된 선택지로 두고, 선택 상태와 편집 가능 여부를 구분한다. 두 보기의 내용이 같을 때도 모드가 보여야 한다. 클릭 시 생기는 테두리와 키보드 포커스를 따로 확인한다.
3. HTTP 오류 시 console에 상태와 마스킹된 서버 응답을 줄바꿈 그대로 표시한다. 응답이 없는 연결 오류는 실제 코드와 메시지를 표시한다. 로그인 비밀값과 토큰은 계속 보호하며 최근 1,000줄의 세션 한도를 적용한다.
4. 드롭다운은 기존 글래스 컨트롤의 색·키보드 조작을 유지하고 열린 목록도 줄인다. 오류 툴팁의 클리핑, 요청 한 행의 높이, Home 결과의 독립된 버튼과 메타데이터 배치를 실제 창에서 점검한다.
5. TermRail의 좌우·상하 분할선에 PostRail과 같은 그립을 적용한다. 기존 드래그·키보드·저장한 비율을 유지한다.
