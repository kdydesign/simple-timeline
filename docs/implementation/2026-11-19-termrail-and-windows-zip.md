## TermRail

메인 프로세스의 ssh2가 각 사용자가 연 직접 SSH 연결과 PTY를 소유한다. renderer의 xterm.js는 UTF-8 출력과 키 입력을 처리하고 분할 영역 크기에 맞춰 행·열 수를 전달한다. SSH IPC는 메인 창의 신뢰된 프레임에서만 호출할 수 있다. 별도 창은 sandbox가 적용된 같은 출처의 화면이며 메인 창에서 React 포털로 그린다. 별도 창은 같은 출처의 opener를 공유하므로 독립 보안 경계로 취급하지 않는다. 다른 메뉴로 이동하거나 트레이에 숨겨도 세션을 유지한다. 앱을 종료하면 세션을 정리한다.

프로필과 저장한 레이아웃은 이 PC의 앱 프로필에 보관한다. 서버 이름·주소·포트, 분할 방향·비율, 탭과 창 배치를 저장한다. 접속할 때마다 아이디와 비밀번호를 입력한다. 첫 연결은 서버 키의 SHA-256 지문 확인을 기다리고, 다른 키를 받으면 기존 지문과 새 지문을 표시한다. 승인된 키는 프로필 하위 `termrail-known-hosts.json`에 주소·포트별로 보관한다.

서버 이름을 더블클릭하면 새 탭이 열리고, 가장자리에 끌어 놓으면 해당 방향으로 분할한다. 현재 레이아웃을 교체하기 전에 저장된 서버 참조와 창 배치를 검사한다. 교체 후 각 터미널에서 다시 로그인한다. 별도 창을 일반 닫기로 닫으면 해당 탭 전체가 같은 세션으로 돌아온다. 터미널 제목의 닫기는 해당 세션만 종료하고 남은 영역이 공간을 채운다.

## Windows Node 설치

WorkRail이 해당 Node 릴리스의 Windows x64 ZIP과 서명된 해시 목록을 다운로드해 검사하고, nvm의 실제 버전 저장 루트에 준비한 디렉터리를 게시한다. 현재 사용 버전 전환은 별도의 **사용** 동작으로 시작한다. WSL2의 Linux 배포판에서는 기존 nodenv와 node-build를 사용한다.

공식 classic 관리자 판정에 과거 릴리스의 nvm.exe SHA-256을 사용한다. 구형 설치본은 공식 setup 또는 portable ZIP에서 실행 파일을 추출해 대조했다. 새 classic 빌드에서 인식 가능한 버전 힌트가 있으면 공식 릴리스 ZIP의 실행 파일 전체와 비교한다. 오프라인 판정 자료가 없고 공식 배포처에 연결할 수 없으면 앱에 제한 사유를 표시한다. 관리자 식별 이후에도 설정·저장 경로·기능별 검사를 수행한다.

nvm 2.0.0·2.0.1의 공식 실행 파일 및 보조 실행 파일은 SHA-256으로 식별한다. 2.x는 유효 레지스트리 설정의 버전 저장 루트, shim/link 모드, 오프라인·프록시·미러·서명자 정책을 검사한다. ZIP 다운로드와 압축 해제는 앱이 수행한다. 관리자 감지, 정책·서명 확인과 사용 전환에는 Windows API를 호출하는 PowerShell 단계가 남아 있다.

## 검증 범위

일회성 SSH 서버로 키 승인·키 교체·인증 취소·로그인·한글 입출력·PTY 크기와 종료를 검사한다. 별도 창의 위치 복원, 트레이와 탭 복귀, 잘못된 배치 복원 시 기존 세션 보존을 별도로 검사한다. Windows 인수 workflow에서 classic 1.1.10·1.1.11·1.2.2는 임시 저장 경로와 감지 fixture를 사용하고 실제 ZIP 설치, nvm 목록·CLI 전환과 Node/npm 실행을 검사한다. 2.0.1은 일반 사용자 계정에서 공식 CLI로 빈 버전 폴더를 지정하고, 제품 어댑터와 서비스로 shim/link 첫 설치와 전환을 실행한다. 공식 설치기가 포함한 Node 버전은 기존 저장소에 남는다. 2.0.0은 공식 실행 파일·보조 파일과 목록 구현을 대조했다. 사내 단말 보안 제품과 사용자 다중 모니터 구성은 별도 실기 인수 대상이다.

Linux x64·Node 24.22.1에서 변경을 포함한 작업 트리(기준 `c5e630e`, dirty)의 `verify:app` 7단계가 통과했다. 세 시간대에서 단위 561개씩, UI 300개, 네이티브 98개, sandbox Electron E2E 121개가 통과했다. E2E에는 실제 로컬 SSH 서버에 접속해 창 분리·복귀·트레이 이후에도 같은 PTY에서 출력과 키 입력을 확인하는 사례가 포함된다. Windows 전용 검사의 결과는 해당 소스 SHA의 원격 실행에서 확인한다.

원격 검사에서 저장된 카탈로그가 먼저 표시되는 경우, 새로고침 완료 후 설치 권한을 검사하도록 UI 테스트를 수정했다. WSL 권한 확인은 설정 경로와 실제 경로의 조상을 모두 대조하면서 소유자와 모드를 한 번의 stat 호출로 읽는다. 공백·개행·글로브 문자를 포함한 경로로 회귀를 검사했다. Windows 표준 사용자 인수 fixture는 첫 비대화형 로그인에서도 현재 사용자 SID로 등록된 프로필 하위에 AppData를 준비한다.
