# 다크 전용 화면·간트 탐색 보정

기준: `363ac6ff28f06b07d05352baedaebc6e16e5a907` + 작업 트리 변경. 버전0.6.5 구현 완료.
사용자가 [설계](../design/forest-crystal.md#후속-협의--다크-전용간트-탐색휴일-강조)의 Q1~Q5와 전체 구현을 승인했다.
[구현 계획](../superpowers/plans/2026-11-11-dark-navigation.md)을 이 세션에서 직접 실행했다.

## 구현 범위

- 처음 로딩하는 HTML부터 다크로 고정하고 테마 버튼을 제거했다. 기존 preferences 키를 읽어 배율·접힘을 보존하며 theme만 dark로 정규화한다.
- popup/glass alpha0.5, control0.3, 별도 list-control0.6을 적용했다. workspace padding14px, app-shell margin6px14px0, 이름 버튼 hover 투명 배경과 가운데 이름 머리글을 적용했다.
- 공유 프로젝트 저장은 기존 Radix Switch를 사용한다. 호스트만 조작하고 저장 전 확인·공유 해제 제한은 유지한다.
- 간트 본문 안에 빈 상태 안내를 배치하고 하단을 배율20%/가로 이동80%로 분리했다. 배율50~300%, 기본100%, 초기화·저장·왼쪽 날짜 기준을 유지한다.
- `GanttNavigation`의 가로 이동은 가상화 offset을 제어하는 유한 크기 range 기반 scrollbar다. 지원 날짜 전체 너비의 native DOM을 만들지 않으며 기존 방향키·휠·팬과 연동한다.
- 일반 스크롤바는 얇고 둥근 반투명 손잡이와 투명 track이다. hover/focus 때 색상을 부드럽게 드러내고 native thumb의 active 상태를 유지한다. 모션 줄이기·고대비 대체 표시를 제공한다.
- 주말은 시간대 없는 ordinal로 판정한다. 보이는 날짜에만 머리글·행·행 아래 빈 날짜 영역의 붉은 강조를 생성한다. 기존 일정 색·드래그·오늘·선택은 유지한다.
- 의존성·DB·IPC·공유 프로토콜·네이티브 창 재질은 변경하지 않는다. Windows Acrylic 자체의 투명도 조정은 이번 요청 범위가 아니다.

## 공휴일 데이터 보류 — 사용자 승인

요청 범위는 대한민국2026~2027년 공식 공휴일이다. 앱에 원격 API·개인 API키를 추가하지 않는다.
KASI에 게시된 우주항공청2025-06-30 공식2026 월력요항 HWP를 내려받아20일 명단을 대조했다.
하지만2026년 이후 법 개정 반영과2027년 관보 본문은 HTTP503으로 확인하지 못했다.
KASI 달력자료 TXT에는 공식 발표 자료가 아니라는 안내가 있고, 두 해의 노동절·제헌절 표기도 다르다.
출처와 확인 범위는 설계 문서에 기록했다. 확인 전 임의 날짜나 비공식 명단을 공식 자료로 추가하지 않았다.
2026-11-11 사용자가 “공휴일만 보류·나머지 완료”를 승인했다. 0.6.5는 주말만 강조한다. 공휴일 날짜 표와 미지원 연도 안내는 공식 자료 검증 후 별도 작업으로 진행한다.

## 검증과 검토

- 신규 다크 설정 보존·공유 Switch 테스트의 기존 동작 실패를 확인한 후 수정했다. 해당2개 테스트 통과.
- 배율/가로 조작 분리·빈 안내 위치와 주말 표시 UI 회귀30개 통과, 전체 UI120개 통과.
- 요일 ordinal 경계0001/9999 및 주말/평일6개 단위 검사 통과.
- 실제 Linux Electron의 표면 값·20:80 배치·배율 앵커·가로 이동·빈 공유 상태·주말 강조와 기존 유리 화면10개 통과.
- native 세로 스크롤바 hover/focus 표시·손잡이 드래그·고대비 에뮬레이션 검사 통과.
- 독립 코드 검토에서 주말 머리글 hover 배경이 기존 높은 specificity에 가려지는 문제를 발견했다. 전환이 끝난 뒤 읽는 재현 검사가 실패하는 것을 확인하고 `--date-base`로 통합하여 통과했다. 별도 구체적인 코드 결함은 보고되지 않았다.
- 전체 `verify:app` 첫 실행은6단계 통과, Electron79개 통과/1개 실패였다. 실패는 숨겨진 창의 클릭 응답을 복원 전에 기다리는 기존 테스트 순서였다. native 숨김 확인→복원→클릭 성공 확인으로 보정했으며 입력 보존 검사는 유지한다. 단독 보정 검사 후 전체 재검증을 통과했다.

초기 전체 공유 UI 검사에는 타임아웃도 있었고 별도 전체 UI 재실행은120개 모두 통과했다. 실패 로그를 보존한다.
최초 Electron 실행 실패는 테스트용 Xorg 백그라운드 프로세스가 종료된 환경 문제였다. 세션을 유지하는 전용 Xorg로 재실행했고 제품 sandbox는 변경하지 않았다.
테스트를 생략하거나 개별 제한 시간을 늘리지 않았다. 폐지된 테마 전환/가로 slider의 테스트만 새 다크/scrollbar 계약에 맞추고 기존 기능 검사를 유지했다.

## 0.6.6 후속 수정 — 트랙 경계와 그룹 구분

기준: `3d87ff3deaaed4b044539f2776d79ea105d5127e` + 작업 트리 변경. 사용자가 제공한 설치 화면에서 주말 강조가 실제 행 아래 빈 공간까지 이어지는 문제를 확인했다. 0.6.5의 `.gantt-tail`이 남은 본문 높이에 주말 열을 추가로 그린 것이 원인이다. 해당 렌더링과 전용 스타일을 제거하고 트랙 내부 강조만 유지했다. 간트의 남은 작업 공간과 하단 고정 배치는 유지한다.

기존 Electron 검사를 표시 경계 검사로 보정했다. 수정 전 마지막 행 하단438px보다 강조 하단836px가 커서 실패했고, 수정 후 일반 행·프로젝트 접힘·빈 공유 필터에서 통과했다. 날짜 눈금 강조, 기존20:80 배율·가로 이동, 스크롤바 검사까지 관련4개 테스트가 통과했다.

CSS 구분선은 하단 두 영역 사이와 상단 세 그룹 경계에 추가했다. 기존 반응형 간격에 맞추고 고대비에서는 시스템 테두리 색을 사용한다. 포인터·키보드 조작과 배율 값은 변경하지 않는다. `documentation-and-adrs` 지침에 따라 별도 ADR 없이 기존 설계와 이 기록을 보정했다.

Linux Electron 캡처에서 빈 영역의 붉은 배경 제거와 상·하단 구분선을 확인했다. Windows 설치본 실기 확인은 미검증이다. 공휴일은 여전히 보류이며 현재 붉은 강조는 토요일·일요일에만 적용된다.


전체 검증 첫 실행은 타입·배포·날짜 검사를 통과했으나 UI119/120에서 중단됐다. `tests/ui/gantt.test.tsx`의 기존 `.gantt-tail` 존재 기대가 새 승인 범위와 충돌했다. 이를 모든 본문 강조가 실제 트랙 안에 속하는지 확인하도록 보정했다. 최초 실패 증거는 `artifacts/track-boundaries/verify-app-first.{log,json}`에 보존했다. 테스트 생략·제한 시간 확대는 하지 않았다.

Linux x64/Node24.22.1, 기준 HEAD `3d87ff3deaaed4b044539f2776d79ea105d5127e` + dirty 작업 트리, UTC `2026-11-11T03:39:21.157Z` → `2026-11-11T03:43:32.312Z`.
