# Planrail 구현·검증 기록

작성일: 2026-11-05. 기준 소스: `5c41982ee23e1f0f76f1aa0875c5361bd94a865b`.
상태: 구현·main 반영·Windows/Linux CI 완료. 고정 소스 56080cc의 설치 근거는 [Windows 기록](../release/windows-validation.md#planrail-030)을 따른다.

## 승인과 범위

사용자는 grilling Q1~Q12와 A Zinc 시안을 선택한 뒤 Superpowers·Wayfinder로 구현을 지시했다.
[확정 설계](../design/planrail-improvements.md)와 [구현 계획](../superpowers/plans/2026-11-05-planrail.md)을 따른다.
Wayfinder context는 `selected: null`, `frontier: []`다. 완료된 MVP 지도를 다시 열지 않고 후속 개선으로 진행한다.

제품명 변경, 사용자별 설치 폴더 선택, 트레이 숨김/실제 종료, 공유 선택 날짜·왼쪽 날짜 탐색,
간트 확대·가로 이동, A Zinc/shadcn 공통 컴포넌트, 제한된 헤더 툴팁이 이번 범위다.
DB 스키마·업무 CRUD·오프라인·시간대 없는 날짜 계약은 유지한다.

## 호환성 결정

표시명은 Planrail, 버전은0.3.0으로 구분한다. 기존 DB·테마·접힌 프로젝트 설정을 유지하기 위해
내부 package 이름 `simple-timeline`, appId `com.kdydesign.simpletimeline`,
프로필 `%APPDATA%\SimpleTimeline`, 설정 키 `simple-timeline.preferences.v1`은 바꾸지 않는다.
이유와 대안은 승인 설계에 있으며 별도 ADR로 복제하지 않는다.

## 검증 경계

이 Linux 환경의 실제 Electron 검사와 Windows Server CI, 사용자 Windows11 실기는 구분한다.
기존 사용자 설치 인수 결과는0.3.0의 검증으로 전용하지 않는다.
일반 종료는 트레이 숨김이므로 설치·제거 전 실제 종료는 트레이 ‘종료’를 사용한다.
OS 강제 종료·설치기의 강제 프로세스 종료 시 메모리의 미저장 입력 보존은 보장하지 않는다.

작업별 커밋·검사 수·화면 증거와 미검증 경계를 아래에 기록한다.

## 첫 작업 근거 — 트레이·설치·명칭

커밋 `194d620f31d3970afb84a6461e70e5ca8cf245b2`는 Planrail0.3.0 표시명·트레이 생명주기·설치 폴더 선택과
실제0.2.1 업그레이드 fixture를 추가했다. 닫기는 숨김, 실제 종료는 저장 대기·미저장 확인 경로다.
새 renderer IPC를 만들지 않았다. 트레이 생성 실패 시 기존 보호 닫기로 돌아간다.

기본 builder 폴더 선택 옵션은 선택 경로 뒤에 제품명을 덧붙이므로 기존 폴더 재사용과 충돌했다.
표준 NSIS directory page를 custom hook에 넣어 선택한 경로를 그대로 사용한다.
이 보정은 제품 설치 정책 변경이 아니며 Windows compilation·실제 UI 결과는 별도 확인 대상이다.

Linux x64·Node24.22.1·DISPLAY=:97에서 최초 결함 재현 후 focused tray/flat9개,
release15개·타입·하네스7종을 통과했다. 전체 앱 검사는 기준5c41982+dirty 상태에서
release15·unit39×3TZ·UI34·native·E2E47 및 빌드를 통과했다(01:05:11~01:07:16 UTC).
그 뒤 강화한 두 번째 실제 프로세스 복원·저장 중 숨김 검사는 focused9개로 확인했다.
독립 작업 검토는 중요한 소스 결함을 발견하지 못했으며 Windows runtime은 검증 불가로 남겼다.
이는 최종 통합 버전의 검사 결과를 대신하지 않는다.

Playwright Electron launcher의 기본 인자는 테스트 런타임과 제품 보안 설정의 증거 범위를 제한한다.
제품 BrowserWindow의 sandbox/contextIsolation/nodeIntegration 설정과 보안 회귀는 유지했다.
Playwright 화면 검사만으로 운영 Chromium OS sandbox 적용까지 입증했다고 주장하지 않는다.

## 두 번째 작업 근거 — 날짜·간트 조작

커밋 `e62291f`는 선택 날짜 공유, 상단 일자 입력·왼쪽 탐색, 세션 탐색 범위,
14~84px 확대·배율 저장·포인터 앵커, Space 가로 이동을 추가했다.
프로젝트/일정 행은64/60px로 맞췄으며 가상화·막대·눈금·히트 테스트가 같은 날짜 너비를 사용한다.

실제 Electron에서14px 하루 막대가 기존 패딩 때문에21px로 늘어나는 실패를 재현하고 수정했다.
패닝 후 Enter가 차단되는 클릭 억제와, 값이 바뀌지 않은 날짜 입력 blur가 화면을 재정렬하는 문제도
각각 실패 검사로 고정했다. 명시적 Enter는 같은 날짜여도 다시 탐색한다.
달력 드래그의 월 탐색은 선택일을 바꾸지 않으며 취소 후 탐색한 월을 남긴다.
이를 위해 표시 월과 선택일을 분리하고 일반 날짜 탐색에서는 다시 동기화한다.

최종 Linux 앱 검사는01:29:44~01:31:49 UTC, 기준194d620+dirty에서 모든7단계를 통과했다.
release15, unit40×3TZ, UI61, native, E2E50 및 타입·빌드다. 기존47개 Electron 회귀를 유지했다.
하네스7종도 통과했다. 초기 전체 실행의 유일한 실패는 제거된 연월 버튼을 찾는 예전 테스트였으며,
새 날짜 입력의 Alt+ArrowDown·Escape·포커스 복귀 검사로 의도를 유지해 보정한 뒤 전체 통과했다.

## 작업 환경 중단과 재개

화면 통합 도중 원격 실행 환경의 연결이 offline/unavailable로 바뀌어 명령이 중단됐다.
상태 조회에는 원인 정보가 없었고 보존된 진단 기록도 없으므로 원인은 미확인이다.
사용자 PC나 제품 코드가 원인이라고 추정하지 않았다. 이때 push하지 않았으며 중단된 검사는 미완료로 남겼다.
연결 복구 후 e62291f까지의 두 커밋과 미커밋 파일이 남아 있음을 확인하고, 완료된 작업을 반복하지 않고
DISPLAY=:96의 새 테스트 실행으로 화면 통합을 이어갔다. 중단 직전의 검사를 통과로 재사용하지 않았다.

## 세 번째 작업 근거 — A Zinc·shadcn 화면

구현 커밋 `6041e82`는 공식 shadcn/ui 소스 커밋 `8a3536678a528cc012b9e62484290e79d0be410f`의
Button·Input·Select·Popover·Tooltip·AlertDialog를 현재 React 화면에 연결했다.
[출처와 수정 범위](../../resources/licenses/shadcn-ui-NOTICE.md), MIT 원문을 저장소와 배포 파일에 포함한다.
CDN·설치 CLI 없이 소스를 가져왔으며 Tailwind preflight를 제외해 기존 화면 reset과 충돌하지 않게 했다.
날짜 도메인·0001~9999년 입력·한국어/월요일 시작·C안 배치는 유지한다.

툴팁은 승인된 상단 7개 버튼에만 적용한다. 실제 Electron에서 버튼 기준 위치·250ms 대기·
포커스/호버·Escape/클릭 닫힘을 검사했다. 비대화형 툴팁에 남던 hover grace,
확인 수락 후 취소 콜백도 실행되던 문제, 중첩 월 선택기의 제목 표시줄 충돌을 각각 실패로 재현해 수정했다.
화면 검토에서 확인창의 이중 좌표 변환과 간트 하단 9px 넘침도 발견해 회귀 검사로 고정했다.

실제 Electron 변경 전 9장·변경 후 18장을 `artifacts/screenshots/planrail-before/`,
`artifacts/screenshots/planrail-after/`에 기록하고 비교했다. 후자는 라이트/다크의 간트·달력·편집·날짜/프로젝트 선택기,
긴 프로젝트 목록·짧은 화면·중첩 팝오버·확인창을 포함한다. 생성 시 pageerror는 없었다.
일반 화면의 프로젝트 팝오버는290×442px, 1280×500 화면에서는 높이393.5px로 제한됐다.
스크린샷은 로컬 검증 산출물이며 Git에 포함하거나 Windows 실기 화면으로 표기하지 않는다.

첫 전체 통합 검사는01:56:40~01:59:19 UTC, 기준e62291f+dirty에서 모든7단계를 통과했다.
release15, unit40×3TZ, UI65, native13, E2E55 및 타입·빌드다.
그 뒤 독립 검토에서 Radix 모달이 custom titlebar의 클릭도 막는 결함을 실제 마우스로 재현했다.
후속 커밋 `b64d856`은 제목 표시줄만 pointer 입력을 허용해 모달의 본문 차단·포커스 보호를 유지했다.
실제 X 클릭의 숨김/복원·입력과 확인창 유지·수락/취소를 실패 후 통과로 검증했다.
Linux 창 관리자가 있는 환경에서는 최소화·최대화/복원 실제 상태까지 통과했다.
창 관리자 없는 환경에서는 지원되지 않는 native 상태만 미검증으로 표시하며,
실제 Electron 명령 전달과 숨김/복원 검사는 그대로 실행한다. 제품 의존성을 추가하지 않았다.

## 작업 중 판단

- 기존 main 작업 공간과 직접 push 승인을 이어 사용했다. 별도 worktree로 옮기지 않은 판단이 잘못되면 일반 revert로 되돌린다.
- 구현 지시를 최종 설계 승인으로 받아 재승인을 요청하지 않았다. 승인 해석이 다르면 구현 재작업이 필요하다.
- 클라우드 스킬의 shell helper를 읽을 수 없어 같은 내용의 작업 명세·ledger·diff 검토 묶음을 직접 만들었다. 자동화 대신 수동 기록 누락 가능성이 있다.
- 기본 builder 폴더 선택 대신 표준 NSIS directory page를 사용했다. 선택한 기존 경로를 정확히 보존하기 위한 것이며 Windows에서 별도 컴파일·실행 확인이 필요하다.
- 달력 드래그 중 탐색한 월과 선택 날짜를 분리했다. 기존 취소 후 탐색 월 유지와 선택일 유지 계약을 함께 만족하지만, 다음 명시적 탐색 전에는 상단 선택일이 표시 월 밖일 수 있다.

## 최종 통합·남은 확인

최종 컨트롤러 검사는2026-11-05 02:06:53~02:09:27 UTC에 `DISPLAY=:96 npm run verify:app`로 실행했다.
원본 보고서의 기준은 `b64d856ecb067ca2e713ab96d8a9e6a2d6c20cab`, dirty=true다.
당시 미커밋 변경은 문서였으며 검사 중 문서 커밋b1679af를 만들었고 제품 소스는 바꾸지 않았다.
검사 결과는7단계 PASS: 타입, release15, unit40×3TZ, UI65, 빌드, native13, Electron56이다.
하네스7종·공백 검사·변경 문서의 로컬 링크 대상176개도 통과했다.
실행 중인 제품 소스를 clean b1679af에서 검사했다고 바꾸어 기록하지 않는다.

작업별 독립 검토와 최종 전체 검토는 소스·승인 설계·출처·운영 안내를 대조했다.
최종 전체 검토 범위는5c41982..b1679af이며 설계 준수 PASS·품질 APPROVED, 남은 중요/경미 발견 사항은 없었다.
Task3에서 발견한 창 버튼 결함은b64d856으로 수정하고 범위 재검토를 통과했다.
검증 결과 보고서에는 실행 SHA·dirty·OS가 남는다. 원격 실행과 설치본은
[Application 실행 목록](https://github.com/kdydesign/simple-timeline/actions/workflows/app.yml)의 해당 push SHA로 확인한다.
[Repository harness](https://github.com/kdydesign/simple-timeline/actions/workflows/harness.yml)도 같은 SHA를 기준으로 확인한다.
CI의 성공은 실제 Windows Server VM에서 자동화한 범위의 증거이며 사용자 Windows11 인수를 뜻하지 않는다.
Windows11 실기의 설치 폴더 선택/권한 거부·UAC·트레이 위치·배율·마우스/트랙패드 체감은
[수동 확인표](../release/manual-checklist.md)의 후속 확인이다. 이전 회사 PC 시작 지연은 이번 변경으로 해결했다고 주장하지 않는다.

## 원격 검증 확정 — 2026-11-05

[Application](https://github.com/kdydesign/simple-timeline/actions/runs/41953558125)과
