# 일정 알림·간트 계층 개선 구현 기록

2026-11-05(KST). [Q15 승인 설계](../design/reminders-and-hierarchy.md), [구현 계획](../superpowers/plans/2026-11-05-reminders.md).
버전 0.4.0, DB schema v2. 사용자별 설치·프로필·appId·기존 날짜 범위를 유지한다.

## 변경

- 일정별 알림 폼과 SQLite 마이그레이션, main 선점/처리 이력, Windows 일반 알림 어댑터를 추가했다.
- 실행·트레이에서 당일 후보를 처리하며 시작/종료 병합, 수정·재시작 중복 억제, 실패/불명 구분을 적용했다.
- 별도 제한 IPC로 알림 상태·실패 재시도·클릭 탐색을 제공한다. renderer에 네이티브 권한을 추가하지 않았다.
- A안 프로젝트/일정 계층, 간트 참여자 요약 제거, 붉은 삭제 버튼, 배율 숫자 클릭 100% 복귀를 적용했다.
- schema 변경을 구분할 설치 버전은 0.4.0으로 정했다. 의존성 버전은 바꾸지 않았다.

알림 계산·저장·실행·UI의 실패 테스트 후 구현했다. 독립 리뷰의 중요 결함 3건은 회귀 테스트로 재현하고 수정했다.

- Windows 배너 timeout 및 전송 응답 불명 뒤에도 실행 중 알림 센터 클릭을 보존한다.
- 표시 요청 이후 비동기 native 실패를 이력과 지속 안내에 반영하며 명확한 실패만 사용자 재시도 대상으로 바꾼다.
- 사용자 재시도 중 자동 평가가 겹쳐도 같은 identity를 재시도 한 번에 반복하지 않는다. 비활성화로 남은 후보의 재시도 권한도 그 요청 종료 시 폐기한다.

검사 중 기존 UI 테스트의 5초 시간 초과가 발생했다. 단독 실행·전체 재검사로 확인했고 테스트 제한 시간이나 기대 동작은 완화하지 않았다.
기존 간트 참여자 표시 기대는 제거 요구에 맞춰 바꾸되 저장 데이터 보존을 검사한다. Windows 패키지 검사는 실제 0.2.1 업그레이드 후 새 기본 알림 꺼짐·schema2를 확인하도록 확장했다.

실제 Electron 화면을 `artifacts/screenshots/reminders-final/`에 캡처했다. 라이트/다크 1280×900과 작은 창 760×500에서
15px 프로젝트·13px 일정, 간트 참여자 요약 제거, 붉은 삭제 버튼, 알림 폼·스크롤·저장 접근을 확인했다. 디자인 시안용 DOM/CSS 주입 없이 제품 화면을 검사했다.

## 작업 중 판단

승인된 구현을 이 세션에서 실행하고 마지막에 독립 리뷰를 받았다. AGENTS의 상시 승인에 따라 main 직접 반영을 사용했다.
새 기능·schema 업그레이드를 0.4.0으로 구분했으며 의존성은 변경하지 않았다.
리뷰에서 제외한 실제 Windows OS 동작은 아래 미검증으로 남기고, 콜드 활성화는 Q15의 제외 범위를 유지한다.

## 한계

Linux에서 네이티브 Windows 배너·알림 센터·소리·Windows 절전/방해 금지를 직접 검증할 수 없다.
Electron 통합은 주입한 알림 어댑터로 DB/preload/renderer를 검증하며 실제 OS 알림 인수와 구분한다.
Windows CI의 패키징·설치·업데이트 성공도 사용자 Windows 11 알림 실기 통과를 뜻하지 않는다.
비정상 종료 경계의 전송 누락 가능성과 완전 종료 후 콜드 알림 활성화 제외는 승인된 설계 한계다.
