# 0.8.4 편집·탐색·전체 기능 도움말

상태: 구현·독립 검토·로컬 전체 검증 완료. Windows CI 결과와 최종 커밋은 종료 보고에서 확인한다. 기준 main `a060eb6955f898939c6be541413aab83a55a5e38`(0.8.3). [Q1~Q8 승인 설계](../design/editing-navigation-and-help.md), [구현 계획·판단 기록](../superpowers/plans/2026-11-16-editing-navigation-help.md).

## 반영

- 프로젝트·일정·빠른 알림·공유 설정 전환/닫기와 Exit는 초안을 확인 없이 폐기. 주 창 X는 트레이 숨김으로 입력 유지. UPDATE는 검증 후 미저장 입력과 날짜 초안만으로 대기하지 않으며 진행 저장/결과 불명 보호·재실행 후 명시적 설치는 유지.
- 드래그/빠른 작업 차단 안내는4초 경고 토스트. 입력 오류와 DB·통신 오류는 지속 안내 유지.
- 간트 가로/배율 range 포커스 뒤 Space+드래그 허용. 제목 옆 호스트·멤버 배지는 역할만 표시.
- 주 화면 ui-ready 뒤1초에 도움말 사전 준비. 도움말 X는 숨김·재사용, 명시적으로 닫힌 창은 트레이 Open에 부활하지 않음. 종료 때 파괴. 기존 읽기 전용 sandbox/IPC 검사를 유지하고 준비 완료 메시지는 현재 열기 ID만 인정.
- 오프라인 도움말25개 항목. 기본 프로젝트·일정·간트 탐색/확대·드래그·달력·알림·트레이·설치·오류 안내 추가. 실제 격리 앱에서 가상 데이터로 사진 재촬영, 본문 번호·검색·관련 항목 검증.
- `help-latest.json`에 최근20회 열기 표시/준비 시간만 기록. 검색어나 프로젝트 내용은 기록하지 않음. 늦게 실패한 사전 로딩 응답은 이후 정상 열기의 화면을 덮지 않음.

## 검증

TDD 실패/성공 및 중간 로그는 ignored `artifacts/editing-help/`. 최종 명령·결과는 아래에 기록한다. 초기 촬영 실패는 종료된 Xvfb 세션으로 DISPLAY가 없었던 환경 문제였으며 준비 후 재실행했다. 테스트에서 삭제 확인은 유지하고 초안 폐기 확인만 새 정책으로 갱신했다.

회사 Windows PC의 클릭 후 창1초·본문3초 목표는 실측 전 미검증이다. Linux/CI 결과로 회사 보안 프로그램의 프로세스 지연까지 해결됐다고 주장하지 않는다. 사전 준비 전 첫 클릭은 프로세스 시작 지연을 겪을 수 있으며 도움말을 준비한 동안 별도 renderer 메모리를 사용한다.

## 독립 검토 보정

읽기 전용 전체 검토에서 Important2건을 찾아 재현 검사 후 보정했다. 공유 설정 저장의 IPC_UNAVAILABLE/rejection은 별도 결과 불명 상태로 유지하여 UPDATE를 막고, 단순 poll/다른 성공 작업으로 이전 저장을 확정하지 않는다. 재실행 후 실제 설정을 확인한다. 미리 준비하거나 사용자가 닫은 도움말의 실패는 일반 주 창 복원을 방해하지 않고 다음 명시적 도움말 열기에서 다시 생성한다.

Minor1건: 멤버 화면 그림의1번 번호가 연결 아이콘보다 역할 배지 쪽에 가까워 추후 좌표 보정이 필요하다. 기능·본문은 정상이다. 최초 전체 실행은 Electron84개 통과 단계에서360초 제한으로 중단되어, 전체 예산을600초로 보정하고 개별 테스트 제한은 유지했다. 미저장 확인을 기다리던 기존 E2E1건도 새 계약으로 수정했다.

보정 후 실제 Electron 관련15개는 모두 통과했다. Linux 가상 화면의 가상자료 실행에서 도움말 cold 열기는 클릭→표시115ms/본문 준비250ms, 열린 창 재호출0ms/91ms, 닫고 재열기1ms/88ms였다. 표시는 main show 호출 시점, 본문 준비는 renderer 상태 반영 후 두 프레임 시점이다. 이 값은 단일 Linux 실행의 기능 계측이며 Windows/회사PC 성능 보증이나 이전 버전 대비 개선율이 아니다. 회사PC의 유휴 메모리 실측은 미검증이며 Linux의 이전 버전 비교는 아래와 같다.

같은 Linux/Xvfb에서0.8.3 원본 archive와0.8.4를 각각 격리 프로필로 실행하고 주 화면 준비 후2초 유휴 시간을 준 비교도 수행했다. Playwright 명령·검색 입력 확인을 포함한 사용 가능 시간은 첫 열기357→133ms, 기존 창 호출87→67ms, X 후 재열기248→46ms였다. 단일 순차 실행이며 OS 캐시/스케줄링 영향을 통제한 성능 시험은 아니다. 주 화면 준비는1732→978ms였고, 사전 준비 뒤 renderer working set 합계는152,108→283,196KB로 증가했다(약128MiB 추가). 숨긴 도움말을 유지하는 비용이며 회사PC의 유휴 메모리 및 체감 시간은 별도로 확인해야 한다.

의도적으로 sharing_config를 지운 복구 검사는 정상 서비스 종료가 아니라 손상 후 프로세스 재실행을 시험하도록 조정했다. 제품에 강제 종료를 추가하지 않았으며, 원본 DB 보존·DB_CORRUPT 차단 화면은 실제 Electron에서 통과했다.

## 첫 CI 보정

`f84587a`의 Repository harness 양 OS와 Application Linux는 성공했다. Application Windows는 E2E99/100으로, 도움말 멤버 촬영의 최초 승인→connected 대기7초가 만료됐다(마지막 상태 connecting). 승인 자격 활성화와 첫 snapshot은 별도2초 poll에서 처리되므로, 촬영 검사를 승인 완료(pendingPair 해제, 최대15초)→connected(기존7초) 순으로 분리했다. 제품 poll/통신 제한·동기화 성능 목표는 바꾸지 않는다. 최초 승인의 추가 지연을 허용하는 테스트이므로 제품 속도 개선의 근거로 사용하지 않는다. 이후 CI 결과는 종료 보고에 기록한다.

보정된 실제 Electron 도움말 멤버 촬영은 Linux에서5회 연속 통과했다(47.7초). 하네스·diff 검사도 통과했다. 이번 보정은 테스트 대기 조건과 이 기록만 변경한다.
