# PostRail 요청 실행과 Home 즐겨찾기

WorkRail 상단의 PostRail에서 먼저 우측 하단 **환경 관리**를 열어 환경 이름과 필요한 변수를 저장한다. 좌측 **＋ → 요청 추가**에서 이름과 URL을 저장한 뒤 메서드·헤더·본문·인증을 편집한다. 별표를 켜면 Home에서도 현재 환경으로 저장한 요청을 실행할 수 있다. [승인 설계](../design/postrail-workspace.md) · [구현 계획](../superpowers/plans/2026-11-20-postrail.md)

## 저장과 인증

- 메인 프로세스가 사용자 프로필의 `postrail.sqlite`에 그룹, 요청, 즐겨찾기, 환경과 요청별 다음 인덱스를 저장한다. 요청 복제는 새 인덱스 1로 시작한다. 그룹 삭제 시 소속 요청은 미분류로 이동한다.
- 로그인 URL과 토큰 수신 API 주소를 환경마다 설정한다. 비밀번호를 참조할 때는 `${password}`를 사용한다. 보호 저장을 선택하면 Electron의 OS 보호 저장소를 이용하며, 세션 전용 비밀번호와 발급 토큰은 메모리에 둔다.
- 해당 환경의 인증 요청은 유효한 토큰을 재사용한다. 인증 설정 변경·로그아웃·만료·인증 요청의 401은 다음 인증 요청에서 새 로그인이 필요하다. 평문 HTTP는 실제 전송 주소를 확인하고, HTTPS는 Electron의 기본 인증서 검증을 사용한다. 자동 리디렉션과 실패 회차 재전송은 수행하지 않는다. [전송 경계](../../src/main/postrail/ipc.ts) · [실행기](../../src/main/postrail/runner.ts)

## 요청 실행과 결과

- GET·POST·DELETE를 한 건씩 보낼 수 있다. POST는 명시적으로 양의 정수 횟수를 지정해 순차 실행할 수 있다. 기본 응답 대기는 30초이며 요청에서 변경할 수 있다. 인덱스가 있는 요청은 본 요청을 보내기 직전에 다음 번호를 저장한다.
- 현재 회차가 끝나면 중지하며 트레이로 숨겨도 실행은 계속된다. 완전 종료는 진행 중인 한 건의 응답 또는 시간 초과를 기다린다. 결과는 현재 또는 마지막 실행만 임시 SQLite에 두고 footer에서 100줄씩 읽는다.
- Home은 그룹·요청 순서대로 최대 다섯 개의 즐겨찾기를 표시한다. 기본 실행은 한 건이며 POST의 **반복…**을 누르면 별도로 횟수를 지정할 수 있다. Home과 편집기는 같은 전송 상태와 번호를 사용한다. [Home 위젯](../../src/renderer/workrail/PostRailWidget.tsx) · [작업 화면](../../src/renderer/postrail/PostRail.tsx)

## 검증 범위

[저장소 테스트](../../tests/unit/postrail-store.test.ts), [실행기 테스트](../../tests/unit/postrail-runner.test.ts), [IPC 테스트](../../tests/unit/postrail-ipc.test.ts)는 일회성 프로필·루프백·격리된 전송을 사용한다. [Electron 통합 테스트](../../tests/e2e/postrail.spec.ts)는 화면에서 저장한 요청을 편집기와 Home으로 보내 실제 수신 본문과 회차 결과를 확인한다.

Linux x64, Node 24.22.1, 기준 커밋 `47030c8`의 변경 작업 트리에서 Electron 통합 테스트 두 건이 통과했다. 실제 HTTP 서버가 편집기·Home으로부터 인덱스 1·2를 받았으며, 별도 종료 시나리오에서는 트레이에 숨겨도 다음 회차를 전송하고 완전 종료 시 진행 중인 회차까지 마쳤다. 같은 프로필로 다시 시작해 자동 발송과 이전 토큰이 없음을 확인한 뒤, 직접 실행해 새 토큰으로 인덱스 3을 보냈다. Windows 설치본·실제 사내 CA와 업무용 로그인 서버는 이 로컬 검사의 대상에 포함되지 않는다.
