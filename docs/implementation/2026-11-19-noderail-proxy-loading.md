# NodeRail 사내 프록시와 작업 화면

[확정 설계](../design/noderail-proxy-and-loading.md) · [구현 계획](../superpowers/plans/2026-11-19-noderail-proxy-loading.md) · [사용 안내](../release/user-guide.md#사내-프록시에서-node-설치)

- Windows는 클래식 설정 파일과 2.0.1의 레지스트리 설정에서 미러와 프록시를 별도로 확인한다. 주소에 포함된 자격 증명 및 2.x 별도 인증 설정은 값을 노출하지 않고 설치 단계에서 안내한다. 기존 미러·서명 정책과 로컬 전환 가능 여부를 각각 검사한다.
- nvm-windows 1.1.11·1.2.2의 설정 파일 프록시 분기는 Go TLS 전송 설정의 인증서 검증에 영향을 준다. 설치 시 검증한 원본 설정의 데이터 루트를 유지한 임시 설정과 자식 프로세스의 HTTP(S)_PROXY로 같은 경유지를 전달해 기본 TLS 검증을 사용한다. 사용자의 설정 파일은 보존한다. [1.1.11의 전송 설정](https://github.com/nvm-windows/nvm/blob/1.1.11/src/web/web.go) · [1.2.2의 전송 설정](https://github.com/nvm-windows/nvm/blob/1.2.2/src/web/web.go)
- WSL은 선택한 배포판 기본 사용자의 로그인 환경에서 node-build를 실행한다. WorkRail에서 수집하는 화면·디스크 로그에는 프록시 인증 진단을 가린다. Electron의 배포 목록 조회와 node-build의 다운로드 오류는 각각 해당 작업에서 안내한다.
- 설치·사용은 Home과 NodeRail이 작업 상태를 공유한다. NodeRail은 두 목록의 입력을 잠그고 레이어 하나에 실제 단계를 표시한다. 종료를 확인할 수 없는 작업은 복구 절차를 유지한다. 두 목록 헤더는 테마별 반투명 배경과 12px 블러를 공유한다.

## 확인 범위

회귀 검사는 Windows 관리자 계열·프록시 표현별 설치 허용과 거절, WSL 배포판별 프록시와 예외, 로그 마스킹, 두 목록을 덮는 레이어의 크기·입력·스크롤, 다크·라이트 고정 헤더를 다룬다. 사내 프록시를 경유한 실제 Windows UAC 설치와 운영 WSL2 배포판 다운로드는 사내 PC에서 확인할 항목이다. WSL Linux에서 도구 자체가 별도로 작성하는 진단 파일은 WorkRail 저장 로그와 별도로 관리된다.

집중 검사에서 Electron의 Node 화면 사례 7개를 통과했다. 스크롤한 행이 사용 중인 버전으로 바뀌면서 맨 위로 재정렬될 때 Chromium이 스크롤까지 옮기는 문제가 재현되어 두 목록의 자동 스크롤 앵커링을 해제했다. 작업 전후의 두 스크롤 위치, 버튼에서 레이어로 이동한 포커스와 종료 후 목록 제목 복귀를 검증했다.

Linux에서 실제 nodenv·node-build와 테스트용 로컬 프록시·배포 파일로 바이너리 설치와 소형 소스 빌드를 확인했다. Linux PowerShell에서는 생성된 설치 스크립트의 프록시 전달과 원본 설정 보존을 확인했다. 전체 앱·하네스 보고서는 실행 SHA별로 확인한다.
