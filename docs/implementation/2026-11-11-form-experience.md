# 저장 진행·필드 오류·공유 설정 보정

기준: `589872de8763aced5bdb5a9a769c434644d8f0d1` + 작업 트리 변경. 버전0.6.7.
사용자가 [시안과 Q1~Q5](../design/forest-crystal.md#후속-시안-검토--툴바-간격저장-진행필드-오류)를 승인하고 공유 설정 팝업9항목을 추가했다. [구현 계획](../superpowers/plans/2026-11-11-form-experience.md)에 따라 진행한다.

## 확인한 원인과 범위

- 기존 툴바 구분선은 공통 left와 반응형 덮어쓰기 때문에 세 그룹의 원하는 위치를 각각 지정하지 못했다. 새 요청의 gap16px·필터 margin2px·작업 padding2px와 세 left값을 적용한다.
- 공유 빈 목록에도 공통 간트 제목·날짜 눈금·하단 탐색이 표시됐다. 공유 프로젝트가 없을 때만 숨기고, 일정 없는 프로젝트가 존재하면 행은 유지한다.
- 저장 API는 진행률이 아니라 결과만 전달한다. 따라서 실제 백분율 대신 불확정 진행 막대를 사용한다. `sharing.busy`와 timeline의 mutation 상태를 구분하여 동기화 중 전체 화면을 막지 않는다.
- 기존 검증은 첫 오류 하나와 전역 상태 영역에 의존했다. 필드별 표시에는 복수 오류 수집·입력 ID·Select 접근성 연결·수정 후 재검증이 함께 필요하다. 도메인 정규화·서버 검증은 유지한다.
- 트레이는 색상 아이콘과 라벨의 `●` 문자를 함께 표시해 동그라미가 두 개였다. 라벨에서 문자만 제거하고 실제 상태 아이콘과 클릭 동작은 유지한다.
- 공유 설정만 별도 배경 alpha0.3을 사용한다. 다른 확인창·날짜별 전체 일정 창의 배경은 변경하지 않는다. 팝오버·공유 설정의 blur10px와 요청한 패딩·높이는 승인 범위다.

## 구현과 시각 확인

요청한 간격·1:8 탐색·공유 빈 목록 처리, 저장 진행·필드 오류·PC 배치 및 공유 팝업 값을 구현했다. 렌더러에 필드별 오류 지도를 추가하고 기존 단일 API 오류는 그대로 유지한다. 실제 저장 응답과 후속 조회 결과를 구분하여, 저장 후 조회가 실패해도 중복 저장을 유도하지 않는다.

Linux Electron에서 `artifacts/form-experience/screens/project-errors.png`, `sharing-lan-menu.png`, `saving-pending.png`를 직접 확인했다. 입력 아래 오류·붉은 테두리, 상단2px 진행 막대, 공유 설정 X와 LAN 메뉴10px blur·영역 내 배치를 검증했다. Windows 실제 바탕화면 blur·트레이 표시 인수는 미검증이며 로컬 Linux 결과와 구분한다.

## 검증·리뷰 과정

- 최초 복수 오류/저장 덮개2건의 실패를 확인한 후 구현했다. 서버 필드 오류의 덮개 해제 후 포커스와 무관한 필드 수정 시 서버 오류 보존도 각각 실패 재현 후 보정했다.
- 전체 UI 첫 실행120통과/5실패는 새 완료 애니메이션에 따른 포커스 순서, PC 미선택의 로컬 차단, 저장 성공 후 조회 실패 메시지로 분류했다. 기존 기능 검사를 유지하면서 승인 동작으로 보정하여 UI126개를 통과했다.
- 첫 신규 Electron 검사의 LAN 항목 접근성 이름 오타를 실제 ‘공유할 LAN IP’로 수정했다. 관련6개가 통과했다. 테스트 오타와 제품 결함을 구분하여 로그를 보존했다.
- 독립 검토에서 동일 kind/id의 새 초안 교체 시 이전 오류가 남는 문제와 저장 중 트레이에서 열린 공유 설정 포털이 키보드 차단을 우회하는 문제를 발견했다. 두 경계 상황은 재현 검사와 함께 보정 대상으로 기록했다.
- 전체 `verify:app` 후보1은 타입·배포·단위·UI·빌드·native6단계 통과, Electron79/82였다. 연속 raw mouse 드래그3건은 새 데이터 렌더 이후 완료 덮개 해제 전 다음 입력을 보내는 순서를 확인할 대상이다. `artifacts/form-experience/verify-app-first.{json,log}`에 실패를 보존했다.

독립 검토 보정: 새 편집 세션마다 별도 식별자를 발급해 같은 kind/id로 초안을 바꿔도 이전 필드·서버 오류와 검증 상태를 초기화한다. 일반 입력 수정과 공유 데이터 갱신에서는 세션을 유지한다. 저장 중 들어온 트레이 공유 설정 요청은 보존하되 pending·saving·완료 덮개가 끝난 뒤 표시한다. 두 문제 모두 수정 전 재현 검사2건이 실패했고, 수정 후 관련 UI29개가 통과했다.
