# TermRail 시작 파일과 기본 셸

[확정 설계](../design/termrail-startup-input-and-server-edit.md) · [사용 안내](../release/user-guide.md#시작-파일로-열기)

## 기존 파일을 여는 방식

시작 파일을 가져올 때의 UTF-8 형식과 프로필의 암호화 파일 참조를 유지한다. 인증 후 SSH 서비스는 수동 로그인과 같은 기본 셸을 요청한다. 명령이 없는 파일도 기존 Bash 준비 신호를 기다리던 문제가 이 경로에서 해소된다. 인증 응답과 셸 열기는 메시지와 제한 시간을 구분한다.

메인 프로세스는 프롬프트를 확인하면 다음 한 줄과 Enter를 보내고, 화면에는 같은 PTY의 출력을 표시한다. 프롬프트 판정에는 셸이 출력하는 OSC 133 시작·끝 표식이나, readline의 bracketed paste 활성화 신호와 일반적인 사용자·호스트·경로 프롬프트 조합을 사용한다. 첫 줄을 보낸 후에는 직전 명령의 에코와 개행 또는 셸의 명령 제출 신호도 확인한다. 프롬프트만 다시 그려지는 경우 남은 줄은 수동으로 넘긴다. 셸이나 원격 프로그램이 출력한 문자만으로 모든 프롬프트를 식별할 수는 없다. 판정이 불분명하면 열린 세션에서 수동 입력을 계속한다. 추가 질문, 직접 타이핑, 제어 문자가 포함된 입력 줄, 10초 동안의 미확인 등으로 중단된 자동 입력은 나중에 프롬프트가 나타나도 재개하지 않는다.

서버 수정과 추가는 같은 표준 팝업 스타일을 사용한다. 기존 값, 파일 등록, 주소·포트 변경 시 재등록, 취소 시 원래 서버로 돌아가는 흐름을 유지한다.

## 검증

일회성 SSH 서버에 대해 호스트 키 확인·인증 실패·셸 열기 실패와 정상 연결을 구분한다. Linux에서는 기본 Bash PTY에서 헤더만 있는 파일과 실제 `ls`, `pwd`의 출력, 이후 사용자 입력을 검사한다. 질문·계속 입력·사용자 개입·프롬프트 다시 그리기·10초 경과 뒤에 추가 명령이 발송되지 않는지도 검사한다. 암호화 저장소가 있는 환경의 Electron 검사는 파일 가져오기와 복원된 세션을 연결한다. Linux의 키링이 없는 환경에서는 가져오기 실패 경로를 검사한다.

서버 수정 팝업은 밝은·어두운 테마와 두 화면 너비에서 추가 창과 실제 컨트롤 배치를 비교한다. 전체 로컬 검사의 커밋·OS·작업 트리 상태·단계별 결과는 `artifacts/app/latest.json`에서, Windows 설치 검사 결과는 해당 커밋의 GitHub Actions에서 확인한다. 사내 서버의 셸 프롬프트 지원 여부는 실제 접속 환경에서 별도로 확인할 항목이다.

로컬 Linux에서 `39b3e86` 앱 검사 7단계와 Electron E2E 126개가 통과했다. 같은 커밋의 Windows CI에서는 시작 진단 파일을 읽는 단위 검사가 마지막 스냅샷을 관측하기 전에 만료됐다. 이 검사는 실제 rename이 완료된 뒤 최종 파일을 읽도록 변경했다. 임시 파일 쓰기가 멈춘 동안 이전 파일이 완전한지 확인하는 검사와 제품의 저장 동작을 유지한다.
