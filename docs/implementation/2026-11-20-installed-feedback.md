# NodeRail·TermRail 설치본 피드백 반영

[요구사항 및 인수 기준](../design/noderail-termrail-installed-feedback.md) · [TermRail 사용 방법](../release/user-guide.md#termrail-ssh-연결)

## ZIP 권한과 작업 이력

세션 내 최근 작업 이력에 Windows ZIP 작업 시각·버전·관리자 계열, 실패한 단계·폴더 역할·확인한 OS 오류 코드를 남긴다. 정리 실패는 최초 오류에 덧붙인다. 처음 보고된 26.13.1 실패의 단계는 당시 이력에서 알 수 없다. 쓰기 권한 검사, 2.x 접근 제어 검사와 ZIP 서명 검사를 계속 적용한다. 불완전한 버전 폴더의 실제 경로는 사용자에게 복구를 안내할 때 사용하고, 진단 복사는 이력의 일반 텍스트로 한정한다.

Home의 폴더 열기와 창 포커스에 따른 환경 조회가 겹치면 조회를 마친 뒤 선택 환경과 작업 잠금을 확인한다. 명시적인 환경 재검사에 성공하면 이전 폴더·릴리스 열기 오류를 지운다. 26.11.0 설치 이력에서 확인한 EPERM은 임시 폴더를 대상 버전 폴더로 최종 이동하는 단계에서 발생했다. 해당 PC에서 이동을 거부한 원인은 추가 확인이 필요하다.

## SSH 시작 파일

등록 시 파일 선택과 암호화는 Electron 메인 프로세스가 맡는다. 원본 파일이 나중에 바뀌어도 사용자가 다시 가져오기 전까지 등록한 내용으로 동작한다. 프로필에는 파일 이름과 참조만 저장한다. 호스트·포트가 달라지면 서버 수정 화면에서 시작 파일을 다시 선택한다. 첫 접속과 호스트 키 변경 시 키 확인을 기다리고, 인증 실패 시 원격 명령을 보내지 않는다. 원격 서버는 Bash와 대화형 터미널을 지원해야 한다.

작업 탭의 한 칸은 연결 하나다. 탭 이동·메뉴 전환·창 분리·트레이는 새 SSH 인증이나 시작 파일 실행을 유발하지 않는다. 저장 레이아웃을 열면 모든 서버에 연결하며, 시작 파일이 있는 칸은 사용자가 그 칸에서 로그인을 선택할 때 같은 연결에서 인증을 이어간다.

## 검사 범위

- Windows ZIP 실패 경로 검사는 임시 폴더 생성, ACL 조회, 대상 폴더 이동, 동시에 생성된 불완전한 버전 폴더, 정리 실패, 재검사 이후의 성공을 다룬다.
- 실제 SSH 서버와 일회성 계정으로 호스트 키 확인·인증 거부·성공을 검사한다. Linux에서 긴 한 줄과 한글을 포함한 시작 파일, 초기 작업 후 `pwd`, 셸 변수와 사용자 입력이 같은 대화형 Bash에 남는지 확인한다.
- sandbox Electron에서 메뉴를 바꿨을 때 터미널이 보이지 않고 숨은 창이 입력을 받지 않는지 검사한다. 밝은·어두운 테마의 버전 목록에서 실제 배경에 합성한 색 대비를 비교한다.
- Windows 데스크톱 E2E는 기본 파일 선택 결과만 테스트 파일로 대체하고 Electron 보안 저장소·SSH 인증·화면을 연결한다. Linux에 보안 키링이 없는 경우는 파일 가져오기가 실패하고 프로필에 남지 않는 별도 경로를 확인한다. 사용자의 사내 서버·단말은 실기 인수 대상으로 남는다.

Linux 일회성 프로필에서 실제 Bash와 SSH 세션 검사 6개, 시작 파일 보호 저장소·IPC 검사 16개와 작업 탭·프롬프트 UI 검사 19개가 통과했다. Electron에서는 세 메뉴 전환 뒤 입력·표시 격리, Windows 진단 이력의 일반 텍스트 복사, 보안 키링을 사용할 수 없을 때 가져오기 거부를 확인했다. 같은 커밋의 Windows 보호 저장소와 NSIS 설치·업그레이드 결과는 GitHub Actions의 Application 실행에서 확인한다.
