# Windows 11 상세 후속 검증 양식

2026-11-04 기본 설치·실행·업데이트·제거·재설치는 [사용자 인수 기록](user-acceptance.md)으로 마무리했다.
사용자는 상세 개선·오류 검증을 별도로 진행하기로 했다. 아래 목록은 후속 검증용이며 스테이지 7의 미해결 차단 조건이 아니다.
실제 결과를 받은 항목만 통과로 기록한다. 운영 데이터가 없는 테스트 Windows 사용자/VM에서 진행한다.
설치본·소스 SHA·파일 해시·다운로드 링크는 해당 실행의 인수인계에 고정한다. 서명 없는 비공개 검증용이다.
[과거 배포·검증 기록](windows-validation.md)와 [설치·사용 안내](user-guide.md)를 확인한다.
확인할 현재 설치본과 UPDATE-TEST-ONLY ZIP을 각각 별도 폴더에 풀어 두고, 표준 사용자 계정으로 시작한다.
이름 변경 업그레이드는 실제 기존0.2.1 설치본을 별도로 사용한다. 합성 버전 fixture로 대신하지 않는다.
보안 정책으로 막히거나 UAC 관리자 자격 증명을 요구하면 그 결과를 기록한다. 설정을 우회해 통과로 만들지 않는다.

## 환경과 파일

- Windows 11 버전/빌드 (`winver`):
- CPU 아키텍처(x64):
- 표준 사용자/관리자 계정 및 UAC 표시 여부:
- 설치 파일 이름·버전·소스 SHA:
- 설치 파일 SHA256 (`Get-FileHash -Algorithm SHA256`):
- 네트워크 차단 방법(예: Wi-Fi 끔/유선 케이블 분리):
- SmartScreen/게시자 경고 또는 정책 차단:

## 기본 오프라인 시나리오

1. ZIP을 풀고 해시를 확인한 뒤 네트워크를 끊는다. 첫 설치·최초 실행이 동작하는지 기록한다.
2. `1.1.1 핫픽스` 프로젝트를 만들고 색상·참여자를 저장한다.
3. 개발 `2026-11-11~2026-12-11`, QA `2026-12-12~2026-12-17`, 운영 배포 `2026-12-18`을 만든다.
4. 간트에 `2026-11-01~2026-12-31`의 전체 일정과 31/6/1일 기간이 포함되는지 확인한다.
   오늘·탐색한 날짜가 그 밖이면 표시 범위가 해당 월까지 확장된다.
5. 선택 월 2026-12의 달력에서 같은 이름·색상·기간과 주별 조각을 확인한다.
6. QA 이름/기간을 수정하고 두 모드에서 반영을 확인한다. 운영 배포 일정을 삭제한다.
7. 종료·재실행 후 프로젝트·남은 일정이 그대로인지 확인한다. 선택 날짜는 현지 오늘로 돌아간다. 트레이 숨김/복원은 새 실행이 아니다.

각 번호별 결과: 통과 / 실패(정확한 메시지·행동) / 미실행.

결과 전달은 다음처럼 텍스트로 작성하면 된다. 미실행은 이유를 남긴다.

```text
Windows 빌드 / x64 / 계정 종류:
설치본 버전·소스 SHA / exe 해시 일치 여부:
네트워크 차단 방법 / 경고·UAC:
기본 시나리오 1~7 각각:
업데이트 / 제거 후 DB / 재설치 / 다른 사용자 영향:
100% / 200% / 키보드 / Narrator:
잠금 / 권한 / 용량 / 강제 종료 / 손상 / 고버전 / migration:
실패한 항목의 정확한 메시지·행동:
```

## 업데이트·재설치·제거

- 일반 설치본의 데이터가 있는 상태에서 UPDATE-TEST-ONLY 설치본을 같은 테스트 사용자에게 설치한다.
  이 파일은 같은 소스의 가상 다음 버전이며 일반 사용자 배포본이 아니다.
- 업데이트 뒤 동일 DB 경로의 데이터/ID가 유지되는지 확인한다. 앱 재실행 뒤에도 같아야 한다.
- 제거 후 `%APPDATA%\SimpleTimeline\data\timeline.sqlite3`가 남는지 확인한다.
- 같은 검증 버전 재설치 후 기존 데이터가 보이는지 확인한다.
- 설치/제거가 다른 Windows 사용자의 앱이나 데이터를 변경하지 않는지 기록한다.

## 표시·접근성

- Windows 배율 100% / 200%에서 툴바·패널·저장/삭제 확인·더 보기 목록이 사용 가능한지 기록한다.
- Tab/Enter/Space/Escape와 간트·목록 위아래/Home/End만으로 추가·편집·삭제가 가능한지 확인한다.
- Narrator에서 모드·선택 날짜·일정 전체 기간·오류·확인창이 읽히고 포커스가 갇히거나 사라지지 않는지 기록한다.
- 기존 간트 scrollbar gutter 차이는 0.2.0에서 날짜 헤더와 행의 폭을 맞춰 보정했다.
  Windows 실기에서도 End의 마지막 막대·손잡이와 날짜 눈금 정렬을 확인한다.

## 실패 경로

잠금·권한·용량 부족·강제 종료·손상·고버전·migration 실패는 **격리된 별도 Windows 사용자/VM의 복제 데이터에서만** 실험한다.
운영 DB를 손상시키거나 디스크를 채우지 않는다. 준비되지 않은 항목은 미실행으로 기록한다.
CI의 native/오류 주입 통과와 실제 OS·설치본 실험을 구분한다. 미실행을 통과로 쓰지 않는다.

## 0.2.0 후속 개선 실기 확인

- 설치 완료 화면에서 실행 체크를 유지/해제한 각각의 결과, 마침 버튼을 확인한다.
- 설치 파일·설치된 EXE·작업 표시줄·바탕화면/시작 메뉴 바로가기에서 남색 B 아이콘을 확인한다.
- 라이트/다크와 프로젝트 접힘을 바꾼 뒤 재실행·업데이트 후 유지 여부를 기록한다.
- 두 모드의 날짜 클릭 추가·날짜 선택기·드래그 이동/양 끝 조절·Escape/영역 밖 취소를 확인한다.
- 월 이동·화면 가장자리 자동 탐색, 미저장 패널 차단, 2초 토스트와 지속 오류 안내를 확인한다.
- 같은 PC·같은 데이터에서 시작 메뉴 클릭부터 창 표시/조회·편집 가능까지 각각 반복 측정한다.
  정상 재실행의 3초/5초 목표와 비교하고 최초·복구·마이그레이션은 별도 기록한다.
  [시작 기록 안내](user-guide.md)의 `startup-latest.json`은 프로세스 생성 전 대기를 포함하지 않으므로 수동 측정과 함께 기록한다.

## Planrail 0.3.0 상세 실기 확인

아래는 아직 사용자 Windows11 통과 기록이 없는 체크리스트다. CI 성공과 구분해서 기록한다.

- 신규 설치 폴더 기본값 `%LOCALAPPDATA%\Programs\Planrail`, 다른 쓰기 가능한 폴더 선택,
  쓰기 권한 없는 폴더 거부, UAC 관리자 승격 없음, 완료 후 실행 체크 유지/해제를 각각 확인한다.
- 실제0.2.1에서 DB·다크 모드·접힌 프로젝트를 만든 뒤 트레이가 없는 구버전 앱을 종료한다.
  Planrail 업데이트의 기존 경로 기본값, 경로 변경 설치, 기존 EXE/바로가기 정리와 데이터·설정 유지를 확인한다.
- 새 앱 X/Alt+F4 후 숨김, 트레이 열기·아이콘 클릭·시작 메뉴 재실행 복원, 최소화 복원을 확인한다.
  편집/저장 중 숨김 후 입력·결과를 확인하고, 트레이 종료의 저장 대기·미저장 확인 취소/확정을 확인한다.
- 설치/제거 전 트레이 ‘종료’를 사용한다. 별도 일회성 데이터로 실행 중 설치/제거의 안내와 종료 처리를 확인한다.
  강제 종료된 미저장 폼의 보존을 기대하지 않는다.
- 날짜 공유 강조, 오늘·상단 날짜의 간트 왼쪽 정렬, 날짜 칸 클릭 시 화면 위치 유지,
  월말 보정·0001/9999년·범위 끝 빈 공간에 가짜 날짜가 없는지 확인한다.
- 간트14/28/84px에서 Ctrl+휠 앵커·날짜 클릭·1일 막대 양끝/몸통 드래그,
  Space 이동 종료/취소·입력창 공백을 확인한다. 재실행 후 배율을 확인한다.
- Windows100%/125%/200%에서 A Zinc 라이트/다크·프로젝트 목록 스크롤·편집 패널·날짜/월 선택기를 확인한다.
  툴팁은 지정된 헤더 버튼에만 나타나고 버튼 아래에 붙는지, 화면 끝에서 잘리지 않는지 확인한다.

## 0.8.1 로그인 자동 실행·수동 설치

- 설치의 로그인 자동 실행 기본 체크와 완료 화면의 즉시 실행이 독립적인지 확인한다. 각각 해제한 설치도 확인한다.
- 트레이 자동 실행 체크를 켜고 끈 뒤 재실행·재설치·UPDATE에서 유지되는지 확인한다. Windows 작업 관리자의 사용 중지 상태도 반영해야 한다.
- 실제 로그아웃/로그인 후 창 깜빡임 없이 트레이에서 실행되고 Open·바로가기는 창을 여는지 확인한다. 트레이·DB 시작 실패에서는 창이 보여야 한다.
- 일회성 데이터의0.8.0 앱을 실행하고 미저장 초안을 만든 뒤0.8.1 설치 EXE를 직접 실행한다. 추가 버리기 확인 없이 해당 설치의 앱만 종료되고, 설치 후 commit된 데이터는 유지되는지 확인한다. 진행 중 저장의 취소/완료는 종료 시점에 따라 달라질 수 있다.
- 0.8.1 이상은 미저장 초안을 버리되 수락된 저장을 마무리하고 정상 종료한다. 종료 실패 시 파일 교체를 중단해야 한다.
- 다른 설치 경로·확인 불가능한 프로세스·다른 사용자·무인 설치·앱 내 UPDATE에는0.8.0 강제 종료 예외가 적용되지 않아야 한다.
- 제거 후 자동 실행 등록이 없어지고 DB는 보존되는지, 업데이트 중 내부 제거에서는 자동 실행 선택이 사라지지 않는지 확인한다.
