# WorkRail — Windows 설치·사용 안내

대상은 Windows 11 x64다. WorkRail 자체는 현재 사용자에게만 설치하며 관리자 권한으로 상시 실행하지 않는다. Node 설치·전환에는 별도의 Windows 권한 확인이 표시될 수 있다.
첫 설치본은 서명하지 않은 비공개 검증용이다. 클라우드 로그인·수동 백업/복원은 없다. 선택적인 사내 LAN 공유와0.8.0부터 호스트를 통한 멤버 업데이트를 제공한다.

## 홈과 도구

앱은 통합 현황 홈에서 시작한다. 상단 메뉴의 **Home · PlanRail · NodeRail**로 이동한다. Planrail에서 작성하던 입력과 날짜·화면 상태는 메뉴를 바꿔도 유지되며 일정 공유·알림도 계속 동작한다. 앱 종료 후 미저장 입력의 복구를 보장하는 기능은 아니다.

Node 관리는 각 PC의 개발 환경이며 일정 공유 역할과 관계없다. WorkRail은 기존 nvm-windows 1.x·2.x의 실행 파일과 설정을 검증하고 조회·설치·사용 기능을 각각 확인한다. 지원이 확인된 기능은 기존 관리자로 계속 사용할 수 있다. nvm 2.0.1에서 활성 버전과 기존 Node 설치가 모두 없으면 첫 설치가 기본 버전을 자동 설정한다. 이 상태에서는 Windows 터미널에서 공식 nvm으로 첫 버전을 설치한 뒤 다시 확인한다.

Home과 NodeRail은 같은 관리 대상을 표시한다. 환경이 하나면 자동으로 선택하며, 여러 개면 마지막 선택을 복원하거나 최초에 선택을 요청한다. 종료된 WSL2 배포판은 **환경 시작**을 누른 뒤 내부 환경을 확인한다. nodenv와 node-build는 배포판 기본 사용자로 설치하고 셸 초기화를 직접 설정한다. node-build가 없더라도 지원되는 기존 버전 조회·전환은 가능하다. 필요한 경우 소스 빌드에 Linux 컴파일 도구와 충분한 시간·디스크 공간이 필요하다. [nodenv 설치 안내](https://github.com/nodenv/nodenv#installation) · [node-build 설치 안내](https://github.com/nodenv/node-build#installation)

Home의 **오늘의 일정**은 종료일까지 남은 달력 일수를 표시한다. 종료일 당일에는 **오늘 마감**으로 표시한다. **Node 작업**에서 버전을 바꾸면 위젯 안에서 진행 상태와 결과를 확인할 수 있다. **내 개발 환경**의 폴더 버튼은 선택한 Windows nvm의 버전 저장 폴더 또는 실행 중인 WSL 기본 사용자의 nodenv 루트를 탐색기에서 연다.

NodeRail의 **환경 다시 검사**를 누르면 현재 버전 패널 상단에 진행선이 표시된다. 제목 오른쪽에서 환경과 관리자 버전을 확인하고 **최신 릴리스**로 공식 다운로드 페이지를 열 수 있다. 설치된 버전 목록은 제목 아래에서 독립적으로 스크롤된다.

공식 Node 목록에서 **설치**를 선택하고, 설치된 버전의 **사용**을 별도로 누른다. WSL에서는 기본 사용자의 Node 기본 버전에 적용되며 프로젝트의 `.node-version`과 셸의 `NODENV_VERSION`이 우선한다. 실행 중인 Node 프로세스는 그대로 유지된다. 작업 중에는 메뉴를 이동할 수 있으며 환경 변경과 앱 종료·업데이트 설치는 대기한다. WSL 작업 종료를 확인할 수 없다면 로그를 보존하고 같은 배포판이 종료된 상태임을 **다시 확인**한다. WorkRail은 배포판을 자동 종료하지 않는다. nodenv 재해시 잠금 오류가 나오면 실제 작업 로그와 공식 복구 방법을 확인한다.

### 사내 프록시에서 Node 설치

Windows에서 기존 nvm에 설정된 사용자명·비밀번호 없는 HTTP(S) 주소·포트 프록시는 그대로 사용할 수 있다. Node와 npm 미러는 공식 주소를 사용한다. 별도 프록시 인증정보가 필요한 설정이면 NodeRail에서 이유를 표시한다. 이 경우 승인된 환경의 터미널에서 설치하고 **환경 다시 검사**를 누르면 설치 목록이 갱신된다.

Windows x64에서 공식 nvm-windows **1.1.10 또는 1.1.11**을 사용하면 WorkRail이 공식 Node ZIP을 내려받아 서명과 SHA-256을 확인한 후 nvm 버전 폴더에 설치한다. **사용**을 눌러야 현재 버전이 전환된다. 불완전한 기존 폴더가 발견되면 표시된 경로를 확인한다. 설치 실패 후 **환경 다시 검사**를 누르면 종료된 작업 상태와 현재 설치 목록을 다시 확인한다. 작업이 실제로 진행 중이거나 종료 여부를 확인할 수 없으면 화면에 다음 조치가 표시된다.

WSL2에서는 선택한 배포판 기본 사용자의 로그인 환경에 내보낸 프록시와 `NO_PROXY` 예외를 해당 다운로드 도구가 사용한다. 소문자 환경 변수도 다운로드 도구의 규칙을 따른다. 여러 배포판을 사용한다면 각각의 사용자 설정을 확인한다. **공식 배포 목록**은 WorkRail의 Electron 네트워크 연결을 사용하므로, 목록 조회가 실패한 경우와 nvm 또는 node-build 다운로드가 실패한 경우를 구분해 확인한다.

NodeRail에서 설치나 사용을 선택하면 두 버전 목록 위에 작업 대상과 진행 단계가 표시된다. 메뉴를 전환해도 같은 작업이 이어진다. WSL 작업에서 취소·로그가 제공되는 경우 레이어에서 확인할 수 있다.

### Windows 관리자 설치

Windows에 nvm이 없으면 공식 1.2.2 설치 지원을 선택하고 Windows 설치 창을 완료한 뒤 다시 확인한다. 최초 PATH 설정 후에는 터미널을 다시 열어야 할 수 있다. 설치 파일 다운로드는 시스템 프록시를 자동 발견하지 않는다. 실패하면 공식 릴리스에서 수동 설치한 뒤 환경을 확인한다. [공식 nvm-windows 1.2.2 릴리스](https://github.com/nvm-windows/nvm/releases/tag/1.2.2)

기존 설치·데이터와의 호환성을 위해 앱 ID, 설치된 실행 파일 `Planrail.exe`, 내부 경로·Windows 자동 실행 등록 이름은 유지한다. 아래 일정 관리 안내는 Planrail 메뉴에 해당한다. WorkRail1.0.0 후속 개선의 실제 검증 범위는 [구현 기록](../implementation/2026-11-19-workrail-environments.md)을 따른다.

기존 Node와 충돌하면 검증된 공식 MSI 설치에 한해 사용자 확인 후 Windows 표준 제거 화면으로 진행한다. 제거 전에는 작업을 저장하고 필요한 설정·전역 npm 도구 목록을 백업한다. 프로젝트 파일이나 잔여 폴더·PATH를 자동 삭제하거나 전역 도구를 이관하지 않는다. 제거 후 환경 재검사로 충돌 해소를 확인한 다음 **nvm-windows 설치**를 별도로 누른다. 개발 실행에서는 독립 관리 창으로 이어지며 시작 메뉴의 **WorkRail Node 환경 복구**로 다시 열 수 있다. 재부팅 필요나 작업 종료 불명 상태에서는 다음 설치를 차단한다.

물음표 또는 **F1**으로 현재 메뉴의 도움말을 연다. 설정 창에서는 공통 설정 도움말을 연다. 앱을 실행하는 동안 메뉴마다 마지막 글·검색어·스크롤을 기억하며, 전체 검색 결과에는 글이 속한 메뉴를 표시한다. Home의 PlanRail 상태에는 내 WorkRail 버전과 멤버가 동기화에서 받은 호스트의 실행 버전이 표시된다. 호스트가 버전 정보를 보내지 않으면 **확인 불가**로 표시하고 동기화는 계속한다.

**설정 → 공유 설정**에서 호스트↔멤버 역할을 확인 후 바꿀 수 있다. 이전 호스트 원본은 **중지된 공유 자료**에서 조회하며 현재 일정과 알림에 섞이지 않는다. 호스트로 복귀하면 기존 등록·승인을 재사용하되 공유·업데이트 배포는 따로 시작한다. 멤버에서 호스트로 바꾸면 수신 자료·접속 자격을 정리하므로 다시 멤버가 될 때 재승인이 필요하다. 개인 자료는 유지한다.

## 내려받기와 확인

GitHub 저장소의 Application Actions에서 해당 커밋의
`WorkRail-Windows11-x64-unsigned-<소스 SHA>` artifact를 내려받아 GitHub가 제공한 ZIP을 푼다.
설치 파일은 `WorkRail-<버전>-win-x64-<소스 SHA>.exe`다. 같은 artifact 안의 `WorkRail-<버전>-win-x64-<소스 SHA>-update.zip`은 빌드에서 생성한 LAN 업데이트 묶음이다.
`release-manifest.json`의 버전·소스 SHA·SHA256과 함께 제공한 `.sha256` 파일을 확인한다.
PowerShell의 `Get-FileHash -Algorithm SHA256 <설치파일>` 결과가 일치해야 한다.
CI의 가상 다음 버전 설치 파일은 별도 비공개 artifact `WorkRail-UPDATE-TEST-ONLY-<소스 SHA>`에 담긴다. 업데이트 검증용 Windows 사용자/VM에서만 사용한다.

## 설치와 제거

설치 파일을 실행하면 현재 사용자용으로 설치한다. 완료 화면에서 기본 체크된 `WorkRail 실행`을
그대로 두고 `마침`을 누르면 실행한다. 체크를 해제하면 설치만 마치며 시작 메뉴에서 나중에 열 수 있다.
Windows가 알 수 없는 게시자/SmartScreen 경고를 표시할 수 있다.
저장소·커밋·해시를 확인하고 신뢰하는 파일인지 판단한 뒤 Windows 안내에 따라 실행한다.
보안 기능을 전역으로 끌 필요는 없다. 정책으로 실행이 막히면 그 상태를 알려준다.

호환성을 위해 신규 기본 설치 위치도 `%LOCALAPPDATA%\Programs\Planrail`이며 설치 화면에서 현재 사용자가 쓸 수 있는 폴더를 선택한다.
기존 앱을 업데이트하면 기존 설치 위치를 기본으로 재사용한다. 예전 폴더 이름을 강제로 바꾸지 않는다.
쓰기 권한이 없는 폴더 대신 사용자 폴더를 선택한다. 관리자 승격이나 전체 사용자 설치는 제공하지 않는다.
Windows 설정의 설치된 앱에서 WorkRail을 제거할 수 있다. **제거해도 일정 DB는 남는다.**
같은 앱을 재설치하면 보존한 데이터로 시작한다. 앱 제거는 데이터 삭제 방법이 아니다.

## 데이터와 오프라인 사용

일정 DB는 `%APPDATA%\SimpleTimeline\data\timeline.sqlite3`다.
앱·설치 파일 폴더와 별개이며 일반 업데이트·재설치·제거 때 보존한다.
앱을 실행 중인 상태에서 DB 한 파일 복사를 일관된 백업으로 보장하지 않는다.
수동 백업·복원·다른 PC 이동 기능은 MVP에서 제외했다. 내부 migration 사본도 디스크 손실 복구를 보장하지 않는다.

WorkRail 설치와 Planrail 일정 조회·추가·수정·삭제에는 인터넷이 필요하지 않다. Node 배포 목록 갱신과 설치 파일 다운로드에는 인터넷이 필요하다.
개발 도구 설치와 CI 빌드의 다운로드는 사용자 앱의 오프라인 실행과 구분한다.
호스트·최초 도입·수동 업데이트는 새 설치 파일을 직접 실행한다.0.8.1 설치본부터 수동 설치에서 실행 중인 같은 설치 위치의 앱 종료를 처리한다.0.8.1 이상 앱에는 정상 종료를 요청하고,0.8.0은 현재 사용자·경로·버전이 확인된 대화형 수동 설치에서만 강제 종료한다. **수동 설치를 시작하면 미저장 입력은 확인 없이 사라진다.** 이미 저장된 데이터는 유지하며 진행 중 저장은 종료 시점에 따라 반영됐을 수 있다. 대상 확인이나 종료가 실패하면 설치를 중단한다.
0.8.4 앱 내 UPDATE는 검증 후 진행 중 저장을 안전하게 마무리하고 미저장 입력을 확인 없이 폐기한다. 그 밖의 구버전과 앱 제거 전에는 트레이에서 ‘Exit’를 선택한다. 창 X는 트레이 숨김이며 완전 종료가 아니다.

## 기본 사용

1. 프로젝트 추가에서 이름·색상을 저장한다. 참여자 이름은 호스트만 관리하며 개인 전용·멤버는 기존 이름을 읽기 전용으로 보존한다.
2. 일정 추가에서 이름·시작일·종료일을 입력하고 저장·확인을 완료한다. 양 끝 날짜를 포함하며 같은 날은 하루다.
3. 간트/달력을 전환한다. 간트는 전체 일정과 탐색한 달 범위, 달력은 선택 날짜의 월을 보여준다.
4. 이름 또는 막대로 편집한다. 달력의 더 보기는 해당 날짜 전체 일정을 연다.
5. 프로젝트 삭제는 소속 일정도 함께 삭제하므로 확인 내용을 읽는다.

간트 가로 손잡이는 좌우 하루, PageUp/Down 한 화면, Home/End 처음/끝 이동이다.
간트 이름 버튼과 날짜 전체 목록에서는 위아래 키로 화면 밖 항목에도 접근한다.
오류·결과 불명 안내가 나오면 입력을 유지하고 다시 조회한다. 같은 생성을 자동 재전송하지 않는다.
DB 손상·초기화 실패 안내가 나오면 원본을 지우거나 빈 DB로 대체하지 말고 안내 경로와 오류를 기록한다.

## 추가 편집·화면 기능 (0.2.0)

- 0.6.5부터 다크 모드만 제공한다. 기존 라이트 설정이 있어도 다크로 열리며 배율·프로젝트 접힘 상태는 유지한다.
- 달력의 날짜나 간트 날짜 눈금·빈 행을 클릭하면 그 날짜로 일정 추가 패널이 열린다. 간트 행의 프로젝트를 우선한다.
- 시작일·종료일 옆 달력에서 날짜를 고르거나 YYYY-MM-DD로 입력한다. 저장 버튼으로 확정한다.
- 간트 프로젝트 왼쪽 화살표로 접고 펼친다. 접힌 상태를 기억하며 달력의 일정은 숨기지 않는다.
- 막대 몸통을 끌면 기간을 유지하며 이동한다. 실제 시작·끝의 손잡이는 해당 날짜만 바꾼다.
  여러 주로 나뉜 막대의 중간 경계는 손잡이가 아니다. 놓으면 저장하며 Escape·영역 밖 드롭으로 취소한다.
  미저장 입력이 있으면 먼저 저장하거나 버린다. 간트 가장자리는 자동 스크롤, 달력 이전/다음 월 버튼 위 대기는 월 이동이다.
- `오늘`은 오늘을 선택하고 간트 날짜 영역의 맨 왼쪽에 맞춘다. 일정 전체도 계속 포함한다.
- 성공 알림은 우측 하단에 2초 표시한다. 조치가 필요한 오류는 사라지지 않는다.

## Planrail 화면·날짜 탐색 (0.3.0)

A Zinc 화면은 C안의 배치를 유지한다. 상단 폴더 아이콘은 프로젝트 목록을 연다.
목록이 길면 가운데 항목만 스크롤하며 제목·닫기·프로젝트 추가는 고정된다.
이름은 프로젝트 편집, 항목 오른쪽 +는 해당 프로젝트의 일정 추가다.

상단 날짜 입력을 클릭하면 날짜 달력이 열린다. YYYY-MM-DD 직접 입력은 Enter나 포커스 이동으로 확정한다.
날짜를 선택하면 간트는 그 날짜를 날짜 영역 맨 왼쪽에 놓고, 달력은 해당 월에서 선택 날짜를 강조한다.
이 상단 탐색은 일정 추가 패널을 열지 않는다. 반면 날짜 눈금·빈 행·달력 날짜 클릭은 기존처럼 일정 추가를 연다.
이때 클릭 위치는 그대로 유지하고 선택 날짜만 강조한다. 다른 편집 항목으로 전환하면 기존 미저장 입력은 확인 없이 폐기한다.
이전/다음 달은 일자를 유지하되 없는 날은 해당 월 말일로 맞춘다. 새 실행은 오늘부터 시작한다.
달력 일정 드래그로 월을 탐색할 때는 선택 날짜를 바꾸지 않는다. 취소해도 탐색한 월은 남으며,
상단 날짜·오늘 등으로 다시 탐색하면 선택 날짜의 월로 맞춘다.

간트 날짜 영역에서 Ctrl+휠로 확대·축소한다. 기본 1일28px, 범위14~84px이며 마지막 배율을 기억한다.
포인터 아래 날짜를 기준으로 확대한다. 하단 배율 숫자를 클릭하거나 키보드로 실행하면 100%로 복귀하며 현재 왼쪽 날짜를 유지한다. 100%를 지나갈 때 자동으로 멈추지는 않는다. 일반 휠은 세로 이동, 가로 휠·Shift+휠은 가로 이동이다.
Space를 누른 채 왼쪽 마우스로 끌면 현재 표시 범위 안에서 가로 이동하며 일정 날짜를 바꾸지 않는다.
Space·마우스를 놓거나 Escape·창 포커스 이탈로 이동을 끝낸다. 달력은7열을 유지한다.

상단 프로젝트 추가·일정 추가·프로젝트 목록·간트·달력·오늘과 연결 상태·도움말 등의 설명 아이콘은 마우스 오버/키보드 탐색으로 툴팁을 확인한다. 테마 전환 버튼은 없다.
다른 버튼은 접근성 이름과 기존 텍스트를 유지한다. 프로젝트·월 선택기는 키보드로 조작할 수 있다.
날짜 선택기는 입력 옆에 겹쳐 열려 폼을 밀지 않는다. 중첩 목록은 Escape로 안쪽부터 닫는다.
한국어·월요일 시작, YYYY-MM-DD와0001~9999년 직접 입력을 지원한다.

## 창 숨김과 종료

0.6.8부터 X/Alt+F4는 질문 없이 창을 트레이로 숨긴다.
창 숨김은 편집 중인 입력·날짜·화면 위치·진행 중인 저장·일정 알림을 유지한다.
0.8.4의 ‘완전 종료’는 진행 저장을 안전하게 마무리하고 미저장 입력은 확인 없이 폐기한다. 완전히 종료하면 일정 알림을 보내지 않는다.
트레이 아이콘을 클릭하거나 메뉴의 ‘Open’를 선택하면 같은 창을 복원한다. 시작 메뉴에서 다시 실행해도 기존 창을 연다.
최소화 버튼은 작업 표시줄 최소화다.0.8.1부터 로그인 자동 실행을 선택할 수 있으며, 아래 자동 실행 안내를 따른다.

트레이 메뉴의 ‘Exit’도 같은 완전 종료 절차를 사용한다. Windows 설정에 따라 아이콘은 알림 영역 또는 숨겨진 아이콘에 표시된다.
트레이 생성 실패가 안내되면 닫기 선택창에서 완전 종료·취소만 제공한다.
트레이 메뉴의 ‘About’은 앱 아이콘·설치 버전·개발자 daeyong·저작권·설명을 보여준다. 편집 중 입력을 바꾸지 않는다.
OS 강제 종료나 전원 손실 때 저장하지 않은 입력까지 보존하는 기능은 아니다.

## 달력 미리보기와 창 크기 (0.5.0)

달력에서 일정을 끌거나 양 끝을 조절하면 원래 막대는 흐려지고, 예상 위치·기간은 반투명 막대로 표시된다.
포인터 옆에 예상 시작일·종료일이 나타난다. 겹친 일정의 3줄 제한과 별개로 미리보기를 표시하며,
화면에 보이는 인접 월 날짜에도 표시한다. 놓기 전에는 저장하지 않으며 영역 밖에 놓으면 취소한다.

기본 창 크기는 1707×890 논리 단위이며 Windows 배율과 모니터 작업 영역에 맞춰 줄어들 수 있다.
마지막 창 크기는 저장하지 않는다. 트레이 복원은 기존 창 크기를 유지한다.
간트의 배율과 가로 이동 막대는 작업 영역 맨 아래에 유지하며 본문만 세로로 스크롤한다.
편집 패널을 닫을 때 키보드 위치는 복원하되 툴팁은 자동으로 띄우지 않는다. 실제 마우스 오버·키보드 탐색에서는 표시한다.

## 일정 알림 (0.4.0)

일정 추가·편집의 날짜 아래에서 ‘며칠 전’과 ‘알림 시각’을 입력하고 시작일/종료일 알림을 선택한 뒤 저장한다.
초기값은 2일 전·09:00이며 둘 다 꺼져 있다. N은 주말·공휴일을 포함한 0~365일이고 0은 당일이다.
시작·종료는 같은 N과 시각을 사용한다. 시각은 PC 현지 24시간제 HH:mm이며 시간대가 바뀌면 현지 시각을 따른다.
예를 들어 11월 11일 시작·2일 전·09:00이면 11월 9일 오전 9시 이후 평가에서 알린다.

앱이 실행 중이거나 트레이에 있을 때 Windows 일반 알림을 보낸다. 트레이의 ‘Exit’를 선택한 뒤에는 보내지 않는다.
다시 실행하거나 절전에서 돌아오면 오늘 시각을 놓친 미처리 알림만 제공하며 어제 이전 것은 보내지 않는다.
같은 일정의 시작·종료가 같은 시각이면 하나로 합치며 여러 일정은 개별 전달한다.
Windows 알림 설정·방해 금지·회사 정책에 따라 배너와 소리가 제한될 수 있다. 반복해서 울리는 알람은 아니다.

알림에는 프로젝트명·일정명·대상 날짜가 표시되며 잠금 화면 노출 여부는 Windows 설정을 따른다.
실행 중 알림을 클릭하면 해당 일정 편집을 연다. 다른 미저장 입력이 있으면 확인 없이 폐기한다. 진행 중 저장은 안전하게 마무리한다.
완전히 종료된 앱을 과거 알림 센터 항목으로 다시 실행하는 동작은 지원하지 않는다.

날짜·N·시각을 변경하면 새 예정으로 평가한다. 이름 변경이나 동일 설정을 껐다 켜는 동작은 이미 처리한 알림을 반복하지 않는다.
간트·달력 드래그도 기존 알림을 유지한다. 알림 날짜가 0001-01-01 이전으로 내려가면 날짜 변경을 저장하지 않으므로 알림 설정을 먼저 조정한다.

전송 실패 안내의 ‘오늘의 실패한 알림 재시도’는 아직 켜져 있고 오늘 예정인 명확한 실패만 재시도한다.
결과 불명은 중복 방지를 위해 자동 재전송하지 않는다. 전송 직전 비정상 종료 때에는 알림이 누락될 수 있다.
Windows 전달과 사용자 읽음은 다르며 읽음 확인 기능은 없다.
0.4.0은 schema v2, 0.6.0은 공유용 v3, 0.6.9는 참여자 삭제용 v4, 0.7.0은 공유 변경 알림용 v5로 업그레이드한다. 업데이트한 DB를 구버전 앱으로 되돌려 여는 것은 지원하지 않는다. 업데이트 전 앱을 정상 종료한다.

## 시작 지연 확인

정상 재실행 목표는 창 표시 3초, 조회·편집 가능 5초다. 사용자 PC 달성 여부는 아직 미확인이다.
같은 PC·같은 데이터에서 시작 메뉴 클릭부터 두 시간을 각각 반복 측정한다.
`%APPDATA%\SimpleTimeline\startup-latest.json`에는 최근 실행의 프로세스 시작 이후 구간별 시간이 남는다.
0.2.1은 지연 원인을 좁히는 진단 보강판이다. 기본 GPU 설정을 유지하며 성능 개선 완료를 뜻하지 않는다.
`schemaVersion: 2`의 `stages`·`requests`는 main Node 시작 기준 ms이며, `renderer`는 페이지 navigation 시작 기준 ms다.
두 시계의 값을 직접 빼지 않는다. requests에는 파일 종류·시작/완료 시간만 남고 경로나 일정 내용은 없다.
`window-shown`은 창 표시 요청의 이벤트이며 사용자가 실제 화면을 본 시점과 같지 않다.
이 기록은 바로가기 클릭부터 Node 초기화 전까지의 Windows 대기 시간을 포함하지 않는다.
앱 버전·소스 SHA·수동 측정 시간과 함께 기록을 제공하면 어느 구간에서 지연됐는지 비교할 수 있다.
최초 실행·복구·마이그레이션은 정상 재실행과 구분한다. 일정 내용은 진단 기록에 넣지 않는다.

## Windows 11 인수와 상세 후속 확인 항목

기본 설치·실행·업데이트·제거·재설치는 [사용자 인수 기록](user-acceptance.md)에서 확인했다.
다음 상세 항목은 사용자의 결정에 따라 별도 후속 작업으로 남겼으며 통과로 표시하지 않았다.

운영 데이터가 없는 테스트 Windows 사용자/VM에서 확인한다. 정확한 설치 파일 이름·SHA256·Windows 빌드를 기록한다.

이후 업데이트/재설치, 제거 후 재설치의 데이터 보존을 확인한다. 100%/200% 배율·키보드·Narrator 결과도 기록한다.
손상·용량 부족·권한 실험은 운영 프로필에서 하지 않는다. 상세 절차·실행/미실행 구분은 검증 문서를 따른다.

## 사내 LAN 공유 (0.6.0)

트레이 메뉴는 연결 상태 / 구분선 / About / Windows 시작 시 자동 실행 / 전체 알림 끄기 / 구분선 / Open / Exit 순서다. 자동 실행 설정은 설치된 Windows 앱에서 제공한다.
0.8.8부터 맨 위 연결 상태는 표시 전용이다. 제목 표시줄 설정 → 공유 설정 탭으로 이동한다. 설정을 열어도 기존 개인 편집 입력은 유지된다.

1. 대표 PC 한 대에서 ‘호스트로 공유’를 고르고 실제 공유할 LAN IPv4와 포트를 명시해 저장한 뒤 ‘공유 시작’을 누른다.
   기본 포트는 TCP47831이다. 127.0.0.1은 이 PC에서만 쓰는 주소이므로 다른 PC 연결에는 쓰지 않는다.
2. 회사 정책에 따라 호스트 프로그램/선택 포트의 수신과 멤버의 송신을 사내망 범위로 허용한다. 방화벽을 끄지 않는다.
   정책 변경이 필요하면 IT 담당자에게 선택한 IP·포트를 전달한다. DHCP 주소 변경 시 등록 IP도 명시적으로 수정한다.
3. 호스트에서 참여자 이름과 멤버 PC의 실제 IPv4를 등록한다. 멤버는 ‘멤버로 연결’에서 호스트 IP·같은 포트를 입력한다.
4. 양쪽 화면의 전체64자리 SHA-256 지문이 같은지 비교한다. 호스트의 연결 승인과 멤버의 전체 지문 확인을 모두 완료한다.
   5분이 지나면 새 시도를 시작한다. 지문이 다르면 승인하지 말고 주소·대상 PC를 확인한다.
5. 호스트의 프로젝트 편집에서 공유 저장을 선택하고 각 참여자와 승인 PC를 연결해 확인한다.
   멤버는 자신에게 허용한 프로젝트만 받으며 원본 이름·참여자·날짜·삭제·드래그는 읽기 전용이다.
   멤버는 개인 프로젝트/일정을 계속 편집하고 공유 일정의 자기 알림만 저장한다. 이 알림은 다른 PC로 보내지 않는다.

멤버의 연결 상태는 PlanRail 하단에 표시된다. 연결 상태에 포인터를 올리거나 키보드로 초점을 옮기면 마지막 정상 확인 시각을 볼 수 있다. 초록은 최근 정상 확인과 저장 완료, 빨강은 미확인·연결 오류·승인 취소다.
정상 폴링은2초, 요청 제한5초, 재연결 간격은2/4/8/16/30초이며 정상 확인 후7초를 넘겨 확인하지 못하면 빨강이다.
‘수동 동기화’는 간트/달력 바로 왼쪽이며 정상 수신과 화면 반영을 마친 뒤에만 성공을 표시한다.
전체/개인/공유 필터는 간트·달력·프로젝트 목록에 함께 적용한다. 연결 실패가 개인 저장을 막지는 않는다.
개인 일정 드래그 중에는 도착한 공유 수정·추가가 화면 위치를 흔들지 않도록 종료 뒤 반영한다.
공유 삭제·권한 회수가 확인되면 활성 미리보기를 저장 없이 취소하고 안내한 뒤 제거한다. 알림 권한 확인은 지연하지 않는다.

호스트가 멈추거나 잠들거나 앱을 완전히 종료하면 공유 제공이 중단된다. 자동 절전 방지·Windows 서비스는 없다. 로그인 자동 실행을 켜면 로그인 후 트레이에서 공유 상태를 복원한다.
‘공유 중지’ 상태는 재시작해도 유지하며 공유 중 종료했다면 다음 실행에 재개한다.
오래된 공유 수신본은 연결 오류 때 읽을 수 있지만 최신 확인 없이는 공유 알림을 보내지 않는다.
명시적 승인 취소나 프로젝트 접근 제거가 확인되면 해당 공유 자료·자기 알림을 제거한다.
멤버의 ‘연결 해제’는 확인 후 공유 캐시·자기 공유 알림·접속 자격만 지우며 개인 자료는 유지한다.
삭제 실패 안내가 있으면 파일 접근을 확인하고 ‘연결 해제 다시 시도’를 실행한다.
역할은 자동 전환하지 않고 호스트 이전·다른 호스트로의 자동 이동은 지원하지 않는다.

Linux의 두 격리 프로필 loopback 자동 검증은 실제 회사 LAN·Windows DPAPI·트레이 배율·알림 실기 인수를 대신하지 않는다.
Windows 11 테스트 PC에서 설치 파일 SHA·IP/포트·방화벽 범위·전체 지문·재시작/절전·승인 취소·6대/10프로젝트/60일정의5초 내 전파를 별도 확인한다.
자세한 자동 검증 범위와 남은 인수는 [구현 기록](../implementation/2026-11-10-lan-sharing.md)을 따른다.

## 다크 화면과 간트 탐색 (0.6.7)

간트 하단은 배율 조절과 가로 이동을1:8 비율로 나눈다. 왼쪽은 배율 슬라이더다. 50~300%로 조절하고 배율 숫자를 누르면100%로 돌아온다.
슬라이더를 움직일 때 왼쪽 날짜는 유지되며, Ctrl+휠은 포인터 아래 날짜를 유지한다. 배율은 재실행 후에도 유지한다.
오른쪽은 가로 이동 막대다. 기존 휠·Space+드래그·키보드 탐색도 계속 사용할 수 있다.
일반 스크롤바는 평소 숨겨져 있다가 해당 영역에 마우스를 올리거나 키보드 포커스가 들어오면 나타난다. 드래그 중에도 표시하며 배율 슬라이더는 탐색 영역에서 항상 보인다. 공유 필터에 프로젝트가 하나도 없으면 중앙 안내만 남기고 기간·날짜 눈금·하단 탐색을 숨긴다. 일정이 없는 공유 프로젝트는 행과 추가 동작을 유지한다.
토요일·일요일은 간트 날짜 눈금과 날짜 열에 옅은 붉은 배경으로 표시한다. 일정 색과 기간 계산은 유지한다.
호스트의 프로젝트 편집에서 ‘공유 프로젝트로 저장’은 스위치로 조작한다. 기존처럼 저장 버튼과 공유 확인을 거쳐야 반영된다.


## 저장 진행과 입력 오류 (0.6.7)

프로젝트·일정 추가/수정/삭제나 드래그 저장 중에는 콘텐츠를 잠시 덮고 툴바 위 얇은 막대로 진행 상태를 표시한다. 숫자 퍼센트는 표시하지 않는다. 창 이동·최소화는 사용할 수 있고 동기화만 진행 중일 때는 이 덮개를 표시하지 않는다.
저장 시 잘못된 값이 있으면 해당 입력 아래 작은 안내와 붉은 테두리를 표시하고 첫 오류로 이동한다. 값을 수정하면 다시 검사한다. DB·통신 오류나 저장 결과 불명 안내는 필드 오류와 별도로 유지되며, 안내에 따라 조회 후 처리한다.
프로젝트의 기본 정보·참여자·공유 설정은 구분선으로 나뉜다. 공유 대상 PC 선택은 각 참여자 이름 아래에서 한다. 공유 설정 창은 오른쪽 X로 닫으며 저장하지 않은 입력은 확인 없이 폐기한다.


## 목록 삭제와 알림 간편 편집 (0.6.8)

프로젝트 목록의 일정 추가 옆 휴지통을 누르면 프로젝트명과 하위 일정 수를 확인한 뒤 함께 삭제한다. 되돌리기는 제공하지 않는다. 멤버가 받은 공유 프로젝트는 삭제할 수 없다. 편집 패널과 목록 모두 한 번 확인한다.

간트에서 알림이 켜진 일정 이름 옆의 종 아이콘을 누르면 자신의 알림만 수정하는 작은 팝업이 열린다. N일 전·시각·시작/종료를 수정하고 저장한다. 둘 다 끄면 종 아이콘은 사라지며, 다시 켜려면 일정 편집을 사용한다. 미저장 편집이 있으면 먼저 저장하거나 취소해야 목록 삭제·빠른 알림 편집을 할 수 있다. 빠른 팝업의 변경을 저장하지 않고 닫으면 확인 없이 폐기한다.

### 참여자 입력·삭제와 작은 알림 스위치 (0.6.9)

공유 설정에서 이름과 IPv4 주소를 입력해 등록합니다. 잘못된 값이나 이미 사용 중인 IP는 입력 아래 안내를 확인하세요. 등록 항목과 ‘새 참여자’ 입력은 구분되어 있습니다. 0.6.10부터 이름·IP·작업 버튼을 한 줄로 표시하며 ‘승인’, ‘승인 대기’, ‘승인 취소’ 배지로 연결 승인 상태를 구분합니다.

참여자 옆 휴지통은 영향받는 공유 프로젝트를 확인한 후 등록과 모든 공유 권한을 제거합니다. 프로젝트와 일정은 지우지 않습니다. ‘승인 취소’는 등록 정보를 남기므로 차단 기록을 유지할 때 사용하세요. 삭제 후 다시 공유하려면 새로 등록하고 승인해야 합니다. 오프라인 멤버는 다음 접속 때 권한 회수를 확인합니다.

일정과 빠른 알림 설정의 시작일/종료일 옵션은 종 아이콘 옆 작은 스위치로 조작하고 저장합니다.


## 공유 변경 알림 (0.7.0)

호스트가 공유 프로젝트를 새로 공유하거나 이름을 바꾸고, 공유 일정을 추가·이름/기간 변경·삭제하면 해당 자료를 공유받는 멤버에게 Windows 일반 알림을 요청한다. 호스트 저장과 멤버의 최신 자료 반영이 성공한 뒤에만 알린다. 색상·참여자 표시 이름·자기 일정 알림만 바꾼 경우에는 변경 알림을 보내지 않는다.

멤버의 제목 표시줄 설정 → 공유 설정 탭을 연 뒤 ‘공유 변경 알림’ 스위치로 받기를 선택한다. 기본값은 켜짐이며 PC에 저장된다. 꺼도 자료 동기화와 날짜 기반 시작일/종료일 알림은 계속 동작한다. 다시 켜면 다음 정상 동기화가 새 기준점이 되고 그 뒤의 변경부터 알린다. 꺼 두었던 동안의 변경은 소급하지 않는다.

첫 연결 또는 이 기능을 처음 사용하는 업데이트에서는 현재 공유 프로젝트 수를 요약한 한 건만 알린다. 공유 프로젝트가 없으면 알리지 않는다. 이후에는 같은 수신 묶음의 같은 프로젝트 변경을 합치고, 연결이 끊겼다가 돌아오면 프로젝트별로 요약한다. 같은 일정을 여러 번 수정해도 한 건이며, 수신 전에 추가했다 삭제한 일정은 생략한다. 호스트 기록은 최근30일까지만 사용하므로 오래된 누락은 건수 대신 최신 갱신 안내로 표시한다.

공유 종료가 확인되면 프로젝트명·일정명을 넣지 않은 공통 안내를 보낸다. 잠시 연결이 끊긴 것만으로 공유 종료를 알리지는 않는다. 권한이 회수된 수신 자료는 알림 설정과 관계없이 제거한다. 이미 Windows에 제출한 알림 센터의 과거 내용까지 회수할 수 있다고 보장하지는 않는다.

일정 변경 알림을 누르면 해당 일정으로, 프로젝트 공유·요약은 해당 프로젝트가 보이는 화면으로 이동한다. 삭제된 대상이나 공유 종료는 현재 프로젝트 목록을 연다. 간트/달력 모드는 유지하고 다른 미저장 입력은 확인 없이 폐기한다. 이미 시작된 저장은 안전하게 마무리한다. 멤버의 공유 자료는 계속 읽기 전용이며 자기 일정 알림만 바꿀 수 있다.

앱 실행·트레이 상태에서만 알림을 전달한다. 실제 배너·소리·잠금 화면 표시는 Windows 알림 설정과 회사 정책을 따른다. 확실한 전달 실패는 별도 안내에서 재시도할 수 있지만, 결과 불명은 중복 방지를 위해 자동 재전송하지 않는다. 구버전 호스트에서는 기존 자료 동기화를 유지하며 변경 알림을 사용하려면 양쪽 업데이트가 필요하다고 안내한다.

검증 범위와 Windows 실기 확인 항목은 [구현 기록](../implementation/2026-11-11-shared-change-notifications.md)을 따른다. 자동 앱 업데이트는 이 기능에 포함하지 않는다.

## 호스트를 통한 앱 업데이트 (0.8.0)

처음에는 호스트와 멤버 모두0.8.0 이상 설치 파일을 한 번 수동 설치해야 한다. 기존0.7.0에는 UPDATE 기능이 없다. 실제 Windows11 자동 설치·재실행 인수는 아직 미검증이며 [검증 범위](../implementation/2026-11-11-lan-app-updates.md)를 확인한다.

호스트는 먼저 새 정식 버전을 수동 설치한다. Application Actions의 같은 커밋에서 **`WorkRail-LAN-UPDATE-<소스 SHA>` artifact ZIP**을 다운로드한다. 이 ZIP은 GitHub가 제공하며 루트에 설치 파일·blockmap·`latest.yml`·manifest·체크섬·안내 파일을 담는다. 다운로드한 ZIP을 그대로 사용한다. 설정 → 기본 설정 → 업데이트 배포에서 ‘업데이트 ZIP 가져오기’로 검사하고, 등록 버전·용량을 확인한 뒤 별도로 ‘배포 시작’을 누른다. 공유 서버가 꺼져 있으면 먼저 ‘공유 시작’을 누른다. 호스트 설치만으로 파일이 등록되지는 않는다. 등록 실패 시 기존 배포는 유지된다. UPDATE-TEST-ONLY 파일은 배포할 수 없다.

승인된 멤버는 연결·재연결과 연결 중5분마다 새 버전을 확인한다. 프로젝트를 공유받지 않은 승인 멤버도 대상이다. 새 버전이 있으면 WorkRail 제목 옆에 UPDATE가 나타난다. 한 번 누르면 다운로드·검증을 시작하고 다운로드 중 편집할 수 있다. 진행 창을 닫아도 다운로드는 계속되며 취소와 재시도는 진행 창에서 누른다. 불완전 파일은 정리하고 재시도는 처음부터 시작한다.

0.8.4부터 다운로드·검증 뒤 진행 중 저장을 마무리하고 프로젝트·일정·알림·공유 설정·참여자의 미저장 입력을 확인 없이 폐기한 뒤 자동 설치·재실행한다. 저장 결과를 안전하게 확인할 수 없으면 설치를 중단하고 재시도를 안내한다. 앱을 다시 열어도 검증된 대기 파일은 유지되며 명시적으로 설치해야 한다. 평소 Exit로 종료할 때는 설치하지 않는다.

호스트 연결이 끊기면 알고 있는 UPDATE를 비활성으로 표시한다. 이미 검증한 대기 파일은 연결 신원이 그대로일 때 오프라인 설치할 수 있다. 배포 중지·교체·연결 승인 취소를 확인하면 이전 다운로드와 대기를 취소한다. 호스트가 배포를 중지해도 설치된 앱을 되돌리지는 않는다. 설치 종료 준비가 실패해 편집이 차단되면 앱을 종료한 뒤 다시 열어 현재 버전과 안내를 확인한다. 설치 중에는 동기화와 알림이 잠시 중단된다.


## 오프라인 도움말 (0.8.4)

최상단 설정 버튼 왼쪽의 물음표를 누르면 별도 도움말 창이 열립니다. 처음에는 현재 역할에 맞는 항목을 보여주며, 왼쪽 목차에서 다른 역할의 설명도 볼 수 있습니다. 프로젝트·일정 추가/수정/삭제, 간트 Space+드래그·Ctrl+휠·배율, 달력, 알림, 트레이, 공유·업데이트와 문제 해결을 설명한다. 제목·본문을 검색하고 화면 이미지를 눌러 확대·축소·이동할 수 있습니다. Escape는 확대 보기를 닫습니다. 인터넷 연결은 필요하지 않습니다.

도움말을 다시 누르면 기존 창이 앞으로 나옵니다. 도움말은 주 화면 준비 뒤 미리 준비한다. 도움말의 X는 창을 숨겨 재사용하며 같은 앱 실행 중에는 마지막 항목·검색어·읽기 위치를 기억합니다. 주 창의 편집 입력은 그대로 유지됩니다. 주 창을 트레이로 숨기면 열린 도움말도 숨겨지고 주 창을 다시 열면 함께 복원됩니다. 각 창의 최소화는 독립적으로 동작합니다.

트레이 Exit·업데이트 설치로 앱이 완전히 종료되면 도움말도 닫힙니다. 앱을 다시 실행하면 현재 역할의 첫 항목부터 시작합니다. 도움말의 이름·IP·일정은 예시이며 실제 연결에는 자기 PC와 호스트의 값을 사용하세요.

## Windows 로그인 시 자동 실행 (0.8.1)

설치 화면의 ‘Windows 로그인 시 WorkRail 자동 실행’은 처음 선택할 때 체크되어 있다. 현재 Windows 사용자에게만 적용하며 로그인 전에는 실행하지 않는다. 설치 완료 화면의 ‘WorkRail 실행’은 이번 한 번 실행하는 별도 선택이다.

자동 실행하면 창을 열지 않고 트레이에서 시작한다. 공유 시작·중지의 마지막 선택을 유지하고, 기존 동기화·알림이 동작한다. Open이나 바로가기로 창을 열 수 있다. 트레이 생성 실패·DB 오류처럼 조치가 필요한 시작 문제가 생기면 창을 표시하며, 일시적인 호스트 연결 끊김만으로 창을 띄우지는 않는다.

트레이의 ‘Windows 시작 시 자동 실행’ 체크 항목으로 상태를 확인·변경한다. Windows 작업 관리자에서 시작 앱을 사용 중지했다면 그 상태를 존중한다. 앱에서 직접 다시 켰을 때만 재활성화한다. 개발 실행에서는 시작 앱 등록을 제공하지 않는다.

재설치는 이전 선택을 표시한다. UPDATE를 통한 무인 업데이트는 설정을 유지하며,0.8.0처럼 설정이 없던 PC에 자동으로 켜지 않는다. 앱에서 원하는 경우 직접 켤 수 있다. Exit는 현재 앱만 종료하므로 다음 로그인 자동 실행 설정은 유지된다. 실제 앱 제거 시 자동 실행 등록을 정리하고 일정 DB는 보존한다.


## 알림 제어와 접속 멤버 (0.8.3)

새 버전을 확인하면 멤버에 Windows 업데이트 알림을 한 번 제공한다. 같은 호스트의 같은 버전은 재실행·재배포·재승인으로 반복하지 않는다. 알림 클릭은 창과 UPDATE 안내만 열며 다운로드하지 않는다. 열린 확인창이 있으면 닫은 뒤 안내를 보여주고 편집 입력은 유지한다. UPDATE 또는 안내의 업데이트 다운로드 버튼으로 받기를 시작한다. 호스트만 업데이트해도 구버전 멤버에 이 기능이 생기지는 않는다.

트레이의 Windows 시작 시 자동 실행 아래 ‘전체 알림 끄기’를 체크하면 해당 PC의 개인·공유 일정 날짜 알림, 공유 변경/종료, 업데이트 Windows 알림을 모두 끈다. 기본은 해제이며 선택은 재실행 후 유지한다. 동기화·UPDATE·저장 결과·오류 안내는 유지한다. 무음 해제 후 첫 정상 공유/업데이트 조회까지는 지난 알림을 소급하지 않는다. 개별 알림 설정은 보존하고 기존 Windows 알림 센터 항목은 삭제하지 않는다.

호스트 공유 설정의 참여자 목록에서 연결 수, 각 PC의 연결됨/연결 끊김, 마지막 접속 확인 시각을 볼 수 있다. 승인 배지는 연결 중이라는 뜻이 아니다. 최근10초 이내 인증된 정상 동기화 응답이 완료된 PC만 연결됨이며, 트레이 실행도 포함한다. 공유 중지·승인 취소·IP 수정·절전 후에는 새 통신 전까지 연결되지 않은 상태다. 마지막 시각은 호스트의 현지 시각이고 재실행 후 초기화된다. 구버전 멤버도 기존 동기화로 집계된다.

자동 실행 체크는 Windows의 실제 설정을 조회한 후 우클릭 메뉴에 한 번 표시한다. 조회에 실패하면 ‘자동 실행 상태 확인 불가’가 나타나며 Open·Exit 등은 계속 사용할 수 있다.

## 편집·탐색 변경 (0.8.4)

프로젝트·일정 패널, 빠른 알림, 공유 설정을 닫거나 다른 항목으로 이동하면 미저장 입력을 확인 없이 버립니다. 트레이 Exit도 초안을 버리지만, 이미 시작된 저장은 안전하게 마무리합니다. 주 창 X·Alt+F4는 트레이 숨김이므로 입력을 유지합니다.

미저장 상태의 드래그·빠른 삭제/알림 편집은 계속 차단하며 ‘먼저 저장하거나 변경을 버려주세요.’를 우측 하단 경고 토스트로4초 표시합니다. 먼저 저장하거나 패널을 닫으세요. 필드 유효성 및 DB·통신·저장 실패는 기존 지속 안내를 확인하세요.

간트 하단 가로 스크롤·배율 슬라이더에 포커스가 있어도 Space+마우스 드래그로 날짜 영역을 이동합니다. 텍스트 입력의 공백과 범위 입력의 방향키 동작은 유지합니다. 제목 옆 호스트/멤버 배지는 역할이며 연결 여부와 별개입니다. 개인 전용은 배지를 숨깁니다.

도움말 성능은 `%APPDATA%\SimpleTimeline\help-latest.json`에 최근20회 클릭·표시·본문 준비 시간을 기록합니다. `shownMs-clickedMs`가 창 표시 시간, `readyMs-clickedMs`가 본문 준비 시간입니다. 준비 완료는 읽기 상태 반영 뒤 두 프레임 기준이며 회사 PC에서의 체감 성능과 함께 확인하세요. 목표는 각각1초/3초이고, 해당 PC 실측 전 달성을 보장하지 않습니다.

공유 설정 저장의 응답이 끊겨 결과를 알 수 없으면 그 실행 중에는 UPDATE 설치를 막습니다. 일반 동기화나 다른 설정 저장 성공만으로 이전 저장 결과를 추정하지 않습니다. 앱을 완전히 종료·재실행하여 실제 공유 설정을 확인한 뒤 설치를 다시 시도하세요.


## 릴리즈노트와 저장 확인 (0.8.5)

제목 표시줄에서 도움말 왼쪽 문서 아이콘을 누르면 릴리즈노트 창을 연다. 0.8.0부터 버전별 Feat·Fix·Perf·Docs 중 실제 변경이 있는 항목만 표시한다. 도움말과 동시에 사용할 수 있으며 X는 숨김/재사용이다. 다시 열면 읽던 버전·위치를 유지한다. 트레이로 함께 숨긴 창만 주 창과 함께 복원한다.

일정 추가·수정·삭제, 간트/달력의 이동·기간 변경, 일정 알림 저장은 한 번 확인한다. 드래그는 변경 전후 날짜를 확인하고, 취소하면 원래 날짜로 유지한다. 폼 확인을 취소하면 작성 중 입력을 유지한다. 프로젝트 편집과 목록 삭제는 프로젝트명·하위 일정 수를 확인한 뒤 함께 삭제한다. 확인 단계에서는 아직 저장하지 않는다. 잘못된 필드는 확인창보다 먼저 안내한다.

패널을 저장하지 않고 닫거나 다른 항목으로 전환할 때의 무조건 폐기는 그대로다. 주 창 X는 입력을 유지한 트레이 숨김이다. 도움말의 최초 로딩 지연은 구간 진단을 추가한 상태이며, 13초 지연이 해결됐다는 의미는 아니다.


## 설정·개인 휴일·워킹데이 (0.8.8)

제목 표시줄은 릴리즈노트·도움말 | 설정 | 최소화·최대화·닫기 순서다.
트레이 연결 상태는 표시만 유지한다. 설정 톱니바퀴를 누르면 기본 설정 탭이 열리고,
공유 설정 탭에서 기존 연결·참여자·승인·공유 변경 알림을 관리한다.
승인 요청 알림은 공유 설정의 승인 목록으로 바로 이동한다.

- 기본 설정: 호스트는 업데이트 배포·공통 휴일·개인 휴일, 멤버는 개인 휴일·공통 휴일 조회, 개인 전용은 개인 휴일을 제공한다.
- 탭 이동은 입력을 유지한다. 각 저장 버튼은 해당 설정만 저장하며 X·Escape 닫기는 미저장 입력을 폐기한다.
- 개인 휴일은 모든 역할에서 이 PC에만 보관한다. 호스트의 개인 휴일도 다른 멤버에게 전달하지 않는다.
- 공통+개인 휴일을 모든 보기와 일정에 합산한다. 반복 요일 기본값은 토·일이며 날짜별 기간은 양 끝 포함이다. 같은 출처의 기간 겹침은 금지하고 다른 출처의 겹침은 허용한다.
- 날짜별 휴일은 삼각형에 마우스/키보드 포커스를 두어 공통·개인 이름을 확인한다. 반복 요일은 배경만 표시한다. 휴일 변경 알림은 보내지 않는다.
- 일정 패널에 `총 기간: xx일, 워킹데이: xx일`을 표시한다. 워킹데이는 합산 휴일을 한 번씩 제외하며0일도 가능하다. PC별 개인 휴일이 다르면 같은 공유 일정의 워킹데이도 다를 수 있다. 일정 날짜와 날짜 알림은 이동하지 않는다.
- 연결 해제·승인 취소는 수신 공통 휴일만 제거하며 개인 휴일은 보존한다. 호스트 역할을 설정해도 개인 휴일을 자동 공개하지 않는다.


공통 표에서 토요일을 해제했는데 계속 붉게 보인다면 개인 표의 반복 요일도 확인한다. 한 표라도 해당 요일을 휴일로 지정하면 적용된다. 같은 날짜를 두 표에 등록해도 워킹데이에서 두 번 빼지 않는다.
날짜별 휴일은 한 표당 최대 1,000항목이며, 기간에 포함된 총 날짜도 1,000일까지다. 종료일을 포함하며 하루 휴일은 시작일과 종료일을 같게 지정한다. 휴일 삭제는 해당 표의 항목만 제거한다.
