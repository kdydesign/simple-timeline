# Simple Timeline — Windows 설치·사용 안내

대상은 Windows 11 x64다. 현재 사용자에게만 설치하며 관리자 권한을 요구하지 않는다.
첫 설치본은 서명하지 않은 비공개 검증용이다. 자동 업데이트·로그인·동기화·수동 백업/복원은 없다.

## 내려받기와 확인

GitHub 저장소의 Application Actions에서 해당 커밋의
`SimpleTimeline-Windows11-x64-unsigned-<소스 SHA>` artifact를 내려받아 ZIP을 푼다.
설치 파일은 `SimpleTimeline-<버전>-win-x64-<소스 SHA>.exe`다.
`release-manifest.json`의 버전·소스 SHA·SHA256과 함께 제공한 `.sha256` 파일을 확인한다.
PowerShell의 `Get-FileHash -Algorithm SHA256 <설치파일>` 결과가 일치해야 한다.
CI의 가상 다음 버전 설치 파일은 UPDATE-TEST-ONLY라는 별도 비공개 artifact다. 업데이트 검증용 Windows 사용자/VM에서만 사용하며 일반 사용자 배포본이 아니다.

## 설치와 제거

설치 파일을 실행하면 현재 사용자용으로 설치한다. 완료 화면에서 기본 체크된 `Simple Timeline 실행`을
그대로 두고 `마침`을 누르면 실행한다. 체크를 해제하면 설치만 마치며 시작 메뉴에서 나중에 열 수 있다.
Windows가 알 수 없는 게시자/SmartScreen 경고를 표시할 수 있다.
저장소·커밋·해시를 확인하고 신뢰하는 파일인지 판단한 뒤 Windows 안내에 따라 실행한다.
보안 기능을 전역으로 끌 필요는 없다. 정책으로 실행이 막히면 그 상태를 알려준다.

설치 기본 위치는 사용자 LocalAppData의 Programs 아래다. 실제 위치는 CI 설치 검증 기록과 설치된 바로가기로 확인한다.
Windows 설정의 설치된 앱에서 Simple Timeline을 제거할 수 있다. **제거해도 일정 DB는 남는다.**
같은 앱을 재설치하면 보존한 데이터로 시작한다. 앱 제거는 데이터 삭제 방법이 아니다.

## 데이터와 오프라인 사용

일정 DB는 `%APPDATA%\SimpleTimeline\data\timeline.sqlite3`다.
앱·설치 파일 폴더와 별개이며 일반 업데이트·재설치·제거 때 보존한다.
앱을 실행 중인 상태에서 DB 한 파일 복사를 일관된 백업으로 보장하지 않는다.
수동 백업·복원·다른 PC 이동 기능은 MVP에서 제외했다. 내부 migration 사본도 디스크 손실 복구를 보장하지 않는다.

앱 설치·조회·추가·수정·삭제에는 인터넷이 필요하지 않다.
개발 도구 설치와 CI 빌드의 다운로드는 사용자 앱의 오프라인 실행과 구분한다.
업데이트는 새 설치 파일을 직접 실행한다. 앱을 닫고 기존 DB를 보존한 채 진행한다.

## 기본 사용

1. 프로젝트 추가에서 이름·색상·참여자를 저장한다.
2. 일정 추가에서 이름·시작일·종료일을 저장한다. 양 끝 날짜를 포함하며 같은 날은 하루다.
3. 간트/달력을 전환한다. 간트는 전체 일정 범위, 달력은 선택 월을 보여준다.
4. 이름 또는 막대로 편집한다. 달력의 더 보기는 해당 날짜 전체 일정을 연다.
5. 프로젝트 삭제는 소속 일정도 함께 삭제하므로 확인 내용을 읽는다.

간트 가로 손잡이는 좌우 하루, PageUp/Down 한 화면, Home/End 처음/끝 이동이다.
간트 이름 버튼과 날짜 전체 목록에서는 위아래 키로 화면 밖 항목에도 접근한다.
오류·결과 불명 안내가 나오면 입력을 유지하고 다시 조회한다. 같은 생성을 자동 재전송하지 않는다.
DB 손상·초기화 실패 안내가 나오면 원본을 지우거나 빈 DB로 대체하지 말고 안내 경로와 오류를 기록한다.

## 추가 편집·화면 기능 (0.2.0)

- 상단에서 라이트·다크를 전환한다. 초기값은 라이트이며 선택은 재실행 후에도 유지된다.
- 달력의 날짜나 간트 날짜 눈금·빈 행을 클릭하면 그 날짜로 일정 추가 패널이 열린다. 간트 행의 프로젝트를 우선한다.
- 시작일·종료일 옆 달력에서 날짜를 고르거나 YYYY-MM-DD로 입력한다. 저장 버튼으로 확정한다.
- 간트 프로젝트 왼쪽 화살표로 접고 펼친다. 접힌 상태를 기억하며 달력의 일정은 숨기지 않는다.
- 막대 몸통을 끌면 기간을 유지하며 이동한다. 실제 시작·끝의 손잡이는 해당 날짜만 바꾼다.
  여러 주로 나뉜 막대의 중간 경계는 손잡이가 아니다. 놓으면 저장하며 Escape·영역 밖 드롭으로 취소한다.
  미저장 입력이 있으면 먼저 저장하거나 버린다. 간트 가장자리는 자동 스크롤, 달력 이전/다음 월 버튼 위 대기는 월 이동이다.
- `오늘`은 현재 월로 바꾸고 간트에서 오늘을 중앙에 표시한다. 일정 전체도 계속 포함한다.
- 성공 알림은 우측 하단에 2초 표시한다. 조치가 필요한 오류는 사라지지 않는다.

## 시작 지연 확인

정상 재실행 목표는 창 표시 3초, 조회·편집 가능 5초다. 사용자 PC 달성 여부는 아직 미확인이다.
같은 PC·같은 데이터에서 시작 메뉴 클릭부터 두 시간을 각각 반복 측정한다.
`%APPDATA%\SimpleTimeline\startup-latest.json`에는 최근 실행의 프로세스 시작 이후 구간별 시간이 남는다.
이 기록은 바로가기 클릭부터 프로세스가 생성되기 전까지의 Windows 대기 시간을 포함하지 않는다.
앱 버전·소스 SHA·수동 측정 시간과 함께 기록을 제공하면 어느 구간에서 지연됐는지 비교할 수 있다.
최초 실행·복구·마이그레이션은 정상 재실행과 구분한다. 일정 내용은 진단 기록에 넣지 않는다.

## Windows 11 인수와 상세 후속 확인 항목

기본 설치·실행·업데이트·제거·재설치는 [사용자 인수 기록](user-acceptance.md)에서 확인했다.
다음 상세 항목은 사용자의 결정에 따라 별도 후속 작업으로 남겼으며 통과로 표시하지 않았다.

운영 데이터가 없는 테스트 Windows 사용자/VM에서 확인한다. 정확한 설치 파일 이름·SHA256·Windows 빌드를 기록한다.
네트워크를 끊고 설치→첫 실행→핫픽스 프로젝트와 개발/QA/배포 일정 생성→두 모드→수정·삭제→종료/재실행을 확인한다.
이후 업데이트/재설치, 제거 후 재설치의 데이터 보존을 확인한다. 100%/200% 배율·키보드·Narrator 결과도 기록한다.
손상·용량 부족·권한 실험은 운영 프로필에서 하지 않는다. 상세 절차·실행/미실행 구분은 검증 문서를 따른다.
