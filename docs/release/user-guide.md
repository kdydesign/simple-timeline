# Planrail — Windows 설치·사용 안내

대상은 Windows 11 x64다. 현재 사용자에게만 설치하며 관리자 권한을 요구하지 않는다.
첫 설치본은 서명하지 않은 비공개 검증용이다. 자동 업데이트·클라우드 로그인·수동 백업/복원은 없다. 0.6.0은 선택적인 사내 LAN 공유를 제공한다.

## 내려받기와 확인

GitHub 저장소의 Application Actions에서 해당 커밋의
`Planrail-Windows11-x64-unsigned-<소스 SHA>` artifact를 내려받아 ZIP을 푼다.
설치 파일은 `Planrail-<버전>-win-x64-<소스 SHA>.exe`다.
`release-manifest.json`의 버전·소스 SHA·SHA256과 함께 제공한 `.sha256` 파일을 확인한다.
PowerShell의 `Get-FileHash -Algorithm SHA256 <설치파일>` 결과가 일치해야 한다.
CI의 가상 다음 버전 설치 파일은 UPDATE-TEST-ONLY라는 별도 비공개 artifact다. 업데이트 검증용 Windows 사용자/VM에서만 사용하며 일반 사용자 배포본이 아니다.

## 설치와 제거

설치 파일을 실행하면 현재 사용자용으로 설치한다. 완료 화면에서 기본 체크된 `Planrail 실행`을
그대로 두고 `마침`을 누르면 실행한다. 체크를 해제하면 설치만 마치며 시작 메뉴에서 나중에 열 수 있다.
Windows가 알 수 없는 게시자/SmartScreen 경고를 표시할 수 있다.
저장소·커밋·해시를 확인하고 신뢰하는 파일인지 판단한 뒤 Windows 안내에 따라 실행한다.
보안 기능을 전역으로 끌 필요는 없다. 정책으로 실행이 막히면 그 상태를 알려준다.

신규 기본 설치 위치는 `%LOCALAPPDATA%\Programs\Planrail`이며 설치 화면에서 현재 사용자가 쓸 수 있는 폴더를 선택한다.
기존 앱을 업데이트하면 기존 설치 위치를 기본으로 재사용한다. 예전 폴더 이름을 강제로 바꾸지 않는다.
쓰기 권한이 없는 폴더 대신 사용자 폴더를 선택한다. 관리자 승격이나 전체 사용자 설치는 제공하지 않는다.
Windows 설정의 설치된 앱에서 Planrail을 제거할 수 있다. **제거해도 일정 DB는 남는다.**
같은 앱을 재설치하면 보존한 데이터로 시작한다. 앱 제거는 데이터 삭제 방법이 아니다.

## 데이터와 오프라인 사용

일정 DB는 `%APPDATA%\SimpleTimeline\data\timeline.sqlite3`다.
앱·설치 파일 폴더와 별개이며 일반 업데이트·재설치·제거 때 보존한다.
앱을 실행 중인 상태에서 DB 한 파일 복사를 일관된 백업으로 보장하지 않는다.
수동 백업·복원·다른 PC 이동 기능은 MVP에서 제외했다. 내부 migration 사본도 디스크 손실 복구를 보장하지 않는다.

앱 설치·조회·추가·수정·삭제에는 인터넷이 필요하지 않다.
개발 도구 설치와 CI 빌드의 다운로드는 사용자 앱의 오프라인 실행과 구분한다.
업데이트는 새 설치 파일을 직접 실행한다. **설치·업데이트·제거 전에는 트레이에서 ‘Exit’를 선택한다.**
X 버튼의 선택창에서 ‘트레이로 보내기’를 선택한 경우에는 실제 종료가 아니다. 설치기가 실행 중 앱을 강제로 끝내면 미저장 입력은 보존되지 않을 수 있다.

## 기본 사용

1. 프로젝트 추가에서 이름·색상을 저장한다. 참여자 이름은 호스트만 관리하며 개인 전용·멤버는 기존 이름을 읽기 전용으로 보존한다.
2. 일정 추가에서 이름·시작일·종료일을 저장한다. 양 끝 날짜를 포함하며 같은 날은 하루다.
3. 간트/달력을 전환한다. 간트는 전체 일정과 탐색한 달 범위, 달력은 선택 날짜의 월을 보여준다.
4. 이름 또는 막대로 편집한다. 달력의 더 보기는 해당 날짜 전체 일정을 연다.
5. 프로젝트 삭제는 소속 일정도 함께 삭제하므로 확인 내용을 읽는다.

간트 가로 손잡이는 좌우 하루, PageUp/Down 한 화면, Home/End 처음/끝 이동이다.
간트 이름 버튼과 날짜 전체 목록에서는 위아래 키로 화면 밖 항목에도 접근한다.
오류·결과 불명 안내가 나오면 입력을 유지하고 다시 조회한다. 같은 생성을 자동 재전송하지 않는다.
DB 손상·초기화 실패 안내가 나오면 원본을 지우거나 빈 DB로 대체하지 말고 안내 경로와 오류를 기록한다.

## 추가 편집·화면 기능 (0.2.0)

- 0.6.5부터 다크 모드만 제공한다. 기존 라이트 설정이 있어도 다크로 열리며 배율·프로젝트 접힘 상태는 유지한다.
- 달력의 날짜나 간트 날짜 눈금·빈 행을 클릭하면 그 날짜로 일정 추가 패널이 열린다. 간트 행의 프로젝트를 우선한다.
- 시작일·종료일 옆 달력에서 날짜를 고르거나 YYYY-MM-DD로 입력한다. 저장 버튼으로 확정한다.
- 간트 프로젝트 왼쪽 화살표로 접고 펼친다. 접힌 상태를 기억하며 달력의 일정은 숨기지 않는다.
- 막대 몸통을 끌면 기간을 유지하며 이동한다. 실제 시작·끝의 손잡이는 해당 날짜만 바꾼다.
  여러 주로 나뉜 막대의 중간 경계는 손잡이가 아니다. 놓으면 저장하며 Escape·영역 밖 드롭으로 취소한다.
  미저장 입력이 있으면 먼저 저장하거나 버린다. 간트 가장자리는 자동 스크롤, 달력 이전/다음 월 버튼 위 대기는 월 이동이다.
- `오늘`은 오늘을 선택하고 간트 날짜 영역의 맨 왼쪽에 맞춘다. 일정 전체도 계속 포함한다.
- 성공 알림은 우측 하단에 2초 표시한다. 조치가 필요한 오류는 사라지지 않는다.

## Planrail 화면·날짜 탐색 (0.3.0)

A Zinc 화면은 C안의 배치를 유지한다. 상단 폴더 아이콘은 프로젝트 목록을 연다.
목록이 길면 가운데 항목만 스크롤하며 제목·닫기·프로젝트 추가는 고정된다.
이름은 프로젝트 편집, 항목 오른쪽 +는 해당 프로젝트의 일정 추가다.

상단 날짜 입력을 클릭하면 날짜 달력이 열린다. YYYY-MM-DD 직접 입력은 Enter나 포커스 이동으로 확정한다.
날짜를 선택하면 간트는 그 날짜를 날짜 영역 맨 왼쪽에 놓고, 달력은 해당 월에서 선택 날짜를 강조한다.
이 상단 탐색은 일정 추가 패널을 열지 않는다. 반면 날짜 눈금·빈 행·달력 날짜 클릭은 기존처럼 일정 추가를 연다.
이때 클릭 위치는 그대로 유지하고 선택 날짜만 강조한다. 미저장 입력 버리기를 취소하면 기존 선택도 유지한다.
이전/다음 달은 일자를 유지하되 없는 날은 해당 월 말일로 맞춘다. 새 실행은 오늘부터 시작한다.
달력 일정 드래그로 월을 탐색할 때는 선택 날짜를 바꾸지 않는다. 취소해도 탐색한 월은 남으며,
상단 날짜·오늘 등으로 다시 탐색하면 선택 날짜의 월로 맞춘다.

간트 날짜 영역에서 Ctrl+휠로 확대·축소한다. 기본 1일28px, 범위14~84px이며 마지막 배율을 기억한다.
포인터 아래 날짜를 기준으로 확대한다. 하단 배율 숫자를 클릭하거나 키보드로 실행하면 100%로 복귀하며 현재 왼쪽 날짜를 유지한다. 100%를 지나갈 때 자동으로 멈추지는 않는다. 일반 휠은 세로 이동, 가로 휠·Shift+휠은 가로 이동이다.
Space를 누른 채 왼쪽 마우스로 끌면 현재 표시 범위 안에서 가로 이동하며 일정 날짜를 바꾸지 않는다.
Space·마우스를 놓거나 Escape·창 포커스 이탈로 이동을 끝낸다. 달력은7열을 유지한다.

툴팁은 상단의 테마·프로젝트 추가·일정 추가·프로젝트 목록·간트·달력·오늘에만 표시한다.
다른 버튼은 접근성 이름과 기존 텍스트를 유지한다. 프로젝트·월 선택기는 키보드로 조작할 수 있다.
날짜 선택기는 입력 옆에 겹쳐 열려 폼을 밀지 않는다. 중첩 목록은 Escape로 안쪽부터 닫는다.
한국어·월요일 시작, YYYY-MM-DD와0001~9999년 직접 입력을 지원한다.

## 창 숨김과 종료

0.6.8부터 X/Alt+F4는 질문 없이 창을 트레이로 숨긴다.
창 숨김은 편집 중인 입력·날짜·화면 위치·진행 중인 저장·일정 알림을 유지한다.
‘완전 종료’는 저장 완료를 기다리고 미저장 입력을 버릴지 확인한다. 완전히 종료하면 일정 알림을 보내지 않는다.
트레이 아이콘을 클릭하거나 메뉴의 ‘Open’를 선택하면 같은 창을 복원한다. 시작 메뉴에서 다시 실행해도 기존 창을 연다.
최소화 버튼은 작업 표시줄 최소화다. 로그인 자동 실행은 추가하지 않았다.

트레이 메뉴의 ‘Exit’는 저장 중이면 기다리고, 미저장 입력이 있으면 창을 복원해 버릴지 확인한다.
취소하면 편집을 계속한다. Windows 설정에 따라 아이콘은 알림 영역 또는 숨겨진 아이콘에 표시된다.
트레이 생성 실패가 안내되면 닫기 선택창에서 완전 종료·취소만 제공한다.
트레이 메뉴의 ‘About’은 앱 아이콘·설치 버전·개발자 daeyong·저작권·설명을 보여준다. 편집 중 입력을 바꾸지 않는다.
OS 강제 종료나 전원 손실 때 저장하지 않은 입력까지 보존하는 기능은 아니다.

## 달력 미리보기와 창 크기 (0.5.0)

달력에서 일정을 끌거나 양 끝을 조절하면 원래 막대는 흐려지고, 예상 위치·기간은 반투명 막대로 표시된다.
포인터 옆에 예상 시작일·종료일이 나타난다. 겹친 일정의 3줄 제한과 별개로 미리보기를 표시하며,
화면에 보이는 인접 월 날짜에도 표시한다. 놓기 전에는 저장하지 않으며 영역 밖에 놓으면 취소한다.

기본 창 크기는 1707×890 논리 단위이며 Windows 배율과 모니터 작업 영역에 맞춰 줄어들 수 있다.
마지막 창 크기는 저장하지 않는다. 트레이 복원은 기존 창 크기를 유지한다.
간트의 배율과 가로 이동 막대는 작업 영역 맨 아래에 유지하며 본문만 세로로 스크롤한다.
편집 패널을 닫을 때 키보드 위치는 복원하되 툴팁은 자동으로 띄우지 않는다. 실제 마우스 오버·키보드 탐색에서는 표시한다.

## 일정 알림 (0.4.0)

일정 추가·편집의 날짜 아래에서 ‘며칠 전’과 ‘알림 시각’을 입력하고 시작일/종료일 알림을 선택한 뒤 저장한다.
초기값은 2일 전·09:00이며 둘 다 꺼져 있다. N은 주말·공휴일을 포함한 0~365일이고 0은 당일이다.
시작·종료는 같은 N과 시각을 사용한다. 시각은 PC 현지 24시간제 HH:mm이며 시간대가 바뀌면 현지 시각을 따른다.
예를 들어 11월 11일 시작·2일 전·09:00이면 11월 9일 오전 9시 이후 평가에서 알린다.

앱이 실행 중이거나 트레이에 있을 때 Windows 일반 알림을 보낸다. 트레이의 ‘Exit’를 선택한 뒤에는 보내지 않는다.
다시 실행하거나 절전에서 돌아오면 오늘 시각을 놓친 미처리 알림만 제공하며 어제 이전 것은 보내지 않는다.
같은 일정의 시작·종료가 같은 시각이면 하나로 합치며 여러 일정은 개별 전달한다.
Windows 알림 설정·방해 금지·회사 정책에 따라 배너와 소리가 제한될 수 있다. 반복해서 울리는 알람은 아니다.

알림에는 프로젝트명·일정명·대상 날짜가 표시되며 잠금 화면 노출 여부는 Windows 설정을 따른다.
실행 중 알림을 클릭하면 해당 일정 편집을 연다. 미저장 입력이 있으면 버리기 확인을 하고 취소하면 입력을 보존한다.
완전히 종료된 앱을 과거 알림 센터 항목으로 다시 실행하는 동작은 지원하지 않는다.

날짜·N·시각을 변경하면 새 예정으로 평가한다. 이름 변경이나 동일 설정을 껐다 켜는 동작은 이미 처리한 알림을 반복하지 않는다.
간트·달력 드래그도 기존 알림을 유지한다. 알림 날짜가 0001-01-01 이전으로 내려가면 날짜 변경을 저장하지 않으므로 알림 설정을 먼저 조정한다.

전송 실패 안내의 ‘오늘의 실패한 알림 재시도’는 아직 켜져 있고 오늘 예정인 명확한 실패만 재시도한다.
결과 불명은 중복 방지를 위해 자동 재전송하지 않는다. 전송 직전 비정상 종료 때에는 알림이 누락될 수 있다.
Windows 전달과 사용자 읽음은 다르며 읽음 확인 기능은 없다.
0.4.0은 schema v2, 0.6.0은 공유용 schema v3로 업그레이드한다. 업데이트한 DB를 구버전 앱으로 되돌려 여는 것은 지원하지 않는다. 업데이트 전 앱을 정상 종료한다.

## 시작 지연 확인

정상 재실행 목표는 창 표시 3초, 조회·편집 가능 5초다. 사용자 PC 달성 여부는 아직 미확인이다.
같은 PC·같은 데이터에서 시작 메뉴 클릭부터 두 시간을 각각 반복 측정한다.
`%APPDATA%\SimpleTimeline\startup-latest.json`에는 최근 실행의 프로세스 시작 이후 구간별 시간이 남는다.
0.2.1은 지연 원인을 좁히는 진단 보강판이다. 기본 GPU 설정을 유지하며 성능 개선 완료를 뜻하지 않는다.
`schemaVersion: 2`의 `stages`·`requests`는 main Node 시작 기준 ms이며, `renderer`는 페이지 navigation 시작 기준 ms다.
두 시계의 값을 직접 빼지 않는다. requests에는 파일 종류·시작/완료 시간만 남고 경로나 일정 내용은 없다.
`window-shown`은 창 표시 요청의 이벤트이며 사용자가 실제 화면을 본 시점과 같지 않다.
이 기록은 바로가기 클릭부터 Node 초기화 전까지의 Windows 대기 시간을 포함하지 않는다.
앱 버전·소스 SHA·수동 측정 시간과 함께 기록을 제공하면 어느 구간에서 지연됐는지 비교할 수 있다.
최초 실행·복구·마이그레이션은 정상 재실행과 구분한다. 일정 내용은 진단 기록에 넣지 않는다.

## Windows 11 인수와 상세 후속 확인 항목

기본 설치·실행·업데이트·제거·재설치는 [사용자 인수 기록](user-acceptance.md)에서 확인했다.
다음 상세 항목은 사용자의 결정에 따라 별도 후속 작업으로 남겼으며 통과로 표시하지 않았다.

운영 데이터가 없는 테스트 Windows 사용자/VM에서 확인한다. 정확한 설치 파일 이름·SHA256·Windows 빌드를 기록한다.
네트워크를 끊고 설치→첫 실행→핫픽스 프로젝트와 개발/QA/배포 일정 생성→두 모드→수정·삭제→종료/재실행을 확인한다.
이후 업데이트/재설치, 제거 후 재설치의 데이터 보존을 확인한다. 100%/200% 배율·키보드·Narrator 결과도 기록한다.
손상·용량 부족·권한 실험은 운영 프로필에서 하지 않는다. 상세 절차·실행/미실행 구분은 검증 문서를 따른다.

## 사내 LAN 공유 (0.6.0)

트레이 메뉴는 연결 상태 / 구분선 / About / 구분선 / Open / Exit 순서다.
맨 위 연결 상태를 클릭하면 모든 역할에서 공유 설정을 연다. 설정을 열어도 기존 개인 편집 입력은 유지된다.

1. 대표 PC 한 대에서 ‘호스트로 공유’를 고르고 실제 공유할 LAN IPv4와 포트를 명시해 저장한 뒤 ‘공유 시작’을 누른다.
   기본 포트는 TCP47831이다. 127.0.0.1은 이 PC에서만 쓰는 주소이므로 다른 PC 연결에는 쓰지 않는다.
2. 회사 정책에 따라 호스트 프로그램/선택 포트의 수신과 멤버의 송신을 사내망 범위로 허용한다. 방화벽을 끄지 않는다.
   정책 변경이 필요하면 IT 담당자에게 선택한 IP·포트를 전달한다. DHCP 주소 변경 시 등록 IP도 명시적으로 수정한다.
3. 호스트에서 참여자 이름과 멤버 PC의 실제 IPv4를 등록한다. 멤버는 ‘멤버로 연결’에서 호스트 IP·같은 포트를 입력한다.
4. 양쪽 화면의 전체64자리 SHA-256 지문이 같은지 비교한다. 호스트의 연결 승인과 멤버의 전체 지문 확인을 모두 완료한다.
   5분이 지나면 새 시도를 시작한다. 지문이 다르면 승인하지 말고 주소·대상 PC를 확인한다.
5. 호스트의 프로젝트 편집에서 공유 저장을 선택하고 각 참여자와 승인 PC를 연결해 확인한다.
   멤버는 자신에게 허용한 프로젝트만 받으며 원본 이름·참여자·날짜·삭제·드래그는 읽기 전용이다.
   멤버는 개인 프로젝트/일정을 계속 편집하고 공유 일정의 자기 알림만 저장한다. 이 알림은 다른 PC로 보내지 않는다.

멤버의 연결 상태는 Planrail 제목 옆이다. 초록은 최근 정상 확인과 저장 완료, 빨강은 미확인·연결 오류·승인 취소다.
정상 폴링은2초, 요청 제한5초, 재연결 간격은2/4/8/16/30초이며 정상 확인 후7초를 넘겨 확인하지 못하면 빨강이다.
‘수동 동기화’는 간트/달력 바로 왼쪽이며 정상 수신과 화면 반영을 마친 뒤에만 성공을 표시한다.
전체/개인/공유 필터는 간트·달력·프로젝트 목록에 함께 적용한다. 연결 실패가 개인 저장을 막지는 않는다.
개인 일정 드래그 중에는 도착한 공유 수정·추가가 화면 위치를 흔들지 않도록 종료 뒤 반영한다.
공유 삭제·권한 회수가 확인되면 활성 미리보기를 저장 없이 취소하고 안내한 뒤 제거한다. 알림 권한 확인은 지연하지 않는다.

호스트가 멈추거나 잠들거나 앱을 완전히 종료하면 공유 제공이 중단된다. 자동 절전 방지·로그인 자동 실행·Windows 서비스는 없다.
‘공유 중지’ 상태는 재시작해도 유지하며 공유 중 종료했다면 다음 실행에 재개한다.
오래된 공유 수신본은 연결 오류 때 읽을 수 있지만 최신 확인 없이는 공유 알림을 보내지 않는다.
명시적 승인 취소나 프로젝트 접근 제거가 확인되면 해당 공유 자료·자기 알림을 제거한다.
멤버의 ‘연결 해제’는 확인 후 공유 캐시·자기 공유 알림·접속 자격만 지우며 개인 자료는 유지한다.
삭제 실패 안내가 있으면 파일 접근을 확인하고 ‘연결 해제 다시 시도’를 실행한다.
역할은 자동 전환하지 않고 호스트 이전·다른 호스트로의 자동 이동은 지원하지 않는다.

Linux의 두 격리 프로필 loopback 자동 검증은 실제 회사 LAN·Windows DPAPI·트레이 배율·알림 실기 인수를 대신하지 않는다.
Windows 11 테스트 PC에서 설치 파일 SHA·IP/포트·방화벽 범위·전체 지문·재시작/절전·승인 취소·6대/10프로젝트/60일정의5초 내 전파를 별도 확인한다.
자세한 자동 검증 범위와 남은 인수는 [구현 기록](../implementation/2026-11-10-lan-sharing.md)을 따른다.

## 다크 화면과 간트 탐색 (0.6.7)

간트 하단은 배율 조절과 가로 이동을1:8 비율로 나눈다. 왼쪽은 배율 슬라이더다. 50~300%로 조절하고 배율 숫자를 누르면100%로 돌아온다.
슬라이더를 움직일 때 왼쪽 날짜는 유지되며, Ctrl+휠은 포인터 아래 날짜를 유지한다. 배율은 재실행 후에도 유지한다.
오른쪽은 가로 이동 막대다. 기존 휠·Space+드래그·키보드 탐색도 계속 사용할 수 있다.
일반 스크롤바는 평소 숨겨져 있다가 해당 영역에 마우스를 올리거나 키보드 포커스가 들어오면 나타난다. 드래그 중에도 표시하며 배율 슬라이더는 탐색 영역에서 항상 보인다. 공유 필터에 프로젝트가 하나도 없으면 중앙 안내만 남기고 기간·날짜 눈금·하단 탐색을 숨긴다. 일정이 없는 공유 프로젝트는 행과 추가 동작을 유지한다.
토요일·일요일은 간트 날짜 눈금과 날짜 열에 옅은 붉은 배경으로 표시한다. 일정 색과 기간 계산은 유지한다.
호스트의 프로젝트 편집에서 ‘공유 프로젝트로 저장’은 스위치로 조작한다. 기존처럼 저장 버튼과 공유 확인을 거쳐야 반영된다.


## 저장 진행과 입력 오류 (0.6.7)

프로젝트·일정 추가/수정/삭제나 드래그 저장 중에는 콘텐츠를 잠시 덮고 툴바 위 얇은 막대로 진행 상태를 표시한다. 숫자 퍼센트는 표시하지 않는다. 창 이동·최소화는 사용할 수 있고 동기화만 진행 중일 때는 이 덮개를 표시하지 않는다.
저장 시 잘못된 값이 있으면 해당 입력 아래 작은 안내와 붉은 테두리를 표시하고 첫 오류로 이동한다. 값을 수정하면 다시 검사한다. DB·통신 오류나 저장 결과 불명 안내는 필드 오류와 별도로 유지되며, 안내에 따라 조회 후 처리한다.
프로젝트의 기본 정보·참여자·공유 설정은 구분선으로 나뉜다. 공유 대상 PC 선택은 각 참여자 이름 아래에서 한다. 공유 설정 창은 오른쪽 X로 닫으며 미저장 변경 보호는 유지한다.


## 목록 삭제와 알림 간편 편집 (0.6.8)

프로젝트 목록의 일정 추가 옆 휴지통을 누르면 확인창 없이 프로젝트와 하위 일정이 함께 삭제된다. 되돌리기는 제공하지 않는다. 멤버가 받은 공유 프로젝트는 삭제할 수 없다. 기존 편집 패널에서 삭제하는 경우에는 확인창을 유지한다.

간트에서 알림이 켜진 일정 이름 옆의 종 아이콘을 누르면 자신의 알림만 수정하는 작은 팝업이 열린다. N일 전·시각·시작/종료를 수정하고 저장한다. 둘 다 끄면 종 아이콘은 사라지며, 다시 켜려면 일정 편집을 사용한다. 미저장 편집이 있으면 먼저 저장하거나 취소해야 목록 삭제·빠른 알림 편집을 할 수 있다. 빠른 팝업의 변경을 저장하지 않고 닫으면 버릴지 확인한다.

### 참여자 입력·삭제와 작은 알림 스위치 (0.6.9)

공유 설정에서 이름과 IPv4 주소를 입력해 등록합니다. 잘못된 값이나 이미 사용 중인 IP는 입력 아래 안내를 확인하세요. 등록 항목과 ‘새 참여자’ 입력은 구분되어 있습니다. 0.6.10부터 이름·IP·작업 버튼을 한 줄로 표시하며 ‘승인’, ‘승인 대기’, ‘승인 취소’ 배지로 연결 승인 상태를 구분합니다.

참여자 옆 휴지통은 영향받는 공유 프로젝트를 확인한 후 등록과 모든 공유 권한을 제거합니다. 프로젝트와 일정은 지우지 않습니다. ‘승인 취소’는 등록 정보를 남기므로 차단 기록을 유지할 때 사용하세요. 삭제 후 다시 공유하려면 새로 등록하고 승인해야 합니다. 오프라인 멤버는 다음 접속 때 권한 회수를 확인합니다.

일정과 빠른 알림 설정의 시작일/종료일 옵션은 종 아이콘 옆 작은 스위치로 조작하고 저장합니다.
